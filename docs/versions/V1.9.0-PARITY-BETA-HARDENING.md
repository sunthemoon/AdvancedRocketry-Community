# v1.9.0 — Feature-Parity Beta Hardening


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

冻结经典功能范围，针对完整内容、升级链、大型服务器、真实玩家和模组组合执行 Beta 级稳定化，为 v2.0 只留下发布收敛工作。

### 玩家可见结果

- 可在长期世界和中型模组包中体验接近完整的社区迁移。
- 从 v1.0 及之后受支持版本升级到候选版。
- 已知限制、被重设计功能和不兼容项公开。

## 2. 前置 Gate

- [ ] `v1.8.0` PASSED，内容范围由 PORTING_MATRIX 与验收证据证明。
- [ ] Feature Freeze。
- [ ] reference modpack 和真实测试者名单确定。
- [ ] 所有迁移 fixture 可用。

前置版本未 `PASSED` 时，本版本只允许只读审计、测试设计和数据样例，不提前实现功能。独立 worktree 不豁免 AGENTS 的版本范围限制。

## 3. 本版范围

- 全系统回归、迁移、专服、真实多人、视觉和性能。
- v1.0→v1.9 逐版本/跨版本升级。
- reference modpack compatibility。
- 8–12 小时 soak。
- 多 GPU/OS 视觉。
- 安全/复制/恢复专项审计。
- 文档、教程、Known Issues 和支持政策。

## 4. 明确不做

- 不新增系统或大型内容。
- 不在 Beta 中做无迁移的大重构。
- 不以删除压力测试场景解决性能失败。
- 不承诺未列入矩阵的任意模组组合。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- v2.0 候选的 save/network/API/content contracts 冻结。
- 仅接受阻断修复和可观测性。
- 每个修复有回归。
- Beta 世界升级到 v2.0 是发布承诺候选。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 冻结 candidate scope/tag 命名。
2. 生成完整迁移世界矩阵。
3. 建立 reference modpack 和固定 lockfile/hash。
4. 运行全套自动测试及随机顺序/重复运行。
5. 运行 packaged server 8–12 小时 soak。
6. 执行 2–4 真实玩家长流程和断线/重启。
7. 在至少两类 GPU/OS 做视觉。
8. 执行安全、packet、NBT、chunk、duplication fuzz/边界。
9. 逐项处理缺陷，一缺陷一回归。
10. 更新文档和 PORTING_MATRIX。
11. 创建 beta/rc 并邀请外部测试。

## 7. 可并行工作流

| 工作流 | 允许写入 | 依赖/说明 |
|---|---|---|
| Migration matrix | fixtures/scripts | 独立 |
| Performance/soak | evidence host | 不改代码 |
| Compatibility | reference modpack | 独立 |
| Visual/multiplayer | client reports | 独立 |
| Security audit | 只读+tests | 独立 |
| Bugfix queue | 最小路径 | 集成串行 |

中央注册、版本、网络总入口、Gradle、`mods.toml` 和状态文件由集成任务独占。

## 8. 存档、网络与数据迁移

- 保留 v1.0、v1.1、v1.2、v1.4、v1.8 代表 fixture。
- 跨多版本升级与逐版本升级结果比较。
- Beta 中间 schema 不丢失。
- 失败可恢复并有管理员诊断。
- 迁移后全流程继续可玩，不只世界能开。

## 9. 自动测试

- [ ] 全量 tests 多次重复。
- [ ] 随机化/属性测试覆盖路线、任务、事务。
- [ ] 所有迁移 fixture。
- [ ] DataGen/release reproducibility。
- [ ] 资源/来源/registry/missing mapping。
- [ ] API test mod。
- [ ] reference modpack startup matrix。

所有勾选项必须对应实际执行命令、退出码、日志和 commit；测试代码存在不等于测试已通过。

## 10. Dedicated Server、重启与多人测试

- [ ] 8 小时 mandatory soak，12 小时推荐。
- [ ] 4 个真实客户端或至少 2 个真实 + 明确自动负载。
- [ ] 连续跨天体/跃迁/任务/终局设备。
- [ ] 周期保存、正常重启、强制停止。
- [ ] CPU/内存/磁盘/网络采样。
- [ ] 无 ticket、任务、实体或缓存泄漏。

## 11. 人工与视觉测试

- [ ] 至少两类 GPU 厂商或集显/独显组合。
- [ ] 所有高风险 GUI/天空/OBJ/大型火箭。
- [ ] 长流程后资源重载和缓存。
- [ ] 不同语言/GUI scale。
- [ ] 候选截图/视频而非旧证据。

Xvfb/LLVMpipe 只形成 `V0` 视觉冒烟证据。涉及 GUI、天空、模型、粒子或客户端性能时，必须在真实 GPU 客户端形成 `V1`；涉及多人时形成 `V2`。

## 12. 安全与滥用测试

- [ ] 独立 threat review。
- [ ] packet/NBT/坐标/权限/重放。
- [ ] 所有资源产生路径 duplication review。
- [ ] 公开 API 恶意/异常适配器。
- [ ] 高风险终局系统 grief controls。
- [ ] release supply-chain/provenance。

## 13. 性能与资源预算

- [ ] 参考服 8–12 小时满足预算。
- [ ] reference modpack 的 MSPT/P95/P99/RSS。
- [ ] 真实客户端大型场景 frame-time。
- [ ] 无单调内存增长。
- [ ] 慢操作有 profile 和修复/豁免 ADR。

## 14. 通过确认

版本只有全部满足后，才可由独立审核者标记 `READY_FOR_AUDIT`，再由维护者标记 `PASSED`：

- [ ] Feature Freeze 后零范围膨胀。
- [ ] 零 Critical/High；零未审核 Medium。
- [ ] 所有 migration/compat/soak/visual/security Gate 通过。
- [ ] PORTING_MATRIX 无 MISSING/UNKNOWN。
- [ ] Beta 测试者反馈中无发布阻断。
- [ ] v2.0 只剩版本和最终证据收敛。

## 15. 必须归档的证据

- full beta test report。
- migration matrix。
- 8–12h soak raw data。
- reference modpack lock/hash/report。
- multi-GPU visual reports。
- independent security review。
- external beta feedback index。

推荐目录：

```text
docs/releases/v1.9.0/
```

通用证据文件沿用 `MANUAL-TEST.md`、`PERFORMANCE.md`、`checksums.txt` 和
`GATE-STATUS.md`；新增迁移、视觉、安全等专项报告作为补充，不替代原 G0–G9 证据。

## 16. 推荐 PR 拆分

- PR 1：freeze/evidence scaffolding。
- PR 2：migration matrix。
- PR 3：compat/performance tooling。
- 后续每缺陷一个 PR。
- Final beta evidence PR。

每个 PR 均附：范围、非目标、迁移影响、命令实跑结果、证据路径和回退方式。

## 17. 失败与回退

- Beta tag 不重写。
- 迁移始终用副本。
- 发现系统性架构缺陷时回到对应 v1.x 修复，不伪装成文档问题。
- 未通过的内容明确移出 v2.0 承诺并经 ADR，而非静默隐藏。
