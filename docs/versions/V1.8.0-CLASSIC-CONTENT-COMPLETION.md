# v1.8.0 — Classic Content Completion


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

在扩展内核稳定后，按来源批次系统性恢复经典机器、物品、护甲、配方、模型、声音和进度，使功能矩阵从“核心闭环”走向“经典内容基本完整”。

### 玩家可见结果

- 获得接近经典版广度的科技树、机器、装备和资产。
- 配方、JEI、研究和教程形成可理解的进阶路径。
- 旧版标志性模型和声音在来源清晰的前提下恢复。

## 3. 本版范围

- 分批迁移剩余经典机器和多方块。
- 物品、护甲、组件、工具、配方和进度。
- OBJ/JSON 模型、纹理、GUI、声音和语言。
- 研究/科技树和平衡闭环。
- 每批 provenance、hash、license 和转换记录。
- PORTING_MATRIX 逐项关闭。
- 缺失/重设计/拒绝项目的 ADR。

## 4. 明确不做

- 不以“一次复制所有 assets”代替迁移。
- 不导入来源不清或许可证不兼容的社区资源。
- 不要求旧 ID/配方数值全部一模一样。
- 不默认提供 1.12.2 世界直接升级。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- 所有内容使用稳定 namespace/registry ID。
- 每批资源有来源 manifest。
- 机器必须使用 v1.2 framework 或有例外 ADR。
- 内容数据可由 DataGen/validator 校验。
- 科技树没有不可达节点或循环硬锁。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 将旧清单按系统/资产/许可证/依赖/优先级重新分类。
2. 建立 migration batches，每批规模可独立审核和回退。
3. 先恢复形成科技链缺口的机器和组件。
4. 每台机器补配方、JEI、保存、GameTest 和视觉。
5. 逐批转换模型/语言/配方/声音。
6. 建立科技树可达性和配方图分析。
7. 更新 PORTING_MATRIX 和玩家文档。
8. 对拒绝/重设计项写 ADR。
9. 进行整包启动、DataGen、资源引用和重复 ID 校验。
10. 完成内容回归世界和多人测试。

## 7. 可并行工作流

| 工作流 | 允许写入 | 依赖/说明 |
|---|---|---|
| Content batch A/B/C | 各自独立 package/assets | 来源不重叠 |
| Recipe graph | data/tools | 可并行 |
| Asset conversion | quarantine→assets | 独立审核 |
| Machine migration | 各机器任务 | 框架已冻结 |
| Docs/tutorial | docs/lang | 可并行 |
| Matrix/provenance audit | ledger/matrix | 只读+审核 |

中央注册、版本、网络总入口、Gradle、`mods.toml` 和状态文件由集成任务独占。

## 8. 存档、网络与数据迁移

- 新增/重命名 registry 有 Missing Mapping 计划。
- 移除内容前扫描代表世界。
- 旧 placeholder item/block 迁移到正式 ID。
- 配方变化不自动重写玩家库存。
- 内容包缺失时给出缺失依赖而非静默删除。

## 9. 自动测试

- [ ] 每个 registry ID 唯一。
- [ ] 所有模型/纹理/sound/lang/recipe 引用存在。
- [ ] DataGen deterministic。
- [ ] 科技树/配方图可达性。
- [ ] 每台机器最少 happy/failure/restart tests。
- [ ] 全内容 Dedicated Server sidedness。
- [ ] 资产 provenance completeness。

所有勾选项必须对应实际执行命令、退出码、日志和 commit；测试代码存在不等于测试已通过。

## 10. Dedicated Server、重启与多人测试

- [ ] 代表科技流程从基础到终局。
- [ ] 大量机器共存和区块卸载。
- [ ] 升级世界中的 placeholder/旧 ID。
- [ ] JEI 有/无。
- [ ] 模组组合 smoke matrix。
- [ ] 长时自动化生产无复制。

## 11. 人工与视觉测试

- [ ] 全部新 GUI/模型/纹理/声音抽样和高风险资产全检。
- [ ] OBJ/多方块/护甲在真实 GPU。
- [ ] 语言、GUI scale 和资源重载。
- [ ] 缺失纹理/模型零容忍。
- [ ] 发布候选科技流程录像。

Xvfb/LLVMpipe 只形成 `V0` 视觉冒烟证据。涉及 GUI、天空、模型、粒子或客户端性能时，必须在真实 GPU 客户端形成 `V1`；涉及多人时形成 `V2`。

## 12. 安全与滥用测试

- [ ] 新增机器 packet 按统一政策。
- [ ] 自动化接口不复制。
- [ ] 终局设备权限保持。
- [ ] 配方/数据包超限。
- [ ] 来源清单阻止未审计文件进入 JAR。

## 13. 性能与资源预算

- [ ] 大量方块实体 idle/active 压力。
- [ ] 复杂 OBJ/多方块客户端渲染。
- [ ] 资源包加载时间和内存。
- [ ] 科技树/JEI 大量配方响应。
- [ ] reference modpack server soak。

## 14. 通过确认

版本只有全部满足后，才可由独立审核者标记 `READY_FOR_AUDIT`，再由维护者标记 `PASSED`：

- [ ] PORTING_MATRIX 中经典内容无 UNKNOWN。
- [ ] 约定范围内无 MISSING；DEFERRED/REJECTED 均有 ADR。
- [ ] 所有导入资产来源完整。
- [ ] 完整科技链可达且可玩。
- [ ] 全内容资源/专服/视觉/性能通过。
- [ ] 零 Critical/High。

## 15. 必须归档的证据

- updated PORTING_MATRIX。
- batch provenance manifests。
- recipe graph report。
- full progression report/video。
- asset validation。
- modpack performance/compat report。

推荐目录：

```text
docs/releases/v1.8.0/
```

通用证据文件沿用 `MANUAL-TEST.md`、`PERFORMANCE.md`、`checksums.txt` 和
`GATE-STATUS.md`；新增迁移、视觉、安全等专项报告作为补充，不替代原 G0–G9 证据。

## 16. 推荐 PR 拆分

- 每个来源批次独立 PR。
- 每组 1–3 台相关机器独立 PR。
- 科技树/配方图独立 PR。
- 最终矩阵和内容冻结 PR。
- 候选 hardening/release PR。

每个 PR 均附：范围、非目标、迁移影响、命令实跑结果、证据路径和回退方式。

## 17. 失败与回退

- 资产批次可整批回退。
- registry 删除前必须提供迁移。
- 不稳定机器可临时禁用；发布范围的 DEFERRED 必须有批准 ADR、迁移策略和玩家影响说明。
- 来源争议立即隔离文件，不继续分发。
