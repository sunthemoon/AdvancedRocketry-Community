# v1.5.0 — Orbital, Station & Warp Systems


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

把基础空间站扩展为围绕任意天体的轨道基础设施，并实现受控、多阶段、可恢复的恒星系/跃迁旅行。

### 玩家可见结果

- 可在不同天体轨道建造和访问空间站。
- 空间站显示轨道环境、太阳能和重力条件。
- 通过跃迁核心在已解锁恒星系之间移动或重新定位。

## 3. 本版范围

- 任意天体 orbit context。
- 空间站创建/扩建/所有权/团队权限。
- 轨道参数、光照/太阳能和可选重力。
- 跃迁核心、能源/燃料、目标和倒计时。
- 多恒星系 catalog 和星际路线。
- 空间站/乘客/停靠火箭跃迁事务日志。
- 失败、重启和回滚。
- 基础空间电梯连接契约，可不完整实现。

## 4. 明确不做

- 不实现所有终局空间站机器。
- 不允许无成本即时传送。
- 不让跃迁加载整个目标区域。
- 不在本版完成完整太空电梯物流。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- station ID 与区域位置稳定。
- 轨道上下文来自 body/station resolver。
- 跃迁是持久化状态机和事务，不是一次 teleport。
- 所有权/邀请/团队权限服务端权威。
- 目标不可用时保留站点和资产。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 扩展 StationRecord schema 和 v1.4 migration。
2. 实现 orbit environment provider。
3. 实现 station region 分配、扩容和冲突检查。
4. 实现轨道光照/太阳能/重力规则。
5. 定义 WarpPlan、WarpState 和 journal。
6. 实现能源锁定、倒计时、目标准备、成员/火箭迁移、提交。
7. 实现每阶段重启恢复和管理员诊断。
8. 加入多恒星系数据与解锁。
9. 实现 UI/反馈/权限。
10. 建立空间电梯端点 contract 和占位验证，不扩大范围。
11. 压力测试多站点和并发跃迁。

## 7. 可并行工作流

| 工作流 | 允许写入 | 依赖/说明 |
|---|---|---|
| Station schema/region | `station/model/**`, `station/region/**` | 先冻结 |
| Orbit environment | `station/orbit/**` | 依赖 BodyContext |
| Warp transaction | `station/warp/**` | 单一核心写入者 |
| Permissions/UI | `station/access/**`, client | 与 transaction 分离 |
| Multi-star data | celestial data | 可并行 |
| Recovery/tests | fixtures/scripts | 独立 |

中央注册、版本、网络总入口、Gradle、`mods.toml` 和状态文件由集成任务独占。

## 17. 失败与回退

- 跃迁失败保持原站点为权威，除非 journal 已明确提交目标。
- 目标站创建后源站删除遵循双实体恢复判定。
- 区域冲突阻止加载而非覆盖。
- 可独立禁用 warp，不影响基础站点访问。

其中目标复制/源删除是原计划的物理迁移假设，不是已冻结协议。跃迁实现前必须以独立
ADR 选择固定区域的轨道重定位或有界物理迁移，并明确乘客、停靠/在途火箭及资源恢复。
ADR-040 只冻结站点基础，不允许仅修改 `orbit_body` 代替这些结果。
