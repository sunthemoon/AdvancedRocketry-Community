# v1.0.0 — Stable Core MVP 完整发布验证


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

在严格 Feature Freeze 下，把当前 `v0.9.0-beta.1` 的地月核心闭环收敛为可重复构建、可升级、可恢复、经过真实客户端和真实多人验证的第一个稳定版本。`v1.0.0` 不承担扩展内核重构。

### 玩家可见结果

- 从全新安装开始完成电解、供氧、造火箭、地月往返、空间站和基础卫星流程。
- 服务器重启、玩家断线和关键事务中断后，核心资产与玩家状态可恢复。
- 最近一次受支持 Beta 世界可安全升级到稳定版。
- 玩家能在发布页清楚看到非官方身份、支持范围、已知限制和问题入口。

## 2. 前置 Gate

- [x] `v0.9.0` 在不可变的 `docs/releases/v0.9.0/GATE-STATUS.md` 中为 `PASSED`，候选 commit/JAR/证据可定位。
- [x] `docs/PORTING_MATRIX.md` 已与真实实现对齐；十条历史核心行的批准和测试见 `docs/work/v1.0.0-core-baseline-audit.md`。
- [x] Feature Freeze 已记录在 `docs/work/v1.0.0-implementation-log.md`：只允许稳定、测试、迁移、文档、可观测性和安全修复。
- [ ] 指定发布负责人、独立审核者和至少一位未参与实现的安装测试者。

前置版本未 `PASSED` 时，本版本只允许只读审计、测试设计和数据样例，不提前实现功能。独立 worktree 不豁免 AGENTS 的版本范围限制。

## 3. 本版范围

- 清理并冻结版本、manifest、mods.toml、README、CHANGELOG、NOTICE 和发布声明。
- 补齐真实客户端、真实双人、真实 GPU 和候选版截图/录像证据。
- 验证 `v0.9.0-beta.1 → v1.0.0` 的代表性存档迁移。
- 验证火箭组装、拆解、跨维度事务的分阶段强制停止与恢复。
- 验证 baseline Forge 与 compatibility lane，JEI 有/无组合。
- 验证干净客户端、打包专服、全新世界和升级世界。
- 完成发行制品可重现、hash、tag、Release 和 `1.0.x` 维护政策。

## 4. 明确不做

- 不新增火星、金星、多恒星、跃迁或完整卫星种类。
- 不把 `RocketDestination` 改为新扩展模型；留给 `v1.1`。
- 不建立完整通用机器/多方块框架；留给 `v1.2`。
- 不承诺直接加载 1.12.2 世界。
- 不进行大规模目录重排或纯审美重构。
- 不宣称“完整 Advanced Rocketry 移植”。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- 现有地球、月球、空间维度和空间站行为作为 `v1.0` 兼容基线。
- 保存 schema、火箭事务日志、空间站/卫星数据必须有已记录版本。
- 客户端不决定燃料、目的地、权限、资源结果或事务提交。
- `v1.0.x` 只接受兼容性、安全、迁移和缺陷修复，不引入破坏性玩法重构。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 创建符合仓库命名规则的 v1.0.0 工作分支，记录 Feature Freeze 和候选基线。
2. 更新 `PORTING_MATRIX`、PRODUCT、README、CURRENT_VERSION、Known Issues，使公开声明和代码一致。
3. 创建包含运行中电解机、密闭房间、已加油火箭、月球火箭、空间站、卫星任务和研究状态的 `v0.9` 代表世界。
4. 从世界副本执行迁移；比较迁移前后资源、实体、任务、权限和 schema。
5. 对组装、拆解和跨维度事务的每个持久化阶段执行真实强制停止与恢复。
6. 在经审计的 Debian 12 或等价节点运行全套 headless、打包专服和至少 4 小时参考负载 soak。
7. 使用两个真实 Minecraft 客户端完成在线模式地月往返、乘客掉线/重连、空间站和卫星流程。
8. 在真实 GPU 上测试 64/512/2048 方块火箭、GUI scale、天空、模型、粒子和缓存释放。
9. 创建 `rc1`，禁止再合入非阻断修复；独立审核 G0–G9。
10. 从干净候选 commit 重建制品，核对 SHA-256、JAR 内容、许可证和来源。
11. 由未参与开发的人按 README 从零安装一次。
12. 人工批准且 RELEASE-EVIDENCE 完整后创建不可变 tag，再从该 tag 重建并比较同一制品，发布正式 GitHub Release。

## 7. 可并行工作流

| 工作流 | 允许写入 | 依赖/说明 |
|---|---|---|
| Release/documentation | `README.md`, `CHANGELOG.md`, `docs/releases/v1.0.0/**` | 不修改运行时代码 |
| Migration/recovery | `scripts/**`, `tests/fixtures/**`, migration tests | 独占代表世界和恢复脚本 |
| Dedicated/performance | 测试脚本与 evidence | 不得降低负载以规避失败 |
| Visual/multiplayer | 报告与截图目录 | 使用真实客户端，不改代码 |
| Bugfix | 缺陷明确涉及的最小路径 | 一缺陷一任务，需回归测试 |
| Independent audit | `docs/work/<audit>/**` | 只读产品代码 |

中央注册、版本、网络总入口、Gradle、`mods.toml` 和状态文件由集成任务独占。

## 8. 存档、网络与数据迁移

- 保留不可修改的 `v0.9.0-beta.1` 原始世界 fixture 和 JAR hash。
- 迁移在副本上运行，失败不得覆盖原世界。
- 核对机器进度/库存/流体、火箭结构/燃料/乘客/位置、站点权限、卫星任务、研究和大气状态。
- 重复打开迁移后的世界不得再次扣减、复制或重置数据。
- 记录 `v1.0` 对未来 `v1.1` 的迁移入口，但不提前改变目标模型。
- 协议不兼容时明确拒绝旧客户端，而不是部分连接。

## 11. 人工与视觉测试

- [ ] 候选版重新制作截图/视频，不沿用旧 Beta 证据。
- [ ] 真实 GPU 环境记录 OS、GPU、驱动、分辨率、GUI scale。

Xvfb/LLVMpipe 只形成 `V0` 视觉冒烟证据。涉及 GUI、天空、模型、粒子或客户端性能时，必须在真实 GPU 客户端形成 `V1`；涉及多人时形成 `V2`。

## 12. 安全与滥用测试

- [ ] 重放发射、拆解、目的地和空间站请求被安全拒绝。
- [ ] 伪造远距离坐标不触发任意区块加载。
- [ ] 第三方/超大 BlockEntity NBT 被拒绝且世界不丢失。
- [ ] 越权玩家不能控制、拆解或改道他人火箭/空间站。
- [ ] 异常 packet 不回显巨大内容或造成日志洪水。
- [ ] Release JAR 不含 token、绝对路径、测试世界或私有日志。

## 13. 性能与资源预算

- [ ] 4 vCPU/8 GiB 参考服满足 `docs/17-*` 的 MSPT/RSS 预算或有批准 ADR。
- [ ] 2048 方块火箭组装/拆解有明确耗时和主线程尖峰记录。
- [ ] 16 个大气设备和多个密闭体不导致无界队列。
- [ ] 真实 GPU 报告记录三档火箭 FPS/1% low/缓存。
- [ ] 4 小时 soak 后内存无持续单调增长。
- [ ] 所有缓存可在实体删除、跨维度和资源重载后释放。

## 16. 推荐 PR 拆分

- PR 1：文档/矩阵对齐与 Feature Freeze。
- PR 2：迁移和恢复测试补强。
- PR 3：专服/多人/视觉证据基础设施。
- PR 4+：每个候选阻断缺陷单独修复。
- PR Final：只包含版本、最终证据、hash 和 release metadata。

每个 PR 均附：范围、非目标、迁移影响、命令实跑结果、证据路径和回退方式。

## 17. 失败与回退

- Critical/High 立即撤销候选推荐，保留不可变失败证据。
- 迁移失败只处理副本；原 fixture 永不修改。
- 发布后 Critical 使用 `v1.0.1` 修复，不重写 `v1.0.0` tag/JAR。
- 任何新重构需求推迟到 `v1.1`，不得借修复名义扩大 v1.0 diff。
