# v1.7.0 — Endgame Systems


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

以独立垂直切片恢复高级终局系统，并为每种高破坏性或高资源系统建立权限、上限、事务和服务器性能边界。

### 玩家可见结果

- 可使用轨道激光、黑洞发电、重力控制和高级轨道设施等代表终局系统。
- 高风险设备有清楚的权限、能源、范围和失败反馈。

## 2. 前置 Gate

- [ ] `v1.2` machine kernel PASSED。
- [ ] `v1.3` public API PASSED。
- [ ] `v1.6.0` PASSED，orbit/mission context 已冻结。
- [ ] 每个终局系统有独立 ADR 和威胁模型。

前置版本未 `PASSED` 时，本版本只允许只读审计、测试设计和数据样例，不提前实现功能。独立 worktree 不豁免 AGENTS 的版本范围限制。

## 3. 本版范围

- 轨道激光/采矿代表实现。
- 轨道炮或目标系统（按安全范围）。
- 黑洞发电或等价高阶能源。
- 重力控制器。
- 空间电梯基础物流闭环。
- 高级多方块与终局配方。
- 权限、保护区、速率、能耗和审计日志。

## 4. 明确不做

- 不一次把所有系统塞入单 PR。
- 不允许无限区块破坏、无限能量或离线无界运行。
- 不绕过服务器/领地保护集成点。
- 不为追求旧版完全一致保留明显复制或崩服行为。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- 每个系统独立 enable/config。
- 破坏性操作服务端验证目标、权限、加载状态和预算。
- 能量/资源扣除和效果提交事务化。
- 跨维度目标使用 TravelTarget/BodyContext。
- 操作有审计事件和管理员诊断。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 为每个候选终局系统建立旧行为、重设计和风险清单。
2. 按优先级一次只实现一个垂直切片。
3. 先实现纯逻辑/事务，再接机器、UI 和视觉。
4. 加入领地/权限扩展事件。
5. 加入范围、每 tick 方块数、队列和停机保护。
6. 实现重启/中断/目标区块卸载恢复。
7. 完成真实多人滥用测试。
8. 每个系统独立性能基准后再开始下一个。
9. 汇总终局平衡和配置文档。

## 7. 可并行工作流

| 工作流 | 允许写入 | 依赖/说明 |
|---|---|---|
| System A vertical slice | 独立 package | 单一负责人 |
| System B analysis | 只读/docs | 不得提前合入 |
| Permission/audit | `security/**`, `events/**` | 共享 contract先冻结 |
| Multiblock/content | 对应机器包 | 依赖逻辑 |
| Visual | client package | 独立 |
| Abuse/performance | tests/evidence | 独立审核 |

中央注册、版本、网络总入口、Gradle、`mods.toml` 和状态文件由集成任务独占。

## 8. 存档、网络与数据迁移

- 每个系统初次引入带 schema。
- 配置禁用后保存对象保持但不运行。
- 处理中任务升级后只结算一次。
- 旧占位/研究解锁映射。
- 移除或重命名资产有 Missing Mapping/数据迁移计划。

## 9. 自动测试

- [ ] 权限/保护/范围矩阵。
- [ ] 资源扣除与效果原子性。
- [ ] 每个状态阶段 crash recovery。
- [ ] 目标卸载/删除/跨维度。
- [ ] 配置禁用/重启。
- [ ] 队列上限和速率限制。
- [ ] 异常/恶意 packet。

所有勾选项必须对应实际执行命令、退出码、日志和 commit；测试代码存在不等于测试已通过。

## 10. Dedicated Server、重启与多人测试

- [ ] 多人争用同目标。
- [ ] 非所有者/非 OP 越权。
- [ ] 服务器在方块处理批次中停止。
- [ ] 大范围请求被分批或拒绝。
- [ ] 保护模组测试适配或事件模拟。
- [ ] 长时设备运行无 ticket/cache 泄漏。

## 11. 人工与视觉测试

- [ ] 目标选择/危险确认/进度/失败。
- [ ] 激光、黑洞、重力和电梯视觉不遮挡关键反馈。
- [ ] 多个设备同时可见性能。
- [ ] GUI scale 和色盲/文本可读性基本检查。
- [ ] 真实 GPU，不以 LLVMpipe 性能放行。

Xvfb/LLVMpipe 只形成 `V0` 视觉冒烟证据。涉及 GUI、天空、模型、粒子或客户端性能时，必须在真实 GPU 客户端形成 `V1`；涉及多人时形成 `V2`。

## 12. 安全与滥用测试

- [ ] 威胁模型覆盖 grief、duplication、chunk loading、packet spam。
- [ ] 默认配置保守。
- [ ] 审计日志不泄漏敏感坐标给无权限玩家。
- [ ] 目标确认不接受客户端最终结果。
- [ ] 高风险功能可由服务器完全禁用。

## 13. 性能与资源预算

- [ ] 每系统独立 MSPT/内存/区块票预算。
- [ ] 大范围操作分 tick。
- [ ] 视觉效果有粒子/网格上限。
- [ ] 设备 idle 成本低。
- [ ] 参考服长时运行无 watchdog。

## 14. 通过确认

版本只有全部满足后，才可由独立审核者标记 `READY_FOR_AUDIT`，再由维护者标记 `PASSED`：

- [ ] 至少约定的代表终局系统各自形成完整闭环。
- [ ] 所有高风险系统有 ADR、威胁模型、配置和审计。
- [ ] 权限/保护/恢复/性能通过。
- [ ] 禁用功能不会破坏世界加载。
- [ ] 零 Critical/High。

## 15. 必须归档的证据

- 每系统 ADR/threat model。
- permission/abuse report。
- forced-stop recovery。
- performance/visual report。
- configuration docs。
- classic behavior comparison。

推荐目录：

```text
docs/releases/v1.7.0/
```

通用证据文件沿用 `MANUAL-TEST.md`、`PERFORMANCE.md`、`checksums.txt` 和
`GATE-STATUS.md`；新增迁移、视觉、安全等专项报告作为补充，不替代原 G0–G9 证据。

## 16. 推荐 PR 拆分

- 每个终局系统至少拆为 logic、integration、visual/tests 三个 PR。
- 公共权限/审计框架单独 PR。
- 最终平衡/迁移/release PR。

每个 PR 均附：范围、非目标、迁移影响、命令实跑结果、证据路径和回退方式。

## 17. 失败与回退

- 每个系统可独立配置禁用。
- 破坏操作失败时不返还与保留效果同时发生。
- 无法确定事务状态时停止设备并生成诊断。
- 高风险系统不稳定时阻断候选；范围调整须经批准 ADR 并更新公开功能矩阵，不静默移除 Required Gate。
