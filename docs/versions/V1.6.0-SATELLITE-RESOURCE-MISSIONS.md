# v1.6.0 — Satellites & Resource Missions


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

把基础逻辑卫星扩展为可构造、可部署、可恢复的卫星与资源任务体系，并恢复小行星、扫描和气态巨行星等经典任务路径。

### 玩家可见结果

- 可组装和部署多种卫星。
- 可执行矿物/生物群系/数据扫描、太阳能和资源任务。
- 可发起小行星或气体采集任务并取得受控奖励。

## 3. 本版范围

- 卫星组件与组装验证。
- 数据、扫描、太阳能等代表卫星类型。
- 离线/异步任务调度器。
- 小行星任务定义和实例生命周期。
- 气态巨行星采集。
- 发现/研究与任务解锁。
- 资源表、随机种子和可重现奖励。
- 任务取消、重启和超时恢复。

## 4. 明确不做

- 不永久强制加载远程任务区块。
- 不让离线补算产生无限奖励。
- 不在本版实现所有轨道终局武器。
- 不使用真实世界时间作为唯一任务真相。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- 任务 ID/seed/开始 tick/完成 tick 持久化。
- 任务结算服务端权威且幂等。
- 离线补算有上限和预算。
- 奖励生成版本化并可审计。
- 实例区域创建/回收事务化。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 定义 satellite blueprint/component stats。
2. 实现代表卫星类型与部署流程。
3. 扩展 scheduler：队列、预算、离线补算、幂等结算。
4. 实现扫描结果和发现状态。
5. 实现 resource mission definition 和 loot snapshot/version。
6. 实现 asteroid mission instance 或逻辑任务方案。
7. 实现 gas giant harvesting。
8. 接入 UI、研究和星图。
9. 建立取消、模组升级、定义移除和重启恢复。
10. 压力测试 500/1000 任务和多玩家。

## 7. 可并行工作流

| 工作流 | 允许写入 | 依赖/说明 |
|---|---|---|
| Satellite assembly | `satellite/assembly/**` | 独立 |
| Scheduler | `mission/scheduler/**` | 核心单写 |

## 8. 存档、网络与数据迁移

- 基础 v1.0 卫星记录映射到新 blueprint/type。
- 进行中的旧任务保持既定完成时间/奖励版本。
- 删除任务定义时保留 snapshot 并可结算/取消。
- 重复加载/回放不会二次发奖。
- 旧研究/发现状态保持。

## 17. 失败与回退

- 结算状态不确定时进入人工可诊断 quarantine，不重复发奖。
- 实例创建失败退回任务/组件。
- 任务定义可禁用，不删除已存在 snapshot。
- scheduler 超载时延后，不无界追赶。
