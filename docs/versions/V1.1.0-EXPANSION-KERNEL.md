# v1.1.0 — Expansion Kernel


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

解除 Core MVP 中目的地、路线和“一维度对应一天体”的硬编码，建立可数据驱动扩展的旅行与环境定位内核，同时无损升级 `v1.0` 世界。

### 玩家可见结果

- 项目可以通过数据定义新增测试天体和路线，而无需增加 Java 枚举分支。
- 同一个共享空间维度中，不同空间站可以属于不同天体轨道。
- 现有地月旅行和空间站行为保持兼容。

## 2. 前置 Gate

- [ ] `v1.0.0` PASSED，稳定 JAR、save fixture 和协议基线可用。
- [ ] 完成目的地/天体定位 ADR。
- [ ] 冻结 `TravelTarget`、`BodyContext`、route schema 草案。

前置版本未 `PASSED` 时，本版本只允许只读审计、测试设计和数据样例，不提前实现功能。独立 worktree 不豁免 AGENTS 的版本范围限制。

## 3. 本版范围

- `RocketDestination enum` 迁移为稳定 `ResourceLocation`/typed target。
- 定义 `TravelTarget`：天体表面、轨道、空间站、任务实例。
- 数据驱动 `RouteDefinition` 和路线校验/规划器。
- 定义 `WorldLocation` 与 `BodyContext`，支持 Level + Position + Region 定位。
- 共享空间维度中的轨道区域索引。
- 空间站围绕任意已定义天体。
- `v1.0 → v1.1` 保存和网络迁移。
- 拆分目的地/转移相关大型管理器的职责。

## 4. 明确不做

- 不正式发布完整火星玩法。
- 不实现跃迁、多恒星或小行星任务。
- 不恢复大量旧机器。
- 不改变玩家已验证的地月燃料平衡，除非单独 ADR。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- 所有持久化目标使用稳定命名 ID，不依赖枚举序号。
- `TravelTarget` 具有版本化 Codec/NBT 和最大尺寸。
- 运行时环境查询通过 `BodyContextResolver`，业务代码不直接假定 `level == body`。
- 路线定义来自验证后的数据，服务端权威计算可达性和成本。
- 未知目标不会自动回退到地球；必须安全拒绝并保留资产。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 冻结旧 `RocketDestination` 的行为映射和 v1.0 fixture。
2. 实现 `TravelTarget` 与 round-trip Codec/NBT，不接入运行时。
3. 实现 `RouteDefinition`、唯一 ID、端点校验、循环/不可达诊断。
4. 实现 `BodyContextResolver` 接口及 Level/region/station resolver 链。
5. 建立共享空间维度轨道区域索引与冲突检测。
6. 改造空间站数据，使 `orbitedBodyId` 支持任意天体。
7. 在适配层中把旧 enum 路线迁移到新 target，不一次性重写所有调用者。
8. 逐步迁移飞行规划、网络、事务日志和 GUI。
9. 加入仅用于测试的 `test_mars` 和两条数据路线，证明无需改 Java 枚举。
10. 实现 v1.0 save migrator、双写/读旧策略或一次性迁移策略，并冻结。
11. 删除生产代码中剩余的 enum switch；保留迁移器中的旧值映射。
12. 执行完整地月回归、共享空间多轨道测试和候选迁移。

## 7. 可并行工作流

| 工作流 | 允许写入 | 依赖/说明 |
|---|---|---|
| Target/Codec | `travel/model/**`, unit tests | 先冻结 |
| Route data | `travel/route/**`, datapack tests | 依赖 target schema |
| Body context | `celestial/context/**` | 可与 route 并行 |
| Station region | `station/orbit/**` | 依赖 BodyContext contract |
| Migration | `migration/v1_1/**`, fixtures | 只读 v1.0 fixture |
| UI/network adaptation | 对应 client/network 小范围 | 等待 contracts frozen |

中央注册、版本、网络总入口、Gradle、`mods.toml` 和状态文件由集成任务独占。

## 8. 存档、网络与数据迁移

- 旧 `EARTH/MOON/SPACE_STATION` 映射到稳定 target ID。
- 旧飞行中事务必须在原语义下恢复，再写入新格式，不能中途改道。
- 空间站旧 `orbitedBody` 缺失时按明确规则迁移并记录 warning。
- 旧客户端与新协议明确不兼容或通过显式适配，不做隐式猜测。
- 迁移后保存一次，再次加载结果完全一致。

## 17. 失败与回退

- 在适配期保留只读旧 target decoder，直到 v1.1 稳定。
- 迁移失败保留 v1.0 原值并阻止危险启动。
- 若共享空间定位失败，禁止发射而不是回退默认天体。
- 不能通过测试时回退接入提交，不删除新 contract 测试。
