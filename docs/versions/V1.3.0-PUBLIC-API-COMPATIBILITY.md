# v1.3.0 — Public API & Compatibility Kernel


> 平台：Minecraft 1.20.1 / Forge / Java 17
> 版本策略：实现、审核和人工批准分离
> 适用规约：`AGENTS.md`、`docs/05-MASTER-TEST-PLAN.md`、`docs/06-RELEASE-AND-ACCEPTANCE-GATES.md`、`docs/14-PARALLEL-DEVELOPMENT-AND-WORKTREE-COORDINATION.md`、`docs/17-V1PLUS-QUALITY-BUDGETS.md`


## 1. 版本目标

建立最小、版本化、可验证的公共扩展 API，使其他模组能安全接入火箭、大气、装备、燃料和天体环境，而无需修改主模组源码。

### 玩家可见结果

- 常见第三方容器可通过适配器安全随火箭移动。
- 模组包作者可以注册燃料、气密方块、氧气装备和火箭组件。
- 不受支持的扩展会给出明确诊断而不是复制或丢失。

## 3. 本版范围

- Rocket BlockEntity adapter registry。
- Rocket movable/immovable predicate/tag/API。
- Airtight block 与 atmosphere boundary API。
- Suit/oxygen provider API。
- Fuel/engine/component definition API。
- Environment/gravity/body-context query API。
- Satellite component/mission extension point。
- 独立 compatibility test mod。
- API version、文档、示例和兼容矩阵。

## 4. 明确不做

- 不保证任意第三方方块实体都能移动。
- 不暴露内部 manager 可变集合。
- 不让外部 API 绕过服务端验证。
- 不承诺 `v1.x` 永不调整；按公开弃用策略演进。

任何非目标若要提前，必须单独 ADR，明确存档、网络、兼容、安全和回退影响。

## 5. 本版待冻结契约

- 外部代码只通过 API 接口/事件/registry，不依赖 internal 包。
- 适配器执行有大小、耗时和异常隔离。
- 序列化数据带 namespace/version。
- API 查询默认只读；改变世界的操作由服务端 command/service 验证。
- API 与实现包在源码结构和文档上明确分离。

契约冻结后，下游任务只能通过变更提案请求调整，不能在各自 worktree 中自行改变公共语义。

## 6. 详细实施顺序

1. 定义 API surface inventory，标记 internal/public。
2. 实现 API version 和 compatibility handshake。
3. 实现 BlockEntity adapter 生命周期：canMove、capture、sanitize、restore、rollback。
4. 实现气密与装备 provider registry。
5. 实现 fuel/engine/component 数据和注册入口。
6. 实现只读 environment/context query。
7. 实现卫星扩展最小契约。
8. 创建独立 `compat-test-mod`，不引用 internal 包。
9. 加入故障适配器、超大 NBT、异常抛出和延迟适配器测试。
10. 撰写 API 文档、示例、弃用和支持政策。

## 8. 存档、网络与数据迁移

- 现有 Vanilla 容器适配迁移到 registry，但行为不变。
- 旧 tag 和配置继续读，写入新 namespace/version。
- API 版本不匹配时给出单一清晰错误。
- 保存中含已卸载外部模组数据时，默认保留 opaque 数据或安全隔离，不静默删除。

- [ ] 主模组 + test mod 全新启动/重启。

## 11. 人工与视觉测试

- [ ] 自定义燃料/组件名称和图标正常。
- [ ] 不支持的 BlockEntity 在组装界面给出原因。
- [ ] 外部氧气装备反馈与原装备一致。
- [ ] 缺少客户端可选集成时专服仍可运行。

Xvfb/LLVMpipe 只形成 `V0` 视觉冒烟证据。涉及 GUI、天空、模型、粒子或客户端性能时，必须在真实 GPU 客户端形成 `V1`；涉及多人时形成 `V2`。

## 12. 安全与滥用测试

- [ ] 适配器 NBT 白名单/大小上限。
- [ ] 异常外部代码不使事务部分提交。
- [ ] API 不暴露任意 chunk loading。
- [ ] registry freeze 后拒绝运行时不安全修改。
- [ ] 公开事件不能重复扣料或重复发奖。

## 13. 性能与资源预算

- [ ] 适配器只在组装/拆解等边界调用，不每 tick 全量序列化。
- [ ] environment query 有受控缓存。
- [ ] test mod 提供故意慢适配器并验证告警/限制。
- [ ] 兼容层在无外部扩展时成本接近零。

## 14. 通过确认

版本只有全部满足后，才可由独立审核者标记 `READY_FOR_AUDIT`，再由维护者标记 `PASSED`：

- [ ] compat test mod 在不修改主源码下完成五类注册。
- [ ] 自定义容器地月往返和崩溃恢复无复制。
- [ ] API 文档覆盖版本、线程、side、权限和限制。
- [ ] internal 包不作为示例或承诺。
- [ ] 外部模组缺失场景有明确政策和测试。
- [ ] 零 Critical/High。

## 17. 失败与回退

- 适配器失败时回滚整个火箭事务。
- 未知外部数据保留并阻止危险操作。
- API 破坏性调整必须延后到明确版本并提供弃用期。
- 不能稳定支持的扩展从 API 移回 experimental，不假装稳定。
