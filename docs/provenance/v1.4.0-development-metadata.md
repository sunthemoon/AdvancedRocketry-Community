# v1.4.0 development metadata adaptation

Date: 2026-09-27. No new upstream code or asset import.

`gradle.properties` remains an adapted Forge 1.20.1-47.4.10 MDK target under
LGPL-2.1-only. Its exact original artifact, source commit, license and retained
notices are recorded in
[the bootstrap provenance](v0.0.2-forge-mdk-and-gradle-wrapper.md) and
[Third-Party Notices](../../THIRD-PARTY-NOTICES.md).

This repository-authored adaptation changes the development version to
`1.3.0-dev`'s successor `1.4.0-dev`, updates the development description to the
implemented schema/capability slice, and adds the modification date to the
file's existing notice. It does not change the target's license, remove an
upstream notice, import another MDK revision or assert new release approval.
Historical approved audit bytes/digests and imported resource hashes are not
rewritten to describe this later change.

## Additive planetary data generation

`build.gradle` is the same recorded MDK-derived LGPL-2.1-only target. The
repository-authored MAP-02 adaptation switches active DataGen output to
`src/generated/v1.4/resources`, retains v1.3 as an existing resource input and
adds the new generated root to packaging. Existing notices and historical
resource outputs are retained. No other MDK revision or third-party code is
imported by this change.

The same recorded MDK-derived `.gitignore` gains the v1.4 DataGen cache exclusion,
matching the earlier generated roots. This keeps transient generator hashes out
of source control; the existing modification notice and license remain intact.

The new planetary definitions, routes, biome/noise/dimension generation and
language entries are original repository work under MIT. They reference vanilla
block/effects/registry IDs through supported APIs; no Minecraft/Mojang/Forge art,
JSON resource file or decompiled implementation is copied. Exact generated file
identities are recorded in the [20-file resource inventory](../work/v1.4.0-map02/generated-resources.json),
with SHA256 and exact packaged-byte comparison after repeatable DataGen. This
is not an original Advanced Rocketry asset import or an upstream gameplay-parity claim.

The environmental extension adds seven original damage/tag JSON resources,
an explicit planetary opt-in and original localized status/death text in the
same current-version output. It imports no upstream implementation or artwork,
and does not alter the historical generated roots or old damage-type tags.
The [27-file environmental inventory](../work/v1.4.0-env/generated-resources.json)
records the resulting current-version resources and exact packaged bytes.

The navigation extension adds original code-drawn schematic geometry and
English/Chinese navigation labels to the same two v1.4 language resources. It
copies no bitmap, vector, platform GUI implementation or upstream star-map code.
The [navigation inventory](../work/v1.4.0-nav/generated-resources.json) records
the 27 resulting current-version resources and their packaged identities.
