The populated persistence tests, recovery verification harnesses, two additional
opt-in flight checkpoints, transaction checkpoint/fault probes, loaded-entity
recovery check and release documentation are community-authored stabilization
work. No upstream code or artwork is imported. The accepted v0.9 assets and their existing source records
remain unchanged; the separate user-supplied planning package is recorded in
[its inventory](v1.0.0-v1plus-planning.md).

The representative-world capture/upgrade harness, bounded NBT projections and
their Python regression tests are also authored here. Its diagnostic datapack
uses native commands to observe a disposable world; it is not shipped in the
mod JAR. The fixture is generated with the unchanged, hash-verified published
Beta JAR and existing command interfaces, not copied from a player's world.
No third-party parser, upstream source, launcher credential or art is added.

The packaged compatibility test tooling is community-authored. Official Forge,
Minecraft runtime files and the pinned JEI dependency are used only in disposable
external test installations; they are not imported as mod assets or redistributed
in the evidence bundle. The tooling does not read existing launcher accounts.

The bootstrap-validator CLI dispatch correction and its tests are authored
here. They keep v1.0+ validation on the same accepted bootstrap commit used by
later v0.x versions; imported files, recorded hashes, approval digests and
historical provenance are not changed.

The build-identity helper, active CI wiring and workflow regression tests are
community-authored. They derive exact artifact names from the existing Gradle
properties and preserve historical release checks. No upstream files, imported
assets, accepted evidence or dependency versions are changed by this CI work.

The flight-console selection model, bounded S2C active-plan snapshot and their
regressions are community-authored defect fixes. No upstream code or asset is
imported. Only the flight-channel revision advances for its additional message;
exact-match compatibility policy and persisted identities remain unchanged.

The selected-route quotation fix and its model/packet regressions are also
community-authored, with no copied upstream input. The existing S2C console
frame now includes three bounded server quotes; flight protocol 4 requires
matching peers. No destination, asset, dependency or persisted ID is added.

The typed transfer-return diagnostic reasons and logging regressions are
community-authored. Existing event IDs/reason strings are preserved; requested
cancellation and transfer faults are distinguished at the producer. No upstream
copy, audit filter, persisted data or protocol change is introduced.

The console layout bounds, shared displayed-destination rule and regression
tests are community-authored presentation corrections. No upstream code or
asset is imported; runtime authority, packet format and save data are unchanged.

The bounded entity seat metadata and shared passenger offsets are community-authored
client positioning fixes. Fixed UUID slots preserve the existing persisted seat
identity and offset geometry without synchronizing full flight data. Flight
protocol 5 requires matching peers for the additional entity metadata. No upstream
code/assets, persistent format, permission or safety budget changes are introduced.

The world-owned rocket persistence override and its Forge GameTest are
community-authored. Pinned local Forge/Minecraft runtime bytecode was inspected
to identify the existing single-player vehicle ownership predicate; no runtime
code or assets were copied into the mod or evidence. Rocket saves retain their
schema and no new protocol is required. Recovery log classification distinguishes
an unchanged, committed, landed singleton from repairs, missing/duplicate entities
and interrupted phases; those cases retain WARN and the scanner is unchanged.

The journal-preferred entity ordering, owner-bound matching and bounded login
reconciliation are community-authored legacy-player-save corrections. The
existing Forge login event is reused; no Minecraft/Forge code or assets are
copied. Refueled committed authority remains eligible without restoring an
older fuel snapshot. Pure ordering tests and a Forge login regression use the
existing schema/protocol, and actual duplicate repairs remain WARN.

Post-landing passenger selection and refueled-arrival lifecycle corrections
are community-authored. The loaded journal-bound entity supplies the latest
seat assignments without activating chunks for unrelated logins; in-flight
recovery retains the journal snapshot. Both LANDED and FUELED committed
authorities settle and release their reservation after successful disassembly.
Focused Forge regressions use existing production adapters and formats.
Only successful unchanged settled singleton recovery uses INFO; repair/error
conditions and strict scanner rules are preserved. No upstream asset or code
is imported.

The passenger entity-readiness guards and UUID-only reconnect queue are
community-authored. Queue capacity, per-tick work and wait lifetime are fixed;
server shutdown clears it and disconnected players are removed. It does not
persist Minecraft objects or accept chunk coordinates from a packet. The
existing bounded journal recovery rebinds missing committed authorities before
login can adopt a replacement. Pure queue tests and a Forge readiness fixture
do not alter any save schema, network protocol, source or license boundary.

The Forge logout listener and service delegation that immediately cancel a
departing player's transient reconnect are community-authored. They neither
load a journal nor modify durable seat assignments, replay/rate-limit state
or chunk tickets. A read-only private-state observer in the Forge regression
checks event-bus cleanup without exposing a production diagnostic API. No
external source, asset or license change is introduced.

`gradle.properties` remains derived from the previously audited Forge MDK.
Its 2026-09-05 change updates the development version and description only;
the LGPL notice and original source record remain intact. Modification dates
are also recorded in `THIRD-PARTY-NOTICES.md`. No dependency, loader range,
save schema, protocol or resource identifier changes are introduced by this
metadata update. This record is not a human G0 approval.
