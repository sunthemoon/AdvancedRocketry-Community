## Authored inputs and generated output

NEW code and text: `V180RocketItemCargoArt`, `V180RocketItemCargoData`, their tests, and the English and Chinese
device names, screen labels and placement message of the item devices. The shared cargo status messages already
exist (W109) and are not re-authored here. The device classes, menu and screen are new code of the same leaf.

GENERATED output under `src/generated/v1.8/resources`: two original 16 by 16 pixel textures drawn in code, with load
and unload port marks distinct from each other and from the fluid devices', two blockstates, block and item models,
two loot tables, the two shaped community recipes of section 5.5 (H `minecraft:hopper`, I `item_io_board`,
M `machine_casing`, C `control_board`) with their unlock advancements, and bilingual entries through the existing
language provider. Models reference vanilla parent IDs without copying their files. The existing project PNG
encoder is reused.

No upstream, LibVulpes, Minecraft, Mojang, Microsoft, Forge or third-party art, model or text is copied, traced,
sampled or used as an authoring input. The asset plan has no row for these textures, so nothing is imported. The
generated provenance JSON will contain target and generator hashes. Screening against both pinned vanilla clients
uses the unchanged audit tool and thresholds; every new texture must be CLEAR. Screening is not human originality
approval or V1 visual acceptance.
