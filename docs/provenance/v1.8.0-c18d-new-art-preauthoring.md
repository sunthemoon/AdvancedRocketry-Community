## Method and permitted references

All pixels will be drawn from integer geometry and a fixed procedural seed in
`datagen/V180ClosureArt.java` and `datagen/V180SpaceSuitArt.java`. Any floating
geometry uses `StrictMath`. The encoders may use Java's PNG writer, as earlier
community providers do. No input bitmap, legacy model, screenshot, tracing,
image-generation service, texture pack or third-party asset is permitted.

Permitted references are the textual purpose and modern target names in
AUDIT-01.csv, modern project model resource IDs, existing project PNG encoding
code, and the native armor mesh's UV coordinates (a geometry contract, not
art). Vanilla client JARs are read only by the unchanged screening tool after
authoring; their pixels are never authoring inputs. No legacy bitmap is opened.
Existing MIT copyright, LICENSE and NOTICE are preserved.

## Replacement boundaries

The audited model files will be rebound in place to these textures. This is
limited to their existing model IDs and avoids duplicate packaged resources or
build-script changes. A dedicated provider will deterministically maintain
those exact audited bindings, alongside the v1.8 bitmap provider. Other older
generated resources remain untouched.

The old electrolyzer inactive generic casing and active sea-lantern reference
become purpose-specific panels. The precision assembler loses its crafting-table
front. The orbital laser gains a dedicated bottom; railgun, satellite builder
and warp core lose their generic front/side placeholders. Existing unmodified
project casing and legally referenced vanilla top faces remain where not in
scope. Solar icons lose vanilla item parents. Suit models and worn layers lose
iron art. No old NEW bitmap is overwritten.

The project armor material preserves iron's numeric protection, durability,
enchantability, toughness, knockback resistance, equip sound and repair input.
Item IDs, oxygen, module payloads and equipment behavior remain unchanged.
All new bitmaps are screened against both pinned client JARs with the existing
thresholds. Any non-CLEAR result prevents delivery of that image. Human
originality and real-client V1 checks remain required after automated screening.
