## Decision

Use the existing synchronized `visual_profile`, unique physical Level mapping,
pressure and solar intensity only as display inputs. Do not query server-only
world state from the client or change gravity, hazards, oxygen, routes or saves.
Shared space has a generic space profile, not a fabricated per-station orbit
context. Earth retains the vanilla renderer; gas giants have no surface.

- Add stable dimension-effects IDs `advancedrocketrycommunity:planetary` and
  `advancedrocketrycommunity:planetary_space`. Mars/Venus/Moon select the first;
  shared Space selects the second. Only `effects` changes in the old type JSON:
  identity, terrain, fixed time, server lighting settings, heights and every
  other property remain unchanged. The surface adapter preserves Overworld's
  ground/lightmap flags and NORMAL fallback; the space adapter preserves End's
  ground/lightmap flags and END fallback. Delegate brightness-dependent fog and
  fallback sunrise computation to the corresponding platform effects instance.
  Both intentionally suppress clouds, rain rendering and rain ticking; this is
  a visual change, not a server weather or light-level change. Keep
  historical generated bytes; packaging excludes exactly the two superseded
  type resources. Existing worlds obtain the effect on their next normal load;
  a pack overriding the type must explicitly select it. No world-file rewrite,
  save schema, API 1.7 or network protocol change is involved.
- Resource packs define `assets/<namespace>/celestial_visuals/<path>.json`,
  selected by `<namespace>:<path>` (at most 128 characters). Schema 1 has finite RGB day/night/fog/sun
  colors (0..16777215), sun radius (0.5..12 degrees), sun opacity and star
  brightness (0..1), fog start fraction (0..0.95), fog end (8..512 blocks),
  optional sound-event ID (128 characters) and volume (0..0.5). Required fields
  cannot silently default malformed input; unknown/future schemas are rejected.
  New fields require defaults or a new explicit schema; stable IDs are not
  renamed in place. These local resources confer no server authority.
- At most 128 winning resource files, 16384 UTF-8 bytes each, nesting 16;
  duplicate keys, invalid UTF-8, non-finite/out-of-range values and invalid IDs
  reject the whole candidate. Reuse the strict bounded JSON reader. Resource
  enumeration is the platform's finite resource index, not a world scan.
  Apply one immutable map on the client reload executor. A failed reload keeps
  the previous valid map and reports one bounded diagnostic; initial failure
  uses packaged authoring defaults. Missing/ambiguous body mappings or missing
  profile IDs use conservative vanilla fallback, with no previous-body bleed.
- Four original profiles use existing IDs `moon`, `space`, `mars`, `venus`.
  Geometry is original code, not copied platform/upstream artwork: a bounded
  sky sphere, 512 deterministic star quads and a 32-segment sun/halo. Upload
  buffers once, not every frame. Allocate, upload and close GPU buffers only on
  the render thread; reload preparation never touches GPU state. Resource
  reload/logout release them on that thread; a render
  error disables the custom renderer until reload and logs once. Restore the
  renderer state before returning to the platform. Missing profile data does
  not imply a valid or breathable environment.
- Preserve fluid, powder-snow, blindness and darkness rendering. Planetary fog
  uses `newFar = min(incomingFar, profileEnd)` and
  `newNear = min(incomingNear, newFar * startFraction)`, retaining incoming
  shape. Only finite incoming distances with `near < far` and positive `far`
  are adapted; other cases are left untouched. Thus neither plane increases
  and visibility is not extended.
  Sun angular size is clamped after applying the synchronized solar intensity;
  pressure only attenuates daytime stars. Neither is an environment calculation.
- Ambience references existing vanilla sound events without copying sound
  files. At most one additional non-looping ambient-channel sound, no more
  often than every 400 unpaused client ticks, only outside in the selected planetary
  Level and air. Stop it on world/profile change, loss of exposure, reload or
  logout. The session cooldown survives all these transitions (including reload)
  rather than resetting to an immediately playable state. Moon/space are silent
  in this additional channel; ordinary game audio
  is not globally muted. Missing sound events are silent, not fatal.

## Verification and limits

Strict unit/resource tests, deterministic geometry and lifecycle/policy tests,
DataGen idempotence, all short build/GameTest checks, bounded packaged restart
and independent actual-diff/key-command review are required. Test old type JSON
equality except `effects`, duplicate-free packaged resources and unchanged API
artifact. Pure tests and a headless server cannot establish rendered or audible
correctness. V1 on two GPU types and V2 remain pending under ADR-018; document
manual cases for rapid travel, resource reload, fluid/status fog and audio.

No ASM, access transformer, new library, global vanilla-effects replacement,
new server context packet, arbitrary dimension registration or future-version
orbital implementation. Ordinary resource-pack overrides remain available.

## Rollback and acceptance

Rollback the presentation slice and its two packaging exclusions together;
no player items, Level IDs, body mappings or station data require conversion.
The independent contract reviewer inspected the actual pinned Forge hooks and
identified the need for separate Space fallback/lightmap behavior and for
near-plane as well as far-plane fog limits. Both are incorporated above,
together with explicit ID bounds, render-thread ownership and persistent
ambience cooldown. Root records acceptance under the maintainer's standing
recommended-solution authorization on 2026-09-27, not a new manual numbered vote.
Actual implementation review and applicable test reruns remain required.
This decision does not approve a version Gate, candidate, tag or release.
