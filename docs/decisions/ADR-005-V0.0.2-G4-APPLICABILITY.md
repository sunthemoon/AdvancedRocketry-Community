## Context

Gate G4 normally requires two-player state consistency and proof that an
optional client mod can be absent without affecting the server. The v0.0.2
bootstrap registers no gameplay, project packet, shared player state,
permission, inventory, or interaction. It also declares no optional runtime or
client-only dependency.

The matching packaged-client join, disconnect, same-world restart, reconnect,
and missing-project-mod observation remain mandatory. This decision does not
replace those tests and does not make G4 pass.

## Proposed decision

For v0.0.2 only, classify these two cases as `NOT_APPLICABLE`:

1. **Two-player consistency:** there is no project-owned multiplayer state in
   this milestone whose consistency can be compared.
2. **Optional client dependency absence:** there is no optional client
   dependency to remove for a distinct test case. A clean packaged client with
   Forge and the project JAR remains required for the matching-client test.

A human reviewer must accept or reject each decision in the manual evidence.
Until then this ADR remains `PROPOSED`, G4 remains `IN_PROGRESS`, and the
version remains `IN_PROGRESS`.

## Risk and user impact

- A bootstrap-only side or connection fault could be missed if the required
  matching-client and missing-project-mod cases are not completed.
- No gameplay consistency claim is made because v0.0.2 exposes no gameplay.
- The decision must not be carried into v0.0.3 or later, where new registered
  content or dependencies may create testable multiplayer behavior.

## Temporary mitigation

- Require the packaged server smoke test and client-class boundary scan.
- Require a physical client/server JAR hash match, first join, disconnect,
  same-world restart, reconnect, and combined log review.
- Require the Forge-only missing-project-mod observation without pre-filling
  whether Forge accepts or rejects the connection.
- Make evidence readiness fail while either applicability review is absent or
  requests an additional test.

## Alternatives

### A. Run two packaged clients

This remains available if the reviewer rejects the first classification. It is
not selected automatically because there is no project state to compare.

### B. Invent an optional dependency for the test

Rejected. Adding an unused dependency would expand the milestone solely to
manufacture a test condition and would violate the vertical-slice scope.
