# v1.6.0 implementation log

## Goal and scope

Deliver [Satellites & Resource Missions](../versions/V1.6.0-SATELLITE-RESOURCE-MISSIONS.md):
constructable and deployable satellite kinds, a bounded offline scheduler,
asteroid and gas-giant resource missions with reproducible, conserved rewards,
and recovery across cancellation, restart, upgrade and definition change.
Development evidence does not approve a release or remove inherited Required Gates.

- [Reference vectors](v1.6.0-preparation/examples.json) with a standard-library

  seed-0 outputs, bounded draws, survey/yield vectors, truncation, durations, gas

Explicit C6 non-goals: any change to production Java, resources, build scripts or
generated data; the runtime version; world migration; new items or blocks; asset
imports; candidate, tag or Gate changes; remote, long-load or real-client tests.

Findings recorded for the contracts:

- The current registry never prunes finished missions, so it locks at 8,192
  records (fixed by ADR-050 §6).
- The 4 MiB registry bound is enforced only by an exception at save time (ADR-050 §6).
- Item rewards cross from SavedData into a block entity; the delivery protocol
  and its crash-cut table are in ADR-051.
- The registry is written by a synchronous barrier flush after every operation
  (serialize, gzip, fsync, read-back, atomic move). ADR-038's discovery ordering
  relies on it, so ADR-050 §2 keeps it only for existing `data` paths.
- `cancel` leaves stale deadline-queue entries, and `schedule` throws at 1,024
  after the maps have changed (ADR-050 §5).
