# v1.1.0 Expansion Kernel implementation plan

## Goal

Replace the fixed destination assumptions with bounded, data-driven travel
targets, routes and position-aware body context while preserving v1.0 Earth,
Moon and station behavior and save data.

## Scope and non-goals

In scope: typed targets, route data, body-context resolution, shared-Space
orbit identity, station integration, save/network migration and regression
evidence. Full Mars gameplay, new dimensions, warp, multiple star systems,
asteroid missions and machine work remain out of scope.

The owner accepted a bounded implementation-order exception in ADR-015 on
2026-09-06. The v1.0 baseline remains `IN_PROGRESS` rather than a formal
release, but scoped v1.1 production slices may proceed from commit `a4ae201`.
The exception expires before v1.1 candidate freeze and waives no release Gate.

## Assumptions and open decisions

- Stable celestial identifiers remain `ResourceLocation` values.
- Runtime station and mission identities remain UUIDs; clients never supply
  coordinates, orbit ownership or route costs.
- Shared-Level resolution uses persisted region indexes and never loads a
  chunk to answer a context query.
- The v1.0 fuel formula and its effective route distances remain unchanged.
- `ADR-014` and its schema-v1 shapes are accepted and frozen. Contract changes
  now require an explicit decision update.

## Active slice

### `V110-CONTRACT-AUDIT` v1.0 identity and migration inventory

- Status: verified
- Observable outcome: the exact enum callers, persistent fields, schema roots,
  protocol versions and reusable station index are recorded by a repeatable
  repository audit.
- Scope / non-goals: read-only source inspection; no production Java or runtime
  data is changed.
- Dependencies / interfaces: v1.0 commit `a4ae201`, ADR-001, ADR-006 and
  ADR-008.
- Acceptance criteria: the audit identifies every Java file that references
  `RocketDestination`, verifies the current NBT identity fields, captures the
  current network/schema numbers and validates all contract sample JSON.
- Verification: `python docs/work/v1.1.0-expansion-kernel/audit.py`.
- Evidence: `docs/work/v1.1.0-expansion-kernel/audit-result.json`.

### `V110-CONTRACT-ADR` freeze the public semantic boundary

- Status: verified
- Observable outcome: one reviewable decision defines concrete target shapes,
  route anchors, resolver precedence, bounds and the two-phase migration.
- Scope / non-goals: contract decision only; runtime integration remains in
  its separately tested slices.
- Dependencies / interfaces: `V110-CONTRACT-AUDIT` and ADR-015.
- Acceptance criteria: maintainer accepts ADR-014; sample schemas agree with
  the decision; no open authority or migration ambiguity remains.
- Verification: schema validation plus independent design review.
- Evidence: `docs/decisions/ADR-014-TRAVEL-TARGET-ROUTES-BODY-CONTEXT.md` and
  `docs/work/v1.1.0-expansion-kernel/contracts/`.

### `V110-CONTRACT-ORACLE` executable pre-integration cases

- Status: verified
- Observable outcome: positive and hostile target/route shapes, shared-Space

- Dependencies / interfaces: accepted ADR-014 and ADR-015 development baseline.

### `V110-ROUTE` bounded data-driven route graph

- Status: verified
- Observable outcome: three built-in baseline routes load atomically from data;
  a deterministic bounded planner produces shortest paths and a shared pure
  fuel formula preserves the v1.0 Earth/Moon/station quotes.
- Scope / non-goals: registers the route reload service but does not replace
  flight/network/UI destination selection yet. `test_mars` remains test data.
- Dependencies / interfaces: accepted `RouteAnchor`/`RouteDefinition` schema
  in ADR-014 and the active celestial catalog.
- Acceptance criteria: exact codecs; resource/declared ID match; known-body,
  unique-route, unique-directed-edge and distinct-endpoint checks; 512 routes,
  256 anchors, 64 outgoing edges, 1,024 expanded nodes and 256 cached plans;
  deterministic equal-cost tie-breaking and atomic invalid-reload rollback.
- Verification: 17 new unit tests, full 431-test suite, DataGen and 51 GameTests.
- Evidence: `docs/work/v1.1.0-expansion-kernel/ROUTE-VERIFICATION.md`,
  `route-gradle-test.txt` and `gametest.txt`.

### `V110-CONTEXT` position-aware body context

- Status: verified
- Observable outcome: server-owned positions in the shared Space Level resolve
  committed station regions to the station's arbitrary orbit body; gaps,
  reservations, deleted stations and unknown bodies remain unresolved.
- Scope / non-goals: adds the context model and station-region adapter plus
  catalog-aware station creation. Rocket target, menu and transfer callers are
  migrated in later slices.
- Dependencies / interfaces: accepted ADR-014, immutable celestial catalog and
  the existing constant-time `StationRegistryModel.findAt` index.
- Acceptance criteria: immutable Level/position query; tri-state resolver
  precedence; unambiguous Level fallback; no chunk access; inclusive region
  boundary; 16-resolver bound; catalog validation before station state or block
  mutation; shared-Space GameTest with Earth and Moon orbit stations.
- Verification: 9 new unit tests, full 440-test suite and all 52 GameTests.
- Evidence: `docs/work/v1.1.0-expansion-kernel/BODY-CONTEXT-VERIFICATION.md`,
  `body-context-gradle-test.txt` and `gametest.txt`.

### `V110-MIGRATION-NETWORK` typed C2S target frame

- Status: verified
- Observable outcome: the client flight-intent frame carries a schema-versioned
  bounded `TravelTarget` rather than a `RocketDestination` ordinal, and the
  flight channel explicitly requires protocol 6.
- Scope / non-goals: C2S intent and S2C plan/quote snapshots use typed targets;
  v1.0 compatibility overloads remain only at explicit adapter boundaries.
- Acceptance criteria: all four closed target shapes round-trip; 154-byte hard
  frame limit; exact schema/type validation; canonical bounded body IDs;
  truncated, trailing, oversized and non-canonical frames rejected; clients do
  not provide coordinates, route IDs, route cost, gravity or fuel cost.
- Verification: hostile/truncated/canonical frame tests, bounded variable S2C
  quote tests and the final 449-test regression.
- Evidence: `docs/work/v1.1.0-expansion-kernel/network-target-gradle-test.txt`
  and `TARGET-INTEGRATION-VERIFICATION.md`.

### `V110-STATION` arbitrary-body station authority

- Status: verified
- Observable outcome: creation rejects undefined orbit bodies before mutation;
  persisted unknown body references are diagnosed and excluded from context and
  flight resolution without deleting recoverable station data.
- Scope / non-goals: the shared Space Level remains fixed; this slice does not
  add a Mars dimension or full Mars gameplay.
- Acceptance criteria: committed Earth and Moon stations resolve distinct
  `BodyContext` values, route planning resolves a station UUID to its persisted
  orbit body, and unassigned Space positions remain unresolved.
- Verification: unit tests plus the `station_context` GameTest in the final
  52-test server run.
- Evidence: `BODY-CONTEXT-VERIFICATION.md` and
  `TARGET-INTEGRATION-VERIFICATION.md`.

### `V110-MIGRATION-SAVE` two-phase save conversion

- Status: verified
- Observable outcome: schema-1 active transfer authority retains its original
  checksum and semantics; only a committed authority record is upgraded to
  schema 2 and rebound to typed current/destination targets.
- Acceptance criteria: a preserved v1.0 committed fixture loads with its old
  checksum, migrates after settlement, rejects premature migration, and its
  first and second schema-2 saves are byte-equivalent NBT structures.
- Verification: `RocketTransferRecordTest`, NBT codec tests, entity migration
  GameTest and shared-Space station migration GameTest.
- Evidence: `MIGRATION-VERIFICATION.md` and
  `src/test/resources/migrations/v110/`.

### `V110-ADAPTER` typed runtime planning and console

- Status: verified
- Observable outcome: production launch requests, route quotes, active plans,
  transfer checksums and menu selection carry exact typed targets. The server
  computes body/station resolution, route distance, gravity and fuel cost.
- Acceptance criteria: test-only Mars reaches the typed planner using data
  files only; unknown body, mission, station and source-dimension spoofing fail
  closed; accessible stations receive exact UUID-bound quotes.
- Verification: final 449 JUnit tests and all 52 required GameTests.
- Evidence: `TARGET-INTEGRATION-VERIFICATION.md`, `unit-tests-final.txt` and
  `gametest-final.txt`.
