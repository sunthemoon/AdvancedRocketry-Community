# v1.2.0 implementation log

## Goal

建立轻量、服务端权威、可迁移且有硬边界的过程机器与多方块内核，并以
三台结构和输入输出差异明显的机器证明复用价值，不复刻 LibVulpes。

```yaml
version: v1.2.0
status: IN_PROGRESS
phase: LIFECYCLE_CORE_COMPLETE
branch: codex/v1.2.0-controller-lifecycle
base_commit: 660cfc95c1dff7901a25ad937cc3c0e3242e51ef
prerequisite: v1.1.0 PASSED
prerequisite_observed: not_satisfied
runtime_implementation_allowed: true
accepted_adrs: [ADR-016, ADR-017, ADR-018]
test_scheduling_adr: ADR-018
last_updated: 2026-09-10
```

## Scope and non-goals

ADR-016/017 已于 2026-09-06 接受，允许从固定基线开展 v1.2.0 生产实现。
开发顺序例外不创建候选、不放行 G0–G9，也不改变 `v1.1.0` 的实际状态。

明确不做：LibVulpes 复刻、全部旧机器迁移、动态 GUI DSL、任意区块强制
加载、v1.3 公共 API、长期压力执行和发布 Gate 判定。

## Decision log

1. 代表机器暂定为 Electrolyzer、Rolling Machine、Precision Assembler。
   三者分别覆盖单方块、普通多方块和复杂多输入结构；Item 与 Energy 被三者
   使用，Fluid 被前两者使用，满足“至少两种实现再抽取”的约束。
2. 实现顺序暂定 Rolling Machine → Electrolyzer → Precision Assembler。
   先用新机器验证框架，再迁移已存在机器，避免为 v0.2 实现量身定制。
3. `advancedrocketrycommunity:electrolyzer`、`electrolyzing` 和
   `arce_machine` schema 1 是兼容输入，不在本阶段更名或删除。
4. pattern 不读取未加载区块；结果为 `WAITING_UNLOADED`，不是结构损坏。
5. ADR-016 中的限制值已由维护者冻结；修改须回到契约评审并记录迁移影响。
6. Pattern cell 与可绑定 part 分开：普通 casing 可参与结构而无需 BlockEntity；
   只有发现到的 binding target 进入 controller 的持久化 part 集合。
7. `QUEUE_FULL` 要求调用者停止继续入队并稍后重试；队列不静默丢弃 dirty 事件。
8. 生命周期核心不等同于机器集成；`V120-LIFE` 在 Rolling Machine 的实际
   controller/part 与方块事件接入完成前保持 `in_progress`。

## Open blockers

- `v1.1.0` 尚未由维护者标为 `PASSED`；ADR-017 只允许生产开发，不能冻结
  v1.2.0 候选或放行继承 Gate。

  完整矩阵在原有机械和维度补全后执行，见 ADR-018；这不改变最终 G0-G9

  `V120-PORT`、`V120-MIG` 和 `V120-MCH`，不能把纯 Java 测试当作运行时证据。

  revision 持久化仍需在 `V120-MCH`/`V120-MIG` 验证。
- 生命周期核心尚未接入注册的 controller/part BlockEntity 或真实方块事件；
  `V120-LIFE-04` 将与首台 Rolling Machine 垂直切片共同完成。
