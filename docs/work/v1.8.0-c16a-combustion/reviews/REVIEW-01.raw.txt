# C16a-02 independent review

Reviewer: delegated independent read-only reviewer. Reviewed the combustion-generator slice against accepted ADR-064 revision 2 and repository governance; compared against the supplied pre-task baseline, not HEAD. Root was the only repository writer. This review does not cover C16a-01/03-06, C16b-d, C17-C19 or version-release acceptance.

## Findings and dispositions

No unresolved Critical, High or Medium findings were identified in the frozen scoped source after the corrections and independently rerun A0/A1 checks below.

1. **H1 — lost fuel on inbound shift-click into an occupied generator slot — fixed.** Initial `quickMoveStack` delegated inbound insertion to vanilla `moveItemStackTo`, but the generator slot returns detached `ItemStack` copies. Mapped vanilla bytecode shows an occupied merge mutates `getItem()` and calls only `setChanged()`, so generator coal 1 plus player coal 8 could leave generator coal 1/player coal 0. The corrected [menu](D:/GitHub/AdvancedRocketry-Community/src/main/java/io/github/sunthemoon/advancedrocketrycommunity/machine/combustion/CombustionGeneratorMenu.java#L123) explicitly inserts into the authoritative bank and writes back the exact player remainder. The new [regression](D:/GitHub/AdvancedRocketry-Community/src/main/java/io/github/sunthemoon/advancedrocketrycommunity/gametest/CombustionGeneratorGameTests.java#L375) covers occupied 1/60/64 coal stacks and an incompatible bucket target. Independently passed in the full GameTest run.

2. **H2 — BE serialization exception allowed native replacement of the chunk without quarantined resources — fixed in reviewed code; native storage evidence is separately recorded below.** Initial `saveAdditional` threw for oversized retained input. Actual mapped `LevelChunk.getBlockEntityNbtForSaving` catches this exception and returns null; `ChunkSerializer.write` omits null BE entries and still writes the chunk. The original direct-save exception test did not exercise that loss. The corrected [BE save](D:/GitHub/AdvancedRocketry-Community/src/main/java/io/github/sunthemoon/advancedrocketrycommunity/machine/combustion/CombustionGeneratorBlockEntity.java#L266) passes the original oversized Tag reference without copying, matching the already accepted ADR-027 caveat. The [complete-chunk save handler](D:/GitHub/AdvancedRocketry-Community/src/main/java/io/github/sunthemoon/advancedrocketrycommunity/machine/combustion/CombustionProtection.java#L30) bounds outgoing BE count by chunk height, preflights generator roots, restores the dirty flag and deliberately throws before the native storage write. This is necessary because the actual Save event is not cancelable, `ChunkMap.save` discards `post`'s boolean and clears the dirty flag before serialization. The [corrected regression](D:/GitHub/AdvancedRocketry-Community/src/main/java/io/github/sunthemoon/advancedrocketrycommunity/gametest/CombustionGeneratorGameTests.java#L238) exercises actual `ChunkSerializer.write` and Forge Save-event dispatch, verifies no-copy retention and dirty retry, and independently passed. It is not by itself an on-disk preservation proof.

3. **L1 — native probe's expected-error matcher used the wrong coordinate format — fixed before native execution.** The first script allowed only `Failed to save chunk [8, 8]`; the actual native save logger formats `Failed to save chunk {},{}`. The frozen script allows the coordinate-exact `8,8` line and its deliberate oversized-save event exception, and retains rejection of unrelated scanner findings. This was a probe false-negative risk, not a runtime resource-loss defect.

The subsequent native attempts exposed additional probe-only marker problems: persisted `forceload` flags have different console feedback, and the earlier logger row could finish a query before its console-feedback duplicate, letting the duplicate satisfy the following command. The reviewed final probe explicitly queries the target's persisted force-load status and waits for the final MinecraftServer console report. Its oversized fixture uses two 4,096-byte arrays: the combined root still exceeds the unchanged 8,192-byte host budget, while each collection stays inside the unchanged Python NBT reader limit. Five independently rerun Python tests cover markers, coordinate rejection, safe patching and ambiguous-marker refusal.

No further actionable scoped issue was found in fuel credit, container handling, shared 1,000 FE/t push/pull accounting, callback exclusion, capability revocation, loaded-only neighbor access, bounded strict decoding, future/corrupt-root retention, menu authority/wire bounds, registration, crafting/bootstrap, data generation or source/provenance declarations. This is an evidence-bounded review result, not a blanket third-party callback or crash-atomicity guarantee.
