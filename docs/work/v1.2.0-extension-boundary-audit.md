## API/package and compatibility baseline

The main Java source tree has no project-owned `api` package. Existing `public`
classes are implementation-accessible types, not an independently versioned
external surface. [settings.gradle](../../settings.gradle) defines one root
project; [build.gradle](../../build.gradle) publishes the main JAR and sources
JAR, not a separate API artifact or independent compatibility test mod.

Existing network compatibility is channel-specific exact matching:
[celestial](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/celestial/network/CelestialNetwork.java),
[life support](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/network/LifeSupportNetwork.java)
and [rocket visual](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/network/RocketVisualNetwork.java)
use protocol `1`; [rocket flight](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/network/RocketFlightNetwork.java)
uses `6`. These are not a Java API version, nor evidence of an extension
compatibility handshake. API versioning must not silently alter these channels.

## Domain inventory

### Rocket movement and components

[RocketBlockEntityAdapter](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/forge/RocketBlockEntityAdapter.java)
has only `id`, `supports`, `capture` and `restore`. The
[adapter collection](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/forge/RocketBlockEntityAdapters.java)
is immutable after construction, rejects duplicate IDs and uses the first
supporting adapter. Its default contains only the
[chest/barrel adapter](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/forge/VanillaContainerRocketAdapter.java).
The production [RocketManager](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketManager.java)
selects this default; constructor injection exists internally, but no external
registration event/freeze contract is wired to that production construction.

Exception handling is narrower than a third-party isolation contract: the
collection catches `RuntimeException` from `capture`, not `supports`, and
delegates `restore` directly. The built-in adapter validates an explicit NBT
whitelist and catches its own restore exceptions. There are no adapter-level
`canMove`, separate sanitization or rollback hooks, nor callback time enforcement.
The surrounding rocket transactions own rollback; they must remain authoritative
rather than assuming an arbitrary provider's side effects can be reversed.
In particular, [world restoration](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/forge/ServerLevelRocketTransactionWorld.java)
cleans a newly placed block on `restore=false`, but an exception skips that
local branch; [disassembly rollback](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/transaction/RocketDisassemblyTransaction.java)
tracks successfully restored entries. External throwing adapters therefore
need explicit partial-placement handling before registration is opened.
This is not a reproduced defect in the built-in adapter, which returns false
on its own restore exceptions.

[RocketBlockEntityPayload](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/model/RocketBlockEntityPayload.java)
copies NBT, rejects top-level world identity fields and stores an adapter ID.
It has no separate generic provider-payload version field; the built-in ID is
`advancedrocketrycommunity:vanilla_container_v1`. The
[existing limits](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/RocketLimits.java)
include 262,144 bytes per BE payload, 1,048,576 aggregate NBT bytes, 2,048 blocks,
32,768 bounding volume and 256 scan inspections per tick. These are current
host limits, not a bound on arbitrary external callback execution.

[ServerLevelRocketScanWorld](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/forge/ServerLevelRocketScanWorld.java)
checks loaded chunks before reading; hard-forbidden blocks and the forbidden
tag override the movable tag. A movable-tagged BE still needs an adapter.
[RocketForgeMetrics](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/forge/RocketForgeMetrics.java)
uses engine/tank/seat/guidance tags but hard-codes each role's metrics and rejects
overlapping roles. Tags can add members; they do not supply custom engine stats.
[FuelLoaderBlockEntity](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/fuel/FuelLoaderBlockEntity.java)
accepts the built-in rocket fuel cell and returns an empty canister through its
existing owner-bound buffered transfer. It is not a fuel-definition registry.

Existing payload/schema checks are in
[RocketSnapshotNbtCodecTest](../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/persistence/RocketSnapshotNbtCodecTest.java).
The [transaction tests](../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/transaction/RocketTransactionsTest.java)
and [runtime tests](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/gametest/RocketGameTests.java)
exercise the existing built-in behavior;
they do not establish a frozen third-party callback contract.

### Atmosphere, equipment and environment queries

[ServerLevelVolumeWorldView](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/server/ServerLevelVolumeWorldView.java)
is the loaded-only block adapter for bounded volume scanning. Existing sealing
and permeable tags can configure block classification; an explicit sealing tag
wins before door-open/permeability handling. There is no external provider
registration/freeze lifecycle in that adapter.

[AtmosphereManager](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/server/AtmosphereManager.java)
owns per-level [services](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/server/AtmosphereLevelService.java).
`breathabilityAt` can lazily create a service and update its environment, so it
is not a pure, off-thread-safe snapshot accessor. Dirty blocks, chunk events,
changed environment booleans and shutdown affect cached volumes. Inspection of
the atmosphere event/service code found no explicit tag-reload cache invalidation
hook; future provider reload semantics must address that boundary instead of
assuming generic datapack reload makes every cached volume fresh.
The [host limits](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/AtmosphereLimits.java)
include 4,096 volume cells, 256 observations per task/tick, 1,024 per level/tick,
64 active scans and 128 indexed volumes. These constrain the built-in scanner,
not arbitrary provider callback duration.

[PlayerLifeSupportService](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/server/PlayerLifeSupportService.java)
recognizes the built-in `SpaceSuitArmorItem` in the matching armor slots.
[SpaceSuitOxygen](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/content/SpaceSuitOxygen.java)
handles the built-in chestplate's schema-1 oxygen storage, not a third-party
equipment/provider registry. Future providers must specify authoritative
resource consumption and partial-transfer behavior rather than supplying only
a client-side protected/unprotected flag. Existing decision and storage checks
are in [PlayerLifeSupportEngineTest](../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/life/PlayerLifeSupportEngineTest.java)
and [SpaceSuitOxygenTest](../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/atmosphere/content/SpaceSuitOxygenTest.java).

[CelestialEnvironmentService.forLevel](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/celestial/service/CelestialEnvironmentService.java)
reads level-mapped gravity/atmosphere values. Separately,
[BodyContextResolver](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/celestial/context/BodyContextResolver.java)
accepts an immutable ordered list of up to 16 instance resolvers and resolves
position-based body identity. An authoritative `UNRESOLVED` result stops
fallback; otherwise the fallback requires exactly one body mapped to the level.
[RocketTargetContextService](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketTargetContextService.java)
constructs this resolver with the existing station-region resolver for travel
and migration; it is not an externally registered resolver list.

These environment and identity services are not yet one position-sensitive
environment API. [Player gravity](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/celestial/service/CelestialGravityController.java)
and atmosphere still consume the level service, not each station's body context.
The [stored station profile](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/station/model/StationEnvironmentProfile.java)
must not be described as already applying station-specific gravity and vacuum
through those consumers.

Metadata context resolution does not inspect query-position chunks; unlike
world scanning, it need not require them to be loaded. Its production setup
does obtain station SavedData, so that setup is not an arbitrary off-thread
operation. The resolver itself has no result cache, external exception isolation
or per-provider time enforcement. Existing
[BodyContextResolverTest](../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/celestial/context/BodyContextResolverTest.java)
checks resolution, authoritative stop and bounds, not a stable public API.

### Satellite definitions and missions

[SatelliteDefinition](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/model/SatelliteDefinition.java)
is a schema-1 datapack record: duration, research yield, discovery cost and
allowed body IDs. It does not contain arbitrary mission/component callbacks.
[SatelliteCatalog](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/service/SatelliteCatalog.java)
accepts additional definition IDs but requires the built-in `data_satellite`;
all definitions use the same existing research/discovery behavior.

[SatelliteCatalogDecoder](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/service/SatelliteCatalogDecoder.java)
validates the entire candidate, and
[SatelliteCatalogManager](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/service/SatelliteCatalogManager.java)
publishes an immutable catalog generation, retaining the last valid one after
a rejected reload. This data extension is not a runtime provider registry.

[SatelliteMissionSavedData](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/persistence/SatelliteMissionSavedData.java)
owns the mission registry in overworld storage. The
[registry](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/mission/SatelliteMissionRegistry.java)
snapshots definition values into missions and controls launch, completion and
claim state; a future extension must not independently award rewards outside
that authority. The
[limits](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/model/SatelliteLimits.java)
include 16 definitions, 16 targets per definition, 32,768 JSON characters,
32 completions / 64 queue inspections per pass and a 20-tick scheduling interval.

[SatelliteRuntime](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/service/SatelliteRuntime.java)
is an internal terminal bridge, not an extension registration API. The
[manager](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/service/SatelliteManager.java)
installs it at server start and clears replay/catalog state on shutdown;
[the mod lifecycle](../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/AdvancedRocketryCommunity.java)
also clears the static bridge. Exposing mutable registry access would bypass
these ownership and persistence boundaries.

Existing test entry points:
[catalog/reload tests](../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/SatelliteCatalogDecoderTest.java)
and [mission authority tests](../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/mission/SatelliteMissionRegistryTest.java).
These cover the implemented data-satellite behavior, not third-party mission
callbacks or the future v1.6 resource-mission systems.

### Machine kernel

The [machine guide](../MACHINE-KERNEL-GUIDE.md) already labels its types internal.
Datapack recipes and patterns configure registered machines; they do not alone
register a new BlockEntity, port layout or controller lifecycle. The common
transaction executor is not a cross-chunk atomicity API. In particular, the
Precision controller Item guarantee must not be generalized to Rolling's
physical ports or arbitrary third-party resources.

## Contract questions before public implementation

The following are proposed design boundaries, not accepted API promises:

1. **Version and ownership:** define an explicit exported package allowlist,
   compatibility result and deprecation policy. Keep API version, mod version,
   wire protocol and persistent schema identities separate. Existing internal
   managers, SavedData access and release-test hooks stay internal.
2. **Registration lifecycle:** declare one owner/namespace per registration,
   reject duplicate IDs deterministically, freeze Java providers before world
   operations, and distinguish this from datapack catalog replacement. Define
   whether optional integrations are server-only, client-only or required on
   both sides instead of assuming every extension needs a new network packet.
3. **World and save authority:** expose immutable results and bounded inputs;
   preserve server-thread and loaded-only validation for world-reading/mutating
   operations. Metadata-only lookups need not load or require a query chunk.
   A provider must not
   acquire chunk tickets or directly commit rewards/resources through the API.
   Missing providers must retain opaque saved payloads and reject unsafe
   operations, not delete unknown data.
4. **Adapter failures:** define capture validation, restore failure and rollback
   ownership before allowing external BlockEntity types. Catching a callback
   exception does not undo external side effects. Checking elapsed time after
   a synchronous callback returns does not forcibly stop one that never returns;
   the contract must distinguish bounded host work, cooperative provider rules
   and over-budget diagnostics. It must not claim same-JVM code sandboxing or
   safe arbitrary callback preemption.
5. **First executable slice after approval:** an explicit API version/compatibility
   contract plus a separately compiled consumer limited to exported types.
   Follow with one real container adapter registration through existing rocket
   assembly/restore authority. This is a starting slice, not a replacement for
   the remaining v1.3 atmosphere, equipment, fuel, environment and satellite scope.

The first slice should leave all existing save roots and network protocols
unchanged. If later adapter payload metadata needs a new version, its migration
and missing-provider behavior require an explicit contract rather than a
mechanical rename of internal types.
