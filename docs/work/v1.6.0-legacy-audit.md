## 4. Legacy safety defects that the redesign must not reproduce

1. Every satellite object ticks every tick (unbounded CPU with satellite count).
2. Ore mapping reads arbitrary client-selected coordinates, loads chunks through
   `getBlockState`, and runs off the main thread.
3. Gas collection force-initializes a dimension and overfills tanks (64,000 mB
   into any tank).
4. Mission rewards depend on `Math.random()` and a shared static `Random`, so
   they are neither reproducible nor auditable.
5. Missions store whole rocket inventories and BlockEntity NBT without a size bound.
6. Global numeric satellite counters and integer dimension IDs are persistence identity.
7. The Observatory preview seed differs from the stored chip seed.

## 5. Current-repository findings relevant to the contracts

- `SatelliteMissionRegistry` never removes CLAIMED/CANCELLED missions. Once
  **8,192** retained records exist, every new launch/start returns
  `CAPACITY_REACHED` permanently. A retention/pruning rule is required before the
  500/1,000-task targets (ADR-050).
- Satellites have no kind, component stats or orbit body; missions have no seed,
  reward snapshot or bound terminal. Records are schema 1; the registry root is
  schema 2 (ADR-049/050).
- The terminal inventory decoder requires exactly `Size=6` (ADR-029). Resource
  rewards need a separate, versioned terminal delivery section (ADR-051).
- Gases are **items** in this project (`EMPTY_CANISTER`, `HYDROGEN_CANISTER`,
  `OXYGEN_CANISTER`); no gas fluids are registered.
- The gas giant is a non-landable body with `gas_giant: true`, discovery required;
  Earth is the home-system root and there is no Sun body (ADR-037/043).
