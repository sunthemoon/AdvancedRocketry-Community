# v0.6.0 Implementation Log — Earth–Moon round trip

## Goal

Deliver the first playable, server-authoritative Earth–Moon round trip: fuel a
v0.5 block rocket, select a fixed destination, launch, transfer passengers,
land, return, disassemble, and recover safely after disconnects or restarts.

## Scope and non-goals

In scope: bounded fuel loading, flight planning/state, fixed Earth/Moon pads,
durable cross-Level transfer, passenger UUID/seat bindings, destination UI,
auditable feedback, landing/disassembly, restart recovery, security tests, and
release evidence.

Out of scope: Space travel, arbitrary planets or coordinates, orbital physics,
stations, satellites, combat, dynamic dimensions, third-party BlockEntity
movement, and any relaxation of v0.5 structure/NBT limits.

## Assumptions and accepted decisions

- v0.5.0 is `PASSED`; this branch starts from
  `b349789c9d330da782c8e719f57ff09d8a262e7f`.
- Earth and Moon use the fixed Levels accepted by ADR-001.
- ADR-006 defines the durable authority boundary and four-case recovery matrix.
- Transit may use a short state/loading transition instead of continuous
  cross-Level interpolation.
- All new resources are community-authored DataGen output; no upstream files
  are copied in this version unless a separate provenance record is added first.

## Decision log

- `2026-09-01`: v0.5.0 is accepted; start from its post-reproduction main
  commit `b349789c9d330da782c8e719f57ff09d8a262e7f`.
- `2026-09-01`: accept ADR-006. Destination coordinates are server-owned fixed
  pads, and durable authority switches only after `DESTINATION_SPAWNED`.
- `2026-09-01`: keep the v0.5 structure snapshot schema at 1; v0.6 adds a
  separate flight/entity schema and relocates snapshots only at committed
  destinations.
- `2026-09-01`: entity schema 2 embeds independently versioned flight data,
  binds its logical rocket, fuel capacity, seat capacity, and current Level to
  the immutable snapshot/entity, and preserves the whole outer payload when a
  binding or nested decode fails.
- `2026-09-01`: Rocket Fuel Cells contain 500 integer fuel units and are made
  from an existing Hydrogen Canister, blaze powder, and redstone. The loader
  returns the empty canister and never accepts a client-supplied rocket id or
  coordinate.
- `2026-09-01`: ordinary rocket interaction opens the flight console while
  shift-interaction retains disassembly. The only C2S flight payload is a
  fixed action, loaded entity id, fixed destination, and request UUID; every
  mutable flight fact is recomputed by the server.
- `2026-09-01`: retain committed landed journal records as fixed-pad
  reservations until disassembly or an atomic replacement by the return
  flight. This prevents concurrent landing overlap without a second mutable
  reservation authority.
- `2026-09-01`: retain source-settlement records while manifested players are
  offline. Login recovery remounts each UUID at the sole authoritative rocket
  and removes the settlement only after every recorded passenger is online.
- `2026-09-01`: the transfer executor was reviewed after exceeding 500 lines;
  entity lookup/movement and restart/reconnect recovery were separated into
  dedicated bounded services. The remaining class owns only preparation and
  the forward phase executor and remains below the mandatory 800-line ADR
  threshold.
- `2026-09-01`: automatic recovery now primes both authority chunks and waits
  for Minecraft's explicit entity-storage-loaded signal before deciding the
  source/destination presence matrix. It does not infer absence from a fixed
  startup delay. Operator recovery follows the same readiness rule.
- `2026-09-01`: packaged flight controls and exact checkpoint freezes are
  registered only when the dedicated process sets
  `advancedrocketrycommunity.releaseTestHooks=true`; normal clients and servers
  cannot register or invoke them.
- `2026-09-01`: repository owner `sunthemoon` approved G0, G8, and G9. ADR-007
  accepts the actual two-client filtered-log record without claiming a
  screenshot or video; the exception expires when v0.7.0 validation begins.
