# v1.7.0 implementation log

## Goal and scope

Deliver [Endgame Systems](../versions/V1.7.0-ENDGAME-SYSTEMS.md): representative
vertical slices of the orbital laser drill, the railgun cargo launcher with its
targeting, black-hole power, the area gravity controller and space-elevator
logistics, each with its own permission, protection, rate, energy, audit and
recovery boundaries. Development evidence does not approve a release or remove
inherited Required Gates.

```yaml

execution_state: ACTIVE
branch: codex/v1.7.0-endgame-systems
accepted_development_baseline: ab10fb53a580e53a9a1c24097a487f2a7c54ad52
runtime_implementation_allowed: true    # ADR-053..059 ACCEPTED on 2026-10-01
runtime_build: 1.20.1-1.6.0-dev         # unchanged in C10
last_updated: 2026-10-01
```

The v1.6 handoff is a development baseline, not a passed prerequisite. ADR-053
must separately authorize this version before any runtime change. Root is the
sole tracked writer. Independent review uses read-only repository access and
fresh Temp outputs. The untracked user documentation bundle stays excluded from
reads and writes. No upstream code or asset is imported.

Implementation decisions for the C11 review:

- `ManagedSavedDataType` gains `firstEpochSchema()` (R2-L7) and

- A tombstone pin is a no-op until C12 (no records or pairs exist yet).

Deviation from the plan above: the device base (identity, ownership,
quarantine), structure validation, the §4 intent guard and the S2C device
view move to C11b, where the laser drill is their first user and the first

### C11b progress (2026-10-01)

Committed in parts: `4387137` (tables, `laser-v1`, the operation rule,
settings and built-in tables), `ea7a744` (device root, structures, admission,
work caps, intent guard, the S2C channel and device view, device commands)
`cf51064` (block, block entity, menu, screen, pattern, DataGen, GameTests)
and `454e962` (screen translation keys spelled out for the resource audit).

Implementation decisions for the C11 review:
- The device root holds every field under `endgame`, including the drill's
  buffers; any defect (unknown field, bad item, value out of bounds)
  quarantines the whole root. A block entity without a root gets a new ID;
  a root that exists but lacks an ID is quarantined (§2 read as: "without
  one" means without a root).
- Placement always creates a new device ID, so an item that carries block
  entity data (operators only, `onlyOpCanSetNbt`) never copies an ID.
- Work caps grant at the end of a tick for the next tick, so a device runs
  one tick after it becomes due; grants are in canonical ID order,
  round-robin.
- The intent rate is checked last, so a refused intent does not use up the
  player's interval. Refusal lines use one translation key with the code.
- A drill operates only where its owner may `OPERATE` at the station; any
  other case is `STATION_UNAVAILABLE` (ADR-055 §1 wording).
- The drill's structure is 3 × 3 × 3 Endgame Casing with the controller in
  the middle of the front face (community-authored). Nothing operates
  before the first validation after loading, so loads do not audit a
  transient `UNFORMED`.
- `/arce endgame device inspect|owner` arrive with the first device.
- Deferred to C11c with the beam visuals: the controller's emitter glow.

C11b evidence: [verification](v1.7.0-c11b-laser-logical/VERIFICATION.md) at
`454e962`: 1,275 JUnit tests and 299 GameTests passed, DataGen clean, the API
jar byte-identical to C11a.

### C11c progress (2026-10-02)

Committed in parts: `df344db` (shaft geometry, classification, counter
steps, codes), `36afa15` (endpoint registration, removal and freeze, the
`laser_target`, tags, beam renderer) and `3006637` (link, selection,
confirmation, layers, debt and credit, GameTests).

Implementation decisions for the C11 review:
- Layer classification order: the first cell, in cell order, that is immune
  or a fluid stops the layer (`BLOCKED_IMMUNE` or `BLOCKED_FLUID`); break
  events are posted only when no cell is immune or fluid.
- Contacts settle a debt whatever the switches and whether the drill runs
  (ADR-054 §1 settlement); credit layers and new layers need every breaking
  condition. A stopped layer takes no payment.
- **Link identity (refinement of §3, for the review).** Each link has a
  `link_id`, stored by the controller and by the marker next to
  `controller_id`. A marker accepts only the link it adopted. Without it, a
  controller relinking a marker it served before would count that marker's
  old `ops_done` as a debt of the new link. A reset remembers the last 8
  link IDs it dropped, so their controllers see `LINK_LOST` (as §3 requires)
  (replaced after the C11 review by the marker generation, C11R-M1, below)
  instead of adopting the marker again with a free credit; a marker that a
  crash returned unlinked still adopts its link and settles it as credit.
- Mode, link and unlink stop a running drill, so physical work always
  restarts through the 200-tick confirmation. A new link counts as settled
  until its first contact.
- Selection lists only `ACTIVE` targets whose footprint is inside the chunk,
  owned by the drill's owner (any owner for operators), in ID order.
- One audit line per physical layer (marker, y, cells, items), as ADR-055 §6
  lists it, plus `DEBT_SETTLED`, `CREDIT_USED`, `LINK_ABANDONED`,
  `MARKER_RESET` and a protection notice at most once per 1,200 ticks.
- Endpoint registration is in its own class (`EndpointRegistrations`);
  candidates are an immutable snapshot read by chunk-load threads.
- Tag files omit `"replace"`, which means `false`.
- The controller block entity is 577 lines with a single responsibility (the
  controller's lifecycle bridge); storage, physical engine, link and button
  effects are separate classes.
- GameTest fixtures post the `ChunkDataEvent.Save` a save would post, because
  vanilla throttles real saves of one chunk to one per 10 s of wall time.
- A GameTest found a crash in the first link (abandoning a link that did not
  exist); fixed before the commit.

Implementation decisions for the C11 review:
- **Composition (refinement of §4, for the review).** Consent needs the
  player, so the field layer is a player function in front of the
  unchanged station-region override inside `CelestialGravityController`
  (field, then station region, then Level profile); the position override
  keeps its signature.
- The five index caps are COMMON values that can only be lowered (ADR-054
  §1); admission checks `ACTIVE_LIMIT` before `FIELD_DENSITY`.
- Activation order: switch, owner, running, redstone, station
  (`STATION_UNAVAILABLE` in the Space Level outside every region,
  `STATION_OWNER_REQUIRED` inside a region), clipped box
  (`FIELD_OUTSIDE_STATION`), chain steps 2–6, energy, index. Upkeep is paid
  every tick after the check; a failed payment drops the field that tick.
- A field near the bottom or top of a Level whose box leaves the build
  height is refused by chain step 2 (`TARGET_OUT_OF_BOUNDS`).
- The trust list lives under `PlayerPersisted.advancedrocketrycommunity_field_trust`;
  unreadable entries are skipped and nothing is rewritten until the player
  changes the list. The commands take a player name or selector
  (`GameProfileArgument`) and refuse every source that is not the player's
  own, non-silent, connected source.
- Public views show the settings and the field size; box coordinates only
  with detail. Particles appear near the nearest player inside an active
  field's cube (client side, at most 4 per tick).
- `EndgameEnergyBuffer` is the shared bounded input-only buffer for new
  devices; the laser drill keeps its own C11b storage.

### C11 review fixes (2026-10-02)

The independent review of C11a–C11d (at `8d52d7f`) accepted C11a with
required changes and C11d, and rejected C11b and C11c until their findings
are fixed. Each finding is fixed in its own commit; the dispositions,
tests and the second review round go into the C11 review packet.

- **C11R-C1** (partial shift-click not persisted): device menu slots are
  `EndgameItemSlot`s, which forward `setChanged()` to the owning block
  entity. Forge's `SlotItemHandler` returns the handler's live stack and its
  `setChanged()` reaches only a dummy container, so a partial move out of a
  slot or a merge into a non-empty slot changed the stack without marking
  the chunk. Covers the drill's lens and output, the laser target buffer
  and the generator's fuel; GameTests save a chunk after a partial move.
- **C11R-C1, older menus**: the review asked to check the repository's other
  `SlotItemHandler` menus. The satellite terminal and builder (v1.5/v1.6)
  hold up to 64 redstone in their charge slots and had the same defect; their
  slots now mark the block entity changed too (separate commit, GameTest for
  both). The machine menus write moved stacks back with `set` and the
  microwave receiver's slots hold one item, so neither was affected.
- **C11R-M1** (8 revoked links): the marker keeps a `generation` that every
  reset raises and never lowers, in place of the bounded revoked list; the
  controller's link records the generation of its first contact (`-1`
  before). An unlinked marker adopts only a link that never touched it or one
  recorded at its current generation, so no number of later links and resets
  brings an old link's credit back, while a marker a crash returned unlinked
  still settles its link. The marker root and the drill's link gain a
  required `generation` and the marker loses `revoked`; no world with the
  earlier development format exists outside test runs (v1.7 is unreleased).

Cygnus X-1 data) and `e5d267a` (block, block entity, menu, screen,

Implementation decisions for the C12 review:
- "Plain item" means an item stack without NBT; the fuel slots refuse
  anything else, including through automation.
- A generator holds an active place while it is eligible (formed, enabled,
  owned, on a station orbiting a singularity); ineligibility releases it.
- Pulling energy through the capability shares the 20,000 FE per tick output
  with the push; the generator exposes no `receiveEnergy`.
- The structure is 3 × 3 × 3: Endgame Casing, obsidian on the two sides and
  the back of the middle layer, a crying obsidian core, the controller in the
  front face (community-authored).
- The block entity is 546 lines with a single responsibility (the
  controller's lifecycle); codecs, data, burn rule and settings are separate.
- GameTest fixtures that need block entities to tick in a Level without
  players force their chunk: vanilla stops a Level's entities and block
  entities 300 ticks after it has neither players nor forced chunks, and
  region tickets do not count. The pinned packaged-body count becomes nine.
