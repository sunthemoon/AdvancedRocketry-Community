## Goal

Deliver a bounded, server-authoritative vertical slice that scans a connected
block rocket from an assembler, reports deterministic structure statistics,
converts it transactionally into a same-dimension `RocketEntity`, and restores
the exact approved structure and container contents at its original origin.

## Scope and non-goals

In scope: loaded-chunk-only connected scanning, fixed structure/NBT limits,
diagnostic validation, canonical schema-1 snapshots, content hashes, server-
recomputed statistics, region locking, fault-injected assembly rollback,
collision-safe disassembly, vanilla container adapters, a thin persistent
entity, bounded tracking-player visual synchronization, cached block rendering,
DataGen, GameTests, dedicated-server restart, concurrency, conservation, and
manual rendering evidence.

Explicit non-goals: no launch, fuel consumption, flight state machine,
destination selection, cross-dimension transfer, orbital physics, arbitrary
third-party BlockEntity movement, chunk forcing, dynamic dimensions, stations,
satellites, or v0.6+ travel behavior.

No upstream code or binary asset will be copied for this slice. Upstream is a
behavior/algorithm reference only; all Java, data, text, and visual resources
introduced here are community-authored and must be recorded as such.

## Fixed safety and authority decisions

The repository-approved defaults in `docs/03-TARGET-ARCHITECTURE.md` are the
v0.5 release limits. Reducing or increasing them requires benchmark evidence
and an ADR.

| Boundary | Value | Failure behavior |
|---|---:|---|
| Rocket blocks | 2,048 | stop scan; `TOO_MANY_BLOCKS` |
| Bounding-box volume | 32,768 | stop scan; `BOUNDING_VOLUME_EXCEEDED` |
| BlockEntities | 128 | reject before extraction |
| One approved BlockEntity NBT | 262,144 bytes | reject before extraction |
| Total snapshot NBT | 1,048,576 bytes | reject before extraction |
| Visual snapshot payload | 524,288 bytes | do not track/render; retain server entity |
| S2C visual chunk | 32,768 bytes | reject malformed count/index/length |
| Concurrent visual reassemblies/client | 8 | evict incomplete oldest entry |

Only already-loaded chunks may be inspected or modified. The client submits an
operation intent and target identity, never blocks, statistics, snapshot NBT,
or material counts. Ordinary approved states may move. Vanilla chest/barrel
contents use a bounded explicit adapter. Project-owned adapters must opt in.
Every other BlockEntity, including all unregistered third-party types, is
rejected by default with its position and registry identifier. Command blocks,
portals, moving pistons, structure blocks, jigsaws, spawners, and known chunk-
loading/administrative blocks are forbidden.

## Active slice

### `V050-SCAN-001` Connected server-selected structure discovery

- Status: `in-progress`
- Observable outcome: starting from a server-chosen block above the assembler,
  the scanner discovers exactly the connected component of movable states and
  returns stable relative blocks, metrics, anchors, and diagnostics.
- Scope / non-goals: pure resumable scanner plus world-view interface; no chunk
  tickets, synchronous load, world mutation, entity spawn, or client data.
- Dependencies / interfaces: verified snapshot vocabulary, six-neighbor integer
  positions, a classification/metrics resolver, and approved BE capture result.
- Acceptance criteria: deterministic result independent of neighbor order;
  empty/non-movable/forbidden/unsupported-BE inputs name their exact position;
  the server-selected seed is the only authority for scan origin.
- Verification: fake-world JUnit tests for connected/disconnected structures,
  deterministic order, all classifications, and malicious world-view behavior.
- Evidence: pending scanner implementation and test output.

### `V050-SCAN-002` Loaded-chunk and work-budget enforcement

- Status: `ready`
- Observable outcome: an unloaded candidate suspends or rejects without invoking
  any loading API, and each scanner step performs at most its supplied positive
  inspection budget.
- Scope / non-goals: loaded-state observation only; no forced chunks, tickets,
  async world access, or unbounded one-tick flood fill.
- Dependencies / interfaces: `V050-SCAN-001` and a tri-state loaded-world view.
- Acceptance criteria: unloaded seed/neighbor returns `UNLOADED_CHUNK`; a
  malicious view cannot make inspection count exceed the fixed limit; block,
  extent, volume, palette, BE count, per-BE NBT, and total NBT growth stop at the
  first invalid observation.
- Verification: exact-counter boundary tests plus Forge GameTests after the
  ServerLevel adapter exists.
- Evidence: pending.
