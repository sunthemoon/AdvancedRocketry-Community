## Goal

Deliver one complete Electrolyzer machine vertical slice that proves bounded
recipe decoding, server-authoritative item/fluid/energy processing, capability
sides, persistence, menu synchronization, automation, multiplayer consistency,
performance, and restart behavior without recreating LibVulpes.

## Scope and non-goals

In scope: one single-block Electrolyzer, one bounded recipe type, four machine
inventory slots, one water tank, one Forge Energy buffer, standard menu sync,
DataGen, tests, dedicated restart, two-player observation, and release evidence.

Explicit non-goals: no general machine base, power cables/generator network,
custom GUI DSL, multiblock matcher, JEI dependency, custom C2S result packet,
gas fluid registration, dimensions, atmosphere, rockets, or later-version
progression. Gas is represented only by two output canister items in this slice.

## Decision log

- `2026-08-31`: choose a single-block Electrolyzer rather than the legacy
  multiblock. The old recipe is behavior reference only; the modern slice uses
  gas canister items so one machine exercises both item and fluid boundaries
  without adding a premature gas-fluid subsystem.
- `2026-08-31`: exact cycle is 2 empty canisters + 1000 mB water + 2000 FE over
  100 ticks -> 1 hydrogen canister + 1 oxygen canister.
- `2026-08-31`: allow redstone charging at 2000 FE per dust solely to make the
  isolated survival flow self-contained; side Forge Energy remains supported.
- `2026-08-31`: consume inputs/fluid only at atomic completion and lock them
  while progress is nonzero, preventing partial loss and concurrent mutation.
- `2026-08-31`: defer JEI because it is optional and not needed to prove this
  vertical slice; present/absent compatibility therefore remains not applicable.
