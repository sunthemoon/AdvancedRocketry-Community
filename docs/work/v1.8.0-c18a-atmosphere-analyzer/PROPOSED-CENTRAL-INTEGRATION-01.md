## Item, configuration and creative tab

Add to `registry/ModItems.java`, using the existing DeferredRegister:

```java
public static final RegistryObject<Item> ATMOSPHERE_ANALYZER = ITEMS.register(
        "atmosphere_analyzer", () -> new AtmosphereAnalyzerItem(new Item.Properties(),
                () -> CommonConfig.CLASSIC_DEVICES_ENABLED.get()));
```

The new imports refer to the owned item and existing configuration class.
The item enforces a stack size of one. It owns no durability, capability or NBT.
Its constructor also accepts an explicit read callback for isolated adapter tests;
the two-argument constructor uses the lifecycle-managed analyzer runtime.

Add one COMMON BooleanValue before CommonConfig's spec is built:

```java
public static final ForgeConfigSpec.BooleanValue CLASSIC_DEVICES_ENABLED = BUILDER
        .comment("Enable classic atmosphere instruments; registered items and recipes remain available.")
        .define("lifeSupport.classicDevicesEnabled", true);
```

The worker source does not reference this not-yet-existing field. Root's config
test must verify the exact key/default and the changed total key count, without
weakening existing range checks. Add only
`output.accept(ModItems.ATMOSPHERE_ANALYZER.get());` to the main creative tab.

## Host lifecycle

In the mod constructor, alongside the existing environment-query lifecycle,
construct and register:

```java
AtmosphereAnalyzerLifecycle analyzers = new AtmosphereAnalyzerLifecycle(celestialCatalogs,
        () -> atmosphereManager);
MinecraftForge.EVENT_BUS.addListener(analyzers::onServerStarted);
MinecraftForge.EVENT_BUS.addListener(EventPriority.HIGHEST, analyzers::onServerStopping);
MinecraftForge.EVENT_BUS.addListener(EventPriority.HIGHEST, analyzers::onServerStopped);
```

Common setup already initializes the existing AtmosphereManager before
ServerStarted. The supplier is evaluated at ServerStarted only. The new
lifecycle acquires StationRegistrySavedData once at startup and exposes only its
existing committed lookup. Stopping/stopped removal matches the private handle
and owning server. Do not clear or replace existing atmosphere/equipment state
from item use. No new network or public API registration is proposed.

## DataGen and language

In BootstrapDataGenerators.gatherData add one provider:

```java
generator.addProvider(event.includeClient() || event.includeServer(),
        new V180AtmosphereAnalyzerData(output, event.includeClient(), event.includeServer()));
```

In the existing single V180LanguageProvider.addTranslations add:

```java
V180AtmosphereAnalyzerLanguage.translations(chinese).forEach(this::add);
```

The provider writes exactly one original texture, one item model, one NEW
shapeless recipe and one normal recipe-unlock advancement. The language map has
15 bilingual unique keys, including only the previously missing Space body name.
No old recipe, body name or other asset is changed. The pre-authoring provenance
record is already committed; Root must bind generated bytes and source hashes
after integration and examine the original art/derivation and V1 evidence.

## Validation and limits

Owned GameTests resolve the registered item by stable ID, so compiling them does
not require an unowned ModItems field. They are not runnable until Root supplies
the registration, lifecycle and generated recipe. Compile/scoped unit evidence
does not establish lifecycle/native-use, disabled/cooldown world behavior, native
restart or V1/V2. Root must run the full required Java/DataGen/GameTest and resource
checks on the integrated committed cohort, then independently exercise actual
player/native/client behavior under the adopted ownership limits. The leaf does
not authorize the unresolved synthetic native-player draft or any query-side
resource writer. No migration or saved schema is required.
