# v1.4.0 implementation log

## Goal and scope

Deliver [Planetary Expansion](../versions/V1.4.0-PLANETARY-EXPANSION.md):
explorable contrasting worlds, non-landable logical bodies, authoritative
environment, navigation/discovery and sky presentation. Complete the scoped
implementation before the deferred full acceptance campaign; do not equate
development progress with release approval.

```yaml
version: v1.4.0
status: IN_PROGRESS
phase: IMPLEMENTING
branch: codex/v1.4.0-planetary-expansion
accepted_development_baseline: 1a192b4b9b9a90372c11643e086f7b0fbdcd1860
runtime_implementation_allowed: true
last_updated: 2026-09-27
```

The baseline contains the reviewed v1.3 implementation and development handoff,
not a passed v1.3 candidate. Inherited acceptance remains open. Root is the sole
tracked writer; independent review is read-only with fresh Temp outputs. The
user-supplied untracked documentation bundle is excluded from reads and writes.

Preparation non-goals: runtime changes, new assets, changing an existing world,
candidate/tag/release approval, remote/client/long-load tests or v1.5+ features.
No physics, terrain, sky, discovery or API implementation is implied by contract
acceptance. Runtime permission is limited to the accepted current-version
contracts; later persistent/public changes still need their own decisions.

### V140-DATA-01 execution scope

- Status: verified, starting from `8947fac9641dc11ce2dce1ed8a3877984be044ab`.
- Owner/write scope: root only; celestial model/catalog/commands/snapshot,
  typed flight planning/quotes, legacy target migration/import adaptation,
  station creation admission, legacy DataGen encoding, corresponding unit and
  GameTests, current development metadata and this slice's evidence.

  [data guide](../CELESTIAL-DATA-GUIDE.md); no external asset is introduced.
- Dependencies: accepted ADR-030/031 and unchanged API 1.7/persistent contracts.
- Observable result: schema-2 unmapped bodies can load and synchronize without
  acquiring a surface; closed arrivals are rejected before fuel/journal mutation,
  while existing mapped sources and committed stations can depart.
- Non-goals: new actual worlds, durable custom mapping ledger, joint/raw reload
  (DATA-02), temperature/solar gameplay, sky/assets, new API exports, save schema
  changes, full acceptance, remote or long-load tests. Built-in v0.3 generated
  resources keep their original authoring format and hashes through an explicit
  checked legacy encoder, not silent downgrade of schema-2 intent.
- Verification: actual production Codec/constructor boundaries and legacy
  round trips, mapping/migration/planner/snapshot tests, live authority GameTests,
  clean build/DataGen, bounded packaged restart, API export identity and
  independent actual-diff/key-command review. Final independent execution passed
  792 JUnit tests, 213 GameTests and five Python runner tests; DataGen changed
  no resource. Two actual packaged processes passed the bounded same-world
  restart. Earlier failures and their corrections remain in
  [slice evidence](v1.4.0-data01/VERIFICATION.md).

`V140-DATA-01` adds the definition decoder/model and adapts every current
consumer of mandatory Level mappings, including snapshots and authoritative
destination checks. Its outcome is a usable non-landable definition in the
existing runtime, not a standalone unused model. Existing IDs, environment
values, physical Levels, station UUID/orbit-body records and flight journals
must not be rewritten merely because a data definition gets a version.

Acceptance includes legacy/default round trips, invalid capability/value input,
unmapped-body behavior, destination refusal without fuel mutation, departing a
still-mapped body closed to new arrivals, and matching display protocol checks.
The short unit/GameTest/build/DataGen checks and bounded packaged restart were
executed against the implementation; full acceptance was not started.
Joint resource reload is DATA-02;
DATA-01 alone must not advertise cross-catalog atomicity.
New-world travel also depends on MAP-01/02: the existing landing selector and
player station-creation flow still restrict physical destinations to Earth/Moon.
Schema support is not evidence that Mars is already reachable or that arbitrary
custom body remapping is safe across restarts.
