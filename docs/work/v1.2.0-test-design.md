## A1 — representative machine GameTests

### Rolling Machine

- `V120-ROLL-001`: form at every supported transform and process one mixed Item/Fluid batch.
- `V120-ROLL-002`: wrong casing, missing port and blocked output expose distinct diagnostics.
- `V120-ROLL-003`: automated insertion/extraction follows local-side port policy.
- `V120-ROLL-004`: break during progress, rebuild and resume/stop per frozen policy without loss.

### Electrolyzer migration

- `V120-ELEC-001`: all existing Electrolyzer GameTests remain registered and pass unchanged.
- `V120-ELEC-002`: schema 1 fixture upgrades with identical slots, water, energy and progress.
- `V120-ELEC-003`: 50-cycle ledger before/after migration is byte-for-byte equivalent.
- `V120-ELEC-004`: existing block/menu/recipe IDs and side policies remain stable.

- `V120-PREC-001`: 2-input and 5-input definitions select deterministically.
- `V120-PREC-002`: multiple outputs commit atomically or not at all.
- `V120-PREC-003`: wildcard port placement resolves to deterministic channels.
- `V120-PREC-004`: concurrent viewers/automation cannot complete the same batch twice.

## Performance design

Short deterministic checks run before the deferred reference load:

- `V120-PERF-001`: 100 idle controllers for 2,000 ticks; no pattern scan without dirty event.
- `V120-PERF-002`: bounded active-machine batch; record tick calls, recipe lookups and commits.
- `V120-PERF-003`: dirty queue drains under configured per-tick cell/controller budget.
- `V120-PERF-004`: repeated capability queries return cached views and invalidate once.
- `V120-PERF-005`: 5×5×5 Arc Furnace-shaped fixture stays inside cell budget.

Final `G7` still requires the repository's 4 vCPU/8 GiB Debian 12 reference workload and
100 idle plus defined active machines. The owner-deferred long soak is not replaced by
the short checks and remains `NOT_RUN` until later acceptance.

## Evidence map

Implementation must archive raw logs and summaries under `docs/releases/v1.2.0/`:

- A0 XML/test reports → `TEST-REPORT.md`;
- GameTest log + structure fixtures → `evidence/gametest/`;
- schema fixtures and forced-stop matrix → `MIGRATION-REPORT.md`;
- capability/security cases → `SECURITY-REVIEW.md`;
- short and reference workloads → `PERFORMANCE.md`;
- GUI/JEI/real GPU evidence → `VISUAL-VALIDATION-REPORT.md`;
- exact candidate commit/JAR/checksums → `RELEASE-EVIDENCE.md` and `checksums.txt`.

No test may be checked complete from source presence alone. Each result records command,
exit code, tested commit, environment and raw evidence path.
