## Gate ordering prerequisite: provenance subreview before capture

Do **not** begin the packaged-client session while the v0.0.2 provenance review
is pending. Approval of this G0 provenance/license subreview changes review
fields in `THIRD-PARTY-NOTICES.md`, and that file is packaged into both JARs. A
client run made before that change would bind an obsolete artifact even if every
screenshot and connection step passed.

The repository owner or explicitly assigned license reviewer must first:

1. from a clean checkout, generate and verify the commit-bound review packet;
2. resolve the four neutral questions in the packet against the exact
   provenance record, manifest, notice, license copies, target blobs, and
   mechanical evidence it contains;
3. update the authoritative review fields consistently while leaving
   `reviewed_content_sha256` null, run the approval-candidate mode, inspect and
   explicitly apply the resulting candidate digest, then require the approved
   state;
4. rebuild both JARs, regenerate the committed artifact manifest, all four G0
   mechanical evidence files, and release checksums; commit the approved review
   and refreshed evidence together, rerun all local Required Gate commands, and
   obtain successful blocking CI for that exact commit;
5. refresh the tested commit/run/artifact fields in this handoff.

The packet path must not already exist. It is ignored build output and never
edits an authoritative file:

```text
python -I -S -c "from pathlib import Path; Path('build').mkdir(exist_ok=True)"
python -I -S scripts/prepare_v002_g0_review_packet.py generate --commit HEAD --output build/v0.0.2-g0-review-packet
python -I -S scripts/prepare_v002_g0_review_packet.py verify --commit HEAD --packet build/v0.0.2-g0-review-packet
```

Keep `-I -S`: those flags prevent host `sitecustomize`, user-site packages, and
ambient Python path configuration from running before the packet tool verifies
its commit-bound runtime inputs. The first command creates only the ignored
parent directory; packet generation then rejects a symlink/reparse parent, a
pre-existing packet path, or overlap with any tracked index path.

The diagnostic digest in the packet is labeled
`PENDING_CONTENT_DIAGNOSTIC_ONLY` and must never be copied into approval
metadata. After the authorized reviewer completes every decision and all
approval metadata except the digest, run the candidate command below. It
refuses the current pending state and writes no files. Apply the printed
candidate explicitly to both authoritative fields before running the second
command:

```text

python -I -S scripts/validate_bootstrap_provenance.py --require-approved-review
```

With the approved review still in the worktree, rebuild and refresh every
artifact-derived tracked file before committing:


## Evidence and privacy boundaries

- Use only new disposable server, client, and world directories under ignored
  `build/` paths. Do not point the test at an existing game directory or world.
- Use a loopback-only server. `online-mode=false` and
  `enforce-secure-profile=false` are permitted only for this local disposable
  instance and must never be copied to a public server.
- For Minecraft roles, capture the full Minecraft window, not the launcher,
  desktop, terminal, browser, account selector, or unrelated windows. The
  `readme_render` role is the sole exception: capture the full browser or editor
  Markdown-preview window with no unrelated tabs, account UI, or desktop area.
- Do not commit account names, launcher profile names, access tokens, player
  UUIDs, or unredacted player identities. Keep full logs in the ignored local
  session; copy only selected UTF-8 excerpts and replace the test identity with
  `[REDACTED_TEST_PLAYER]`, noting that redaction in the evidence file.
- Use a repository-approved tester identifier in the report; do not reuse a
  Minecraft or launcher account name as that identifier.
- Enter the exact disposable Minecraft test name only in the ignored
  `build/.../session.json` `privacy.player_names` list. The matching join and
  leave lines must use that identity in both server cycles; the collector
  verifies the identity and archives only redacted lines plus an opaque HMAC
  made with a per-run 32-byte secret that is never archived.
- Do not include unrelated worlds, saved servers, chat, or personal resource
  packs. The isolated client directory should make those lists empty.
- Record observations exactly. A failed or surprising mismatch result keeps
  the relevant Gate open; it must not be rewritten as a pass.
