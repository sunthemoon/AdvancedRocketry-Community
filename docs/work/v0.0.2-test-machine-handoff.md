## Evidence and privacy boundaries

- Use only new disposable server, client, and world directories under ignored
  `build/` paths. Do not point the test at an existing game directory or world.
- Use a loopback-only server. `online-mode=false` and
  `enforce-secure-profile=false` are permitted only for this local disposable
  instance and must never be copied to a public server.
- Capture the full Minecraft window, not the launcher, desktop, terminal,
  browser, account selector, or unrelated windows.
- Do not commit account names, launcher profile names, access tokens, player
  UUIDs, or unredacted player identities. Keep full logs in the ignored local
  session; copy only selected UTF-8 excerpts and replace the test identity with
  `[REDACTED_TEST_PLAYER]`, noting that redaction in the evidence file.
- Use a repository-approved tester identifier in the report; do not reuse a
  Minecraft or launcher account name as that identifier.
- Do not include unrelated worlds, saved servers, chat, or personal resource
  packs. The isolated client directory should make those lists empty.
- Record observations exactly. A failed or surprising mismatch result keeps
  the relevant Gate open; it must not be rewritten as a pass.

## 2. Create and retain the loopback server

Choose a new absolute session directory that does not exist, then run the smoke
harness with the final artifact and offline mode:

```text
python scripts/run_dedicated_server_smoke.py build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar --offline-mode --session-dir <new-absolute-server-session-directory>
```

The harness downloads and verifies the pinned official Forge installer,
installs Forge 47.4.10, binds the instance to `127.0.0.1`, copies the artifact,
runs first-start and same-world restart cycles, and stops. Retain the complete
printed session directory: it is the packaged server used for the player test,
not a staging source for a different server.

Record the port from `server.properties` or `evidence/summary.json`. Confirm
that both smoke cycles passed before continuing. Do not delete or recreate the
world between the manual join and reconnect cycles.

## 3. Create a clean packaged Forge client

The final client evidence must come from a packaged Forge profile. ForgeGradle
`runClient` is not an acceptable substitute because it loads development
outputs rather than the distributable JAR.

1. Use the official Forge 1.20.1-47.4.10 installer. The installer cached and
   hash-verified by the server harness may be reused; select **Install client**.
2. In the Minecraft launcher, create a new installation using the installed
   Forge 1.20.1-47.4.10 version, Java 17, and a new isolated game directory
   under `build/`. Do not reuse or reveal an existing launcher installation.
3. Create the isolated directory's `mods/` folder and copy the already-built
   artifact into it. Install no other mods.
4. Do not rebuild, rename, re-sign, optimize, or otherwise transform the JAR.

Verify the source artifact, retained server copy, and isolated client copy are
byte-identical. On PowerShell:

```powershell
$artifact = (Resolve-Path 'build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar').Path
$serverJar = '<server-session>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar'
$clientJar = '<client-game-directory>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar'
$hashes = @($artifact, $serverJar, $clientJar) | ForEach-Object {
    Get-FileHash -Algorithm SHA256 -LiteralPath $_
}
$hashes | Format-Table Path, Hash
if (@($hashes.Hash | Sort-Object -Unique).Count -ne 1) {
    throw 'Source, server, and client JAR SHA-256 values differ'
}
```

On Linux:

```bash
sha256sum \
  build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <server-session>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <client-game-directory>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar
test "$(sha256sum \
  build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <server-session>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <client-game-directory>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  | awk '{print $1}' | sort -u | wc -l)" -eq 1
```

Copy the three displayed paths and their one shared hash into the test record.
A mod version shown in the UI is not a replacement for this equality check.

## 4. Capture packaged-client metadata and world startup

Launch the isolated packaged Forge profile and complete these observations:

1. Open **Mods**, select **Advanced Rocketry: Community Edition**, and capture
   the full Minecraft window showing name, version, description, credits,
   license, and logo.
2. Create a disposable single-player world, wait until the player is in-world,
   and capture the full Minecraft window.
3. Save and return to the title screen.
4. Review `<client-game-directory>/logs/latest.log`. Record the project-source

Keep the raw log locally. Archive only screenshots that pass the privacy review
and selected log lines needed to show project initialization and world entry.

## 5. Join, disconnect, restart, and reconnect

From the retained server directory, start Forge with Java 17:

```powershell
# PowerShell
java -Xms512M -Xmx1024M '@libraries/net/minecraftforge/forge/1.20.1-47.4.10/win_args.txt' nogui
```

```bash
# Linux shell
java -Xms512M -Xmx1024M @libraries/net/minecraftforge/forge/1.20.1-47.4.10/unix_args.txt nogui
```

Use the isolated packaged client that passed the three-way JAR hash check:

1. Add only `127.0.0.1:<recorded-port>` to its empty multiplayer list.
2. Before joining, record the server-list compatibility indicator and any
   Forge compatibility text shown for the matching client.
3. Join and wait until the player is fully in-world. Capture the full Minecraft
   window and record the corresponding server join line.
4. Disconnect through the client UI and record the server leave line.
5. At the server console, run `save-all flush`, wait for the save confirmation,
   then run `stop` and require exit code 0.
6. Before restarting, preserve the first cycle's full `logs/latest.log` inside
   the ignored test session.
7. Start the same server directory again without changing the world, port, or
   JAR. Reconnect with the same packaged client and capture the in-world result.
8. Disconnect, run `save-all flush`, then `stop`; require exit code 0 and
   preserve the second cycle log.
9. Review both client and server logs for project-source ERROR/WARN lines and
   client-class linkage failures. Record counts and explanations rather than
   deleting findings.

Both connections must use the exact client/server JAR hash recorded in step 3.
The earlier headless smoke cycles alone do not satisfy this player-connection
case.

## 6. Observe the declared mismatch policy

The mod declares `displayTest="MATCH_VERSION"`. Observe its packaged behavior
without altering the positive client profile:

1. Create a second new isolated Forge 1.20.1-47.4.10 game directory containing
   no project JAR and no other mods.
2. Start the retained loopback server.
3. In that Forge-only client's multiplayer list, record the actual
   compatibility indicator and complete message for the same loopback server.
4. Attempt the connection once. Record whether Forge rejects it before world
   entry or accepts it, together with the client and server messages.
5. Disconnect if necessary and stop the server cleanly.

This is a missing-project-mod observation, not an optional-dependency test.
Do not prefill the outcome. If the observed behavior conflicts with the
declared policy or is ambiguous, leave G4 `IN_PROGRESS` and document the
finding for review.

## Diagnostic-only fallback

If the packaged client fails and additional diagnosis is needed, the isolated
ForgeGradle run remains available:

```text
./gradlew -ParceEvidenceRun=true runClient --no-daemon --stacktrace
```

Label all output from this command `DIAGNOSTIC_ONLY`. It may help reproduce a
failure, but it must not be used as the Mods-page, world-start, JAR-loading,
join, reconnect, or mismatch evidence for the packaged acceptance case.
