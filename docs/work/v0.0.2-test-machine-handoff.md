### Preserve a failed attempt before retrying

Every manual-session path below is intentionally create-once. If a server,
client, snapshot, or mismatch step fails, stop only the Minecraft client and
dedicated-server Java processes launched for this evidence attempt; leave
unrelated Java or Minecraft processes alone. Retain the entire failed root before
starting again. From the repository root, the following PowerShell block verifies
that the source and destination remain below this checkout's ignored `build/`
directory, rejects reparse-point roots, then moves the failed attempt without
deleting or merging any evidence:

```powershell
$repoRoot = (Resolve-Path -LiteralPath '.').Path
$buildRoot = (Resolve-Path -LiteralPath 'build').Path
$manualRoot = (Resolve-Path -LiteralPath 'build/v0.0.2-manual' -ErrorAction Stop).Path
$buildItem = Get-Item -Force -LiteralPath $buildRoot -ErrorAction Stop
$manualItem = Get-Item -Force -LiteralPath $manualRoot -ErrorAction Stop
$separator = [System.IO.Path]::DirectorySeparatorChar
$reparsePoint = [System.IO.FileAttributes]::ReparsePoint
if (-not $buildRoot.StartsWith($repoRoot + $separator, [System.StringComparison]::OrdinalIgnoreCase)) {
    throw 'Resolved build directory is outside the repository'
}
if (-not $manualRoot.StartsWith($buildRoot + $separator, [System.StringComparison]::OrdinalIgnoreCase)) {
    throw 'Resolved manual attempt is outside build/'
}
if (($buildItem.Attributes -band $reparsePoint) -ne 0) {
    throw 'Refusing to move evidence through a reparse-point build root'
}
if (($manualItem.Attributes -band $reparsePoint) -ne 0) {
    throw 'Refusing to move a reparse-point manual root'
}
$failedRoot = Join-Path $buildRoot ("v0.0.2-manual-failed-" + (Get-Date -Format 'yyyyMMdd-HHmmss'))
if (Test-Path -LiteralPath $failedRoot) {
    throw "Failed-attempt destination already exists: $failedRoot"
}
Move-Item -LiteralPath $manualRoot -Destination $failedRoot -ErrorAction Stop
Write-Output "Retained failed attempt at $failedRoot"
```

Record the failure reason and retained path in the work log, recreate the exact
`build/v0.0.2-manual` paths with the commands below, and rerun the procedure from
the template step. Launcher installations must again point at the newly created
absolute paths. Do not reuse a snapshot, raw log, server runtime, or screenshot
from the retained attempt in the fresh session. On Linux, apply the same rule
with a new timestamped sibling below the verified repository `build/` directory.

A failed strict collection leaves the canonical client-bundle destination
absent. If that destination exists, do not delete or replace it: it represents a
successful atomic collection or an already tracked bundle and requires evidence-
owner review before another attempt. Non-strict failure bundles belong only in
the retained ignored attempt root.
