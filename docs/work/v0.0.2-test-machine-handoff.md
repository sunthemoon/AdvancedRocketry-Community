## Evidence and privacy boundaries

- Use only new disposable server, client, and world directories under ignored
  `build/` paths. Do not point the test at an existing game directory or world.
- Use a loopback-only server. `online-mode=false` and
  `enforce-secure-profile=false` are permitted only for this local disposable
  instance and must never be copied to a public server.
- Capture the full Minecraft window, not the launcher, desktop, terminal,
  browser, account selector, or unrelated windows.
- Do not commit account names, launcher profile names, access tokens, player
  UUIDs, or unredacted player identities. Keep full logs in the ignored local
  session; copy only selected UTF-8 excerpts and replace the test identity with
  `[REDACTED_TEST_PLAYER]`, noting that redaction in the evidence file.
- Use a repository-approved tester identifier in the report; do not reuse a
  Minecraft or launcher account name as that identifier.
- Do not include unrelated worlds, saved servers, chat, or personal resource
  packs. The isolated client directory should make those lists empty.
- Record observations exactly. A failed or surprising mismatch result keeps
  the relevant Gate open; it must not be rewritten as a pass.

## 3. Create a clean packaged Forge client

The final client evidence must come from a packaged Forge profile. ForgeGradle
`runClient` is not an acceptable substitute because it loads development
outputs rather than the distributable JAR.

1. Use the official Forge 1.20.1-47.4.10 installer. The installer cached and
   hash-verified by the server harness may be reused; select **Install client**.
2. In the Minecraft launcher, create a new installation using the installed
   Forge 1.20.1-47.4.10 version, Java 17, and a new isolated game directory
   under `build/`. Do not reuse or reveal an existing launcher installation.
3. Create the isolated directory's `mods/` folder and copy the already-built
   artifact into it. Install no other mods.
4. Do not rebuild, rename, re-sign, optimize, or otherwise transform the JAR.

Verify the source artifact, retained server copy, and isolated client copy are
byte-identical. On PowerShell:

```powershell
$artifact = (Resolve-Path 'build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar').Path
$serverJar = '<server-session>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar'
$clientJar = '<client-game-directory>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar'
$hashes = @($artifact, $serverJar, $clientJar) | ForEach-Object {
    Get-FileHash -Algorithm SHA256 -LiteralPath $_
}
$hashes | Format-Table Path, Hash
if (@($hashes.Hash | Sort-Object -Unique).Count -ne 1) {
    throw 'Source, server, and client JAR SHA-256 values differ'
}
```

On Linux:

```bash
sha256sum \
  build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <server-session>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <client-game-directory>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar
test "$(sha256sum \
  build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <server-session>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  <client-game-directory>/mods/advancedrocketry-community-1.20.1-0.0.2-dev.jar \
  | awk '{print $1}' | sort -u | wc -l)" -eq 1
```

Copy the three displayed paths and their one shared hash into the test record.
A mod version shown in the UI is not a replacement for this equality check.

## 5. Join, disconnect, restart, and reconnect

Start the player-cycle harness in a separate terminal. The session and evidence
paths must not already exist:

```text
python scripts/run_dedicated_server_smoke.py build/libs/advancedrocketry-community-1.20.1-0.0.2-dev.jar --offline-mode --manual-player-cycles --player-timeout 900 --work-root build/v0.0.2-manual/player-server-work --session-dir build/v0.0.2-manual/server --evidence-dir build/v0.0.2-manual/server-player-evidence
```

The harness prints a `[WAIT]` line after each cycle reaches `Done`. In each
cycle it waits for a matching client join followed by a disconnect, issues
`save-all flush`, waits for `Saved the game`, sends `stop`, and requires exit
code 0. It then starts the second cycle against the same world and port. Do not
start or stop the server outside this harness, edit the world marker, or reuse a
previous session directory.

Use the isolated packaged client that passed the three-way JAR hash check:

1. Read the loopback port from the harness console or
   `build/v0.0.2-manual/server/server.properties`, then add only
   `127.0.0.1:<recorded-port>` to the empty multiplayer list. While the first
   cycle is waiting, complete the three-way JAR hash check in section 3.
2. Before joining, record the server-list compatibility indicator and any
   Forge compatibility text shown for the matching client.
3. Join and wait until the player is fully in-world. Capture the full Minecraft
   window and record the corresponding server join line.
4. Disconnect through the client UI and record the server leave line.
5. Let the harness save, stop, and restart. Do not type server commands while it
   owns the session. Wait for its second `[WAIT]` line, reconnect with the same
   packaged client, and capture the in-world result.
6. Disconnect through the client UI and wait for the harness to report PASS.
   Retain `build/v0.0.2-manual/server-player-evidence/summary.json`,
   `build/v0.0.2-manual/server/first-start-full.txt`, and
   `build/v0.0.2-manual/server/restart-full.txt`; do not edit them. The shorter
   selected logs remain in `build/v0.0.2-manual/server-player-evidence/` but do
   not replace either complete raw log.
7. Review both client and server logs for project-source ERROR/WARN lines and
   client-class linkage failures. Record counts and explanations rather than
   deleting findings.

Both connections must use the exact client/server JAR hash recorded in step 3.
The earlier headless smoke cycles alone do not satisfy this player-connection
case. A project-source server ERROR or WARN, client-class linkage finding,
missing join/leave marker, failed save/stop, or nonzero exit makes the harness
fail; preserve that failure instead of changing the log.

## 6. Observe the declared mismatch policy

The mod declares `displayTest="MATCH_VERSION"`. Observe its packaged behavior
without altering the positive client profile:

1. Create a second new isolated Forge 1.20.1-47.4.10 game directory containing
   no project JAR and no other mods.
2. After the section 5 harness has reported PASS and exited, start its retained
   server directly from `build/v0.0.2-manual/server`. Do not invoke the harness
   again: it intentionally refuses an existing runtime session. Use Java 17 and
   the platform command below.
3. Wait for `Done (` in the server console. In the Forge-only client's
   multiplayer list, record the actual
   compatibility indicator and complete message for the same loopback server.
4. Attempt the connection once. Record whether Forge rejects it before world
   entry or accepts it, together with the client and server messages.
5. Disconnect if necessary. In the server console, enter `save-all flush`, wait
   for `Saved the game`, then enter `stop` and require exit code 0.

PowerShell:

```powershell
Push-Location 'build/v0.0.2-manual/server'
try {
    $archive = Join-Path (Resolve-Path -LiteralPath '..').Path 'mismatch-server-full.txt'
    if (Test-Path -LiteralPath $archive) {
        throw "Refusing to replace existing mismatch log: $archive"
    }
    & java -Xms512M -Xmx1024M '-Djava.net.preferIPv4Stack=true' '@libraries/net/minecraftforge/forge/1.20.1-47.4.10/win_args.txt' nogui
    $serverExit = $LASTEXITCODE
    [System.IO.File]::Copy(
        (Resolve-Path -LiteralPath 'logs/latest.log').Path,
        $archive,
        $false
    )
    if ($serverExit -ne 0) {
        throw "Mismatch-observation server exited with code $serverExit"
    }
} finally {
    Pop-Location
}
```

Linux:

```bash
set -euo pipefail
cd build/v0.0.2-manual/server
test ! -e ../mismatch-server-full.txt
set +e
java -Xms512M -Xmx1024M -Djava.net.preferIPv4Stack=true \
  @libraries/net/minecraftforge/forge/1.20.1-47.4.10/unix_args.txt nogui
server_exit=$?
set -e
set -o noclobber
cat -- logs/latest.log > ../mismatch-server-full.txt
set +o noclobber
cd ../../..
if [ "$server_exit" -ne 0 ]; then
  echo "Mismatch-observation server exited with code $server_exit" >&2
  exit "$server_exit"
fi
```

This direct third startup is only the mismatch observation. Preserve
`build/v0.0.2-manual/mismatch-server-full.txt` locally and select any relevant
lines for the recorded actual result. Do not add it to the two-cycle schema-v2
summary, replace either harness full log, or describe it as matching-client
restart evidence.

This is a missing-project-mod observation, not an optional-dependency test.
Do not prefill the outcome. If the observed behavior conflicts with the
declared policy or is ambiguous, leave G4 `IN_PROGRESS` and document the
finding for review.

For a completed player harness session, set the generated template entry to:

```json

  "summary": "build/v0.0.2-manual/server-player-evidence/summary.json",
```

Use `build/v0.0.2-manual/server/first-start-full.txt` and
`build/v0.0.2-manual/server/restart-full.txt` as the two server log sources. The
collector independently scans each complete raw source and every archived
excerpt for project ERROR,
project WARN, broad ERROR/WARN, and client-class linkage markers. Any numeric
finding entered in the session must equal the independently derived count; a
self-reported zero cannot hide a detected project finding.

The schema-v2 harness summary binds the server artifact hash, loopback port,
timestamps, two cycle IDs, full-log filenames and hashes, exit codes, player
join/leave observations, and the same-world marker plus pre/post `level.dat`
snapshots. Strict readiness requires those bindings and lifecycle order
(`join -> leave -> Saved the game -> Stopping server`, with `Done` before the
restart join). The committed bundle keeps the verified summary and raw-log
audit records; build-local validation also rehashes and rescans the physical
sources.

Screenshots must be full-window RGB/RGBA PNGs. The helper enforces dimensions,
pixel and per-file limits, at most 128 chunks, a 40 MiB total payload, and only
essential chunks plus small recognized color/transparency chunks. Textual,
unknown, or other nonessential ancillary chunks are rejected rather than
trusted for privacy. A human must still review visible pixels for names,
addresses, notifications, and other private content.

## Diagnostic-only fallback

If the packaged client fails and additional diagnosis is needed, the isolated
ForgeGradle run remains available:

```text
./gradlew -ParceEvidenceRun=true runClient --no-daemon --stacktrace
```

Label all output from this command `DIAGNOSTIC_ONLY`. It may help reproduce a
failure, but it must not be used as the Mods-page, world-start, JAR-loading,
join, reconnect, or mismatch evidence for the packaged acceptance case.
