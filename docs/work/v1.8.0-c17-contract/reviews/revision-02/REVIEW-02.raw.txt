## Finding: 0 Critical / 0 High / 1 Medium / 0 Low

### M6 - Persisted analytic orientation has no restart-safe clock contract

**Location:** ADR-065 revision 2 lines 466-469, 475-483 and 887-888. The proposal
stores phase/rate/epoch permanently in station schema 3, samples server logical
time when changing a rate and computes phase from elapsed time. The exact frozen
wire layout additionally rejects `epoch > sampledServerLogicalTime`. It never
identifies this time's authority, persistence owner, initialization or recovery
when the source time is behind a durable epoch.

**Actual baseline:** [StationSkyContextService.java](D:/GitHub/AdvancedRocketry-Community/src/main/java/io/github/sunthemoon/advancedrocketrycommunity/station/orbit/StationSkyContextService.java):57-59
uses server getTickCount only for a transient pass schedule. Current station
registry/codec contain no logical-clock state. The separate
[MonotonicMissionClock.java](D:/GitHub/AdvancedRocketry-Community/src/main/java/io/github/sunthemoon/advancedrocketrycommunity/satellite/mission/MonotonicMissionClock.java):4-42
defines a persistable satellite clock and rollback handling; the proposal does
not adopt it or another authority for stations. The C17 author confirmed through
review clarification that the revision-2 clock is not frozen and is not an existing
station capability. Owner D2 confirmation chooses continuous analytic rotation,
not a persistent clock implementation.

**Impact:** using session tickCount as epoch/sample would put a saved epoch ahead
of sample after restart; using an independently saved world time may also put
a checked station update ahead of its saved clock after a crash/rollback. The
current text allows incompatible phase jumps, rejected context frames, stalled
rotation or arbitrary epoch resets. No precise assertion oracle exists for the
advertised restart/migration behavior. This is a missing contract, not an alleged
executed bug in C17 runtime, which is not implemented here.

**Required revision:** name one bounded restart-safe clock authority and its
source/persistence owner; define old-record initialization, co-commit consistency
of epoch/clock with station updates, restart/offline/rollback handling, overflow
and epoch-ahead-of-sample invalid data. Preserve checked-write outcome-unknown
semantics and fixed station budgets. Freeze sampling/interpolation rules so the
wire invariant and continuous phase use the same time basis. It need not reuse
the satellite clock or add a public API. Add deterministic migration, positive/
negative rate, long-elapsed, clean restart, checked-station-write ahead of world
save and backward-time fixtures. Do not infer persistence from getTickCount or
silently normalize a future/corrupt root. Re-review this correction before freezing
the affected orbital contract; no heavy/native work is needed to specify it.
