# v0.9.0 Implementation Log — Beta hardening

## Goal

Freeze the accepted v0.8.0 feature set and produce a Beta candidate that can
upgrade an accepted Alpha world safely, run the complete core loop on a small
dedicated server for two hours, remain inside fixed performance/security
bounds, and publish an auditable compatibility and support contract.

## Scope and non-goals

In scope: pre-start SavedData backup and sequential migration, failure rollback,
migration fixtures, bounded configuration, stable diagnostics, packet-abuse and
authority regression, maximum combined load, two-hour soak, Forge baseline and
latest lanes, JEI present/absent, accessibility/resource audit, and release
evidence.

Out of scope: new content systems, new destinations or satellite types, direct
1.12.2 world conversion, broad architecture replacement, multi-loader support,
and universal modpack compatibility.

## Assumptions and open decisions

- v0.8.0 is `PASSED` at final evidence commit
  `0d59c01da458e13ed0014e98f91379c6f783e19d`; all four final checks passed.
- `1.20.1-0.9.0-beta.1` is the first candidate identity.
- ADR-012 and the feature-freeze record require repository-owner approval
  before the candidate may be marked `READY_FOR_AUDIT`.
- The supported valued-world source is v0.8.0. v0.5–v0.7 remain migration
  fixtures and codec regressions, not a blanket direct-world promise.
- No upstream source or asset import is planned. Any later import must enter
  provenance before it enters production paths.
