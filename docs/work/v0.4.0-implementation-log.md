## Goal

Deliver server-authoritative vacuum survival, a four-piece space suit with
bounded oxygen storage, one powered Oxygen Vent, and incremental sealed-volume
scanning that cannot force-load chunks or exceed fixed per-tick and total
budgets.

## Scope and non-goals

In scope: `VACUUM`/`BREATHABLE` queries, vacuum damage, suit oxygen, canister
refill, Vent item/energy storage, bounded flood fill, scan deduplication,
volume indexing/invalidation, doors and block-boundary rules, restart-safe
fail-closed behavior, bounded status synchronization, a minimal HUD, debug
commands, DataGen, GameTests, packaged-server restart, two-player evidence,
and a 16-Vent performance run.

Explicit non-goals: no multi-gas simulation, pressure or thermodynamics, toxic
gas, terraforming, arbitrary chunk loading, persistent breathable caches,
unbounded scans, general power network, custom equipment slots, or v0.5+
rocket/station systems.

No upstream source or binary asset will be copied for this slice. The existing
MIT upstream is behavior context only; all v0.4 Java, JSON, text, and any new
visual resources are community-authored and must enter the provenance record.

## Fixed budgets and behavior

| Boundary | Value | Failure behavior |
|---|---:|---|
| Traversable cells per volume | 4,096 | `TOO_LARGE`; stop growth immediately |
| Cell inspections per task per tick | 256 | retain bounded task state |
| Cell inspections per level per tick | 1,024 | round-robin remaining work |
| Active scan tasks per level | 64 | reject new work as `BUSY` |
| Indexed volumes per level | 128 | evict inactive entries fail-closed |
| Indexed traversable cells per level | 65,536 | evict inactive entries fail-closed |
| Dirty positions per level | 8,192 | collapse overflow to bounded cache clear |
| Oxygen per canister | 1,000 units | canister is not consumed unless accepted |
| Suit oxygen capacity | 2,000 units | server rejects overflow |
| Vent oxygen capacity | 4,000 units | server rejects overflow |
| Vent energy capacity/use | 40,000 FE / 20 FE per tick | `NO_POWER` |

An oxygen unit is consumed once per second by a protected player or an active
room provider. A player in a breathable base atmosphere consumes none. Vacuum
damage is evaluated only on the server. A volume is breathable only while its
elected provider has both oxygen and energy; provider loss invalidates
breathability immediately.

Unloaded-neighbor inspection returns `PENDING` without loading the chunk.
Breaking or placing a boundary and opening or closing a door invalidates the
old result before rescanning. Volume cache bytes are intentionally not saved;
after restart or chunk unload, unknown space is vacuum until a fresh bounded
scan succeeds. Vent inventory, oxygen, energy, and schema are persisted by the
BlockEntity.

## Decision log

- `2026-08-31`: use a project-owned incremental flood fill over loaded cells;
  never use tickets or synchronous chunk loads for atmosphere discovery.
- `2026-08-31`: treat cached volume data as reconstructable acceleration, not
  authoritative persisted state. Restart and unload therefore fail closed.
- `2026-08-31`: elect one provider per sealed volume. Additional Vents attach
  to the same volume but neither multiply breathability nor consume oxygen in
  parallel.
- `2026-08-31`: use vanilla armor slots rather than adding a capability or
  third-party equipment dependency. Oxygen is bounded NBT on the chest piece.
- `2026-08-31`: existing Electrolyzer oxygen canisters become the shared,
  server-validated refill input; no new gas-fluid system is introduced.
