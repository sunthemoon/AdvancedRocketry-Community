## Frozen player-facing scope

The v1.0 core feature set is fixed at the accepted v0.8.0 behavior:

- Electrolyzer material processing;
- fixed Earth, Moon, and Space celestial topology;
- vacuum, suits, oxygen, and bounded sealed rooms;
- transactional block-built rockets and reliable Earth–Moon travel;
- shared-space stations with ownership and safe arrivals;
- one logical data-satellite research and discovery loop.

## Allowed v0.9.0 changes

- Critical/High defect fixes and directly related regression tests;
- bounded save backup, migration, rollback, and diagnostics;
- verified performance fixes based on profiles;
- configuration bounds and server/operator diagnostics;
- security, packet, permission, duplication, and chunk-ticket hardening;
- isolated optional JEI integration;
- localization, accessibility, resource-integrity, support, and release work;
- test-only hooks required for deterministic packaged-server evidence.

## Excluded changes

- new machines, satellite types, destinations, research branches, or fuels;
- dynamic dimensions, warp, terraforming, asteroid mining, orbital weapons,
  space elevators, or other post-MVP systems;
- broad architecture rewrites without a reproduced blocking defect;
- direct 1.12.2 world upgrades or an all-modpack compatibility promise;
- relaxed safety bounds, ignored exceptions, or longer timeouts used only to
  turn a failing Gate green.

## Exception rule

An excluded change requires its own accepted ADR with the user-visible reason,
scope, risk, owner, expiry milestone, and removal condition. Without that
record, the change does not enter the v0.9.0 branch.

## Approval condition

Owner approval confirms the scope boundary, not any implementation or Gate.
Every v0.9.0 acceptance item still requires its own observed evidence.
