## Tests

All use real files and inject a status failure for exactly one path with a presence function. The low-level
failing stat itself is already covered by `ManagedRootPresenceTest`.

- `UnknownPresenceStartupTest` (3 tests):
  - for each of the 10 managed types, an unknown presence refuses startup with that type, and every file in the
    world keeps its bytes, with no backup and no new file; a later clean start passes over the same bytes;
  - an unknown data directory refuses startup instead of reporting no data;
  - an unknown ledger or receipt presence gets the escrow hint.
- `EscrowLedgerStartupTest` (3 tests):
  - over an existing two-record ledger, UNKNOWN stays NOT_LOADED (never NO_FILE) with one WARN `reason=PRESENCE_UNKNOWN`;
  - every consumer's reservation, including the creation step's `tryReserve`, answers UNAVAILABLE, and nothing is
    charged, created or replaced;
  - a later clean start binds the same ledger, LOADED, with its two slots, and leaves the file's bytes unchanged;
  - UNKNOWN with no file creates none, and only the real check's proven absence gives NO_FILE;
  - a present unloadable file gets `reason=LOAD_FAILED`.
- `BayReceiptsStartupReasonTest` (2 tests): over an existing two-receipt file, UNKNOWN stays NOT_LOADED with the
  WARN `reason=PRESENCE_UNKNOWN`, which never claims the file exists. No root can be created, every package and
  rocket stays refused, and nothing changes. A later clean start loads both receipts and leaves the bytes
  unchanged. A present unloadable file gets `reason=LOAD_FAILED`, and a proven absence logs no WARN.

**Each new test fails without its fix.** I checked this by temporarily restoring the old behaviour in the
production code, running the class, and then restoring the fix. Logs are `mutation-*.log`.

- `Files.exists` semantics in the pre-start check and the hint: all 3 tests of `UnknownPresenceStartupTest` failed.
- `Files.exists` semantics in `EscrowLedgerStartup`, together with the old bay WARN text: 4 of the 5 ledger and bay
  tests failed.
- The old ledger WARN text: `aPresentFileThatDidNotLoadKeepsItsOwnReason`, the fifth test, failed, and so did the
  UNKNOWN test.

## Choices where the task left room

- **The pre-start check refuses startup** for an unknown presence (design note section 1), instead of passing it
  on. Three stores (celestial, satellite missions and endgame) have no unknown-presence handling of their own. The
  stores' own handling stays as the second line.
- **No new diagnostic code.** The refusal reuses `ARCE-BETA-2000` and the rejoin sidecar's rule, so there is one
  rule with one code. The message reads "`<data name>` presence is unknown: its file status check failed, so its
  absence is not proven".
- **The `data` directory is included.** An unknown directory status used to report "no managed data".
- **The WARNs name the file name, not the absolute path.** This keeps each line bounded and fixed in shape.
- **A dangling symlink at the ledger path** used to read as absent, because the old check followed links. The
  no-follow check now reads it as present, so the ledger stays NOT_LOADED with `LOAD_FAILED`. This is more
  conservative, and the pre-start check refuses a symlinked managed path anyway.
- **No ADR or register edit.** The TASK assigns the register to Root, and the design note gives the proposed text.
  Root may also want an implementation note in the ADR that holds R-035 and R-039, because the startup refusal is
  a protection that refuses work (AGENTS.md section 3.3).

## Known risks

- **Startup refusal.** Any world whose managed path's status check fails now refuses to start, including a world
  with no ARCE data. Before this change, such a world started with hidden holds: the bay's server-wide NOT_LOADED,
  W44's UNREADABLE roots, or empty roots that could later replace existing files. Recovery is to fix the storage
  or permissions and restart. Nothing on disk changes.
- **A race window remains.** A status check that passes before startup and fails at a store's own start is handled
  by that store: NOT_LOADED for the ledger and the bay, and UNREADABLE for W44's roots. The celestial,
  satellite-mission and endgame roots still have no handling of their own for that window.
