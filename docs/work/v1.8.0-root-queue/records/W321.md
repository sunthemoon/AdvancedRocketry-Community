## Investigation

`ScreenMessageState.accept` already replaces and refreshes a timed notice for every
incoming action-bar message. `StationWarpCountdowns` announces only 10, 5, 3, 2 and 1
seconds, whereas the controller view updates its countdown independently. Thus 10
remaining visible at 9 and 7 is not a lost message. `deliverOutcome` sends cancellation
in chat, which the mirror ignores, leaving the prior notice until its six-second
lifetime ends. The client now recognizes matching structured outcome notices,
without inventing seconds or changing the server's announcement schedule. It matches
the existing station-name and target components, never localized prose. Ordinary chat
and other stations' or targets' outcomes do not replace the current notice.

## Design decisions and limits

Root decision R379 is preserved: the rocket's structure-sized box is unchanged.
The player guide advises placing interactable devices outside its full rectangular
outline, including the fin span. The list refusal changes no station access rule.
No ADR decision, packet, protocol, saved field, persistence schema or save protection
changes. No upstream asset or code is copied.

The mirror follows actual announcements at 10, 5, 3, 2 and 1 seconds; it does not
interpolate a one-second countdown. The controller already displays its independently
updated server countdown. Per-second station-notice mirroring would need a different
server announcement cadence, or an unambiguous station association with the existing
controller view. Its open data has controller position and body IDs; its countdown
view does not identify the station by name or UUID. Associating any received station's
notice with that local countdown would be unsafe; this task changes neither contract.

Matching commit/abort chat notices now replace the prior countdown immediately when
received, while retaining the ordinary chat message and the existing six-second timed
lifetime. The server notices identify a station by name and target, not UUID. Two equally
named stations warping to the same target remain indistinguishable in these captions;
this display-only limitation changes no authority or station state.

At scale 2 the banner stays below the panel. At the 427 by 240 GUI size corresponding
to a 1280 by 720 window at scale 3, it moves inside the panel's unused bottom area with
a four-pixel inset, below the actual wrapped status. If a resource pack or dense status
leaves insufficient space, the duplicate banner is omitted rather than covering text
or the border; the countdown/status and outcome chat remain available. Other screens'
notices and persistent refusals retain their existing behavior.
