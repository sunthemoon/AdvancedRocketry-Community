## Design decisions and files

Rechecking W11CD sections 2.2, 3.2 and 3.3 found moved implementation sites, not a
design conflict. C-K's direction-independent accessor, composite floors/bindings,
guards, exclusive admission and capacity preview are present, as are W100F and
C-I. C-P part 1 supplies a fluid-only envelope validator; it is not repurposed for
items. W112 is absent from this base.

All Java changes are under `io/github/sunthemoon/advancedrocketrycommunity/resourceescrow`
in `src/main/java` and the corresponding test package.

- `EscrowOperation`, `EscrowEndpoint`, `EscrowSignatureKind`, `EscrowAdapterIds`
  and `EscrowCargoCapture` add the item load/unload kinds, `CONTAINER`,
  `ITEM_BUFFER_V1` and direction-correct capture. Both cargo kinds still use one
  whole-rocket PRIMARY key and composite frontiers. Existing bindings, floors,
  guard checks and exclusion machinery are reused without changing their rules.
- New `EscrowItemStackCodec` preflights native NBT before recursive copying.
  After W110F R3, durable payloads require canonical non-air ID syntax, exact byte
  count 1..64 and 4,096 bytes/depth 16/512 nodes; separate native validation also
  requires registration, the native item maximum and an exact immediate round trip. It rejects
  `ForgeCaps`, including nested occurrences, and reports `CARGO_TOO_LARGE` or
  `INVALID_DATA` without repairing input. `EscrowItemCargoPayload` adds the
  schema-1 cursor/stack/from/to frame and directional 4-slot/27-slot bounds.
- New `EscrowItemBuffer` signs `{slots: [slot0, slot1, slot2, slot3]}`. Each slot is
  the exact native stack or an empty compound. The digest is
  `hash("arce-escrow-item-buffer-1:" + deviceUUID + ":" + signature(frame))`.
  This is a signature projection, not a device save format. Counts, slot order
  and typed tags are signed. Merge identity uses `isSameItemSameTags` and the
  canonical id/tag digest, excluding Count only for comparison; saved stacks,
  payloads and buffers retain and sign Count. Display text is not identity.
- `EscrowSettlementIntent` requires item quantity 0, and
  `EscrowSettlementCapacity` previews that representation. Typed buffer
  observations sign the whole buffer. Presence comes from state, never quantity.
  Rocket O1/O4 observations remain fuel-vector plus invariant; receipts keep
  `payload_amount=0`, the exact payload hash and UNKNOWN accounting.
- Eight new test classes and `EscrowItemFixtures` cover local/framed/O1 bounds,
  canonical equality/signatures, capture, floors, queued/captured/durable exclusion,
  exact checked L1 writes, settlements, normalization, both ABANDON survivors,
  pruning/arming models and old-format compatibility. Synthetic commitments and
  capture fixtures are not real container mutations or native durability proofs.

The plan and this record are the only documentation changes. No upstream content,
assets, central state/ledger, build configuration, receipt dictionary, proof,
lease, replay exclusion, timeout or limit changed. Intent schema 2 and receipt
schema 3 are unchanged. The escrow root is unpublished with production admission
disabled (R-035), so implementing these reserved operation kinds needs no migration.
An older jar refuses a ledger containing `CONTAINER`, `ITEM_BUFFER_V1` or
`ITEM_CARGO_*` as `INVALID_SCHEMA`, not `FUTURE_SCHEMA`: startup of the whole
world is refused and the bytes are kept. Production admission remains disabled.

### R3: structural durable decoding, explicit native validation

`EscrowItemStackCodec.validateStructure` checks the exact saved field set, ID
syntax/non-air identity, byte Count 1..64, the unchanged local envelope and
`ForgeCaps` at any depth. It performs no registry lookup, constructs no native
stack and invokes no item hook. `EscrowItemCargoPayload` now uses that check.
`validateNative` additionally checks the registry, native maximum and exact
immediate native round trip, including structural validation of the output.
The existing `decode` method remains a native-materialization alias, preserving
its callers and assertions. Live `encode` and merge comparison use the explicit
native method. Hashes, encoded fields, schema versions and bounds do not change.

`EscrowItemDurableValidationTest` reproduces missing-item, newly serialized
capability and lowered-native-maximum failures on the old decoder, then checks
both item directions in PREPARED and SETTLING states through the real pre-start
`WorldDataMigrationService`, durable decode/re-encode and coordinator construction.
File bytes remain identical and no backup is created. Native validation of those
same records refuses with `INVALID_DATA`; live encoding still refuses the
capability and over-limit cases. Structural malformed/boundary tests remain strict.

The capability fixture installs a per-stack `CapabilityDispatcher` at the test
item's native maximum lookup, exercising actual `ItemStack.save`/`serializeCaps`.
It bypasses only the transformed Forge attachment event bus, which plain JUnit
does not supply. The first fixture attempt left Forge capabilities lazy; the
second hit `ForgeCapabilities`' untransformed `CapabilityToken`. Both failed runs
are retained. With the
dispatcher fixture, all three pre-fix cases fail at startup as `INVALID_SCHEMA`.
An initial post-fix run exposed an invalid test fixture that edited an already
frozen settlement digest; the fixture now freezes the changed record normally,
without changing the product's frozen-record check.

C-E/D-E must call `validateNative` at admission, O2 and readback and turn a native
failure into a REPAIR hold on that operation only. Those call sites are outside
W110F; this is codec/startup evidence, not a native-server recovery claim. Fluid
decoding and its existing environment-dependent validation are unchanged.

### R2: player-head refusal before native loading

Structural and native validation now refuse any string `tag.SkullOwner` on
`minecraft:player_head`, including the empty string, as `INVALID_DATA` before
`ItemStack.of`. Admission-time live encoding shares the refusal. A canonical
compound owner remains supported. `EscrowItemPlayerHeadTest` installs
`SkullBlockEntity.setup` with cached profile services and a queued main-thread
executor. Its control demonstrates the deferred native rewrite, then the codec
refusals leave the input unchanged and schedule no rewrite. The same refusal is
tested without services. Before the fix, 2 of 3 tests failed; the compound-owner
control already passed.
The first post-fix run found the live-stack fixture invoking the item hook itself
through `setTag`; it now sets the string directly in the live tag before admission.
The codec assertions and refusal requirements were not changed.

No general `verifyTagAfterLoad` override detector has been established in both
development and obfuscated production environments, so no reflective runtime
filter is introduced. Arbitrary modded deferred hooks remain a residual: an
immediate round trip cannot prove future immutability. A later signature mismatch
must fail closed to that operation's REPAIR hold in D-E, rather than normalize
the saved bytes or refuse the whole world. The named vanilla case is refused
without relying on method names or environment-dependent reflection.

### R4: direction-specific item endpoints

`EscrowOperation` now checks item roles before native-binding validation:
LOAD requires a `rocket_item_loader` source and native rocket destination;
UNLOAD requires native rocket source and `rocket_item_unloader` destination.
Both endpoints require `CONTAINER`. Other role combinations refuse with the
item codec's `INVALID_DATA` status. `EscrowAdapterIds` retains the direction-free
projection predicate and adds a direction-specific overload. All fluid/fuel
validation and the saved representation are unchanged.
