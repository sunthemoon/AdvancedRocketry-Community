## Design decisions and files

Rechecking W11CD sections 2.2, 3.2 and 3.3 found moved implementation sites, not a
design conflict. C-K's direction-independent accessor, composite floors/bindings,
guards, exclusive admission and capacity preview are present, as are W100F and
C-I. C-P part 1 supplies a fluid-only envelope validator; it is not repurposed for
items. W112 is absent from this base.

All Java changes are under `io/github/sunthemoon/advancedrocketrycommunity/resourceescrow`
in `src/main/java` and the corresponding test package.

- `EscrowOperation`, `EscrowEndpoint`, `EscrowSignatureKind`, `EscrowAdapterIds`
  and `EscrowCargoCapture` add the item load/unload kinds, `CONTAINER`,
  `ITEM_BUFFER_V1` and direction-correct capture. Both cargo kinds still use one
  whole-rocket PRIMARY key and composite frontiers. Existing bindings, floors,
  guard checks and exclusion machinery are reused without changing their rules.
- New `EscrowItemStackCodec` preflights native NBT before recursive copying,
  requires a canonical registered non-air ID, exact byte count, native item maximum,
  4,096 bytes/depth 16/512 nodes and lossless native round trip. It rejects
  `ForgeCaps`, including nested occurrences, and reports `CARGO_TOO_LARGE` or
  `INVALID_DATA` without repairing input. `EscrowItemCargoPayload` adds the
  schema-1 cursor/stack/from/to frame and directional 4-slot/27-slot bounds.
- New `EscrowItemBuffer` signs `{slots: [slot0, slot1, slot2, slot3]}`. Each slot is
  the exact native stack or an empty compound. The digest is
  `hash("arce-escrow-item-buffer-1:" + deviceUUID + ":" + signature(frame))`.
  This is a signature projection, not a device save format. Counts, slot order
  and typed tags are signed. Merge identity uses `isSameItemSameTags` and the
  canonical id/tag digest, excluding Count only for comparison; saved stacks,
  payloads and buffers retain and sign Count. Display text is not identity.
- `EscrowSettlementIntent` requires item quantity 0, and
  `EscrowSettlementCapacity` previews that representation. Typed buffer
  observations sign the whole buffer. Presence comes from state, never quantity.
  Rocket O1/O4 observations remain fuel-vector plus invariant; receipts keep
  `payload_amount=0`, the exact payload hash and UNKNOWN accounting.
- Eight new test classes and `EscrowItemFixtures` cover local/framed/O1 bounds,
  canonical equality/signatures, capture, floors, queued/captured/durable exclusion,
  exact checked L1 writes, settlements, normalization, both ABANDON survivors,
  pruning/arming models and old-format compatibility. Synthetic commitments and
  capture fixtures are not real container mutations or native durability proofs.

The plan and this record are the only documentation changes. No upstream content,
assets, central state/ledger, build configuration, receipt dictionary, proof,
lease, replay exclusion, timeout or limit changed. Intent schema 2 and receipt
schema 3 are unchanged. The escrow root is unpublished with production admission
disabled (R-035), so implementing these reserved operation kinds needs no migration.
An older jar refuses a ledger containing `CONTAINER`, `ITEM_BUFFER_V1` or
`ITEM_CARGO_*` as `INVALID_SCHEMA`, not `FUTURE_SCHEMA`: startup of the whole
world is refused and the bytes are kept. Production admission remains disabled.

### Implementation design and write scope

This section is written before W110F Java changes. Only the item stack codec,
item payload, item endpoint validation, their tests and this record are writable.
Size measurements add test coverage without changing production capacity code.

- R1 measures real dimensions in both directions, with and without transfer guards,
  using the unchanged five-marker preflight and encoders. It replaces the broad
  size verdict; bounds, allowances, layout and `ESCROW_FULL` mapping stay unchanged.
- R3 separates structural validation (canonical non-air ID syntax, byte Count
  1..64, exact fields, bounds and recursive capability exclusion) from native
  materialization (registry, item-specific maximum and immediate round trip).
  Durable payload construction uses only structural validation. The codec exposes
  native validation for future admission, O2 and readback callers; live encoding
  still requires it. Missing items or new native capabilities must not invalidate
  the entire ledger at startup. C-E/D-E own operation-local REPAIR handling.
- R2 refuses string `tag.SkullOwner` on `minecraft:player_head` structurally, before
  native materialization, including when profile services are installed. General
  modded deferred post-load rewrites remain a residual unless a development and
  production-safe override check can be established without new infrastructure.
- R4 binds LOAD to item-loader source/rocket destination and UNLOAD to rocket
  source/item-unloader destination. R5 corrects downgrade and cleanup statements
  above; it changes no code and requires no regression test.

Each review item gets its own local commit. Tests for code defects run before and
after the fix, followed by each changed class alone and the whole unit suite.
One full GameTest runs on committed source in a detached script under the heavy
lock, after C:/D: space checks; that script also checks logs and cleans its world
