**Write scope.** Admission, capacity diagnostics, transient queue/turn lifecycle

may gain only exact entries for deliberately exercised new warnings. Temporary

**Design and commit order.** (1) Extract transfer/cargo admission and pure fill
checks from the coordinator without changing fill behaviour. (2) Preserve the
closed Fill contract while distinguishing cargo stale inputs, marker limits,
root reservation exhaustion and candidate component size through typed results
or exceptions; propagate these to device statuses. (3) Add separate per-kind
cargo switches, false in production and enabled only through the existing gated
test mechanism. (4) Connect fluid devices to the runtime-owned preparation ticket,
staged native capture and final admission, checking the exact unchanged device
and owner-thread state. (5) Reuse the fill creation ordering: pure virtual-root
checks, reservation, empty ledger binding/baseline, queued operation, exact L1.
(6) Share one bounded FIFO resource queue with fuel. Keep eight visits, one fuel
capture per tick and 256 slots; retain a cargo continuation until completion,
using the existing 16 MiB/16,384-visit session budget and one reconstruction per
tick. Bound admission commits to 64. (7) Register RAM-only per-rocket turn hints
for loaded devices, discarding them on unload, rebind and session end. Each item
has its own implementation commit and regression tests where observable.

**Persistence and failure boundary.** No saved format, schema, hash, dictionary,
bound, proof, lease, budget or timeout changes. Successful cargo admission ends
at acknowledged PREPARED with both endpoints locked. Reconciliation remains
RECONCILIATION_UNIMPLEMENTED. Refusals allocate no sequence/reservation/write;
temporary preparation state is cancelled when inputs change or admission refuses.
The first-ledger baseline retains the existing definite-failure versus UNKNOWN
handling. No new save refusal, quarantine, resource publication or log is intended.
The coordinator must shrink, RocketTransferService remains below 800 lines and
new classes remain below 500 lines.

**Verification.** Run each changed/new unit class alone, negative controls where

full GameTest and the unchanged log checker against committed source. A detached

Record exact commands, source commits, outcomes and evidence. Independent review
before merge belongs to Root. No Gate is self-approved.

**Non-goals.** C-E2/C-E3 reconciliation, permits, readback, settlement, pruning,
flight/disassembly integration; item devices; production enablement; assets and
data generation; ADRs, risk register, status files, content ledger and build files.
