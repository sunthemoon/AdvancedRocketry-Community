## Code citations and design decisions

The source prefix below is `src/main/java/io/github/sunthemoon/advancedrocketrycommunity/`.
These files, and the tracked test seeds and payload fixture, have no diff between C4 and this branch.
Manifest citations give full paths, source hashes, exact lines and excerpts for each pack.

- Atomic planetary publication and logs: `celestial/data/PlanetaryDefinitionReloadListener.java:31-39,87-100`.
  Acceptance logs generation, bodies, routes and anchors. Refusal logs
  `Rejected planetary catalog; last valid generation remains active: ...`.
  `celestial/data/PlanetaryCatalogManager.java:41-57` preserves the prior pair on rejection. Invalid initial
  catalogs abort startup; refusal cases must follow an already valid load and must be restored before restart.
- Count/resource-name checks: `celestial/data/PlanetaryDefinitionReloadListener.java:50-72`.
  `celestial/service/CelestialCatalog.java:20,82-105` sets 128 bodies and requires fixed Earth/Moon/Space.
  `celestial/model/BoundedCelestialCodecs.java:17` sets 128 ID characters, including namespace and colon.
  `celestial/model/CelestialDefinitionCodec.java:99-140` reads the bounded ID and the legacy/schema-2 fields.
- Invalid type and unknown body: `travel/route/model/RouteAnchor.java:53-58` and
  `travel/route/service/RouteCatalog.java:73-81`. The unknown-body candidate is a rejection test, not a way to
  publish a selectable unknown destination. Hold a test_mars selection, remove its valid pack and reload to
  exercise an actually removed destination; record the UI result rather than claiming it from these tests.
- Route readback: `celestial/command/PlanetaryRouteCommands.java:43-47`. Fuel calculation:
  `travel/route/service/TravelFuelFormula.java:37-43`; required fuel depends on rocket mass, gravity settings,
  route-plan distance and later propulsion quoting. No numeric server quote is fabricated.
  `travel/route/service/RoutePlanner.java:20-25,81-85` minimizes graph distance. C4 also has bidirectional
  `earth_surface_orbit` and `moon_earth_orbit`, each distance 25. Increasing the direct `earth_moon` definition
  from 50 to 75 changes the shortest plan from the direct leg to Earth surface → Earth orbit → Moon surface,
  still total 50. This is a valid definition/plan-reload control, **not** a promised +25 fuel-price control.
  An unchanged fuel quote alone cannot show that the old route cache survived; capture generation, the
  direct definition and the selected plan's legs as well. The sealed manifest promises no numeric quote.
- Discovery admission: `rocket/server/RocketFlightService.java:482-490`. The locked fixture uses the existing
  built-in Mars Level, on an undiscovered copy. No discovery, research balance or SavedData is edited.
  `celestial/model/CelestialBodyDefinition.java:93-96` distinguishes metadata eligibility from a live Level;
  `rocket/server/PlanetaryFlightAdmission.java:60-64` checks the live destination Level. The exact test_mars
  seeds deliberately do not create a dimension. Catalog acceptance does not prove that surface travel works.
- The 48-character name is a **station** limit, `station/model/StationLimits.java:23`; the strict body codec has
  no `name` field. The manifest supplies `K06 station ` followed by 36 ASCII `n` characters for K08's permitted
  station-creation operation. No unsupported body field or fictitious station datapack loader was added.
  `rocket/menu/RocketNavigation.java:16` sets the full-catalog cooldown to 100 ticks; effective runtime retry
  and presentation still need observation.
- Lifetime bindings: `celestial/binding/PlanetaryBindings.java:17-22,54-65`. Removed IDs remain reserved, and
  128 is the lifetime limit. Use separate complete baseline copies for catalog variants, with only the 11 C4
  body bindings; do not erase or selectively restore binding history. New large-catalog bodies have no Level,
  are non-landable/orbitable, retain a valid Earth parent, and do not add routes or claim 128 visitable surfaces.
- Station classification: `station/warp/WarpCostClass.java:25-30`; shipped defaults are 2,000,000 and
  8,000,000 in `station/warp/WarpSettings.java:7`. The baseline target is independent of stock routes and
  satellite references. Reparenting changes its system without changing its absent Level binding. The final
  cost check is `station/warp/StationWarpService.java:536-542`; the manifest's `warp_commit` key also cites the
  equivalent confirmation check at line 317. Missing targets are refused at lines 606-608. Actual costs are
  read from C4's effective common configuration, not presumed from defaults.
- Atmosphere tag precedence: `atmosphere/server/ServerLevelVolumeWorldView.java:54-55`. The pack bytes are
  tested against [AtmosphereRun.tag_pack](../../../../scripts/run_v130_atmosphere_boundary_smoke.py), lines
  111-119. Actual merge/load diagnostics depend on the compatibility fixture and stay **to be observed**.
- Payload fields and limits: `satellite/model/SatelliteDefinition.java:22-46`,
  `satellite/model/SatelliteLimits.java:23-29`; successful reload logging is at
  `satellite/service/SatelliteDefinitionReloadListener.java:54-60`. Original registration comes from
  [SatellitePayloadFixture](../../../../src/adapterTest/java/io/github/sunthemoon/arceadaptertest/SatellitePayloadFixture.java),
  line 44. The changed pack is byte-tested against [SatelliteRun.write_override](../../../../scripts/run_v130_satellite_payload_smoke.py),
  lines 252-256. This preserves D08's 400/137/11 starting values instead of treating the runner's 20/211/11
  reload override as its initial registration. Actual mission snapshots, stale actions and claim outcomes remain unobserved.
- Client sky bounds/schema: `celestial/visual/SkyProfile.java:15-17,41-43`; byte refusal:
  `celestial/data/BoundedDefinitionJson.java:31-33`; presentation retention:
  `client/sky/SkyProfileReloadListener.java:66-74`; missing selection:
