## Change and design

`EscrowFlightSource.observe()` first refuses an already-invalid capture or transient motion,
then performs `same()`, and only then asks the transient launch boundary. A false `same()`
permanently clears `unchanged`, whether or not the boundary refuses. A boundary-only refusal
returns false without clearing the flag. Native fields and the terminal passenger prerequisite
therefore cannot be hidden by that refusal. The existing motion tests are unchanged.

The terminal previously combined passenger presence and the boundary in one supplier.
`EscrowGovernedTerminal.waitSource` now passes passenger presence as a separate persistent
prerequisite. Its failure remains sticky; explicit `passengerLeft` and native invalidation
continue clearing `unchanged`, including while the launch boundary refuses. F1 and F7
off-thread leases still read `unchanged`; they do not read Minecraft objects or the boundary.

The return's existing proof callback releases the rejected result and retained proofs, then
proves again under its existing scheduling. It does not recapture the source after refusal.
The only return-adapter refactoring is the package-private `sourceHold` predicate used by both
the real refusal branch and its unit test. The early HELD boundary check remains unchanged:
persistent refusal does not serialize the rocket or rebuild work every visit.

Disk validators, saved proofs, envelopes, schema/IDs, network, retry schedules, limits, budgets,
timeouts, log manifest and admission switches are unchanged. No upstream code or assets were
copied. This slice adds no client-visible content.
