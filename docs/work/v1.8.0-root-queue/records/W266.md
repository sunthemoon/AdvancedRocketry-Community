## Completed scope and design

W262-R1 is addressed in the harness and its gated reporter. The reporter excludes only the actual
`TicketType.UNKNOWN` object when its timeout is exactly one. Every remaining ticket is reported by chunk, type,
level, key and force flag as whitespace-safe base64 JSON. The comparison is a multiset, preserving duplicates and
ignoring iteration order. Only refresh timestamps are omitted. Missing or unreadable identity evidence fails the
comparison. Existing held/timed totals and type counts remain diagnostics; the previous chunk/held-count checks and
the synchronous, timestamp-sensitive full-ticket-map assertions are retained.

The Java tests also retain a custom timed type named `unknown`, proving that the exception is not a name or timeout
classification. They check PORTAL, POST_TELEPORT, flight and custom timed tickets, each identity field, multiplicity,
refresh normalization and the empty observation. Python negative tests cover all four additions, a same-total type
replacement, changed chunk/level/key/force fields, removal and duplication. UNKNOWN churn remains a passing control.
No exit production decision, movement rule, grant, admission gate, budget, timeout or persistent state was changed.
No new ADR choice was needed; R294 specifies the exception.

W262-R2 is addressed in V2 checklist step 3.5: the command is now
`/execute at <B> run tp <B> ~0.1 ~ ~`, relative to B above the same floor. The tester must record B's actual coordinates
