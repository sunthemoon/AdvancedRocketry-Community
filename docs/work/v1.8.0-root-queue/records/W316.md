## Implementation and decisions

- The 98-logical-pixel station button now reserves six logical pixels on each
  side before fitting the complete selected/unselected/countdown label. The
  complete component is always its hover tooltip; the empty-list explanation
  is retained. The button bounds and selection behavior do not change.
- `EndgameRefusalScreen` makes the railgun, elevator, orbital laser drill and
  black-hole generator inherit `ScreenActionMessages.RefusalOwner`. It delegates
  notice storage, lifetime, replacement and screen ownership to W311's unchanged
  `ScreenActionMessages` and `ScreenMessageState`; there is no second pin or timer.
- All three button factories use the shared release-before-send hook. The common
  slot hook also covers normal clicks, shift-click, swaps, drops and quick-craft,
  including the buttonless generator. Scrolling the drill's detail tooltip is
  another explicit screen action and releases the refusal.
- Only a structured endgame status-line component with a known code is eligible.
  `OK`, `STOPPED`, `COMPLETE`, `GENERATING`, `CONFIRM_REQUIRED`,
  `AWAITING_WORLD_SAVE` and `RIDE_COUNTDOWN` are not refusals. Literal text,
  unknown codes, foreign translation keys and malformed argument lists are not
  classified by text or by a bracket suffix.
- The observer uses existing server views and menu slots. It releases a refusal
  when its current status clears, a recorded failed operation becomes successful,
  detail access changes, or the relevant selection, settings, structure, pair,
  link or body changes. Merely recording the refusal does not release it.
  Routine operation/transit/receipt counters and physical-link paid credit do
  not dismiss unrelated refusals. An available outbox answers `OUTBOX_FULL`;
  device-slot changes answer inventory/buffer refusals, but player-inventory
  changes and unrelated authority refusals do not.
- The railgun already sends a configured route quote. Charging to that cost
  releases `INSUFFICIENT_ENERGY`; partial charging does not. Missing/malformed
  quotes are not guessed. Other systems do not send their configured energy
  quotes, so energy alone is not taken as proof there; the next action or a
  relevant server-view change still releases the notice. A delayed first view
  establishes an observation baseline rather than dismissing the refusal.
- The panel's status remains the device's server status. A refused action does
  not replace it with a client-invented device status. The retained bottom
  notice explains the refused action separately, as Root requested.

No accepted ADR was changed, and no open ADR choice required a new decision.
These are conservative presentation choices within the existing data boundary.
