# W155: transfer-history journal leases

## Plan and design (before implementation)

This task implements R103 from [TASK-W155](../TASK-W155-TRANSFER-LEASE-HISTORY.md) on
`codex/v1.8.0-w155`, starting at `f2905bffa01972de9a9e0828b44f96935fdaebd7`.
The initial worktree is clean. Other worker sessions use different worktrees; this
worker neither delegates nor changes the shared branch.

The write scope is `RocketJournalLeases.java`, its mutation notifications and API
documentation in `RocketTransferSavedData.java`, lease-related tests in
`rocket.flight.persistence` and `resourceescrow`, and this record. Disposable logs,
scripts and results belong to `D:/GitHub/ARCE-Task-Evidence/root-queue/W155/`.

1. Add an unsampled peer-publication/removal regression to the journal and F1 lease
   tests, and run it against the original implementation.
2. Track transfer mutations independently of logical-rocket mutations, using the
   existing 1,024-entry history bound and a monotonic conservative eviction floor.
   Successful put, migration, removal and replacement notify both identities;
   replacement also remembers the superseded transfer. Acknowledgement prunes
   pending removals, not transfer history. Lease reads use only an immutable view
   published through the existing volatile field and compare against acquisition's
   mutation sequence. An evicted change newer than acquisition refuses the lease;
   a new lease may be acquired once the existing acknowledgement/conflict checks pass.
3. Check all logical-lease consumers and test unchanged-transfer independence,
   replacement, overflow, off-thread reads and F1 serial capture. Preserve the
   existing pending-removal and peer-serial coverage. Update the old test that
   explicitly allowed a retained T lease to revive: R103 now requires refusal.
4. Run each changed test class alone, both affected packages, the complete unit
   suite, and one full GameTest plus the unchanged log checker. Check C: and D:
   each exceed 10 GiB and free physical memory exceeds 6 GiB. GameTest uses a
   detached script, atomic heavy-JVM lock, ownership-checked release and cleanup;
   consecutive acquisitions would wait at least 90 seconds.
5. Commit only this task's files locally, record results against the source commit,
   and leave the fresh-session review and merge to Root.

No saved schema, encoded fields, journal limits, timeouts, budgets, client request-ID
policy or assets change. No upstream files are copied. ADRs, risk register, status
files, ledger, build configuration and log expectations are outside this task.
This RAM-only history lasts for one journal instance; existing leases do not survive
restart. Conservative overflow can refuse an otherwise unrelated old lease, as
with logical history, but cannot turn forgotten history into permission. This does
not refuse saves or discard player data. Current-version G0-G9 and prior-version
acceptance remain outside this slice; no Gate approval is claimed.

## Execution

The original production code fails all four new unsampled-history regressions
(two journal cases and two F1 capture/replacement cases). The implementation adds
one bounded transfer-history map and floor to `RocketJournalLeases`; the four
successful mutation sites in `RocketTransferSavedData` now supply the transfer ID.
No other production class changes. `RocketTransferSavedData` remains 797 lines;
history policy stays in its dedicated helper rather than adding another adapter
responsibility. The tests also compare empty encoded roots before and after peer
activity, cover incoming replacement transfers and history eviction, and check
owner-thread/off-thread agreement. The existing old-lease revival assertion is
strengthened to refusal under R103, while fresh acquisition remains accepted.

### Consumer inspection

- F1 `PreparationLease` keeps the original L/T supplier through actual-serial
  capture. Peer prospective-serial and pending-removal tests remain unchanged.
- Governed cleanup (`absent`, `blockedReason`, `prune`), launch `afterArm`, and
  pre-F2 cancellation use `noTransfer`. New acquisitions after checked removal
  remain valid; retained suppliers now also reject intervening T activity.
- Reconciliation and settlement use `members`, retaining one supplier per L/T.
  O4 acquires a new group after O3's checked removals, so its intentional journal
  changes do not invalidate a reused O3 group. Added group/helper regressions
  check duplicates, empty groups, null T and unrelated T behavior.
- F6 `JournalHold` and F7 handoff `Proof` keep their exact-record suppliers, and
  `actionableLease` passes null T. Their existing L/record, serial, acknowledgement,
  failure and lifecycle checks remain intact. No caller needs a code change.

The three changed test classes pass individually: `RocketJournalLeaseTest` 16,
`EscrowPreparationLeaseTest` 7, and `EscrowFlightJournalGovernedTest` 4, with no
failures, errors or skips. Broader verification is in progress. Fresh-session
review is Root's pre-merge responsibility; this worker must not launch another agent.
