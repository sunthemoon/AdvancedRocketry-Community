## Decision

No measurement correction is justified by the evidence. The local runs have not
reproduced a 500 ms median failure, but START really executes the whole-root
preflight and allocates approximately 164 MiB per call. Its measured CPU and GC
cost is substantial; it is not principally measurement overhead. The test,
helper, production code, limit, warm-up count, sample count and every assertion
remain unchanged. There is consequently no manufactured red/green regression
test or claimed correction.

The hosted failure remains open for Root. Its XML reports
`missions=5242 root_bytes=16743201 median_ms=572.9 max_ms=613.2 cost_median_ms=570.7 cost_max_ms=612.2`;
the assertion's unrounded median is 570.709567 ms. Unlike local CPU contention,
that run has almost identical cost and wall medians. The artifact does not split
CPU from GC or include stage timings, so these measurements do not establish
which component made that particular hosted run slower. A timing-only fix would
be speculation. Root should retain the incident and use a separate design task
for any production remedy; a similarly instrumented hosted run would resolve
the remaining attribution question before choosing that remedy.

All 105 measured diagnostic STARTs take one whole-root preflight. They make
**zero `CompoundTag.copy` calls**: the validation wrapper shares the root.
Serialization buffer copies are included in the write/read stages, not claimed
as absent. Complete START allocates approximately 164.3 MiB, of which root
encoding accounts for about 98.4 MiB and validation about 65.9 MiB. That includes
about 55.8 MiB in the bounded read and 5.1 MiB in the write. The remaining
validation work includes payload equality and cleanup; it is not free.

Idle/loaded START CPU medians are 265.625/312.5 ms (median of per-run medians).
Across their 35 individual measured calls, GC-counter deltas range from 24–41
and 17–44 ms. Independent pause-log medians are 34.124 and 31.714 ms; these
include pauses that the integer collection counter does not fully represent.
The log comparison uses millisecond JVM-uptime windows, so sub-millisecond
differences are not exact attribution. There is no large positive GC overcharge
in these runs. Global JIT-counter deltas range from 0–39 ms across all measured
diagnostic calls; that counter is diagnostic only and is not added to START's
cost.

For every idle and ambient diagnostic sample, the original asserted cost equals
the directly measured START CPU plus its GC-counter delta. Loaded differences
have median zero and maximum one 15.625 ms Windows CPU quantum. Neither that
resolution nor the approximately 0.1 ms counter-read cost establishes a fault
explaining the hosted 70.7 ms median excess. GC is observable real suspension
while START creates substantial allocation pressure; removing it would change
the budget's meaning, not repair a demonstrated measurement error.
