Recorded on 2026-10-12. Implementer branch: `codex/v1.8.0-propulsion`.

## Design before persistence changes

This implementer owns C17a propulsion model, assembly, fuel, snapshot/flight codecs,
registered propulsion hardware, generated resources and tests in the assigned
`codex/v1.8.0-propulsion` worktree. Loader variants, monitoring, cargo mutation,
station controls, other workers' files, status files and the ledger are excluded.

The immutable assembly descriptor has an independent schema. Schema-1 snapshots
retain their original hash and abstract fuel semantics. New descriptors are
included in schema-2 snapshot hashes and survive relocation. Explicit ADR-026
definitions take precedence over host identities before classification.

Moving fuel has one immutable authority in flight data, with a primary bank and
an optional oxidizer bank, native Fluid identity/tag and a shared debit ledger.
Plans capture both debits and their exact resource binding. The existing transfer
journal owns the once-only checkpoint and recovery; no second resource journal
or cargo source is introduced. Disassembly quotes bind the entire immutable fuel
state and disposal happens only after successful materialization.

Native roots are bounded before copying/decoding. Unsupported or oversized roots
disable operation and are preserved verbatim, with oversized roots retained by
reference. No new block entities or chunk-save refusal mechanism are introduced.
Root must arrange the separate-session persistence review before integration.

### Conservative ADR choices

Basic-only mono and external capacity/metrics remain unchanged even under
non-default multipliers. Advanced mono scales its matching bank; typed modes
scale each matching bank. Host thrust is rounded after summing a tier. Each
core's scaled integer support rating is captured before connected ratings are
summed, then nuclear support is capped before the global thrust multiplier.
This keeps the accepted scalar helper unchanged and within its arithmetic domain.
Coefficient bounds derive from the existing block count and maximum multiplier,
including large mixed-tier fractions; no existing safety budget is increased.

All four Fluid allowlists and toggles are captured at assembly. Efficiencies and
both debits are frozen when a plan is accepted. Catalog reload cannot reinterpret
an accepted debit. An explicit definition for a new host ID remains one external
component. The old item loader stays abstract at 25 units/tick; it has no Fluid
path to reuse. Whole bucket/canister exchange uses the existing audited planner,
including exact creative container consumption. There are no new tank BEs.

Unknown fields, schemas and oversized native roots retain the original payload.
Oversized roots are held by reference rather than recursively copied. The new
native preflight uses depth 32 and 65,536 nodes within existing byte budgets.
Old scalar snapshots keep their hashes, balances and ledger without acquiring
Fluid eligibility. Ordinary cargo is outside propulsion disposal authority.
