## Findings from the rehearsal

No product finding was made. Nothing here was fixed.

| # | Finding | Cause |
|---|---|---|
| 1 | Both disposable clients logged `Error starting SoundSystem. Turning off sounds & music` (`Failed to open OpenAL device`), and F3 showed `Sounds: 0/0 + 0/0`. Why the device could not be opened is not established. The runner was a process created through WMI, and one sound device on this PC reports an error, so either may be the reason. Until a client has sound, C22's audio cadence and every audio check in the campaign cannot be done this way. | Harness launch context or environment, open |
| 2 | The harness writes `pauseOnLostFocus:false` into the disposable client's options, while the fixture's pause step lists `pauseOnLostFocus=true` as a precondition. The Escape-menu pause still worked. A focus-loss pause cannot be rehearsed without changing the option in the client. | Harness and fixture disagree |
| 3 | The copied integrated save shows Forge's "Worlds using Experimental Settings are not supported" screen once before loading. The operator has to click Proceed; the fixture's usage notes do not mention it. | Fixture |
| 4 | The harness labels every lock it takes `W399 campaign pid=...` in `owner.txt`, whoever runs it. Another worker reading the lock cannot tell that W430 held it. | Harness, cosmetic |
| 5 | The `request` command accepts only a list of actions, and the fixture's files are `{id, ops}` objects. I copied the fixture files into `requests/` by the documented file-drop protocol, which keeps their ids. This works, but the README's command list does not say which path to use for fixture files. | Harness documentation |
| 6 | On this PC a process created through WMI is refused `powershell.exe` ("Access is denied"), and the `pwsh` alias cannot be started that way either. The round runner therefore had to be a Python script. | Environment |
