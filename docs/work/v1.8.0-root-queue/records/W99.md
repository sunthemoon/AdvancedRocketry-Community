## 2. The structure digest

- `RocketStructureSnapshot.structureDigest()` is SHA-256, as 64 lowercase hex characters, over the UTF-8 prefix
  `arce-rocket-structure-1:` followed by the content hash's own field encoding with one difference: each payload writes
  its presence and adapter ID but not its data. Then come a propulsion flag and, when present, the propulsion signature.
  The fields are the schema, dimension, origin, bounds, each block's position, block ID and sorted properties, the
  anchors and the eight stats. The snapshot ID and the creation time are not included.
- `RocketSnapshotHasher` now writes the shared fields once, with a flag for payload data. The content hash's bytes do
  not change: `RocketStructureDigestTest` pins two content hashes computed at `10bc96e6` before the change.
- The digest is computed once, in the constructor, beside the content hash, and kept in a final field. Recognition
  therefore never hashes, and the value is safe to read from any thread. `RocketSnapshotNbtCodec` is unchanged, so the
  digest is never written; the test checks the encoded snapshot for it.
- **Budget.** No reconstruction-budget accountant exists before C-P. The digest's pass is part of every snapshot
  construction, which is the reconstruction that ADR-065 section 4.1.1 charges. `structureDigestBytes()` reports the
  exact byte length of the hashed input, and the pass visits each block record once. For the largest admitted shape
  (2,048 blocks, 128 chest payloads of 8,000 bytes each) the pass hashes 97,676 bytes, and the figure does not change
  with payload size. The digest's input is never longer than the content hash's own input plus 93 bytes (the prefix,
  the propulsion flag and the signature), so construction hashes at most about twice as many bytes as before.

## 3. The grouped recognition predicate

`RocketTransferEntities.recognizes(recorded, current, currentLedgerBinding, epoch)` is the pure rule:
`sameSnapshotId && (sameContentHash || (epoch > 0 && sameStructureDigest && currentLedgerBinding))`. It is the
section 2.5 predicate with the second branch's terms reordered so that the cheap ones run first. Both
`isCommittedAuthority` and the private `matches` call it after their existing owner, logical, physical and state
checks, which are unchanged.

- **Equal snapshot ID is required in both branches.** It is the first conjunct.
- **A neutral rocket keeps the exact-hash rule.** With epoch 0 the second branch is false before the ledger is read.
- **Current ledger binding** means the rocket's section names a ledger and that ID equals the loaded
  `ResourceEscrowSavedData.existing(server).ledger().id()`. Off the server thread, or with no loaded ledger, it is
  false, as in `RocketEscrowGate.escrowIdle`. It is evaluated lazily, only after the snapshot ID, the epoch and the
  digest have matched.
- **Recognition, not authority.** No fence, floor, veto, governed route, acknowledgement order, proof, lease or replay
  exclusion changed. The new branch only admits rockets whose epoch is nonzero, and
  `EscrowRecoveryFence.Rocket.protectedResources()` already treats every such rocket as protected. The effect on
  recovery is therefore that a changed protected copy becomes visible to the duplicate veto and the floor checks; it
  can never become discardable.
- `RocketTransferRecoveryService`, which W98 is changing, is not edited. Its election reaches the predicate through
  `loadedMatches` and `findMatches`.
- No saved format changed: no codec, schema or persisted field.

**Reachability today.** A rocket's content can change under one snapshot ID only through an acknowledged cargo
operation, and none exists before C-K, C-P and C-E. So in production the new branch is reachable only through the
fixtures. The forward-flight paths that act on the first match without the fence (`removeSource`, `tickSource`,
`transferPassengers`, `RocketDestinationCompletion.tickDestination`) see no new candidate in practice, because
`resourceMutationAllowed` refuses cargo while a transfer is pending. C-E's real stale-PREPARED and both-entity cases
cover them.

## 6. Choices where the design left room

1. **Eager digest.** Computed in the constructor rather than lazily: one pass per snapshot, inside the construction that
   ADR-065 section 4.1.1 charges, never at recognition time, and safe across threads.
2. **`structureDigestBytes()`** is added so that C-P can charge the exact pass. It is the only API beyond
   `structureDigest()`.
3. **Shared writer.** The content hash and the digest share one field writer instead of two copies, so that a later
   field cannot reach one and miss the other. Pinned content hashes prove the content hash's bytes did not change.
4. **Ledger binding** is read from `ResourceEscrowSavedData.existing`, as `RocketTransferFences.state` and
   `RocketEscrowGate` do, and is false off the server thread.
5. **Scope.** Beyond the files the TASK names, the change touches `RocketSnapshotHasher` (the snapshot's
   package-private hashing helper in `rocket/model`) and adds the main-source fixture class beside the new GameTest,
   following `FirstEventRocketFixtures`. No other file changed. `RocketTransferEntities` grows from 579 to 604 lines;
   it was over 500 before, and the addition is the recognition rule that its two existing sites share.

## 8. Known risks

- Every snapshot construction now hashes once more. Construction happens at scan, decode, relocation and pad selection;
  the extra pass omits payload data, so it costs at most about as much as the content hash's structure part. No
  benchmark was run for this leaf; C-B measures reconstruction cost.
- `currentLedgerBinding` can read `DimensionDataStorage` during an entity-index callback. It does so only for a rocket
  that already has the record's snapshot ID, a nonzero epoch and an equal digest, and the same read already happens in
  `RocketTransferFences.state` for every recovery candidate.
- The forward-flight paths in section 3 use the first match without the fence. C-I adds no candidate there today; C-E
  must show the same once cargo exists.
