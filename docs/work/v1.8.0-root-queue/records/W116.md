## 1. Plan (committed before any code)

The task changes how an ordinary return and its recovery wait or proceed, so it follows the persistence-slice rule.
No saved format, journal schema, hash, bound, proof rule, lease, budget or timeout changes, and no assertion is relaxed.

1. **W98-R3, the discarded copy's column.** Where an attempt now refreshes only the source origin's flight ticket
   (`keepLoaded` in `start`), it refreshes the same ordinary flight ticket (the transfer-keyed `arce_rocket_flight`
   ticket every ordinary flight holds on its origin columns) on each census column that is an end's origin column. The
   I1 and I2 census holds only origin columns (R4); an I3 discarded slot off the origin column gets no ticket (W90 allows
   one column per end) and keeps its existing `SLOT_UNLOADED` hold. No new ticket type, governed or margin ticket. The
   source keeps today's origin load; the destination column, already checked loaded, gets only the refresh.
   GameTest: REMOVE_DESTINATION_KEEP_SOURCE with the destination copy in a cold Moon column held only by flight tickets,
   an offline passenger whose reconnect starts the first attempt 150 ticks after recovery's ticket, and a decoy rocket
   naming L (another owner, so not a candidate) in the survivor's slot, which makes the first two attempts fail
   (`BARRIER_VETO`, 200-tick backoff). The third attempt runs after recovery's 400-tick ticket has expired; it must
   find the column loaded, prove it empty and retire T. Without the fix the return holds on `SLOT_UNLOADED`.
2. **W98-R6, an offline crew after a cancelled countdown.** Recovery passes `offlineAllowed = true` exactly when T is
   PREPARED and the kept source's loaded image, read before recovery changes it, is COUNTDOWN or stationary at its
   snapshot origin (FUELED or ASSEMBLED, no plan, no active transfer, exactly at the origin). REBUILD_SOURCE, the
   reconnect site and every other case keep `false`. Unit test of the predicate on both sides; GameTests: a COUNTDOWN
   image and a FUELED-at-origin image retire without the reconnect, and a FUELED image away from its origin waits.
3. **W98-R10.**
   - A small guard class `RocketRetirementGuards` takes the static guards: the admission column policy, `crewReady`,
     `projection`, `destinationAdmitted`, and R6's predicate. The coordinator keeps only the pending limit and the
     per-rocket WARN of `admits`.
   - `RocketTransferEscrowRules` gets one token-aware `flightAllowed` overload, and the coordinator's copy is deleted.
     The existing overload and the new one share one private rule; each keeps its present check order.
   - The release-test pause moves to a gated `RocketRetirementTestHook` with the same property, labels and log lines.
   - The coordinator reaches Minecraft only through a `Port`, implemented by `RocketRetirementWorld`, so R12 can test
     its state machine without a server. Behavior does not change; `RocketTransferService` is not touched.
   - **Mixed barrier batches:** a batch with both governed and ordinary attempts goes through a new `forceMixed`; an
     all-governed or all-ordinary batch keeps the present code unchanged. In a mixed batch a governed attempt fails only
     on a governed own-store failure or on the failed force of a worker that a governed attempt uses, so an ordinary
     failure never fails it and never counts in `ioFailures`; an ordinary attempt still fails on any failure in its
     batch. One force per worker per batch, as now. Unit tests with real `IOWorker`s over a temporary directory.
   - The W98 record's two claims get a correction note that points here.
4. **W98-R12.** Unit tests of the coordinator through a fake port and a real detached journal: DEADLINE, IO,
   SUPERSEDING_SAVE, BUSY, SLOT_UNLOADED and SAVE_OFF each release the reservation, and `clean()` is false for at most
