## Why the dismount setup is unreachable

1. [EscrowRuntime.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/resourceescrow/EscrowRuntime.java),
   lines 271-291, classifies the ledger at `ServerStartingEvent`, before the first tick and player login. A failed
   load remains missing in that session. Production creation requires NO_FILE in
   [ResourceEscrowSavedData.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/resourceescrow/ResourceEscrowSavedData.java),
   lines 54-79. There is no supported production operation that detaches an already loaded ledger; replacement is
   explicitly test-gated in `EscrowRuntime.replaceLedgerForTests`, lines 256-269.
2. [RocketEscrowGate.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/resourceescrow/RocketEscrowGate.java),
   lines 16-17 and 91-103, returns non-idle under NOT_LOADED, even for a neutral rocket.
   [RocketEscrowInterlocks.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/resourceescrow/RocketEscrowInterlocks.java),
   lines 17-19 and 47-62, therefore cancels mounts. Its dismount branch intentionally does not cancel, but needs an
   already seated rider.
3. The bay mount exceptions do not bypass this: `BayPassengerRouting.mountAllowed` (lines 26-29) and
   `BayReleasedResume.mountAllowed` (lines 127-130) both require `escrowIdle`. The released-flight effect exception in
   `rocket/server/BayReleasedFlight.java`, lines 244-250, requires `BayReleasedResume.destinationCurrent`, lines
   166-167, which requires `bayNeutral` and thus `escrowIdle`. Governed flight mounting requires a valid scoped
   authority; [EscrowGovernedPhases.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/resourceescrow/EscrowGovernedPhases.java),
   lines 197-201 and 221-225, cannot obtain it without the loaded ledger.
4. A saved seat assignment is not physical occupancy. Rockets remain world/journal-owned rather than becoming a
   player's vanilla saved vehicle: [RocketEntity.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/entity/RocketEntity.java),
   lines 625-629. A login or remount still meets the mount event above. The native `X_LEDGER` rider check also finds
   the login unseated. The existing `r042-L_LEDGER` executable dismount limitation was not changed into a PASS.

Thus there is neither an ordinary seated rider before classification nor an allowed later mount during the hold.
This argument excludes reflection, foreign mods replacing storage, and gated test detachment. Root can correct the
register's claim; this task does not edit the register.

- `EscrowItemCutProbe` and `EscrowItemSettlementCuts` add only release-test cuts. Pre-O1 recovery must retain REPAIR
  without an invented choice. A veto preserves its frozen intent and locks both endpoints: 74 raw mixed-store items
  are not 74 spendable items. Ordinary completed stores conserve 70 typed items. The load-veto ERROR check reuses the
  existing exact fluid own-store oracle; existing cases retain their expectations.
- The five-line change in the production class `EscrowRuntime.cargoStoreAllowed` is an explicit release-test seam,
  not an ungated rule change. It consults the existing item probe only under `EscrowTestEndpoints.HOOKS`; probe
  attachment additionally needs the selected release case and release gate. Without those gates it does nothing.
- `ReleaseTestLoadFailure` adds an opt-in rendezvous inside its existing INJECT decision. The Windows harness holds
  a reversible delete-pending handle after the actual vanilla loader begins, then waits for the real production stat
  to return UNKNOWN. It does not replace the presence result. Failed-case archival now releases the handle first.
- `EscrowLedgerNotLoadedGameTests` adds two real item-device checks, including removal protection, ESCROW_PENDING,
  neutral roots, and unchanged NBT under protective reads. They run in the existing isolated hold batch.
- `scripts/item_cuts_oracle.py`, the item/R-042 runners, and the integrated campaign append the new cases/families.
  Java/Python tests and `escrow-probe-cases.tsv` update exact inventories and exercise rejection mutations. No existing
  case is removed. No ADR choice or waiver is introduced.
