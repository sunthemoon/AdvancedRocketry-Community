## Protocol and design decisions

`--settled-disassembly-protocol` defaults off and requires the existing
`--sealed-disassembly-receipt` option. Both older opt-in modes and
`--wait-ready-status` were also enabled for every corrected case.

For destination recovery, the runner waits before its first disassembly
command for the exact whole same-transfer settlement line. Resumed DESCENT
requires `landed_reservation_retained`, including transfer, logical ID,
entity, COMMITTED phase and exact fuel fields. Already LANDED recovery uses
C6's exact INFO `ARCE_TRANSFER_RECOVERY` line: the recovery callback adds T
to settled before logging it. Its earlier WARN form cannot substitute for
settlement. This follows the control flow recorded in [W462](W462.md).
Source-side cases retain the existing verified RECOVERED contract.

C6 has no preparation-ready audit line. Pending or REGION_BUSY therefore
permits a fresh authorized request at a fixed two-second interval, always
using the exact fuel from the validated report. Neither answer counts as
destructive admission; every other refusal fails. Requests stop on the first
receipt. The opt-in requires identified SEALED and DONE receipts, rejects a
second receipt through the inventory check, and still verifies entity absence,
all five restored blocks and exactly slot 0's 17 diamonds plus slot 26's
64 iron ingots. A legacy success remains available only in the older modes.

The first command starts one 45-second budget covering preparation, fresh
requests, receipts, blocks and inventory. Settlement is observed before that
command. The existing 30-second checkpoint pause budget is unchanged.
No timeout, assertion, performance budget or existing test is relaxed.
The two-second interval and fail-closed C6 inventory text format are the
conservative harness choices; no product ADR or runtime change is introduced.
