**Risk-register text for Root to register before merge.** An observed native
incompatibility in `arce_fluid_fuel_loader` denies terrain saves for its one chunk,
including after its live block entity unloads or is replaced. The existing guard
retains 256 distinct coordinates; a duplicate does not consume capacity, and
the 257th distinct denial saturates that ServerLevel, denying subsequent terrain
saves throughout it until lifecycle close. Entities, players and global stores
still save independently: this is not an atomic world pause. The retained raw
root is not discarded or cleaned. Unsupported data disables the device and
ordinary removal until a supporting installation or offline repair resolves it;
restarting alone does not repair it. Each unsupported load and refused live
replacement emits one bounded WARN, not a per-tick audit. Inherited Forge/native
save retries and repeated loads have no lifetime log cap. Recovery requires
stopping the server, retaining and hashing the complete original world (all
Levels' terrain/entity/POI files, global data/journals/ledger, players and
metadata), repairing a whole-world copy, checking conservation and two complete
save/restart cycles, and replacing the world as a whole. Never restore one store.
Command/raw replacement remains a detectable residual, not prevented salvage.

to the fluid fuel loader, without changing schema 1, operational bounds, native

only observed incompatibilities; the serialized-root event catches unloaded
roots. The existing chunk-save event exception restores the dirty flag and
prevents omission; `saveAdditional` itself retains the raw tag and never throws
as a normal save-control mechanism. Scope, duration, logging and recovery are
exactly those in the preceding risk text. This note changes no admission policy
and accepts no risk; Root must register both texts before merge.
