## New behavior and design decisions

- `cells.py` validates schema 1, both Forge lanes, declared artifact hashes,
  candidate copies in server/client mods folders, and JEI presence/absence and
  hash. JEI detection also inspects bounded mod metadata to catch renamed JARs.
- `attach.py` uses injectable process/window lookups. The native adapter queries
  executable basename, liveness and creation time, never arguments. It requires
  exactly one visible `GLFW30` Minecraft window, checks expected client dimensions,
  the last user-setting log line, saved language/GUI scale, and records every mod
  JAR hash. The record explicitly identifies game-directory binding as an owner
  declaration, not something proved from process arguments.
- Attach batches are fully parsed first. Every input target is checked before
  the batch and every individual input message rechecks identity and foreground.
  Attach never steals focus and refuses client-close requests before any action.
  Owned processes are kept separately from attached clients throughout cleanup.
- Disposable JVMs start suspended, enter a dedicated Windows job before resume,
  and stop by that owned job. Cleanup waits for the job's active-process count to
  become zero, even if its original parent has exited. A process-cleanup failure
  retains both copies and the machine lock for operator recovery. No arbitrary
  PID killing, shell command execution, RCON connection or account lookup exists.
- Server settings are explicit, UUIDs are validated, ops use level 4 without
  player-limit bypass, RCON is disabled and old RCON credentials are removed.
  JVM properties are passed as individual arguments. Ordinary escaped property
  values are preserved; escaped keys/continuations are refused as ambiguous.
  No marker, test switch, owner decision or network restriction is invented.
- Request limits are 256 KiB, 200 actions and two clients. Input pacing is shared
  across clients with a 50 ms minimum. The six-hour maximum includes JVM startup;
  bounded cleanup grace periods follow the action deadline. Session metadata,
  results, summaries, streamed output and copied log snapshots use redaction.
- Compatibility choice: wait strings in `server.wait` and `client_wait.pattern`
  are literal substrings rather than historical regular expressions. This avoids
  unbounded regex evaluation inside a timed session. Historical regex batches
  must be converted before use; the JSON envelope and action names are preserved.
  There is no automatic reconnect that could hide a first-join failure.
- `frametimes.py` analyzes existing PresentMon v1/v2 CSVs with an explicit PID/name
  filter and required stall threshold. Output defines summed-frame duration,
  count/duration average FPS, the mean of the slowest ceiling-1% frames for 1% low,
  nearest-rank P99, longest frame and first-stall start time. No capture tool was
  selected, installed or started.

The [package guide](../../../../scripts/campaign_client/README.md) documents the
session schema, commands, request actions, evidence files and operational limits.

## Unfinished work, risks and Gates

The P9 real-client dry run on C4 is still required: qualify native input and F2,
foreground/focus behavior on the owner's Windows desktop, disposable launch and
job cleanup, two authenticated attach sessions, server restarts, and each W400
Forge/JEI cell. None ran here. Actual player joining is not inferred from a window
appearing. The owner must supply truthful PID/game-directory bindings and saved
settings; this harness deliberately cannot prove those by inspecting credentials.
If focus changes while a key is held, release input is refused too, so the owner
may need to release that key in Minecraft. Prepared copies should be retained
separately for restart tests because successful cleanup removes disposable worlds.
