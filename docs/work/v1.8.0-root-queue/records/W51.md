## Pre-implementation design

This slice adds one transient server-to-client projection (a block-entity update tag field), so AGENTS.md
section 13 asks for a design note before the code and a read-only review before the merge.

**Import.** The plan `tools/import/v180-k1-plan.json` names three entries:

- `models/centrifuge.obj` (coverage row 14) and `textures/models/centrifuge.png` (coverage row 91): upstream byte
  copies at the same asset path;
- `models/centrifuge.mtl`: a NEW material library. The upstream OBJ names `mtllib centrifuge.mtl` and `usemtl None`,
  but the upstream tree has no `centrifuge.mtl`; the 1.12 renderer bound the texture by hand. The NEW file defines
  the material `None` with `map_Kd advancedrocketrycommunity:models/centrifuge`, so the OBJ stays a byte copy.

The MTL is committed on its own first, because a NEW source is read at its authoring commit. If the importer's
derivation or history check reports anything other than CLEAR, the import stops: no record, no runtime asset, no
asset-plan change, and the MTL leaves the runtime tree again (the plan still reads it from the authoring commit).

**Client loader (physical client only, `client/model/`).**

- A client reload listener reads each catalogued model in its preparation phase through that reload's resource
  manager, with byte caps: the OBJ, its MTL and each texture it names.
- A Java port of the `tools/audit/obj_mtl_check.py` rules checks the bytes before Forge sees them:
  - the format;
  - 65,536 vertices per baked object (positions, and four corners per face);
  - 262,144 vertices and 16 MiB per cached set (OBJ, MTL and PNG bytes);
  - references: relative or `advancedrocketrycommunity:` only, never absolute, external, parent-directory, URL or
    `#variable`.

  Counting stops at the first statement over a budget, so no oversized model reaches Forge's parser.
- Only then does Forge's `ObjModel.parse` run, on the checked bytes. `bakeRenderable` turns the result into a
  direct-texture `CompositeRenderable`, as the 1.12 renderer bound its texture, so nothing joins the block atlas.
  Forge reads the MTL a second time through its own `ObjLoader`; the render lookup still admits only the textures
  the check resolved.
- Each texture must exist in the mod's resources and be a PNG of at most 1,024 pixels a side. A missing or
  unusable texture, or a material without `map_Kd`, renders with the model's explicit fallback. For the centrifuge
  that is its NEW controller face `textures/block/centrifuge.png` (`V180C16cMachineArt`), never `missingno`.
- No source path, download or URL: the catalog is compiled in, and every location is a resource location in the mod
  namespace.

**Reload.**

- Success publishes the new set and releases the textures that only the old set used.
- A malformed, oversized or badly referenced model fails the whole reload. The last good geometry is kept, and its
  textures are resolved again against the new resources.
- A model whose OBJ is absent is not a failure: it has no geometry, and the block keeps its JSON model.

**Fixture.** A test-resource JSON per model freezes the following, and a unit test compares the catalog with it:

- orientation: a mirror in x, then the controller rotation from `FACING`, as `ClassicControllerBlockEntity` maps
  it to the pattern transform;
- scale 1;
- rendering: `entity_cutout`, `flip_v`, shaded, not emissive, light sampled at the air cell above the controller;
- the bounding volume.

The mirror is needed because the modern C16c pattern is the mirror image of the 1.12 structure: for a
north-facing controller, local x runs east, while the 1.12 renderer placed the hull to the west. The mirror is an
exact text transform of the checked bytes (negate `v` and `vn` x, reverse face corners), so winding and normals
stay consistent and the committed OBJ stays a byte copy. The test checks that the transformed bounds equal the
generated pattern's footprint for all four facings, that the pattern is unchanged and that the controller's
collision shape is still one full block.

**Formed projection (common code, the one wire change).**

- `ClassicControllerBlockEntity`'s vanilla update tag gains an optional `formed` byte, for catalogued kinds only
  (the centrifuge). It is written only while `formed()` holds, and `sendBlockUpdated` runs only when that value
  changes, after revalidation and invalidation.
- The client decodes it strictly (only byte 1 counts) into a transient field. It is never saved, never read on
  the server and never used for authority.
- Every other kind's tag is byte-identical to today's, so the W42 sound projection and its tests are unchanged.
- The same kinds report a render bounding box equal to the pattern footprint, so the renderer is not culled while
  the controller block is off screen.

**Renderer.** A block-entity renderer for the centrifuge draws the model only while the projected flag is set and
the model is loaded. Otherwise the controller keeps its JSON block model. It does not hide blocks, change
collision or touch the pattern. The 1.12 cylinder spin needs an activity flag the centrifuge does not send, so the
cylinder is static.
