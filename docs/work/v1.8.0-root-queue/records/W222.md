# W222 — BI O-veto guarded-save log qualification

## Scope and design (before implementation, 2026-10-31)

The assigned worktree starts clean at `bf29282485525cb2b30e6277e2b5f14896af7823`
on `codex/v1.8.0-w222`. Root's TASK authorizes a test-side correction only.
The write scope is `scripts/loader_s6_chain.py`, its dedicated Python tests
and retained log fixture, and this record. External working evidence belongs
to `D:/GitHub/ARCE-Task-Evidence/root-queue/W222/`. W211's evidence is read-only.
Other worktrees and sessions are not modified or delegated to. There is no
production, schema, ADR, timeout, budget, status, ledger, build or workflow
change, and no push or merge.

Both failed restarts contain sixteen refusals of the same overworld terrain
chunk `(4,4)`. Each has an EventBus exception and the corresponding ChunkMap
catch of that exception. Their route is `ChunkMap.save` (830),
`saveChunkIfNeeded` (796), `processUnloads` (490), and `tick` (454).
The last part of `processUnloads` saves visible chunks; the method name does
not make these unload callbacks. This is the per-tick incremental save sweep,
not the periodic full-world autosave. The fixture installs its Level-lifetime
denial at START before the first recovery tick. `GuardedChunkSaves.fail`
restores the dirty flag and throws before ChunkMap's write. A failed save
does not install the successful save's ten-second cooldown. A still-accessible
chunk can therefore be retried on later ticks while recovery waits for its
loaded/ticking endpoints and journal. Sixteen is an observed count, not a
bipropellant invariant or a new budget. The same window is possible in either
fuel selection. The precise readiness delay is not instrumented in the old
logs; it is not attributed to a particular asynchronous wait.

The correction will keep exactly one selected own-store guard error and allow
only complete ordinary-save refusal pairs for that same reason and chunk.
Each event retains the existing 96-line bound, one exact throwable, no nested
exception, and the actual guarded pre-store stack. The two halves must match
after normalizing the different JVM stack renderings. Unknown errors, FATAL,
missing/extra halves, foreign chunks/reasons, store/write stacks, duplicate
own attempts and incomplete stacks remain failures. No count wildcard for
arbitrary ERROR messages is introduced. The raw held-component oracle stays
mandatory and unchanged: it checks both typed fuel banks, both loaders,
epochs, markers, full captures/bindings and frozen authority across both
restarts, with no release or availability/loss inferred from a raw sum.

Tests will fail first on an unchanged retained restart log, then replay all
three logs and native-form images of the failed attempt. Its original FAILED
verdict and input files will not be changed. An oracle-only correction can be
verified against those retained inputs without another native start; any
need for fixture changes or unexplained native behaviour will be reported
rather than changed in production. Root's hosted regression remains the full
GameTest evidence, and version Required Gates are not marked passed here.

## Delivery

The design is committed as `0e8eb1b66448edee0e873b3453f580d965ccc469`.
The implementation and its tests are committed as
`1a9f79254068b8aa463817362dc2ee3d4bba54fb`. All commits are local on the assigned
branch. The full Java suite and final Python/replay checks use this committed
implementation. This record is a subsequent documentation-only commit.

The cause is test-side: the previous oracle treated every ERROR as the sole
selected own-store exception. The product correctly refuses every observed
attempt before submitting the guarded terrain store. Its incremental save
path catches the exception and logs a second ERROR; the own-store path instead
reports BARRIER_VETO and retains the complete decision. The guard covers one
terrain chunk containing both loaders, not sixteen chunks or the entity store.
Other chunks in the same region file may still save; changing whole-region
hashes are not proof that the guarded slot was written.

The changed areas are:

- [The chain log oracle](../../../../scripts/loader_s6_chain.py) now requires
  exactly one complete own-store refusal and classifies every additional ERROR
  as one half of an adjacent, matching EventBus/ChunkMap incremental-refusal
  pair. The exact reason, chunk, throwable and full ordered method sequence
  are checked. JVM module/artifact decorations are normalized; paired frame
  locations must still agree. Only the compiler-assigned lambda index varies.
- [The chain tests](../../../../tests/test_loader_s6_chain.py) add five methods.
  Counts 0, 1, 2, 16 and 17 are exercised for both fuels and all three starts,
  on either side of the own attempt. Negative cases cover unpaired/reordered
  errors, mismatched stacks, foreign chunks/reasons/errors, FATAL, unload/full
  autosave routes, nested exceptions, overlong blocks, missing/duplicate own
  attempts, and extra write/store frames. Refusal logs do not qualify changed
  native tanks, banks, epochs, markers or ledger authority. Non-veto rows
  continue rejecting all ERROR/FATAL messages.
- [The retained BI restart log](../../../../tests/fixtures/loader_s6/veto-restart-bi.log)
  is byte-identical to W211's failed attempt's first restart, SHA-256
  `14323143d78fdde11167c834644b316f2d35223992bfd290129c5258ad13b481`.
  No old test or raw held-state assertion is removed or weakened.

There is no open ADR choice or new save-refusal mechanism in this correction.
The classifier deliberately qualifies only the observed incremental route;
another save route must be investigated, not admitted by a generic ERROR rule.
