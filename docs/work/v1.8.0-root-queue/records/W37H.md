# W37H: W37F review fixes (a newer point wins, the End exit, fresher decisions)

## Design (written before the code, 2026-10-14)

This worker owns `SleepRespawnService`, `RespawnPointBackup`, their tests, one new generic
respawn message (with its `runData` output), `scripts/gametest_expected_log.json`, the sleep
section of `docs/CELESTIAL-DATA-GUIDE.md`, one atmosphere GameTest and this record. Status files,
the ledger, ADRs, the risk register, build files and other tasks' files are not changed.

**F1: which point governs.** A decodable backup governs only while the player's native tuple is
either the backup's own tuple (restored, waiting for completion) or exactly the cleared tuple that
W37F writes (Overworld, null position, raw angle bits of 0.0F, not forced) with no foreign setter
seen since that clear. Every decision and restore point applies this rule first: the server-tick
END, the DISCARDED final check, the respawn event, login and logout. Any other tuple, or a cleared
tuple after a foreign setter, supersedes the backup. The backup is then removed at once, any
retained opaque root goes back under its key, and no field is written. For a dead player, or one
on the End credits, the newer tuple is then judged as a fresh saved point. A restore writes the
four fields only into the exact cleared tuple. Completion still waits until the connection owns
the player (W37F's alias guard). A superseded backup is removed without that wait. In W37F's
interrupted-listener window this means a reconnect saves neither point; vanilla would lose the
newer point there as well.

**The foreign-setter flag.** A `PlayerSetSpawnEvent` listener at `EventPriority.LOWEST`, which
sees only non-cancelled events, records the player's UUID when that player has a decodable backup.
It does this regardless of `connection.player`. The service's own writes post no event. The flag
lives in a service-owned set. It is dropped when the service writes its clear, when a backup is
removed, at login and when the server stops. At logout (`PlayerLoggedOutEvent` fires before the
native save) the rule is applied once more and the flag is then dropped. If the server stops
abnormally between a foreign clear and the next tick, the flag is lost; at login the tuple check
alone decides, so a cleared tuple restores the backup.

**F2, F3 and F4: one decision at the end of the server tick.** The `PlayerTickEvent` listener and
the old server-tick restore become one `ServerTickEvent` END listener at `EventPriority.LOWEST`.
It walks the PlayerList's players and skips FakePlayers. A player that is dead, or has `wonGame`
set, gets a decision; every other player gets the restore. The listener runs after every Level
tick, every connection tick and the atmosphere authority's own END tick, and it no longer depends
on `Player.tick` or `doTick`'s spectator guard. The End credits return is judged like a death
respawn: a refused point is set aside before `respawn(player, true)` reads it, and it is restored
on the respawn event. Between the decision and the native read, only the inter-tick task queue
(packets, commands and `/reload` completion) and the config watcher can still change state. The
DISCARDED leave event stays as the final check.

**F5.** One WARN per player, per case and per server session, for an unencodable native tuple, a
foreign non-compound `PlayerPersisted` parent, and an unreadable or future backup root. Each WARN
gives the UUID, the case and the recovery pointer. The sets that limit them are service-owned and
cleared when the server stops. Behaviour stays fail-open as W37F designed it.

**F6.** `RespawnPointBackup` maps each refused outcome to a pinned token in an exhaustive switch.
A schema-1 backup whose outcome token is a string this version does not know decodes with no
outcome. Its point is kept, and the restore sends a new generic message.

**F7.** A refused decision rewrites the backup only when its tuple or outcome changed. It writes
the fields only when they are not already cleared.

**F8.** No code change. One GameTest puts a vent in a visible but unfinished chunk next to a
completed chunk of its room. It shows that the room reads as unsupplied without loading the vent's
chunk.

**Tests.** The decision now runs at the server-tick END, so tests that called `connection.tick()`
to drive it move between steps on real ticks, with one `onEachTick` registration. Tests that hold
a non-default option across a tick get their own batch, so concurrent tests keep the defaults.

## How each decision was carried out

**F1.** `RespawnPointBackup.governs` is the whole rule, as a pure function with a unit-tested
matrix. `SleepRespawnService.governing` applies it at every decision and restore point and calls
`release` for a superseded backup. `release` puts any retained root back under its key. A restore
writes the fields only when the tuple is not already the backup's own; `governing` guarantees that
case is the exact cleared tuple with no foreign setter. A dead player's superseded tuple goes
through the normal decision as a fresh point. The previous `onSpawnSetter` completion is no longer
needed, because the next restore point now removes a superseded backup. The native tests are:

- `/spawnpoint` through the real dispatcher on a dead player before corpse removal, setting a Moon
  point: the next dead tick removes the older backup and refuses the new point, and the respawn
  restores the new one;
- the same before corpse removal with an Overworld point and an immediate packet, so the DISCARDED
  final check sees it;
- the same after KILLED corpse removal: vanilla respawns at the new point and keeps it;
- a respawn-event setter at `HIGHEST` (before this listener) and at `LOWEST` (after it);
- a foreign null clear while a backup is pending;
- that clear followed by a logout and a reconnect.

**F2.** The END listener decides for `isDeadOrDying() || wonGame`. The End exit's
`respawn(player, true)` reads what the decision left, and the respawn event restores a refused
point. `aRefusedEndExitLandsAtTheOverworldSpawnAndKeepsThePoint` checks the Overworld spawn area
(within the spawn radius), the restored tuple, the message and completion.
`anAcceptedEndExitLandsAtTheSavedPoint` lands beside the Tau Ceti f bed. The guide now says the End
return is judged the same way.

**F3 and F4.** The decision moved to one END listener at `LOWEST`. It skips FakePlayers. The old
`PlayerTickEvent` listener is removed, because the END listener also retries recovery for living
players. The corrected freshness argument is as follows. `MinecraftServer.tickServer` runs the
Level ticks, the connection ticks, the autosave and then the END listeners; this decision is the
last END listener of this mod, after the atmosphere authority's END tick. Between it and the native
read of a later respawn packet, only these can still change state: the inter-tick task queue
(other players' packets, commands, `/reload` completion), the config watcher thread, and any other
mod's `LOWEST` END listener registered after this one. The DISCARDED final check runs at the read
itself. `aDeadPlayerIsDecidedWithoutAnyPlayerTick` never ticks the connection and counts zero
`PlayerTickEvent`s, so the decision no longer depends on `doTick`'s spectator guard. The fixture's
`isSpectator()` override is unchanged, because the test needs no player tick at all.

**F5.** `ARCE_PLANET_RESPAWN_DIAGNOSTIC player=<uuid> case=<case>: <effect>; recovery: <steps>
(ADR-066 planet respawn backup note)`, at WARN, once per player per case per server session. The
cases are `unencodable_tuple`, `foreign_persisted_parent` and `unreadable_backup`. Behaviour stays
fail-open as W37F designed it: the first two skip the refusal and vanilla reads the point; an
unreadable root is kept verbatim. The pointer names an ADR-066 note that Root adds with the risk
text below.

**F6.** `RespawnPointBackup.token` is an exhaustive switch with pinned strings, so a new refused
outcome is a compile error until it gets a token. `decode` still requires a string `outcome`, but
an unknown string (including `accept` and the empty string) gives a backup with no outcome. Its
point is kept, and the restore sends `message.advancedrocketrycommunity.planet_respawn.generic`. The
next refusal replaces the unknown token. `encode` refuses a backup with no outcome. In
`RespawnPointBackupTest`, the `accept` and `future` cases moved out of the rejection list into
`anUnknownOutcomeTokenKeepsThePointWithAGenericMessage`, because Root's decision changes that
behaviour. Two rejection cases were added: a non-string outcome and a missing outcome.

**F7.** A refused decision stores the backup only when the decoded pending backup differs from the
new one (record equality, which compares the angle by `Float.compare`). It writes the four fields
only when they are not already the cleared tuple. The per-player cost on each END tick is as
follows.

- With `allowPlanetRespawn` off (the default), there is no probe: one bounded decode (at most nine
  nodes and 1 KiB) and one record comparison.
- With it on, one probe runs. It does one Level lookup and one catalog query, and at most four
  `getChunkNow` calls. Only after those pass does it do one block read for the bed or anchor and
  vanilla's stand-up search: a fixed list of candidate offsets around the block, each with a floor
  read and one player-sized collision check. Then come the hazard check (one collision check and
  at most 16 block reads), two station lookups (Space only) and two breathability lookups. Every
  read is within `ARRIVAL_REACH` (3) of the saved block, in chunks already checked as loaded.

The cost applies only to players on the death screen or the End credits. There is no global cap;
the total is bounded by the number of such players.

**F8.** `VentCompletedChunkGameTests` builds a sealed Moon room whose vent is in the last column of
one chunk. A room cell sits in the next, completed chunk. With the vent's chunk held visible but
unfinished, that cell reads VACUUM and the vent's chunk is not completed. Once the chunk is
complete again, the cell reads breathable.

## Choices where the decisions left room

- A superseded backup is removed at once, even before the connection adopts the replacement.
  Completion of a restored backup still waits for adoption. The only difference is W37F's
  interrupted-listener window, described in the risks.
- Logout applies the foreign-setter flag before the native save, then drops it. Login drops any
  stale flag. A server stop clears both transient sets.
- A setter is counted only when it is not cancelled, the entity is a `ServerPlayer` on the server
  thread, and that player has a decodable backup. Every such setter counts, as Root decided, not
  only null setters. Its consequence is in the risks.
- When a pending backup's dimension is no longer off-world (for example after a catalog reload),
  the decision is unchanged from W37F: it returns, and the respawn event restores the point.
- The generic message key is `planet_respawn.generic`, in English and Simplified Chinese.
- The tests that hold `allowPlanetRespawn` on across a tick have their own batches,
  `respawn_option_change` and `end_exit_allowed`.

## Proposed risk text (for Root, from review section 5)

**Planet-respawn backup (ADR-066 section 3.3; W37F, W37H).** When the policy refuses a saved
off-world point at a death or End-credits respawn, the exact tuple is written to
`ForgeData.PlayerPersisted.arce_planet_respawn_backup`. The tuple is the dimension, `x`, `y`, `z`,
the raw `angle_bits` and `forced`, in schema 1, at most 1 KiB and nine nodes. The four native fields
are then cleared, so vanilla uses the Overworld. The scope is one player's saved respawn tuple,
never a chunk or a Level. No save is refused, and no exception controls saving. A readable backup
lasts until a verified restore or until a newer tuple supersedes it, across logout, player
save/load, respawn and restart. An unreadable or future root lasts until offline repair or a
compatible reader.

1. **Newer points (F1, fixed in W37H).** The backup governs only its own tuple or the exact cleared
   tuple. Any newer tuple removes it: a command, a bed, or another mod's setter, before or after
   the respawn event. These residual cases remain:
   - another mod's null setter counts as an explicit clear and removes the backup. This includes a
     `PlayerEvent.Clone` listener that copies the old player's cleared tuple to the replacement.
   - a setter seen at `LOWEST` but then cancelled by a later `LOWEST` listener also counts.
   - the foreign-setter flag is in memory. If the server stops abnormally between a foreign clear
     and the next tick, the flag is lost, and the next login restores the backup.
2. **Logs.** One WARN per player, per case and per server session (`ARCE_PLANET_RESPAWN_DIAGNOSTIC`)
   for an unencodable tuple, a foreign non-compound parent, and an unreadable or future root.
   Nothing else is logged. Players with an ordinary pending backup can be found only offline, by
   the key above.
3. **Player experience.** With an unreadable or future root, or after ARCE is removed or downgraded
   while a backup is pending, the native point is empty. The player respawns at the world spawn
   with no chat message. While ARCE is installed, the `unreadable_backup` WARN is the operator's
   signal.
4. **Fail-open cases.** An unencodable native tuple skips the refusal: a non-finite angle, `x` or
   `z` beyond ±30,000,000, or a dimension ID over 256 characters. So does a foreign non-compound
   `PlayerPersisted` parent. Vanilla then reads the point, and may load its chunk, enter a denied
   station or place the player in vacuum. Only other mods or edited data reach these cases.
5. **Interrupted respawn.** If another respawn listener throws before this one, the backup stays
   pending and the server-tick retry restores the fields. Completion waits until the connection
   adopts the replacement, which can need a reconnect. A newer point set on the replacement in that
   window is lost with the old player's native save, as in vanilla, and the superseded backup is
   removed as well.
6. **Offline recovery.**
   1. The player must be offline. Back up `world/playerdata/<uuid>.dat`.
   2. In an NBT editor, open `ForgeData.PlayerPersisted.arce_planet_respawn_backup`.
   3. If it has `schema: 1`, copy `dimension` to `SpawnDimension`, and `x`, `y` and `z` to
      `SpawnX`, `SpawnY` and `SpawnZ`.
   4. Convert the int `angle_bits` to a float with Java `Float.intBitsToFloat` and store it as
      `SpawnAngle`. Copy `forced` (a byte, 0 or 1) to `SpawnForced`.
   5. Remove the key. If it has a `retained` child, put that child back under the key instead.
   6. A non-compound `PlayerPersisted` belongs to another mod. Repair it with that mod's owner,
      because replacing it loses that mod's data.
   7. Save the file and let the player join. Check `/data get entity <player> SpawnX` and that the
      key is gone.

## Known risks

- The residual F1 cases in the risk text above, items 1(a) to 1(c): a null setter from another mod
  removes the backup, a later-cancelled setter counts, and an abnormal stop loses the flag. Root
  chose to count every foreign setter. A narrower rule, counting only setters that change the tuple,
  would keep the point in the `Clone`-copy case, but would let the backup override another mod's
  explicit reset of an already-cleared player.
- In W37F's interrupted-listener window, a newer point set on the replacement is lost and the
  superseded backup is removed.
- The END listener at `LOWEST` still runs before any other mod's `LOWEST` END listener registered
  after it, and the inter-tick task queue still runs before the read.
- With `allowPlanetRespawn` on, every dead or credits player is probed each tick. There is no global
  cap, as Root decided.
- A mod that replaces the native tick, `PlayerList.respawn` or the credits handler can bypass these
  Forge boundaries, as before.
