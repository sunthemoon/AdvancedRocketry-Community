## Changes by area

- `scripts/v180_crash_replay.py` validates the recorded operations, blobs,
  pre-images and kill image. It derives S-OLD, S-EMPTY, S-PREFIX, S-TORN,
  S-STAGED and S-NEW, plus every named late-loss combination. It deduplicates
  whole seam-file hash vectors while retaining every crash-point derivation.
  Sixteen distinct states are accepted; additional states, more than seven
  late-loss combinations, or oversized traces produce `OVER_BOUND`.
- `scripts/run_v180_crash_replay.py` maps all twelve design cases to their
  existing runners. It records and kills the original cut, writes `states.json`
  before any replay start, runs both restarts of each state, compresses logs,
  writes results and checksums, and deletes disposable worlds and server trees.
  It takes the heavy-JVM lock once per case, waits 90 seconds between cases,
  verifies the candidate and clean source, checks C:/D: free space, and limits
  evidence size. Passing logs can be reduced to marker lines with an explicit
  reduction record; failing logs are not reduced.
- The B, F, S, I and R runners gain an opt-in Python API for capture-only and
  restart-only execution. Their normal command-line cases and expectations
  remain unchanged. B/R preserve the failed first-start image before cleanup
  so that the second restart still runs against that image, not a fresh rewind.
- `tests/test_v180_crash_replay.py` covers synthetic traces, exact state bytes,
  crash-point mappings, deduplication, all late-loss combinations, the exact
  sixteen-state boundary, refusal cases, runner modes, candidate case mapping,
  sequential cleanup, failed-start continuity, locks and log reduction.

## Implementation choices

1. The wire format was checked read-only against the committed S1 recorder on
   `codex/v1.8.0-w369` at `7411741ca`. Sequences start at zero; open records
   `target`, `pre` and `preLength`; absent targets use `pre/<seq>.absent`;
   directory force has a null store and is matched by thread and directory.
   Pre-images and blobs are hash-checked, and inconsistent or partial traces
   are refused rather than repaired or sampled.
2. Each case's late-loss window starts at the earliest of the last completed
   writes of its design-named late-loss stores. This excludes fixture creation
   while retaining a continuous, recorded window. The state table records the
   chosen sequence and the pre-image sequences. Intermediate generations and
   the cross product of unfinished writes remain excluded as designed. Root
   should verify these boundaries against the named writes in the real traces
   before accepting S3 results.
3. Item old sides add independent earlier-ledger expectations by using the
   existing typed native conservation reader at `IC_LOAD_L1_BEFORE` and
   `IC_UNLOAD_C6_JOINT_READBACK`. Both require exactly 70 items, exact stack
   types and no flight authority. The old registry side uses R2's durable zero
   satellites and additionally requires R3's terminal and bound package on both
   starts; it never launches the package in the old-side check.
   The earlier item probe is also used to drive the native recovery observation:
   the Java probe distinguishes a before-L1 epoch of zero from a replaced-L1
   epoch of one. Logs are not rewritten to make their case labels match.
4. A state selects the old/new oracle of the store actually rewound. Rewinding
   an unrelated unfinished writer does not switch the primary case's oracle.
   Late-loss failures remain failures, explicitly identified for Root's
   Windows directory-flush residual/resource-loss triage. Deduplicated states
   that also represent an in-flight crash are not classified as residual-only.
5. The harness does not invent a marker-only success oracle. Allowed marker
   lists are empty unless an existing case's complete oracle accepts the hold.
   An unfamiliar hold or REPAIR response therefore remains an oracle failure
   with its markers retained for Root, rather than becoming an automatic PASS.
