## Part 1: the correction-file rule

**The line form.** All six W60 files use one form: a table with the header
`| Line | Corrected text |`, a delimiter row, and one row per broken link, `| <line> | <text> |`.
Each of the 32 broken links is on its own line, and the rows match them one to one. The form is
unambiguous, so I used it as it is and did not change any correction file.

The validator now excuses a broken link on line L of a tracked Markdown file F only when all of the
following hold for some file C:

1. **Name and place.** C is in the same folder as F and is named `<F's stem>-CORRECTION-<id>.md`.
   The id is ASCII letters and digits in hyphen-separated groups, for example `W60` or `TASK-53`.
   Matching is case-sensitive, and the extension must be lowercase `.md`.
2. **Committed.** C is in the Git index inventory that the check already uses. HEAD's tree holds C
   as a regular blob, and C's working-tree bytes hash to that blob's object ID (SHA-1 or SHA-256
   repositories). So an untracked, staged-only or locally changed C does not count.
3. **Names the line.** C contains exactly one `| Line | Corrected text |` table outside code
   fences. It is followed by a delimiter row and at least one row, every row has a distinct line
   number from 1 to 100,000 with no leading zero and nonempty text, and one row names L. One
   malformed row rejects the whole file.
4. **Its own links pass.** The normal check found no broken link in C, and it scanned C to the end.
   Another correction file cannot excuse C's own links.

Both kinds of per-link error can be excused: a missing target and an unsafe target (such as the 21
absolute `D:/` links in `memory-window-69/REPORT.md`). File-level errors (unreadable, non-UTF-8,
over a limit) are never excused.

**Diagnostics.** When F still has an unexcused broken link, each correction file next to it that
failed a condition adds one error line saying which condition failed, for example
`.../REPORT-CORRECTION-W60.md: correction file for .../REPORT.md not used: it is not committed at HEAD`.
The PASS line reports the excused count.

**Bounds.** The rule queries Git only when some broken link has a candidate correction file, and
then it runs one bounded `git ls-tree` for at most 256 files with at most 16 KiB of path bytes. If
either limit is exceeded, the check fails and nothing is excused. Correction files are read with the
existing bounded reader (2 MiB).

## Part 2: R32-03

`G4ApplicabilityTreeTests` drives `validate_v002_g4_applicability(root)`, `_read_stable_file` and
`main()` on temporary trees:

- the ADR file missing, or a folder in its place;
- the ADR file oversized: one byte over 256 KiB, and the exact limit through the reader and through
  a patched `MAX_ADR_BYTES`;
- the ADR file not valid UTF-8;
- the ADR file changing while it is read (`os.fstat` reports another size);
- a linked ADR file: the file as a symlink, its folder as a directory symlink, and its folder as a
  Windows junction. A junction can only be a folder, so the junction case links the ADR's folder;
- an absent bundle with a PROPOSED and an ACCEPTED ADR;
- an invalid bundle (an empty folder, a malformed record, a plain file), each with a PROPOSED and an
  ACCEPTED ADR;
- a bundle whose `lstat` fails, and the early stop when the ADR itself is invalid;
- `main()` in process for a passing tree (exit 0 and the PENDING line) and failing trees (exit 1,
  stdout empty, one `[FAIL]` line per error). It also runs on the repository's own accepted record
  (exit 0 and the PASS line), and as an isolated script (`python -B -I -S`) on a passing and a
  failing tree.

**The defect.** Before the fix, the module ran 33 tests and 2 failed: the directory-symlink and
junction cases returned no error, so a record outside the repository was accepted as ADR-005. The
other bounded readers in the repository already reject such paths (`_inspect_bounded_file` in
`validate_repository.py`, and `_reject_link_components`, which the bundle path uses). `99dcb83f`
adds `_reject_linked_components`, which checks every component of the ADR path below the root
before the read. A missing component still falls through to the read's own error.

**One message changed.** A symlinked ADR file now reports "ADR-005 path must not contain a symlink,
junction, or reparse point" instead of "ADR-005 must be an ordinary file". `_read_stable_file` keeps
its own final-component check, and the test calls it directly. `check_v002_g4_applicability` only
passes error text through, and no other code or test reads this message.

## Choices

1. **"Committed".** I read it strictly: the HEAD tree and the exact bytes, not just the index.
   Comparing the blob ID avoids running `git diff`, which could run configured filters.
2. **The error limit.** Excusable links still count toward the scan's limit of 256 raw errors. If a
   future tree has more than 256 raw errors, the check fails with the stop line even if many of them
   would be excused. This fails closed, and the tree has 32 today.
3. **Older correction files.** Files such as `SOURCE-CORRECTION-06.md` match the name pattern but
   have no line table. They would matter only if a Markdown file with the matching stem (here
   `SOURCE.md`) sat next to them with a broken link. No such file exists with a broken link today,
   and `SOURCE.md` does not exist at all.
4. **The `main()` PASS line.** A temporary tree cannot easily hold an acceptance-ready client bundle,
   so the PASS line is tested on the repository's own record, and the temporary trees cover PENDING
   and FAIL.

## Known risks

- The two real-tree tests depend on the committed state: ADR-005 ACCEPTED with a valid bundle, and
  no broken Markdown link outside W60's six files. A new record with a broken link fails the
  Markdown test, as it fails the strict validator.
- The symlink tests ran here because the session runs as Administrator. On an unprivileged Windows
  account they skip with a reason, and the junction test still runs. Hosted Linux runs the symlink
  tests and skips the junction test.
- The blob comparison is exact. A correction file checked out with CRLF line endings would be
  rejected. The repository's `.gitattributes` gives `*.md` LF line endings, and the
  `proposals/**` folder that holds `REPORT-03-CORRECTION-W60.md` is binary, so a normal checkout
  passes.
