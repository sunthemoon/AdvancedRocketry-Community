# W10: C16c classic machines

## Implementation design

The worktree started clean at `b16423f3` on `codex/v1.8.0-w10-c16c-machines`.
The write scope was the four C16c machines, their shared runtime extensions,
recipe codec, configuration, registry additions, JEI, data generators and their
generated files, tests, exact log expectations, and this record. No other agents
were started. This worker did not push or merge.

The existing classic controller remains the only runtime. Chance outcomes and
their transaction UUID are retained in its job checkpoint before application.
Resource plans are detached and re-simulated against current bank revisions
until completion; missing inputs retain progress and the outcome. PREPARED,
kernel commit verification and publication run synchronously while capabilities
and ordinary removal are locked, with no retained PREPARED plan to re-plan.
This follows the merged kernel's single-snapshot publication design; it does
not establish native crash durability. The job's monotone ordinal is allocated
at start, and exhaustion refuses a new batch. Optional outcome fields preserve
reading of existing schema-1 jobs without changing shared journal schemas.

The etcher restores each debited lens payload to the same input-bank slot in
the detached transaction. Crystallizer gravity comes only from the station
containing the controller or its Level's body profile. Legacy null cells use
the existing clearance tag. Original art is drawn in code. No upstream file
is copied. Layout facts were checked against the pinned `c5cd5af` source.
Venus volcano generation already places enriched lava, so it is not changed.

C18a cartridge recipes, C18b enchantment recipes, kernel ownership/removal
rules, status files, the ledger, native restart and visual acceptance are not
part of this task.

## Design choices and boundaries

Controller crafting uses existing steel plates, redstone, casing and motors,
with the appropriate shell or lens component. The shell uses quartz and crafts
one crucible. The four patterns forbid mirrors and use all four rotations.
The centrifuge candidates remain separate from deterministic outputs; bounded
counts and weights enter the recipe signature. Its seed hashes machine UUID,
signature and ordinal. The built-in order gives iridium an effective 0.25%
chance, disclosed in JEI and checked exhaustively over 10,000 roll pairs and
with 10,000 seeded batches. Duplicate successes merge within native stack
limits; selection stops after four successful candidates, not four slots.

Optional job fields extend the existing independent schema 1 without changing
the shared process/journal schemas. Old jobs without those fields still decode.
Existing exhausted-counter repair/retention behaviour is preserved; starting
a new live batch also refuses `Long.MAX_VALUE`. A nonzero gravity limit refuses
processing when controller environment context is unavailable. Station gravity
is the containing station's configured environment profile, as exposed by the
existing environment API; area fields and players are not consulted.
