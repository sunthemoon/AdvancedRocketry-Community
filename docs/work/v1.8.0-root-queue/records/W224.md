# W224: canonical satellite-root startup refusal

## Design before implementation (2026-10-31)

Assignment: [TASK-W224](../TASK-W224-SATELLITE-ROOT-OPTION-A.md). Base
`aebf5782df8a0e8d9775c89cd9e4ec4920aa4bc7`, clean branch `codex/v1.8.0-w224`.
Root is Claude; this worker commits locally only, without delegation or push.
Write scope: satellite persistence codecs and their startup/migration diagnostic
adapters, related unit tests, this record, and external W224 evidence. Status,
ledger, build and workflow files remain Root-owned. No upstream material is used.

The owner's [D15](OWNER-DECISIONS-20261031.md) selects W173 option A. After
decoding and `finishRestore`, every current-root decode calls the existing
`encodeCurrent` once, not only repaired loads. The actual canonical encoder
enforces the existing per-record bounds and inclusive 16 MiB root bound; section
count checks remain unchanged, and admission reservation budgets are not new
load limits. Historical root-3 validation remains historical; migration to root 4
must pass this same current-root check before discovery can create backups or
stage replacements. There is no schema, identifier, budget or bound change.

`ServerAboutToStart` calls `WorldDataMigrationService` synchronously on the
server startup thread, before Levels and player logins. Its detached semantic
validator loads the registry; the later world-owned SavedData load repeats the
check once for its own decode. Migrating roots can be decoded more often. This
is startup work, not a tick operation or IO-writer task. W173 measured one
near-bound canonical encode at about 106 ms median on the development host;
W216 already adds eager restore sizing, so this cost is additional, not removed.
Known resident sizes could establish numerical totals, but UNKNOWN loses the
specific failure and they do not execute the complete encoder. This slice uses
the complete encode for exact acceptance and diagnostics, not a cache shortcut.
It retains no extra serialized root after validation. Reference-node startup,
concurrent load and soak performance are not established by those measurements.

A typed canonical-bound failure contains only a fixed record kind, UUID (or the
fixed registry data name for the root total), canonical byte count and bound.
Encoders stop at the first failing record in deterministic ID order. SavedData
keeps that failure when blocking, and migration preserves it through its wrapper.
The pre-start hook emits one bounded ERROR without an attached stack trace,
including a fixed offline-repair instruction. It then uses the existing startup
refusal. Platform exception/crash reporting is outside that one mod diagnostic.
There is no per-record list or per-tick output. Dedicated players cannot join;
an integrated host gets the platform's startup-failure UI and consults the log.
No new client UI or translated message is introduced.

The affected scope is the entire registry and therefore the world's startup,
on every attempt until repaired. The decoder and validator never rewrite, move
or delete the original file; failure occurs during discovery, before managed
file migration writes. Recovery: keep the server stopped, back up the complete
world, inspect the named record in an offline NBT editor, and repair consistently
so the canonical representation actually fits (merely adding namespaces cannot
shrink an oversized canonical record), then restart. Do not discard records or
restore isolated authority files without reconciling their dependencies.

This does not prove later lifecycle growth fits, preserve unknown foreign keys,
change runtime admission, implement W173 options B/C/E, or cover other roots.
The exact R-030 and ADR-050 implementation-note drafts and a read-only audit
script go to `D:/GitHub/ARCE-Task-Evidence/root-queue/W224/` before code; only Root
applies those central documents. Independent read-only review precedes merge.
Verification: failing-first new tests, isolated classes, satellite persistence
and mission packages, all units, three satellite GameTest runs under the machine
lock, then a committed-source JAR native refusal/repair/normal-restart check.
Root's hosted complete GameTest substitutes for a local complete run. No Required
Gate or risk acceptance is claimed.

## Native evidence and recovery

The packaged-JAR check used Forge 47.4.10, Java 17 and disposable offline localhost
servers. JAR entries were checked for duplicates and absence of the external
test fixture class. All starts used the same committed-source runtime JAR.

Current record-over, legacy record-over and canonical root-over worlds each
refused before Ready with exactly one mod-owned diagnostic and left the
satellite `.dat` byte-identical, without creating a migration backup. The root
diagnostic reports 16,777,226 bytes against 16,777,216. Forge's existing EventBus,
crash-report and shutdown exception sites were classified separately, with at
most one occurrence per site and no unexplained findings. Refusal processes
returned 0, so readiness absence, the diagnostic and file hashes, not process
exit alone, establish refusal.

With the server stopped, the disposable record was replaced by its consistent
repaired fixture (same mission identity, canonical representation within bounds).
That world started, saved, stopped and restarted. The exact-16-MiB world started
and saved. A normal nonempty world started, saved, stopped and restarted.
All healthy starts reached Ready and stopped with exit 0 and no native-policy
log findings. Independent NBT comparison found all records, root fields,
schemas and epochs unchanged; clocks were checked separately for non-regression.
For these particular healthy fixtures even the compressed file hashes remained
identical. This is fixture evidence, not a promise that a running world's clock
or file bytes can never change.

canonical NBT construction despite removal of byte buffers. Later lifecycle
growth and unknown-key loss remain outside this check. Byte-fit acceptance is
not a new semantic round-trip guarantee: for example, an existing decoder's
accepted bare 128-character identifier can normalize to a longer qualified
identifier subject to the existing later decode policy. This task does not
change that policy or implement options B/C/E. The refusal lasts until offline
repair and blocks the whole world, with the recovery procedure stated above.
