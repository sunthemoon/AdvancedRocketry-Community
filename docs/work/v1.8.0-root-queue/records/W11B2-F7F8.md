## Implemented F7 writer core

`EscrowGovernedHandoff` owns a one-use retained proof bundle after its
request is queued. It requires exactly the recorded slots with their
expected frontiers and positions, the complete terminal survivor, the
checked record lease and an atomic native/passenger lifetime lease. It
repeats complete survivor and assigned-passenger observations on the
owner thread at capture. The writer rechecks only retained atomic tokens
and the journal lease immediately before replacement. No Minecraft object
is read by the IO-thread predicate.

The existing scoped, batched writer records HANDED_OFF or CANCELLED and
updates only an existing READY head. A stale acknowledgement cannot report
success to its callback. UNKNOWN retains the exact candidate, proofs and
capacity; a definite refusal releases the proof watches. The core neither
changes an entity nor removes a journal record, releases a pad/ticket or
prunes an entry. It has no production caller yet: the live observer and
successor-lock integration must be supplied before using it. This is a
partial task checkpoint, not completion of task step 1.

`EscrowGovernedHandoffTest` adds 11 A0 cases using actual checked ledger
and journal writers with explicit native-slot and passenger test tokens.
Both outcomes are covered with and without READY heads. It checks receipt
immutability, exact completion, terminal-only replay after two baseline
reloads, every retained slot token, native/passenger invalidation, a
journal mutation between capture and replacement, a stale callback,
incomplete/frontier-mismatched tokens and UNKNOWN retention. The test also
demonstrates that `logicalLocked` remains true after the successful F7
callback while the terminal entry is retained. These are not native
forced-stop, connected-passenger or live resource-release results.
