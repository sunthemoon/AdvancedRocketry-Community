## Launch kind and design decisions

`launch_kind: "baseline"` is an explicit session opt-in, with `cell` naming a
strict baseline manifest rather than a candidate cell. Only one disposable
offline singleplayer launch is allowed. The two admitted profiles are
`VANILLA_1_20_1` and `FORGE_47_4_10_EMPTY`; other versions, JEI baselines,
unknown fields/kinds and candidate manifests are refused. Existing sessions
without the field, and explicit `candidate` sessions, retain candidate checks.

Identity includes hard-pinned SHA-256 values for the Vanilla JSON/JAR and Forge
version JSON, the declared installer SHA-256, and the actual empty mods inventory
`[]` followed by LF and its hash. Forge also uses the existing official helper's
pinned installer SHA-1 and embedded-profile comparison. Its patched client,
client-extra and runtime-discovered Forge libraries are checked against the
installer; a server JAR cannot stand in for the patched client.

The template contains exactly empty `mods`, `config`, `defaultconfigs`,
`resourcepacks` and `saves` directories. Non-JARs, hidden files, subdirectories,
links/junctions, undeclared version files and account/launcher additions are
refused. Version/game directories stay inside the profile; libraries/assets may
reference the isolated campaign runtime read-only. Inputs are revalidated before
any disposable output or JVM creation. Run directories cannot overlap any input.

Every launch writes new vanilla-only world metadata, rather than copying a C6
world. It requests Quick Play into `saves/baseline`: seed 0, creative/peaceful,
plains superflat without structures, with bedrock/two dirt/grass layers, the
three vanilla dimensions and no initial chunks/entities. Daylight, weather and
mob spawning are disabled. This is the conservative empty-scene choice; native
world loading is still unverified. No save schema, packet, ADR, admission switch
or provenance policy changes.

The existing process ownership, PID/window/launch timestamp receipt, input
identity verification, READY lifecycle and cleanup are reused. Baseline receipts
add the manifest/version/mods and Forge runtime identities plus PID creation
identity and game directory. `candidate_sha256` is null, `jei` is false, and
`forge` is null or `47.4.10`, matching W491's adapter expectations. READY still
means that the window was found, not that the world or capture was qualified.
