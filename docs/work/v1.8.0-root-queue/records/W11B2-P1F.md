# W11b2 part 1 fixes

## Design before implementation

Date: 2026-10-14. Root is Claude; this is the assigned local implementer worktree.
The write scope is the five TASK findings, rocket/journal guards and continuations,
their regression tests, log expectations if needed, and this record. The shared
baseline was merged separately before these changes. No other agent is launched.

F1 compares scalar capacity, amount and committed debits whenever either fuel
state is legacy; native-to-native comparisons retain the complete resource
signature. A representation change is also a resource change. Legacy fuel cannot
receive escrow credits or markers: escrow endpoints require native propulsion,
so supporting scalar updates does not bypass a credited-resource guard.

F2 separates ledger protection from journal durability. Mount/movement events,
kill and live data replacement consult only escrow records, markers, tombstones
or a bound section; dismount events are never cancelled by this interlock.
Board and explicit leave wait only if this rocket's record/removal differs from
the last acknowledged journal snapshot, not for another rocket's generation.
A blocked journal still allows boarding/leaving but refuses launch and fuel
mutation. Refuelling waits for this rocket's own acknowledged authority and the
existing stationary/settled checks. Launch and cancellation still publish their
dependent effects only after an exact checked acknowledgement, including their
own replacement/removal. R1's whole-journal continuation and live-flight barriers
remain unchanged; F3's scheduling redesign is outside this task.

F5 forces the parent directory after replacement and after successful candidate
readback. F6 publishes UNKNOWN after an Error on the writer thread and retains
bounded retries. F7 gives journal continuations an explicit discard callback and
finishes pending player request entries on stop, identity replacement, authority
refusal or an exception; uncertain journal authority itself is not discarded.

No production admission, O2-O4 settlement, O-veto, ADR, risk register, status,
ledger, build script, workflow, asset or language change is planned. The optional
historical-world native crash cut is not included; decoded historical compounds
will exercise legacy gameplay in GameTests, not claim S2 migration acceptance.

### Files and design decisions

Fuel/entity changes are `RocketFuelState`, `RocketEntity` and the existing fuel
unit class. All other production signature callers were inspected: quotation
and checksumming already require native propulsion; vector debiting short-circuits
on legacy fuel; the escrow audit probe constructs native fuel explicitly.

Interlock changes are `RocketEscrowGate`, `RocketEscrowInterlocks`,
`RocketFlightService`, `RocketTransferService`, `RocketTransferSavedData` and
`RocketJournalCheckpoint`. The checkpoint's bounded, RAM-only record versions
contain checksum, phase and destination UUID. The checksum covers the remaining
immutable authority. This avoids server-thread NBT encoding/hashing just to
compare a stationary rocket with its acknowledged record during a disjoint write.
Own removals, phase changes and destination rebindings remain unproved until
acknowledged. UNKNOWN disk outcomes retain the existing conservative resource
fence; loss of disk proof is not treated as a normal disjoint write window.
The two-continuation capacity and whole-journal flight/effect barriers are retained.

Writer changes are `RocketJournalCheckpoint` and `RocketJournalWriter`.
The existing portable directory-force method remains a Windows no-op; ordering
and force-failure behavior are tested through a package-private injected callback.
No Linux-native directory durability or power-loss acceptance is claimed.

Request cleanup adds the package-private `RocketRequestCompletion` and modifies
the journal, flight and transfer services. Refused actions return false to the
continuation, which finishes the player request without removing journal
authority. Stop, abort, superseded generations, changed records and thrown
actions also invoke the discard callback. Error on the server-thread action
still propagates, but its request is finished in a finally block. The transfer
service is 793 lines; the pre-existing over-500-line flight service and entity
remain adapters/services, without introducing another responsibility or a new
over-800-line class.

Test additions are `RocketLegacyFuelGameTests` (four methods),
`RocketJournalInterlockGameTests` (three methods),
`RocketJournalContinuationTest` (three methods), and additions to the fuel,
checkpoint, writer and Python log-checker tests. Every legacy fixture is decoded
from a schema-1 entity compound with a schema-1 snapshot, without native
propulsion. The no-ledger test temporarily isolates and restores the cached
ledger reference within one synchronous test callback. Existing assertions,
timeouts, performance bounds, log counts and the W36 fixture are unchanged.
