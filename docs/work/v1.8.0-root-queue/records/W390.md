## Code reading and mode

`RocketGovernedSourceDispatcher.destination()` first calls arrival tick when the source
is absent and the record is COMMITTED, before F4/F5 inspect the restored pose. Both
calls occur if F4 returns PRESENT, F5 returns COMMITTED and the source remains absent;
the later call is in `RocketGovernedArrivalDispatcher.tick()`. A LANDED arrival can
also take both calls, but the measurement concerns DESCENT only.

For an unchanged, valid binding in the same owner tick, `binding()` repeats the boundary,
native-phase and authority checks, removes retired entries, verifies native identity,
reuses the observation-matching binding and marks it healthy. The clock, flight and
planned pose are unchanged on the second call. A cold first call may install the
binding/start descent; F4/F5 do not invalidate that successfully checked warm path.
There is no new hold, replacement, movement or different result attributable to the
second warm invocation. Serialization, invalid authority or changed native state is
not this warm case and can cause revalidation/refusal. READY_TO_LAND is the same result
the first call computed; consuming it in the dispatcher can initiate first-event
completion and separately checked `land()`. Removing the repeated computation must
not remove those actions or their final authority checks.

`--arrival-second-call-cost` selects the exact existing scenario-property value
`arrival-second-call-cost`, still requiring release-test hooks and GOVERNED_BENCH.
After selection, the gated probe uses the existing `start` lifecycle so the unchanged
first-event seam remains available. Cached mode flags keep native accounting and
attribution enabled. Normal `start` and `recover` do not select the mode or gain report
fields; Java and Python tests cover that default.

At END, the collector selects source-absent COMMITTED benchmark descents with a valid,
observation-matching binding. It times only the extra `arrivals.tick()` with nanoTime,
using the dispatcher's actual boundary and installed bays through a cached MethodHandle.
Observation, position, flight identity, frame, capture count, binding identity and empty
hold must remain unchanged. Known results are reconstructed from the binding's clock
visited in the same tick, not intercepted dispatcher returns. All 661 calls matched:
640 DESCENDING and 21 READY_TO_LAND. One cold observation among 662 eligible descent
visits was excluded; no state guard was weakened.

The original competing chest fixture lacks the schema-3 accounting baseline. Attribution
mode instead uses existing native loader admission and checked debit/credit fixtures,
retaining exact 1000/4000 conservation, ordinary C0-C8 retirement, operator O1-O4 and
product pruning. The default fixture and its existing incompatibility are unchanged.

## Removal design and remaining work

Keep the pre-F4/F5 pose-restoration call and retain its result as a local value for this
dispatch visit. Let the later arrival dispatcher consume that result for descent
feedback, READY_TO_LAND first-event completion, and LANDED terminal processing instead
of recomputing it. Reuse must be conditional on the same record, arrival, binding,
observation and tick; if F4/F5 invalidate those, reacquire/refuse rather than reuse stale
authority. Keep the independent final checks in `land()` and terminal handling. Cover
cold/restarted COMMITTED arrivals, warm descent, holds/invalidation, landing threshold,
deferred world-first acknowledgement and LANDED/F8 before changing the product path.

That implementation is not done or authorized by this cost task. Reflection observes
mod-private benchmark internals and can fail after an internal refactor; its MethodHandle
boundary trampoline is included in timing, with no overhead subtraction. The extra
end-tick call is an attribution proxy, not direct interception of the second call.
Different-engine read-only review remains for Root before integration. N6/F19b remains
open for the removal decision; this record does not satisfy all v1.8 Required Gates.
The next work is Root's review and a scoped current-version removal slice. F17 still
runs on the reference node with both calls present.
