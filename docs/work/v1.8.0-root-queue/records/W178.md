## Key design decisions

- Wait for the first claim's acknowledged result before attempting the replay. Snapshot the stored
  RAM result from terminal NBT, then observe that same result in menu data. This preserves the
  consumer's API/platform-only compilation boundary without importing host implementation types
  or hard-coding a new operation-code ordinal.
- Preserve the original claim tick (430), minimum replay delay (11 GameTest ticks), **460-tick
  timeout**, and every manufacturing, ownership, reward, replay and save/load assertion. Also check
  actual server-tick spacing and menu validity. Reuse `FixtureTickPacer` only while awaiting the
  acknowledgement, giving asynchronous IO normal 20 TPS tick duration within the unchanged budget.
- Register one sequence during setup instead of adding scheduled callbacks from other callbacks.
  No production behaviour, rate limit, timeout or log expectation was relaxed. No ADR choice was changed.
