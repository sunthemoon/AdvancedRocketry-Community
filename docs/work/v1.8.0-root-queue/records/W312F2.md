### The fix

`LogoutExitSafety.inspect` keeps every W312F rule: the shared SAFE case with no fall, the three-block geometric ceiling, the
column and landing proofs, and one paid read region. One rule is added at the point where a fall's landing is proved
SAFE:

- The first stable support is where the player lands, so the proof asks its loaded state once for the largest multiplier
  that can scale the landing (`Region.fallMultiplier(exact, drop)`).
- The fall is SAFE only if `drop x multiplier <= 3` (`DAMAGE_FREE_DISTANCE`, from `LivingEntity.calculateFallDamage`).
  Otherwise the verdict is UNSAFE; no deeper floor is tried, because the player stops on the first support.
- An empty, non-finite or negative multiplier refuses the fall as UNPROVED. A SAFE exit without a fall never asks.

Either refusal keeps the existing seated save, exactly as every other refusal does. The shared proof accepts a landing
only with the feet on the support's whole-block top (its body may not reach into the support), so the real fall is at
most `drop` blocks.

`RocketLogoutExitWorld.fallMultiplier` asks the installed controller, for the logging-out player, at the feet's block and
each of the `drop` blocks below it (at most four bounded lookups, no world read), and returns the largest value. That
covers the exit, every block the falling player's position can be in (each of which a tick could use), and the landing.
The controller's query uses the same layers as its tick, so gravity field controllers (with their owner and trust rules),
station gravity and the Level profile all count. If the controller is missing, or a layer cannot answer for that block,
the result is empty and no fall is accepted.

The bay exit selector, `BayExitSafety`, `BayPassengerExitWorld`, `BayExitBudget`, the gravity rules, fall damage and
seat release are unchanged; the diff touches none of them, apart from the controller refactor above, which moves the
tick's layer order into one helper without changing it. No saved field, packet or protocol changed.

## Choices where the TASK left room

1. **Which blocks count.** The TASK asks for the larger of the exit's and the landing cell's multipliers. The proof takes
   the largest over the exit's block, the landing's block and every block between them, which includes both; a tick
   during the fall can use any of them.
2. **The gravity switch.** `classicGravityEnabled` turns fall scaling off. The proof ignores it and assumes scaling,
   because the configuration can change before the player logs in again.
3. **Verdicts.** A damaging landing is UNSAFE and an unknown multiplier is UNPROVED; both keep the seated save.
4. **The border.** A scaled distance of exactly three blocks (for example 2 blocks at 1.5 g) is accepted, the same border
   as vanilla's own three-block rule at 1 g, which W312F already relies on.
5. **One rule source.** The controller answers the query itself, so the proof does not copy the layer order. A narrow
   holder exposes the controller, which the mod constructor installs once; it holds no world state.
6. **The 2 g test accepts either outcome**, as the TASK says. With the seat kept, it does not land from the seat (a
   seat-height login after an offline release is W312's existing exposure, not a fall this proof creates); instead it
   lands from the refused exit as a control, which must hurt, so the test cannot pass without a real 2 g field.
7. **A new test class.** `RocketLogoutSaveGameTests` already has 449 lines, so the gravity cases are in their own class
   and batch.

## Known risks

- When the proof refuses a fall, the existing seated save is kept. If an operator releases the seat while the player is
  offline, the player logs in at seat height, as before W312 (W312's "Other login paths still exposed").
- Gravity that changes while the player is offline (a field controller moved, retuned or switched off, a trust change,
  another catalog or station gravity) is not covered, just as an offline terrain change is not.
- A landing at exactly three scaled blocks relies on vanilla's float fall distance not exceeding the geometric fall, the
  same assumption as vanilla's three-block rule at 1 g.
- At low gravity the ceiling stays geometric, so a harmless four-block fall still keeps the seated save (as the TASK
  asks).
- The W312F shutdown limit is unchanged: riders beyond one tick's shared allowance keep the seated save.
