## Part A: design and changed files

- [EscrowRelaunchClassesTest](../../../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/resourceescrow/EscrowRelaunchClassesTest.java)
  retains all seven previous checks and adds four: actual-path inventory,
  a direct new dependency, a lambda-handle dependency, and removal of a listed
  dependency even when an unreachable method still mentions it.
- [RelaunchDependencyInventory](../../../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/resourceescrow/RelaunchDependencyInventory.java)
  reads class resources without defining or initializing them. Its roots are all
  overloads of `RocketTransferService.prepareLaunch`, `EscrowGovernedLaunch.prepare`,
  `EscrowFlightCheckpoint.begin` and the `EscrowFlightSource` constructors. It
  follows declared calls, field/type descriptors, arrays, constants, lambda
  handles, initializers, superclasses/interfaces and exception-verification
  references. It is bounded to 2,000 reached mod classes and 10,000 methods.
- [relaunch-existing-dependencies.txt](../../../../src/test/resources/relaunch-existing-dependencies.txt)
  records 282 existing structural dependencies outside W212's 55 measured loads.
  The actual walk reaches 337 classes, and must equal the disjoint union of this
  resource and the production preload list. Neither missing measured entries nor
  new/removed structural dependencies can silently pass. Diagnostics name the
  difference and require an initializer re-audit.

The walker stops at external method bodies and the explicitly declared module,
entity, registration and lifecycle boundaries. Journal validation is traversed,
but `RocketTransferSavedData.get` does not expand world loading. The lazy
`EscrowRuntime.store` factory and its lambda are traversed despite the runtime
lifecycle stop. Vanilla's `EntityPersistentStorage.storeEntities` callback is
followed only when `EscrowEntityStore.captureAndStore` is reached.

Static reachability is not the measured first-use load set. The 282 entries are
not new preloads or an initializer-safety approval; they include already used
types and conservative branch/type dependencies. Future changes require review,
not automatic regeneration. An early method-only discovery omitted the lazy
store factory and exception subtypes referenced by unexecuted methods; correcting
those inspection boundaries accounts for all 55 measured classes. This did not
show that the production list was wrong, so no name was added or removed and
no new production initializer needed approval. The original initializer audit
still runs unchanged.
