The authority is the C6 version of [GameTestObserver](../../../../scripts/ci_gametest/java/arce/ci/GameTestObserver.java),

`git diff c8fa16e16be87554f26c402546733df6555d15e6 HEAD --` over those paths is empty.

- `inventory` is the full sorted live registry, captured before the batch filter, including generated tests.
  `inventory.json` is the initial report: `complete=false`, `executed=[]`, and `failed=[]`.
- `executed` records terminal callbacks, not starts and not only passes. `onTestSuccess` adds an identity
  to `executed`; `onTestFailed` adds the identity to both `executed` and `failed`. An identity carries
  batch, name, structure, required flag, tick/setup limits, and attempt/success limits.
- `failed` contains the identities received by `onTestFailed`, including optional failures. A method
  is counted successful here only after its unique batch/name identity is found in `executed`, its
  full identity agrees with the inventory partition, and the completed report has no failed callback.
- `complete=true` is set by the reporter's `finish()`, which writes `result.json`. It does not alone
  mean success or full execution. The Python checker additionally requires schema 1, native exit 0,
  no failures, exact partition equality, matching raw-log batch/test counts, and unchanged log budgets.
  The union requires four different shards, identical inventories, the same bundle hash, exact disjoint
  union equality, and successful workflow dependencies; a count alone cannot establish membership.
- A whole batch goes to `int.from_bytes(SHA256(batch)[:4], "big") % 4`. Batch hooks and boundaries
  are retained. The workflow builds and seals one runtime bundle, downloads it into each fresh shard,
  restores its bytes without recompilation, and verifies the runtime again afterward.
- `bundle_sha256` hashes the bytes of `identity.json`, not a concatenation of JAR bytes and not the
  release JAR. That manifest pins the source commit and hashes for `main.jar`, `adapterTest.jar`,
  `ciGameTest.jar`, and `release.jar`.
