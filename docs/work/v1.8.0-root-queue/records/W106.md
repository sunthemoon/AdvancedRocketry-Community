## Design decisions and remaining work

The stable adapter ID is `advancedrocketrycommunity:pressurized_tank_v1`;
its exact host type is `advancedrocketrycommunity:pressurized_tank`.
The payload is exactly `{tank: <TankSave root>}`. Schema 1 and the existing
8,192-byte, depth-16, 1,024-node bounds are unchanged. Retained/repair tanks
refuse capture, unsupported schemas refuse restoration, and restoration uses
the existing BE load and recapture-equality check. No migration is introduced.
Capacity is never persisted: fresh selection checks capacity, whereas frozen
replay preserves a legal over-capacity balance without truncation.

Pure replay preserves identity, creation time, geometry, anchors, statistics,
propulsion and every other block, then validates bounds and codec round-trip.
Selection uses canonical order and prefers a compatible nonempty tank before
an empty tank when loading. The capture result contains bindings/digests, not
an after snapshot. The complete tag contains the ten sealed v0.5 values in
order followed by pressurized tank, with no `replace: true`. Trapped chest is
omitted; no new trapped-chest round-trip claim is made.

### Blocking preparation finding

`RocketStructureSnapshot` has a private constructor that synchronously runs
both content and structure hashing in `RocketSnapshotHasher`; decoding calls
that constructor again. A codec-valid, palette-shared 2,048-block fixture encodes
to 91,285 bytes but its two hash inputs alone total 18,002,243 bytes. A second
fixture with a tank and deterministic one-mB cargo mutation encodes to 91,502
bytes and has a two-hash lower bound of 17,993,677 bytes. Both exceed the fixed
16,777,216-byte tick budget before counting copies or codec work. These are
synthetic model/codec fixtures, not assembled native block fixtures.

An external cursor cannot split that private constructor. Accumulating credit
over multiple ticks and then doing the entire reconstruction would violate the
per-tick ceiling. The TASK names existing-class hooks in the adapter list,
runtime and escrow core, but not the snapshot model/hasher/codec. Scope
clarification was requested before modifying those files; no answer is recorded.
No budget, hash, codec or frozen design was changed.

Remaining C-P work is the genuine resumable constructor/codec work, shared
runtime accounting and transient lock, launch/disassembly/resource-mutation
refusals, permit-gated publication with revalidation, and tests of those hooks.
The pure eligibility function is not wired before allocation/queue/reservation
or repeated at final capture; item 3 is therefore only partially implemented.
Its device-envelope fixtures must be checked against C-A's eventual device
codec before wiring it. The budget counter's unit tests prove accounting only,
not bounded reconstruction. No production caller admits cargo.

C-A devices, C-E integration/fair queue, C-D presentation, C-S restart/transaction
evidence, items, fuel changes, schemas, receipts, proofs and leases remain
outside this task. No open ADR decision was changed or new waiver taken.
