## Findings and stopping decision

### W372-F1: activation changes existing permit/admission tests into holds/refusals

The full run contains failures that cannot be fixed by substituting a schema,
byte size, accepted capacity count or receipt status. Representative evidence:

| Existing test | Expected behavior | Actual result |
|---|---|---|
| `EscrowReconciliationActionTest.exactAcknowledgedNextLinkProducesOnlyItsFrozenDeltaAndCannotReplay`, line 17 | Issue the acknowledged next-link permit, then check its exact delta and replay refusal | `EscrowReconciliationView.Refusal: UNKNOWN_BASELINE`, from `EscrowAccountingReconciliation.requireApply`, line 39, through `EscrowReconciliationAction.issue`, line 57. The delta/replay assertions are not reached. |
| `EscrowCargoAdmissionTest.bothDirectionsUseTheExistingExactL1WriterAndRefuseQueuedCapturedAndDurableMixing`, line 31 | `Transfer.QUEUED` | `Transfer.INVALID`. The admitted writer lifecycle is not exercised. |
| `EscrowCargoAdmissionTest.cargoCannotQueueBehindFuelAndARefusalDoesNotIssueSequenceReservationOrWrite`, line 55 | `Transfer.OTHER_TRANSFER_PENDING` | `Transfer.UNKNOWN_BASELINE`. |
| `EscrowCargoAdmissionTest.sameCaptureAllowsOnlyItsOwnMarkerAndRefusesRetainedMarkersBeforeSideEffects`, line 77 | The checked capture passes preflight | `StaleCapture: Legacy fluid component has no accounting baseline`. |

Read-only inspection identifies an important fixture interaction, not a proved
native resource-loss defect. `EscrowReconciliationBindingBoundaryTest.sample`,
line 66, constructs its ledger with the default six-argument constructor.
`EscrowLedger`, lines 17 to 21, now selects schema 3 for that constructor, while
the sample's old operations have no accounting baseline. The new legacy-fluid
hold therefore prevents the historical permit test from reaching its original
assertions. The cargo admission test similarly supplies a legacy capture without
the new row. Changing its expected result to INVALID, or treating the successful
permit as an expected refusal, would discard the behavior those tests protect.
Explicit historical fixtures or fresh accounted captures require a separately
authorized correction, not an unrecorded format-value re-pin in this task.

Across the complete run, failure messages include 34 direct legacy-baseline
`StaleCapture` exceptions and 10 assertion-wrapped instances, six direct
`UNKNOWN_BASELINE` reconciliation refusals, 16 direct `ACCOUNTING_MISMATCH`
reconciliation refusals, and nine plain `QUEUED` versus `INVALID` assertions.
These counts describe observed messages, not distinct production defects or a
claim that every failure has the same cause. The complete 135-failure inventory
retains all test names, exception messages and stacks for Root's triage.

The run also exposes format-only and fixture-boundary failures, for example
`EscrowAccountingMigrationTest.supportedSchemasAndEpochsArePinnedIndependently`
(2 versus 3), the old disabled-activation assertions, the reservation delta
(2,087 versus 2,048), and historical root-2 migration tests whose default source
is now root 3. In particular, the passing method still named
`activationOffDoesNotMigrateOrCreateBackups` does **not** prove that root 2 is
migrated after activation: its implicit fixture now constructs root 3. None of
these tests was rewritten or claimed as new migration evidence.

Implementation stopped when the out-of-category failures were observed. The
already-running unfiltered suite was allowed to finish to preserve its complete
result. No failing test was changed, and no further execution campaign started.
