### Item 1: transient motion in governed proof observations (N1)

- `EscrowFlightSource.observe()` now delegates to a small static rule. Delta movement that is not exactly
  `Vec3.ZERO` (the executors' `EscrowGovernedFrame.transientMotion` rule) returns `false` and leaves the sticky
  `unchanged` flag set. Otherwise the observation compares every field as before, including the captured motion, and
  any mismatch still sets the flag for good. Departure invalidation (`unchanged.set(false)`) is unchanged.
- `EscrowGovernedHandoff.Proof.observe()` takes the live survivor first. Transient motion in it returns `false` and the
  proof stays active. Every other mismatch still ends the proof. The off-thread replacement lease `valid()` is
  unchanged, and the slot proofs still compare the saved `Motion`.
- The disk validators are unchanged: a save taken while the motion was set still refuses its proof
  (`EscrowFlightSourceTest.aSaveTakenWithTransientMotionStillRefusesTheDiskProof`).
- What a caller sees now: the return's proof callback releases its proof and proves again on the next visit, with no
  backoff. The terminal's F6 callback, F1, F4 and the pre-F2 cancellation refuse that attempt and retry on their
  existing schedules, but the capture is no longer poisoned. An impulse at F7's request or capture refuses that F7
  attempt, which the terminal retries with its existing backoff.

**The return does not recapture `state.source`, and why.** Every capture the return keeps is checked against the
record first: `request()` requires `sourceMatches`, the first capture of an already returned rocket requires
`returned(...)`, and the capture after the return is applied follows the transient check in the same call and is
checked by `returned(...)`. E's recorded motion is zero (an accepted F1 needs a live observation with zero motion that
equals its capture), so no capture the return keeps holds transient motion, and a transient impulse can no longer set
its sticky flag. What remains sticky in the return are persistent changes, which R17 item 5 keeps as holds. One
residual is not motion and predates continuation 46: the launch boundary is part of `observe()`, so a boundary refusal
at the exact moment of a return proof callback (for example an overlapping assembly transaction) still holds the
return with `RETURN_ENVELOPE` until a restart. The terminal recaptures in that case; the return does not. Recapturing
would also need a negative cache, or a persistent mismatch would cost a complete capture per visit. I left it for Root
(see Known risks).

Tests: three unit tests (`EscrowFlightSourceTest` 2, `EscrowGovernedFrameTest` 1), three in `EscrowGovernedHandoffTest`
(transient motion keeps the F7 proof for both outcomes and then completes; a persistent placement still ends it even

### Item 3: the three test gaps (N4)

- **Descent cost.** `warmDispatcherDescentVisitsMakeNoCompleteCaptureOrEnvelopeDigest` (new batch
  `escrow_governed_descent_cost`) runs a crewed flight through the installed dispatcher to a COMMITTED descent. It
  samples two counters before and after its own checks on each tick, so its own complete captures are never counted. It
  requires 20 warm visits, after three to settle, in which the arrival had no complete capture and the record's
  metadata computed no native envelope digest. A counted visit must follow the previous sample by exactly one tick and
  move the arrival down without reaching the landing height. A chunk save or load changes `governedObservation`, and
  the binding then revalidates once by design, so such a tick restarts the window instead of being counted. The fixture
  owns its two-block footprints like the departure fixtures.
- **Counters (narrow edits under R13 item 3).** `RocketEntity.governedCaptures()` counts complete native captures of
  that instance; `EscrowNativeEnvelope.rocket(...)` increments it. `EscrowTransferEnvelope.envelopeDigests()` counts
  the native envelope digests that metadata computed while validating records. Both are in memory, per object,
  diagnostics only, never persisted and never read as authority. The unit test
  `builtInDigestCounterMatchesAnInjectedCountingDigestForTheDispatcherGameTest` pins the built-in counter against the
  existing injected counting digest.
- **Manifest exactness.** `EscrowGovernedEnvelopeTest.oneChangedAssignmentWhileTheRidersStayValidComparesUnequal`
  replaces the one assignment that is not riding, keeps two valid riders aboard, and requires the normalization to
  accept both envelopes while their digests and comparisons differ. A different rider subset and order still compares
  equal.
- **Mounted logout.** `mountedLogoutDuringAscentAndLoginAfterLandingCompletesHandoffAndCleanup` (new batch
  `escrow_mounted_logout_complete`) calls `PlayerList.remove` while the passenger rides during ASCENT, so vanilla
  dismounts inside the removal. It requires the player gone, unseated, the rocket alive and loaded with no passengers,
  and then the existing login-after-landing path through checked F7 and F8. The same unseated assertion was added to
  the existing logout variant.
