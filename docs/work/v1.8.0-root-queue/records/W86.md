### Choices made where the review or Root's decisions left something open

- **The bound of 128.** The review's argument ("an absent rocket with a queued continuation was in A") does not hold
  once A advances while the continuation waits for the budget or a failed write. Revision 2 argues from queue order
  instead, and names F2's refused queue call as the one way around it.
- **G12.** The review grouped G12 with G8 as changing path. At `a8d81d24` the writer retries the removal's own snapshot
  (`RocketJournalWriter:107-111`), so G12 already reaches M3 through M2's late branch. Only G8's path changes.
- **The visit during a failed write** moves past acknowledged continuations that wait, instead of stopping at them, so
  that an opt-in continuation (W85's M2) can run.
- **The whole-root API.** `retryChecked` returns `clean()`, and `acknowledgedGuard`, `acknowledgedLease` and
  `actionAuthorityAvailable` are granted only on a clean root. `acknowledgedCurrent()` keeps its meaning for the
  GameTest fixtures. The three release-test hooks move to `clean()`.
- **Reservation placement.** `prepareLaunch` reserves on its legacy branch only, after pad selection, and releases the
  pad on a refusal. The governed branch reserves nothing, because F1 needs a clean root. Each site checks before it
  reserves, and a site that must recheck afterwards passes its token.
- **`canQueueEffect()`** without an argument is removed. Its test line changes as appendix C says.
- **Pruning.** Slot entries keep the transfer IDs that a change removed, until the change is acknowledged and the rocket
  is actionable. The fences and bays prune by that.
- **The Moon-landing WAIT** does not call the FP7A seam `moonDeferred`, because today's tick never reaches that state.
- **A failed recheck in the spawn continuation** leaves the record to recovery instead of failing back, following
  decision 6. Recovery's KEEP_SOURCE reaches the fail-back's end state.
- **N2's first-commit precheck** mirrors what `afterAcknowledged` refuses today, so a failed write does not refuse it.
