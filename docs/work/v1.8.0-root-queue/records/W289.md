# W289: Rocket UI text, placement, and transfer-stable monitor binding

## Binding design note

The initial design was recorded before binding implementation; the native verification follow-up is identified below.

The existing schema-1 monitor binding already stores the assembly/logical rocket UUID, alongside a physical UUID,
Level, locator, and optional station hint. Its saved representation will not change, so old bindings need no NBT
migration. Resolution will use the existing bounded transfer journal's logical-ID lookup for its source or committed
replacement. The replacement must match the journal's physical UUID, logical UUID, owner, Level, origin, and station.
Only the monitor's Level is eligible; no world/entity search,
chunk loading, remote control, or nearest-rocket fallback is introduced. Docked launch checks remain mandatory.
The old persisted binding remains unchanged; a powered reload cannot manufacture a new redstone edge.

Native verification follow-up: F8 intentionally removes completed journal entries. Anchored
flights retain a logical-to-physical authority head in the existing escrow ledger. Both tables have a hard limit of
64 entries. The first native regression exposed that unanchored native flights retain neither entry. They need an
additional transient loaded-identity hint, owned by the server Level and rebuilt from entity join/leave events.
`LoadedRocketIdentities` stores at most 1,024 physical IDs per Level, rejects ambiguous logical IDs, and disables
fallback after overflow until the Level index is cleared. It does not serialize, refuse saves, remove entities, or
change escrow state. Every hint still requires exact loaded UUID, logical identity, owner, Level, locator, and docking
checks. No entity/world scan is added. Native tests cover post-F8 lookup and recreation/duplicate/owner boundaries.

## Unfinished scope and risks

- This headless worker used the server/JUnit setup only. No client run or before-and-after screenshots were produced;
  rendered font/resource-pack behavior and V1 visual confirmation remain unverified. No standalone manual server
  restart was performed; automated tests reload saved schema-1 monitor data and exercise real cold entity reloads.
- The loaded identity hint is deliberately unavailable after more than 1,024 simultaneously indexed physical rockets
  overflow a Level index, until that Level is reloaded. Journal/head lookup still works. No player/world data is
  rejected, deleted, or modified by this limit.
- The existing monitor catalog sends untyped strings. A station deliberately named exactly like a translated body ID
  will display that body name. Unknown IDs and ordinary station names remain literal. This task does not change the
  packet format to distinguish such names.
- This slice does not establish all v1.8 Required Gates, and no version/Gate/status/ledger decision is changed.
  Root still reviews the commits, pushes for hosted sharded regression, and arranges client comparison and acceptance.
  Those W289/v1.8 checks are the next suggested work; no later-version feature is included.
