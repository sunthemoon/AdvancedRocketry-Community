## Implementation

Local commits are `71925bac2` (terminal-cut lifecycle), `212a953ad` (relogin
ordering), and `3cf115abe` (deterministic B1 supersession). Verification uses
`3cf115abec5ae12788f56951f1364ef70e0ceaf8`; nothing has been pushed or merged.

The relogin fixture reconnects after landing, then used to wait for the
dispatcher to remount the player before deliberately dismounting again. That
dispatcher visit also starts F6. The fixture therefore invalidated its own
pending terminal capture and incurred the existing 100-tick retry delay.
The new pre-dismount assertion fails against that ordering. The fixture now
runs the installed F5 executor with the dispatcher's complete native/bay
boundary and performs its deliberate dismount in the same owner-thread
callback, before F6 can start. The ordinary dispatcher still performs the
following remount and all F6/F7/F8 work. Existing mount-refusal, conservation,
handoff, refuel, pad and ticket assertions remain; no timeout changes.

`EscrowGameTestTerminalCut` registers a completion listener on its owning
`GameTestInfo`. Success, assertion failure and timeout close the hook and
resume any paused lease writer. All GameTest terminal-hook installations
and `EscrowTerminalLeaseCut` callers use it. Uninstallation has an individual
ownership token, so delayed cleanup cannot remove a later installation even
when the same callback object is reused. Three new GameTests exercise failed
and timed-out nested test lifecycles, exactly-once resume, the next fixture's
exclusive installation, and stale-owner cleanup. Nested failures are the
tested conditions, not skipped or suppressed registered tests.

[W80 design](W80-DESIGN.md) permits a retained rider to leave during B1:
its N2 proof does not require frozen-manifest equality. The existing
`RocketReleaseProofTest.b0RequiresTheLiveManifestAndB1AllowsOtherPassengersToLeaveWithoutRestoringThem`
already enforces that distinction. W80 separately requires superseding
native saves to invalidate B1 and be retried. The boarding fixture now waits
for the actual B1 capture, checks that departure alone did not advance the
native generation, and explicitly stores the entity chunk to supersede that
generation. It asserts `CAPTURE_FAILED` before S2 and retains all boarding,
reload and old-copy checks. The manifest declares exactly one WARN for this
controlled save in `rocket_release_boarding`; the checker is unchanged.
No production manifest predicate or retry budget was changed.

The only runtime-class change is the gated `EscrowRuntime.terminalCutForTests`
endpoint: it returns an owner-bound uninstaller and tracks installation
identity. All other Java changes are GameTests or test support. Root should
include that runtime diff in the independent pre-merge review. No saved-data,
journal, sidecar, rejoin-native/readback or sealed implementation changed.
