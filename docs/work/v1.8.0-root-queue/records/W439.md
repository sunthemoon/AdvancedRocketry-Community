## Prepared files and decisions

- `dedicated.json` changes only W430's `run_dir` to the fresh `p9-rerun/dedicated/`. The same input cell,
  7200-second limit, one offline ArceTester1, 1280 by 720, GUI scale 3, English and loopback port 25573 remain.
- `sound-probe.json` and `sound-probe-detached.json` are identical except for their fresh run directories.
  They use single-player launch mode, a 300-second limit, and no world navigation. Their submitter waits for
  READY, sleeps 45 seconds, requests status and a title-screen F2 capture, then stops.
- `tools/submit.py` reads the 14 sealed core requests in K16 batch-index order, verifies their hashes and
  copies their original bytes through the temporary-file/rename protocol. It waits for READY, then the
  dedicated join receipt, and waits at most 300 seconds per core request. K16's usage notes specify no other
  per-request limit, so the task's 300-second default applies. Every receipt/error has timestamps and elapsed
  time. Failed/timed-out requests do not prevent subsequent submissions. It never retries or alters a sealed
  request, and finally drops a stop request that sorts after pending core requests. Startup/plan errors also
  attempt stop if a request directory exists. Late receipts and requests not actually dropped are recorded.
- `tools/run_round.py` is Python only. It checks the 23:30-08:00 window before launch and after lock waits,
  reserves ten minutes beyond the session limit, and therefore refuses a dedicated start after 05:50.
  It waits up to seven hours without breaking a lock, waits beyond three hours for a live owner pid, and stops
  for an older lock with a missing/dead owner. The tracked harness alone acquires/releases the lock. Both
  child exit codes are retained. Its watchdog uses the tracked Windows job implementation to terminate and
  verify the whole owned tree, rather than killing only a parent; a forced stop retains any harness lock and
  copies for Root. These Windows live paths were tested with fakes, not exercised on Minecraft.
- `tools/common.py`, `tools/preflight.py` and `tools/test_tools.py` provide shared helpers, source verification
  and portable offline tests. `RUNBOOK.md` gives the exact interactive-probe, WMI-detached-probe, then
  WMI-detached-dedicated commands. WMI creates Python directly, never PowerShell. The command resolves
  `sys.executable` rather than passing this PC's WindowsApps alias to WMI; the resolved interpreter is
  `D:/python/pyenv/pyenv-win/versions/3.13.15/python.exe`.
- `request-plan.json`, `session-comparison.json`, `source-identities.json`, `preflight.json`, check/test logs
  and `artifact-hashes.json` preserve the preparation checks. This is an ordinary unsealed working directory,
  not a new sealed evidence packet. It contains about 145 KB before the repository validator log; no world,
  server, runtime or source tree was duplicated.
