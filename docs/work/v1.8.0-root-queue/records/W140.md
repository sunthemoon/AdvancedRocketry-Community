There is no W129a merge, push, tag or change to a gameplay/recovery assertion or timeout.

The dedicated-server scanner has one opt-in expectation for the exact build
`1.20.1-1.8.0-dev`: server-thread WARN, exact full or Forge-console logger name,
`ARCE_FIRST_EVENT_HELD kind=first_moon_landing reason=SOURCE_UNCONFIRMED`, at most
once per process. Its source is `6edef9dab0d3f0333f739bcfee93a21e1c5451a9`, whose
first-event delivery can precede confirmation of the transfer journal baseline.

all ERROR/FATAL entries and client-linkage failures still block. Raw audit counts still
include the expected warning. No unspecified, historical or future build gets this allowance.

The transaction operator pattern accepts `default_root_schema=2` with the current
numeric station and satellite schema fields. Commit
`37e4be6296093b9ab41020e3e8f4be5439146676` introduced the rename and station split;
the current format also has the satellite field. The historical `root_schema=2`
form remains supported. No other default schema matches.

Both inherited transaction audit paths needed the build argument: the v0.6 flight
clean-stop method and the v0.9 forced-process recorder. Their default strictness remains.
