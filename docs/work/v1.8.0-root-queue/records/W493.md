## Design choices and limits

- P01 uses W487's recommended assembler rotation 0 and offset (2, 0, 0). Its
  independent position oracle now checks the new placement, not the obsolete
  legacy placement. Per-vertex, UV, index, mesh-count, orientation, bounds and
  pattern-hash checks remain; no assertion or tolerance was relaxed.
- The other five hulls cannot match the modern pattern dimensions by translation
  alone. A clarification about scale was requested, but no answer arrived. Under
  WORKER-RULES, the conservative choice keeps scale, orientation and idle parts,
  centres X/Z and aligns the minimum Y with the pattern base. Their render boxes
  contain the resulting mesh and unchanged pattern. Full-scale overhang remains
  a Root/V1 appearance decision, not an accepted result here.
- P02 follows the recommended shared render type, rather than per-model geometric
  nudges. It does not establish whether separate surfaces within a mesh also fight.
- P03 follows the recommended leaf-name convention: `test_` yields `[TEST]`, and
  another untranslated body yields `[PACK]`. Existing translated names win. This
  is presentation only, not trusted metadata or a new body-definition field.
- P06 keeps the one-row status: adding nine pixels would make the 234-pixel panel
  243 pixels high in the 240-pixel window and move controls/inventory. W487
  explicitly permits retaining the full hover/banner text in this case. "No
  selection" was chosen instead of the longer example to fit 82 pixels.
- P11 uses "No bound deliveries" rather than the longer example so that the
  complete English empty-state text fits 118 pixels. Chinese remains in step.
- No save schema, network format, permissions, service logic or ADR changes were
  needed. The elevator view uses its existing key-or-text representation.
