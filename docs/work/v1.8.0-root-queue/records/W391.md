## Implementation choices

The loader accepts registered water in its stored `LoaderTank` envelope. `LF_S6_AC_SUBSTITUTE` therefore
replaces 4,000 mB of rocket fuel with 4,000 mB of `minecraft:water` before preview. As in W373C, the probe
replaces the whole stored block entity with the same owner, device identity, binding and escrow section;
it does not bypass the live protected loader setter.

`LF_S6_AC_BANK_LOSS` and `LF_S6_AC_BANK_GAIN` edit a detached rocket save envelope, decode a fresh rocket,
remove the old instance as unloaded and publish the fresh instance with the same physical UUID. The probe
checks the entire decoded `RocketEntityData` against the edited envelope before publication. Only the primary
amount and its codec-required scalar projection change; identities, escrow epoch, markers, bank revision,
other bank and other payload remain unchanged. The edited stores are saved before preview. No offline runner
edit or production API change is needed.

After pruning both markers in memory, `LF_S6_AC_PRUNE_SPLIT_TANK` calls the existing gated
`EscrowReleaseProbe.newerSave` and joins only the chunk worker. `LF_S6_AC_PRUNE_SPLIT_BANK` calls
`newerEntitySave` and flushes only entity storage. Neither performs a full save at its cut. These are real
one-sided disk saves, not stops between two unsaved in-memory removals. Earlier cases retain their boundaries.

The startup watcher records pre-start artifact names. It requires this attempt's backup containing the ledger,
root 3 at the target, and no new staged file, before killing. The kept snapshot is checked again for the complete
migrated content, byte-equal legacy operation, unchanged endpoints and this attempt's byte-equal root-2 backup.
The captured log still decides completion, including lines captured during the kill. A completed start remains
`NOT_COVERED`; a root-2 snapshot cannot satisfy the new case.
