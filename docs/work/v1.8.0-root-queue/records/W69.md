## Design and scope

The write scope is `scripts/v170_world_fixture.py`, `scripts/run_v180_world_upgrade.py`,
`tests/test_run_v180_world_upgrade.py`, and this record. Production code, build scripts,
status, ledger, workflows, assets and ADRs are not changed.

The historical source is `55da6a58842762c382edce0a5a842d06bb76ff6e`, which introduces
the [v1.7 development handoff](../../../releases/v1.7.0/RELEASE-EVIDENCE.md) and is the
accepted v1.8 development baseline. It is a development build, not an approved release.
The harness builds an unmodified Git export of that commit, records the archive and JAR
hashes, and builds the candidate from a clean committed worktree.

The fixture obtains registered block, item and block-entity identities from Forge's
runtime registry dump. It places the blocks on supported, separated cells and stores
one of every item in indexed chests. Existing release-test commands create representative
station, satellite/research and endgame state. A discovery claim writes the celestial
root and a completed rocket flight writes both rocket journals; the operator report
checks runtime availability. The saved native inventory, not the placement command, is the
comparison authority. Escrow is included if the historical host writes it.

The candidate runs only on a byte-verified world copy. Each of three starts must preserve
all indexed IDs and counts, and managed data except explicitly checked schema migrations
and monotonic runtime clocks. Every command and process result is retained. Unexpected
refusal, ERROR, loss or mutation stops the run without a production fix. A documented
refusal is not reported as successful migration. Original world bytes are rechecked.

Temporary exports, JARs and servers are isolated in a newly owned W69 directory, with
bounded commands, free-space checks and the machine-wide heavy-JVM lock. Evidence retains
logs, decoded inventories, compact native captures and hashes, not reproducible source
trees or worlds. Cleanup only removes this task's temporary directory.
