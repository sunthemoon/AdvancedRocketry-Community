## Session and design decisions

The regular world-root marker has exactly 32 ASCII bytes,
`ARCE_BAY_V2_DISPOSABLE_WORLD_V1\n`, SHA-256
`e67124e2a697a32ccdafc384e672362f81c732e5e01872012a2e22c6e4590f98`.
It is created only in the opened disposable copy and retained in the stopped kit
source. The parent world and ordinary runtime cells never receive it.

`marked`, `intent`, `fuel` and `nohook` session templates follow W399's schema.
Their placeholders intentionally fail validation until bound. `bind` takes an
owner-provided JSON list containing exactly `name`, `uuid`, `pid` and `game_dir`
for each of A and B; it reads no credentials or launcher profiles. It creates a
new private server template, cell projection and valid attach-only session, never
edits an existing cell, and refuses overlap with protected input directories.

The marked mode selects `releaseTestHooks=true` and the two distinct full UUIDs.
Fuel adds only `escrowLoaderAdmission=true`. Intent instead adds the existing
`bayCheckpoint=B18_INTENT` pause from W254's runner. Every property is a test seam,
not production enablement, and has no admission effect without the full release-test
gate. The no-hook control keeps the same marked world but has **no JVM properties**.
Sessions require online mode, enforced whitelist, exactly two declared accounts,
RCON off, loopback and no player operator privileges. The operator seat command
can be issued by the server console; B never opens A's private loader menu.

Native qualification uses two reserved synthetic UUIDs ending `453001` and
`453002` solely to validate startup selection. No account is authenticated and
no client is connected. Startup selection does not prove the connected-player gate.
Actual accounts remain owner input O5; no dummy identity is represented as A or B.

The cap probe names only C6's fixed fixture owner
`00000000-0000-4000-8000-000000128d01`. The typed `w358 owner-fill 16`, settled
pending count and `w358 writer status` can check that owner's union. A parked
fixture launch is not a cap oracle: its reduced fuel can refuse before deployment.
There is no arbitrary-owner cap command, so this recipe cannot prove A's live-menu
cap or another owner's admission. All such unqualified uses remain NOT_COVERED.
