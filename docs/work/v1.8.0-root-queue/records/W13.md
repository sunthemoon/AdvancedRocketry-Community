# W13: named station landing pads

## Implementation boundary and persistence design

This session writes only landing-pad code, its flight/menu/network/transfer
integration, registry and DataGen additions, associated tests, the original-source
declaration and this record. It does not push, merge, start agents, alter the
station's allocated cell geometry, implement station controls/loaders/beacons, or
edit status files, the content ledger or build configuration.

The Overworld-owned pad index has independent schema 1, a 2 MiB native-NBT
budget, at most 4,096 station buckets and eight entries per station. Registration
stores a server-generated pad UUID, physical BE UUID, monotonic epoch, station
owner, bounded name and station-local position. Optional flight references carry
only UUID and observed epoch; the station target supplies their station binding.
Flight-plan schemas 5 and 6 extend the existing abstract and typed-resource plans
without rewriting old plans or their checksums. The journal's embedded plans bind
the reference to the immutable transfer authority and checksum.

Named-pad staging inspects a loaded full rectangular footprint and clearance,
including support, within the existing 16-chunk/2,048-inspection limits. It does
not load chunks or add tickets. A claim belongs to exactly one transfer UUID;
commit, cancellation and successful recovery release it. Existing journal region
reservations continue protecting descents after claim release. Stale orphan
claims are reconciled against the journal before admission. The default cell pad
continues using the existing selection implementation.

Local interaction registers a pad with the held item's custom name (or a default
name); crouching unregisters it. `/arcepad register <name>` and `remove` operate
within eight blocks. `list <station UUID>` produces at most eight clickable
entries. `select <station UUID> <pad UUID> <epoch>` stores a bounded, transient
per-player choice; the next flight console imports that choice. Only its ordinary
C2S launch request can launch the rocket, with player/menu/distance/state/VISIT
admission rechecked. The command does not launch or accept coordinates.
Unknown index/BE roots remain unmodified and unavailable rather than being
normalized. Existing data is never deleted as a recovery mechanism.

## Choices where the ADR left implementation detail open

Names use the existing Java UTF-16 length convention, with 1..32 printable units
and no leading/trailing whitespace. Station buckets additionally cap at 4,096,
but the 2 MiB serialized-root bound remains authoritative. Registration budgets
space for every entry to have a claim before publishing the new entry. Local
mutation is limited to one interaction per actor per ten ticks, with 128 tracked
actors; console choices cap at 128 players and clear on logout/successful launch.

Support is required under every column of the complete bounding rectangle, and
the whole rectangle's height must be clear, not just captured rocket blocks.
This intentionally rejects sparse structures whose full inspection would exceed
2,048 blocks. A specifically named pad is one candidate, without increasing the
existing maximum of eight. Failure reasons are translated and never widen a
budget. Torn index/BE saves are unavailable; local management authority can
clear an obsolete binding or remove the obsolete entry before registering anew.

## Remaining verification and risks

The recovery matrix writes native index/journal files, round-trips the physical
BE and replaces all three Java lifecycle owners before each of 20 recoveries.
It is restart-equivalent serialization coverage, not a stopped/restarted server
or forced-stop S1/S2 result. Real process restart/forced-stop, malformed-root
native writer protection and operator recovery acceptance remain required.
R-023 records the independent-index write refusal and whole-terrain-chunk denial
impact, including existing Level-lifetime saturation and repeated save logs.

Real-client V1/V2, independent review, merged full-build/CI and all other v1.8.0
Required Gates are not claimed. Station controls, loaders, linker, monitor and
beacon are not implemented here. No push, merge, tag, agent launch or version/Gate
pass occurred. Root should review/integrate this v1.8.0 slice and arrange native
restart and real-client evidence before acceptance.

For the real-client check, craft/place pads inside a station as its owner; use a
custom-named held item or `/arcepad register <name>`. Verify an operator can
register/remove and a non-operator member cannot. Run `/arcepad list <station
UUID>`, select a displayed entry, then open the nearby fueled rocket's console
and launch. Observe landing on the chosen pad, translated obstruction/support
refusals, cancellation and a later untargeted default-cell flight. Repeat after
unregistering/replacing the selected pad to check stale intent refusal.

Native follow-up must use a backed-up disposable world: save and stop at transfer
cuts, restart the server and verify the unique authoritative rocket, journal,
claim release and fuel resources. Repeat selected cuts with a forced stop.
Malformed index/BE writer checks and two-restart recovery should follow the
ADR-065 implementation note on a separate copy, not by resetting journals.
