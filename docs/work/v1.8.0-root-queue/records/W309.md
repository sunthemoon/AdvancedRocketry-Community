## Implementation and files

- `StationManager.java` now uses `WarpTargetRule.offered` for station creation. The shared
  Space body is refused with the existing `UNKNOWN_ORBIT_BODY` creation code, just like a
  non-orbitable body. `WarpTargetRule.java` documents the shared use. The catalog definition,
  existing stations and the evacuation warp are unchanged.
- `StationWarpService.java` replaces `routesInSystem` with `routesForOrbit`. It captures the
  current planetary catalog and looks for an exact `RouteAnchor.orbit(targetBody)` at either
  endpoint. A surface endpoint or another body's orbit in the same system does not count.
  Either endpoint of a one-way route counts, as required; this is not a promise that every
  particular flight is legal or that both directions exist. Reloads are read on each query,
  without a new cache. `AdvancedRocketryCommunity.java` wires the new predicate.
- `WarpQuote.java` keeps its final field a boolean in the same position, renamed to
  `targetOrbitHasRoutes`. It remains server-only. `StationWarpCommands.java` warns:
  "The target orbit has no rocket routes; rockets cannot reach or leave the station in that orbit."
  No saved field, packet, protocol, menu data, route, cost or warp admission rule changed.
- Tests are in `StationOrbitAdmissionGameTests.java`, `StationWarpGameTests.java` and
  `WarpOrbitRoutesTest.java`. No data generation, imported asset or provenance entry changed.

### Warp controller screen

The same conditional warning cannot be derived reliably from the data this client has.
`StationControllerMenu.OpenData` carries the controller position and body IDs, not routes.
`WarpControllerMenu.viewValues` and `ClassicControlKind.WARP_CONTROLLER` carry exactly seven
values: selection, current orbit, balance, pending credit, cost, cost class and countdown.
The `WarpQuote` route flag is not among them. `CelestialSnapshot.Entry`, held by
`CelestialClientCache`, carries body metadata and capabilities, not the server's route graph.
An orbitable or landable body does not imply an orbit route, and hardcoding packaged routes
would misrepresent a server data pack. The screen is therefore unchanged.

Showing it accurately would need a server-derived route-availability flag associated with the
displayed quote, with a menu/view layout and protocol change (or a bounded, reload-aware route
summary sent to the client). Those changes are outside this task's permission.

### Tau Ceti e intent

[ADR-043](../../../decisions/ADR-043-STAR-SYSTEMS-AS-ROOT-TREES.md), "Example content", explicitly
makes Tau Ceti e orbit-only and discloses that a docked rocket there cannot fly anywhere.
[ADR-063](../../../decisions/ADR-063-MATERIALS-ORES-AND-PLANETARY-SURFACES.md), "Access path", adds
only `tau_ceti_f_surface_orbit`, `tau_ceti_g_surface_orbit` and `tau_ceti_f_g`, and explicitly
says that Tau Ceti e keeps no route. The three v1.8 route JSON files implement that decision;
none touches Tau Ceti e's orbit. No intended route is missing from this implementation.

### Draft ADR-044 implementation note for Root

> **W309: warn for the target orbit, not its star system (2026-11-06).** Section 4's route
> disclosure is evaluated for the exact `orbit(targetBody)` anchor that section 5's rocket
> planner resolves a station source or destination to. The warning is shown when no current
> rocket route starts or ends at that anchor. Surface routes and routes to another body in
> the same system do not suppress it. Either endpoint counts, including a one-way route;
> this is not a full flight-feasibility check. In particular, Tau Ceti f and g's routes do
> not suppress the warning for Tau Ceti e, which intentionally has none (ADR-043, ADR-063).
> The command says that rockets cannot reach or leave the station in that orbit. A routeless
> orbit remains a valid warp target; admission, costs and relocation are unchanged. The
> server-only quote boolean is renamed in place to `targetOrbitHasRoutes`; no saved or wire
> format changes. The controller cannot display this conditional warning with its existing
> data, so it remains unchanged rather than inferring routes from body capabilities.

The ADR itself was not edited. The conservative choice was to preserve existing orbit-only
targets and warn, not to reject all routeless bodies or add travel routes.
