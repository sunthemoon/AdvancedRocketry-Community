### R92 action table and view layout

The existing three messages/discriminators/directions remain unchanged.
`ClassicControlKind.ROCKET_MONITOR` is byte 4; protocol is exactly `"2"`.
Kinds 0-3 retain their bytes. Unknown-kind samples now use 5. Every existing assertion
was retained, with additional old-frame golden coverage and exact-version refusals.

| Action byte | Meaning | Value / token |
|---|---|---|
| 0 / 1 | Previous / next destination in the menu's frozen opening catalog. | Both zero. |
| 2 | Select catalog entry. | Index 0-159 / zero. |
| 3 | Obtain a fresh server quote. | Both zero. |
| 4 / 5 | Arm the selected destination / disarm. | Both zero; arming requires a current valid displayed quote. |
| 6 | Launch the displayed quote. | Zero / positive displayed quote token. |
| 7 | Toggle height/fuel comparator mode. | Both zero; display mode does not require sufficient launch fuel. |

The view's 21 ints are:
- 0-3: monitor status 0-8, existing flight-state wire ID -1..8, relative milliblocks
  -4,096,000..4,096,000, vertical milliblocks/tick -64,000..64,000.
- 4-9: selected index -1..159, count 0..160, mode 0/1, armed 0/1, existing flight
  request-code index -1..27, bank count 0..2.
- 10-14 and 15-19: role (-1 absent, 0 abstract, 1 mono, 2 bipropellant fuel,
  3 oxidizer, 4 working fluid), amount, capacity, required debit (each 0..2,048,000),
  session Fluid registry number (-1 absent, otherwise nonnegative).
- 20: actual primary required debit 0..2,048,000, using the native plan's vector
  rather than its abstract route units when applicable.

Existing optional `StationManagementCode` supplies control-admission feedback.
Intent/view bounds stay **512 bytes / 8 KiB**. Intents identify the container only,
not positions, target IDs or costs. Forge menu opening carries at most 160 labels,
each UTF length <=128, within 32 KiB. Tokens are menu-local, invalidated by changed
quotes, consumed before launch and never used as request UUIDs.

### Persistence and conservative behavior

The new schema-1 `arce_rocket_monitor` root is metadata only, bounded to
4 KiB/depth 12/128 nodes: owner/device UUIDs, existing optional `LoaderBinding`,
mode, powered latch, armed flag, destination and authority/catalog fingerprint.
No existing item/loader/flight/escrow format changes. Unsupported data stays raw
and inert, without save refusal. Operator-only NBT prevents identity injection;
drops carry no identity/arming. Binding changes clear mode and arming.

A clicked owner/operator-managed registered pad is an alias for its exact
journal-identified docked rocket. Empty/stale/ambiguous pads refuse; there is no
nearest-entity search or automatic future-occupant binding. Pads without retained
journal identity, including a retired governed transfer, require direct rocket
linking. No new persistent pad binding is introduced.

Telemetry follows only the loaded exact physical/logical rocket in the same Level,
including ascent; binding/launch additionally require a stationary rocket within
6 blocks. Unloaded endpoints neither load chunks nor forget arming/latch; transferred
or stale identities are not searched for. Authority, station access/orbit,
catalog content and binding changes invalidate configuration.

Redstone publishes its persisted latch before submitting one fresh server-generated
request per rising edge. A held signal/reload does not retry. Automatic launch uses
the persisted owner with operator=false, the shared request ledger/rate limiter,
planner, passenger/landing checks and ordinary/governed preparation, including async
authority revalidation. Rate admission precedes edge planning. Async outcome display
reads the existing request ledger; it adds no saved state or authority. Fuel/cargo
admission remains unchanged.
