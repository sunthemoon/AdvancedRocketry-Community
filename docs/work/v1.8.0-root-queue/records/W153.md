## R92 implementation plan and layouts (before code)

The 2026-10-24 resume instruction and ADR-065's R92 note supersede the initial stop,
its blocked slice statuses and its protocol-decision handoff below. Implement W153-A
through W153-D locally; do not push or merge into the shared branch. Protocol 2 keeps
the three existing messages/directions and kinds 0-3 byte-identical. Kind 4 is
`ROCKET_MONITOR`; unknown-kind fixtures use 5 without removing assertions.

| Action byte | Meaning | Value/token |
|---|---|---|
| 0 / 1 | Previous / next destination in this menu's bounded opening catalog. | Both zero. |
| 2 | Select destination by opening-catalog index. | Value 0-159; token zero. |
| 3 | Request a fresh server quote for the selection. | Both zero. |
| 4 / 5 | Arm the selected destination / disarm redstone launch. | Both zero; arming requires a current valid displayed quote. |
| 6 | Launch the displayed quote. | Value zero; positive displayed quote token. |
| 7 | Toggle height/fuel comparator mode. | Both zero. |

The view has 21 ints, in order: monitor status (0-8), flight state (-1 or existing
wire ID 0-8), relative height in milliblocks (-4,096,000..4,096,000), vertical velocity
in milliblocks/tick (-64,000..64,000), selected index (-1..159), catalog count (0..160),
comparator mode (0 height, 1 fuel), armed flag (0/1), last flight refusal (-1 or the
existing request-code index 0..27), bank count (0..2), then two bank groups of five
ints: stable role (-1 absent, 0 abstract, 1 mono, 2 bipropellant fuel, 3 oxidizer,
4 working fluid), amount, capacity, required debit (each 0..2,048,000), and the
session's Fluid registry number (-1 absent, otherwise nonnegative). The final int
is primary required cost (0..2,048,000). Existing optional `StationManagementCode`
names carry control-admission feedback; the monitor and flight-refusal scalars carry
the rocket-specific localized detail. No existing status-code or packet field changes.
The token is zero unless a current quote is displayed. All intent/view bounds remain
512 bytes / 8 KiB. Menu opening sends at most 160 bounded target labels through the
new menu's Forge opening payload; intents never echo coordinates, target IDs or costs.

The monitor uses a new schema-1 metadata root, at most 4 KiB/depth 12/128 nodes:
owner/device UUIDs, optional existing `LoaderBinding`, comparator mode, redstone latch,
optional armed destination and an authority/catalog fingerprint. No inventory or
escrow root is added and no existing saved format changes. Unsupported data stays raw
and inert; this device introduces no save refusal. Operator-only NBT prevents identity
injection. Drops carry no identity or arming. Binding changes clear arming and mode.

Conservative pad semantics: a clicked owner/operator-managed, registered pad is an
alias for its exact journal-identified docked rocket. An empty/stale pad refuses;
there is no nearest-rocket scan, automatic rebinding to a future occupant, or changed
loader binding schema. The existing logical-rocket binding remains the authority.
Monitor telemetry follows only that loaded physical/logical rocket in the same Level;
it can observe ascent outside docking range, but launch/binding require a stationary
rocket within 6 blocks. A missing/unloaded/transferred rocket is not searched for.

Redstone keeps its last signal across reloads and submits only on a new rising edge.
Persisted arming is checked against owner, binding, source/destination station access
and orbit, and a content fingerprint of the catalog. Changes disarm it; fuel changes
are re-quoted at the edge. Offline launch uses the persisted owner with operator=false.
The shared request ledger, planner, landing checks and ordinary/governed preparation
remain authoritative, including asynchronous revalidation. No new fuel/cargo admission.

## Initial stop (resolved by R92): the monitor had no admitted wire representation

The task explicitly says to stop and report if a protocol field or ADR change seems
needed. Inspection of the assigned base establishes that boundary:

1. [ADR-065 section 11.1](../../../decisions/ADR-065-CLASSIC-PROPULSION-STATION-CONTROLS-AND-SOLAR.md)
   assigns `classic_controls` protocol 1 exactly three messages: index 0 C2S
   `ClassicControlIntentPacket`, index 1 S2C `ClassicControlViewPacket`, index 2 S2C
   `BeaconMarkerSnapshotPacket`. There is no separate monitor packet entry.
2. [ClassicControlKind](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/classiccontrol/network/ClassicControlKind.java)
   defines only warp (0), gravity (1), altitude (2) and orientation (3), with closed
   action/value/view layouts. Its contract explicitly calls a new kind or changed
   layout a protocol change. Both existing codecs reject unknown kinds.
3. [ClassicControlPacketsTest](../../../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/classiccontrol/network/ClassicControlPacketsTest.java)
   already tests kind 4 as malformed in `malformedIntentFramesAreDecoderExceptions`.
   Reusing that value for the monitor under protocol 1 would change the meaning of
   an existing wire field and invalidate the old peer's decoding contract.
4. The [protocol fixture](../../../../src/test/resources/network-protocols.txt) says
   table changes require an ADR and protocol version bump.
   [NetworkProtocolPinTest](../../../../src/test/java/io/github/sunthemoon/advancedrocketrycommunity/network/NetworkProtocolPinTest.java)
   pins the channel/message registrations. Adding a separate packet/channel instead
   also needs an explicit protocol-table decision; it is not a way around this stop.

The task anticipates a new packet, but does not assign its channel, discriminator or
version, or override the existing field/table contract. Root needs to resolve that
specific protocol delta (monitor kind/layout on the existing channel, or a separately
assigned message/channel) and record the applicable authorization before this worker
resumes. This is not a request for a general redesign or multi-round proposal process.
No production code, protocol fixture, assertion, schema, ADR or asset was changed.
