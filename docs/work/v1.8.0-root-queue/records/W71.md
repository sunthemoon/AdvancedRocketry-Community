**Refusals.** The collector exits 1, names the problem and leaves no staging folder in these cases:
- Before it starts, it checks every input and names all the problems together:
  - a report, the ledger CSV, the matrix or a validator script is missing, empty, not UTF-8 or larger than 16 MB;
  - a report's first line is not its exact title;
  - `--jar` names a file that does not exist.
- The ledger run crashes: an exit code other than 0 or 1, no JSON summary, or a summary whose result contradicts the
  exit code.
- The resource audit or the provenance audit fails.
- An input changes between being read and the end of the run, for example when a concurrent Gradle run rewrites a
  report. Every source is hashed again at the end.
- The output exists and is not an empty folder.
- The package is over AGENTS.md section 9's 100 MB.

It builds the package in a temporary sibling folder and renames it only after the manifest verifies. `--verify`
reports mismatched, missing and unlisted files.

**The two derived reports.**
- `porting-matrix-counts.md` counts dispositions per group and per system.
  - Group:
    - a v1.8 delivery's batch comes from its evidence folder (`docs/work/v1.8.0-<batch>-...`, the validator's own
      pattern);
    - a PLANNED row's batch is its plan column;
    - earlier deliveries are grouped by version;
    - MERGED, DEFERRED and REJECTED rows are grouped by disposition.
  - System: the unit ID's kind, before the colon.
  - The PORTING_MATRIX rows and their status stand beside each group.
- `progression-report.md` lists 21 stages in basic-to-endgame order, each with its machine:
  - the small plate press and the combustion generator;

  Each node shows its first-acquisition producer, round and prerequisites. A stage is marked **UNREACHABLE** when a
  node is marked unreachable or is missing from every witness route. A last column repeats the check from the
  without-Tau-Ceti reports.

## Choices where the TASK and W62 leave room

- `registered-content-resources.md` goes to `assets/`, because it is resource coverage. W62 section 6 lists only the
  three recipe-graph tests under `content/recipe-graph/`.
- The report list is fixed, so a missing report is detected. Any other `build/reports/*.md` is listed under
  `uncollected_reports` in the summary and printed, but not staged. Today there is none; the `.txt` benchmark is
  ignored.
- The ledger run's stdout is parsed and written again in the validator's own format (indent 2, sorted keys, LF), so
  the file does not depend on the platform's newlines. The stderr goes to `ledger-closure-run.json`, capped at 500
  lines.
- A failing resource or provenance audit refuses the package, because the TASK makes the ledger the one exception.
- Matrix rows beside a group:
  - Beside a batch stand the rows that name it in any cell.
  - A family token such as `C16 批次` names each of its batches that no row names in its 最低验收 column. So the
    machine-family row covers C16a to C16c, and C16d gets only its own components row. The OBJ/MTL row stands
    beside C16b, C17a, C18b and C18d, because its target cell names them; it shows the BLOCKED status there.
  - Beside a version stand the rows whose 目标版本 names it.
  - Beside MERGED, DEFERRED and REJECTED stand the rows with that status.
- Stage nodes are registered items, which the item report always lists, or classic advancement goals, which head
  their sections. A formed `machine:` node is not used, because the advancement routes print only the formed
  machine that their witness uses.
- `--jar` is resolved before the provenance subprocess runs, because that subprocess runs from the repository root.

## Known risks

- **Freshness.** The collector proves only that the reports did not change during its own run. It does not prove
  that they came from the commit it records. Run it right after `gradlew test` on a clean tree, or in CI.
  `repository_head` and `repository_clean` in the summary record the tree at collection time.
- **Report formats.** The progression report parses the witness lines that the two reachability tests write. If a
  test changes its line format, the affected stages show up as "not in the witness routes" and are marked
  **UNREACHABLE**. That is loud, but it would need a parser update.
- **Fixed stage list.** The 21 stages name item IDs. A renamed item shows as unreachable until the list is updated.
- **Matrix parsing.** The batch and version tokens are read from free text in the matrix cells. A new cell that
  mentions a batch in passing would add a matrix row beside it.
