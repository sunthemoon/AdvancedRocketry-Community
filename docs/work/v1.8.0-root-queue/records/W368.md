## The main finding

The existing `CheckedSavedDataFile.Committer` seam sees only the atomic move. The staging write, the flush, the close
and the staging readback happen inside `CheckedSavedDataFile.replace` on a channel that the method opens itself, and
the directory flush is a static call. A committer can therefore neither record those operations nor make them fail.
R457 describes the harness as working through the committer seam. That is enough to rebuild X01's crash states, but
not to inject X02's write, flush, close and full-disk faults.

The design proposes one gated file-operations seam inside `CheckedSavedDataFile`, whose default is today's code. It is
question Q1, and it is the one point where the design goes beyond R457's wording.

## Choices made where the task was open

- **The Windows model.** The directory flush is a no-op on Windows, so the conservative rule leaves every acknowledged
  move undurable. The design tests that as bounded "late-loss" states and asks Root how to class a failure there (Q2).
- **Files outside the seam.** Region and entity files, including the escrow barrier's own stores, are taken as they are
  in the kill image. Their power-loss states are a stated residual, with an optional later slice (Q3).
- **Bounds.** Six distinct states for one unfinished write, seven late-loss states and 16 states for one case; 12
  cases, so at most 192 copies and 384 starts. A case over the bound stops with `OVER_BOUND` instead of sampling.
- **One fault more than the task lists.** A failed staging cleanup (F8), because sharing violations make it likely on
  Windows.

## Statements that were not verified

The design marks each of these where it uses it:

- How the JDK implements `ATOMIC_MOVE` on Windows and when NTFS makes a rename durable. This is general knowledge. The
  model does not depend on it.
- The duration of one native start. The machine-time estimate assumes about two minutes.
- The internals of `scripts/run_v180_registry_writer_cuts.py`. The old-side expectation of case X01-12 has to be
  confirmed in slice S2.
- Whether start-up reads or removes a leftover `.arce-pending` file. The replay checks it.
- The thread on which the barrier's force completes. Only the optional slice S6 depends on it.

The case names in the design's section 3 were taken from [W326-MATRIX](W326-MATRIX.md) and from the runners' case
tables; no native case was run to confirm that each one pauses where the design assumes.

## Known risks

- The seam changes a production class on the saved-data path. Its default must be shown to be today's behaviour, and
  the evidence must come from a candidate built after it merges (Q4).
- A PASS in X01 shows that the mod's write protocol tolerates the modelled states. It does not show safety on a real
  power cut; the design's section 5 lists what stays uncovered.
- The late-loss states may produce failures on Windows that the design already records as outside its guarantee.
