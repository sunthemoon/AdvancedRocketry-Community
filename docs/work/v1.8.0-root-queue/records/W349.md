## Design decisions and changed files

**Runner.** After the hard kill and each clean restart stop, scan all active `playerdata/*.dat` files, the entire
transfer-journal NBT, and every stored slot in every entity or terrain region across the stopped world. Recursively
inspect decoded compounds and lists, rather than selecting only known inventory keys, bay adapters, rockets of L or
fixture coordinates. This covers player inventory, ender chest, nested/modded player payloads, non-bay container
snapshots, world block entities and inventory-bearing entities. Match the raw `SatelliteIdentity.satellite_id` against
the fixture's registered data satellite, not the item name or owner. The deliberately unregistered solar identity is
not rejected. Matching identities are rejected even if other identity fields are malformed.

The kill scan explicitly skips only the held Moon's terrain regions; their unsaved contents are not kill-state
evidence. Its entity regions and the saved journal snapshots remain eligible. After both clean restart stops, Moon
terrain is included. No POI file is read. This is not a known-location-only inventory scan, so no assertion that the
fixture contains only predefined inventory locations is needed. Evidence records scanned filenames, SHA-256 hashes,
stored-chunk counts, skipped held-terrain filenames and the empty registered-package result.

The existing bounded NBT readers are reused. The scan refuses more than 256 files, nonempty short region headers,
regions over 128 MiB, linked inputs and unreadable NBT. Exactly zero-byte regions contain no persisted slots and are
recorded with zero stored chunks; native census reads can create such untouched files. These bounds affect only
test acceptance, not world saving or production recovery.

**Python tests.** `tests/test_bay_w349.py` reuses W346's NBT fixtures and W348's complete-case/raw-oracle probe shapes.
Only first-start observations and server I/O are scripted; `run_w346_case`, `cut_disk`, `restart_start`, `restart_disk`
and snapshot copying execute normally. Twenty-seven wrong-state subcases inject the registered identity at the kill,
restart 1 or restart 2 in nine locations. Two more inject it in Moon terrain after the restarts. Controls cover the
solar identity, item-name independence, held-terrain exclusion, evidence manifests, corrupt inputs, file limits and
untouched zero-byte regions. The final file has nine test methods.

**Java test.** `BaySaveBoundaryReleaseTestGateTest.theSaveBoundaryRegistrationItselfRequiresPermissionTwo` registers
`BaySaveBoundaryReleaseTestCommands` alone and checks permissions 0 through 4. Earlier registrations cannot supply
the predicate. Removing only this class's predicate in a separately compiled scratch mutant makes exactly this test
fail; the other four tests still pass. No production source was edited for the mutation.

**POI correction.** The labelled W349 paragraph in [W346-DESIGN](W346-DESIGN.md) states that `poiManager.tick` writes
dirty columns through `SectionStorage` without a `noSave` check. The case uses no POI evidence. No ADR decision or
production save-control behavior changed.
