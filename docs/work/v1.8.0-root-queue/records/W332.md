## Choices where the task was open

- **The load-failure seam throws inside vanilla's own loader**, so the state comes from vanilla's real path: its load
  ERROR and its cached miss, then W328's `LOAD_FAILED` classification. The file's bytes stay valid, so the pre-start
  check passes them. With the property set and the gate closed, the seam refuses with a WARN and the file loads
  normally. It has no static state.
- **Fuel and cargo use one probe cell per owner**: five ordinary rockets, each bound to one real device, in W95's and
  W330's fixture shapes. An attempt opens one device's gated switch for that attempt. An admitted cargo attempt keeps
  its switch open until its operation is captured, then closes it at a tick's end, as W330's probe did. The watch list
  is per server and is forgotten at `ServerStoppedEvent`, like W254's drives.
- **The probe waits for the transfer journal's checked write** before attempting, as W330's cap probe does, so a
  refusal is the admission's own answer.
- **Released receipts in the pool seed** are REPAIR (`REGISTRY_SIGNATURE_CONFLICT`) and REJECTED (`INTERRUPTED`),
  both with the released flag; durable REPAIR receipts use `TRANSFER_AUTHORITY_CONFLICT`. Every row is pending, and the
  seed stays within 64 per server, 16 per owner and 8 per rocket.
- **"Another owner is admitted"** is shown at P_OWNER's S2, after both restarts.

## Not done

- **TASK item 2, unknown presence (`U_BAY`, `U_LEDGER`): NOT_COVERED on this host.** What was tried, with the probes
  under `S/acl-probe/` and the logs of smokes 1 and 2:
  - A deny entry for the server's user on the receipt file did not make the status check fail. The harness token has
    SeBackupPrivilege enabled and bypasses deny entries. A basic-user token of the same user
    (`runas /trustlevel:0x20000`) still read the file's attributes, because Windows grants read-attributes to a caller
    who may list the folder.
  - Adding a list-folder deny on `data` made the basic-user status check fail (`AccessDeniedException`, so UNKNOWN). But
    vanilla 1.20.1 then refused the start itself: its world-folder validator walks every directory before the server
    exists and failed with `AccessDeniedException: .\world-U_BAY\data` ("Failed to start the minecraft server",
    `S/smoke2/U/native/U_BAY-1.log`). That is before `ServerAboutToStartEvent`, so W328's check never ran, and the JVM
    did not exit within the runner's 420-second window.
  - W328's unit tests (`UnknownPresenceStartupTest`, `EscrowLedgerStartupTest`, `BayReceiptsStartupReasonTest`) remain
    the only evidence of the refusal. No disabled-protection run exists for this family.
- **`L_LEDGER`'s vanilla-dismount row: NOT_COVERED.** The rider's login under the hold did not seat it (seat 0 stayed
  assigned). The hold starts only at startup and vetoes every mount, so no player can be seated during the session.
- **The bay's admission of another owner while one owner is full** is not shown, because the bay fixture's owner is
  fixed. W325's `W325_OTHER_OWNER_ROOM` covers that admission union with INTENT seeds.
- No candidate run, no push, and no status file, QUEUE, risk register or ledger change.

## Known risks

- These are smokes on local JARs. They show that the fixtures and oracles work, not that C2 behaves the same.
- `N_BAY` and `L_LEDGER` inject the load failure through a gated seam over valid bytes; they do not show a really
  corrupted file, or a file that keeps failing and needs the whole-world offline procedure.
- The pool seeds are typed rows, as W325's were, not receipts that real deployments wrote.
- Both load-only lookups now pass vanilla a loader lambda that consults the seam. Without the property it returns at
  once, and vanilla calls the loader only on its single read per session. `EscrowRelaunchClassesTest` passed unchanged.
