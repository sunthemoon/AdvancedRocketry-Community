# W287: intentional ground dismount and the seat roster

## Design note (written before implementation)

The write scope is the rocket's server/entity passenger bridge, the shared LEAVE
handler, seat-roster GameTests, and this record. The base is `ef33f273f` on
`codex/v1.8.0-w287`. No assets, loader admission policy, rider coordinates,
screen text, landing selection, central status, ledger, or queue will change.

Forge's `EntityMountEvent` has no cause field. A connected player can be detached
by server handling as well as by input, so that event alone cannot authorize
removing durable membership. Instead, the rocket's server tick observes its
actual connected passengers' `isShiftKeyDown()` input before vanilla ticks those
passengers (`Player.rideTick` uses `wantsToStopRiding()`, which returns exactly
that flag in the pinned 1.20.1 implementation; the wrapper is protected). For an
operational, loaded, stationary rocket (ASSEMBLED, FUELED, or LANDED, with no
active transfer), it invokes the same LEAVE handler as the flight menu. No new
packet, client authority, global collection, or cause inference is introduced.
Only actual passengers are examined, bounded by the existing passenger limit.
The existing escrow, release, rejoin and passenger-mutation guards remain in
force. Held bay exits retain their separate physical-only exit semantics.

An arbitrary `stopRiding`, removal, logout, death, dimension transfer, recovery
or server stop does not itself edit membership. It never enters the new input
handler. Flight phases retain membership even if vanilla detaches the passenger.
The existing internal-passenger-move scope is also respected. Logout and stop
continue to save assigned seats, including a passenger whose last input was
sneak but whose next entity tick never ran.

The only persisted change is removal of this player's existing passenger-seat
entry from the entity's `RocketFlightData`, through `updateFlightData`, exactly
as LEAVE does. Seat capacity, fuel, destinations, transfer records and schemas
are unchanged. Dismount and membership removal execute synchronously on the
owning server thread; a reentrant save during native dismount can see the old
assignment, just as with the existing LEAVE operation, while a save after the
handler returns sees its removal. There is no deferred cleanup window. A crash
before the operation finishes can restore the old assignment; after the entity
save, the current landed manifest (not the historical transfer manifest) governs
reconnect. Tests will round-trip the entity and exercise reconnect against a
historical committed transfer record.

Old saves contain no proof distinguishing a stale ground seat from an offline
passenger's intentionally retained seat. Consequently load does not discard
either. Existing stale assignments can be cleared by LEAVE, or by boarding and
then sneaking out with this fix. Automatic absence-based cleanup would break
the required landed-disconnect recovery and is deliberately not used.

## W287F design note (2026-11-05, before implementation)

This follow-up answers review findings F1 through F4 from W287R. Its write scope
is the rocket server input bridge, the shared LEAVE handler's visibility,
seat-roster GameTests, their precise expected warning, and this record. The
starting commit is `c222724a1`. The assigned worktree was clean; other sessions
are working elsewhere. No shared checkout, status file, ledger, queue, asset,
schema, protocol, build script, or other task's file will be edited.

The native input bridge will move into `RocketSeatInput`, calling the same
package-private LEAVE handler. It will skip sealed-frozen rockets before LEAVE,
letting vanilla detach without removing the persisted seat. Each passenger's
LEAVE call will catch `RuntimeException` and emit one warning containing fixed-size
rocket/player UUIDs and a bounded exception-class reason, without a stack trace.
Existing update refusals retain the previous flight data; this change introduces
no save refusal, rollback format, or recovery policy. Successful sneak removal
will log an INFO line only when the assignment actually disappeared, not for a
held bay's physical-only exit.

Tests will exercise unreadable transaction protection, a refusal raised during
the native dismount callback, ticking inside an internal move, a stationary
active-transfer guard, and rejoin protection. LANDED plus an active transfer is
rejected by the domain constructor, so that defensive case will temporarily set
the private field by reflection and restore it before any save or cleanup. The
unreadable flag will likewise be restored synchronously. Only the callback-refusal
test will expect the new warning, in its own batch. Persisted seat identity and
the existing crash-before-native-save window remain unchanged. F5's other stale
seats and rider coordinates are expressly outside this follow-up.
