## Cause and design decisions

Both supplied screenshots aim at the airlock. Before native door item use,
`AtmosphereServerEvents.onRightClickBlock` conservatively revokes room authority.
The old analyzer has only air-use handling, so the iron-like door's PASS falls through
to the analyzer after that revocation. The following atmosphere tick rescans and
restores supply. Thus direct reads and nearby status-command calls are correct, while
the native click reads a needless temporary invalidation. This is not eye rounding,
a separate manager, localization, a custom packet, or an analyzer cache.

For an unchanged sealed, supplied room, breathable with controlled supply is the
correct measurement. The analyzer now denies target block activation on both logical
sides at the existing HIGH-priority instrument listener. Its exact registered item
uses the existing non-mutating-item predicate, which skips preemptive invalidation
only with `useBlock=DENY`. `useOn` delegates to the existing admitted eye-cell read,
message and shared two-tick cooldown, consuming the action once. It never forces item
permission or clears cancellation. Real state changes still revoke supply immediately;
no cached HUD result or new cache substitutes for the atmosphere manager.

The implementation follows ADR-066's eye-cell measurement and reuses the read-only
routing mechanism introduced for the seal detector by ADR-067, under this task's bug-fix
assignment. No ADR text or open ADR choice was changed. Analyzer clicks now measure
rather than activate their targeted block; ordinary non-instrument interaction is
unchanged.
