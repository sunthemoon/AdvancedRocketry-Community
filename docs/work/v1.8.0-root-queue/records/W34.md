### Non-player effects (ADR-066 section 3.3, bullet 1)

- `NonPlayerAtmosphereService.onLivingTick` handles every server-side `LivingEntity` that is not a
  `Player`. Players stay entirely with `PlayerLifeSupportService`, so nothing doubles.
- The cadence uses only the entity's lifecycle fields: an entity is evaluated when
  `(tickCount + entityId) mod 20 == 0`. There is no per-entity map, no cleanup and no separate pass
  over entities or chunks. On the other 19 ticks the listener does a modulo and returns.
- On a scheduled tick, the pure `NonPlayerAtmosphere.attempt` reuses `PlayerLifeSupportEngine.tick`
  with no suit, no oxygen and the last phase, then `EnvironmentalExposure.tick`. It returns at most
  one attempt: vacuum suffocation first, otherwise the ADR-034 primary hazard (pressure, heat, cold,
  sunlight). The two are never both applied in one interval.
- No suit oxygen exists for mobs. The ADR-034 passive armor tags are read with the existing
  `EnvironmentalProtection.read`, so a mob in four tagged armor pieces is insulated like a player.
- ADR-034 opt-in is unchanged: exposure needs a profile with `environment_effects`.

### `atmosphere_bypass` (bullet 2)

- `advancedrocketrycommunity:atmosphere_bypass` is an entity-type tag, generated empty by
  `V180AtmosphereEntityTags` (`src/generated/v1.8/resources/data/advancedrocketrycommunity/tags/entity_types/atmosphere_bypass.json`).
- It exempts only the atmosphere attempt and the atmosphere spawn rule. The service never touches
  gravity, fire, drowning or other damage, and the GameTest shows a tagged type still burning and
  drowning.

### Spawn admission (bullet 3)

- `NonPlayerAtmosphereService.onPositionCheck` listens to Forge's `MobSpawnEvent.PositionCheck`,
  the 1.20.1 successor of the legacy `CheckSpawn`. In Forge 47.4.10 only
  `NaturalSpawner.isValidPositionForMob` (NATURAL), `NaturalSpawner.spawnMobsForChunkGeneration`
  (CHUNK_GENERATION) and `BaseSpawner` (SPAWNER) post it; I checked the call sites with `javap`.
  The policy ignores any other spawn type that another mod might post.
- A tagged type passes. Otherwise the check is denied (`Result.DENY`) when:
  - the Level's base atmosphere is not breathable and the mob's eye cell is unloaded or above the
    build height, PENDING or vacuum; or
  - the profile opts into ADR-034 effects and the eye cell has any hazard. The hazards are computed
    with no equipment protection, so only a supplied sealed room (`controlledAt`) protects.
- An admitted check keeps the event's result unchanged, so the vanilla spawn rules still decide.
  The biome spawn tables still choose the candidates, and no spawner is added.
- Spawn eggs (`SpawnEggItem` calls `EntityType.spawn` with SPAWN_EGG) and `/summon` never post a
  position check. They are therefore explicit exceptions: they place the mob even in vacuum, and the
  mob then suffocates like any other. The GameTest shows that neither consults the check and that
  both spawned zombies still take the vacuum attempt. The guide states that this is not natural
  spawning being allowed.

### `vacuumDamage` (bullet 4)

- `OXYGEN.vacuumDamage` is a COMMON `DoubleValue`, 0.0 to 20.0, default 2.0, which is
  `PlayerLifeSupportEngine.VACUUM_DAMAGE`, the present engine's damage, not the legacy 1.
- `PlayerLifeSupportEngine.vacuumDamage(decision, configured)` replaces only the damage of a
  scheduled vacuum attempt. The decision's status, oxygen debit and phase are unchanged, so zero
  keeps suit oxygen use, breathability and the exposure attempt. The player path and the non-player
  path both use it. `SuitReserveTransition` and `SuitEquipmentService` are unchanged.
- With zero, a player's tick no longer counts as a suffocation attempt, so ADR-034 exposure damage
  applies on that tick, as the TASK requires.
- The new key has its own exact log expectation, `forge-w34-vacuum-damage-defaulted`
  (`Incorrect key OXYGEN.vacuumDamage was corrected from null to its default, 2.0.`), and
  `CommonConfigTest` now counts 94 values. The OXYGEN section was already excluded from the generic
  rule, whose maximum stays 99.

## Choices where the ADR was open

- **Cadence.** The ADR asks for at most one attempt per 20 entity ticks from lifecycle fields or
  bounded state. I used `tickCount` plus the entity ID, with no state. A mob can therefore take its
  first attempt anywhere from 0 to 19 ticks after it enters vacuum, unlike a player's 20 consecutive
  exposed ticks. The entity ID spreads a freshly loaded group over the interval.
- **Equipment.** No mob suit oxygen exists. The ADR-034 passive armor tags do apply to mobs, because
  the exposure decision is reused unchanged.
- **Exemptions.** The vacuum damage type is tagged `bypasses_invulnerability`, so an entity with the
  vanilla `Invulnerable` flag would be hurt, and an armor stand treats such damage as a kill command.
  I skip both, and dead entities.
- **Spawn hazards.** "An opted-in hostile profile unprotected by a supplied sealed room" is
  implemented as any ADR-034 hazard at the eye cell with no equipment protection, the room being
  the only protection. In a loaded column, sunlight is the existing daytime sky-visibility test; an
  unloaded or chunk-generation cell is assumed to be in sunlight, which only matters on a
  solar-hazard profile.
- **Chunk generation.** It may run on a world-generation thread with a `WorldGenRegion`, so it reads
  only the catalog (an atomic snapshot): it is denied on any nonbreathable Level, and on an opted-in
  profile whenever a hazard is possible (sunlight assumed). A room cannot protect it.
- **Breathable Levels.** "Unavailable" is judged only on a nonbreathable Level. On a breathable
  Level the cell's loaded volume does not change breathability, so an unloaded cell there is
  admitted unless a hazard applies.
- **Admission result.** The policy only denies. It never sets `ALLOW`, so it cannot override
  vanilla light, block or difficulty rules.
- **`vacuumDamage` scope.** It applies to players and other entities, since the ADR text names
  oxygen consumption, which only players have.

## Known risks

- If another mod calls `LivingEntity.tick()` more than once per `tickCount` increment, the stateless
  cadence allows more than one attempt per 20 entity ticks.
- Pets and other mobs on stations or planets now suffocate outside sealed rooms. Packs that want
  vacuum-adapted mobs must tag them.
- STRUCTURE, PATROL, EVENT and other spawn types are not admitted or denied by this policy; their
  mobs suffocate after spawning.
- `CommonConfigTest` pins the value count (now 94). A parallel task that also adds a key (W33 is
  running) will conflict on that number.
- `AdvancedRocketryCommunity.java` is now 493 lines, close to the 500-line review threshold.
