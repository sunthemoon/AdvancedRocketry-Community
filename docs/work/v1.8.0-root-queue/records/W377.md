## Key design decisions

The only authorized semantic change removes the selected legacy PREPARED transfer from the copied
journal. The ledger, terrain, entities, other records, root wrapper, outbox, unknown fields, types,
and compound entry order are preserved. The comparison uses typed serialized NBT, not dictionary
equality. No record checksum, snapshot hash, or structure digest is independently reimplemented.
The matching candidate's FLOOR_CONFLICT fence line supplies the design's recognition evidence;
the operator confirms its provenance, the candidate hash, and the accounting profile in the plan digest.

The accepted record schema is **2**, independently observed in retained member
`r74/classification-01/native/world-FF_REBUILD_SOURCE/data/advancedrocketrycommunity_rocket_transfers.dat`
of `D:/GitHub/ARCE-Task-Evidence/root-queue/W142/w142b-evidence.tar.xz`. The archive was read only,
without extraction or modification. Its verified SHA-256 is
`4b8ccbe76d1f34f99c5839af3473159c1b4e5a6804cbf8e06cef8ec943338cc6`.
That retained journal has root schema 3, independently of its record schema 2.

The root table covers all ten `ManagedSavedDataType` declarations, schema stamps and epochs,
with ledger roots 2/3 selected explicitly by profile. Tests compare the table, schema constants,
switch mappings, and required root fields with Java source. Every present managed root must
already be current. Unknown managed roots, conflicting UUIDs or coordinate-only claims, related
accounts, orphan accounting rows, duplicate rockets across slots, dimensions or passenger trees,
and the geometric FF_KEEP_SOURCE shape refuse rather than authorizing cleanup.

The writer uses gzip time 0, no filename, compression level 9, forced staged writes, typed and byte
readback, and atomic journal replacement inside an unpublished complete copy. It binds the decoded
and compressed SHA-256 values, Python and zlib versions, and all three Python implementation hashes.
Empty transfer lists use END/zero-length bytes. Copy, force, close, replace, readback, rename,
input-lock close failures and catchable interruption remove the worker's output and staging tree.
An existing output or report is never selected for cleanup.

The initial work limits are those in section 3.4: 64 Levels, 100,000 files, 256 GiB, 4,096 regions,
1,024 slots and objects, and passenger depth 8. Additional conservative memory limits are 64 MiB
per region file and 256 MiB aggregate decoded census data. Existing helper limits remain 4 MiB
per decoded NBT tree and compressed root, 262,144 tags, and depth 64. Reports are bounded at
32 MiB and qualifying logs at 64 MiB. Exceeding any limit refuses; no partial census proves absence.
Space checks require three world sizes plus 10 GiB on the output volume and the specified local volumes.

Clock and root-bookkeeping allowlists are deliberately empty until X03-B provides reviewed dry runs.
After-start census reports all file differences, rejects removals and migration evidence, and requires
unchanged target NBT and managed payloads apart from T. A new forced-chunk file is accepted only with
an empty forced list; an existing list must match the backup. Census is explicitly not promotion approval
or evidence of clean server shutdown, codec acceptance, or completed restart cycles.

Historical accounting remains UNKNOWN_BASELINE without a witness, with no discrepancy number.
The optional version-1 external witness has a checksummed body binding endpoint identities, fluid/tag
identity, and `5000/0 -> 4000/1000`. A supplied invalid witness refuses. This supplied witness and its
provenance are operator evidence, not cryptographic proof of a historical server state. Recomputed
plan digests cannot substitute an invented zero account or change the tool's write list. No ledger
account or permanent receipt is created, and no water or propulsion is reconstructed or refunded.
