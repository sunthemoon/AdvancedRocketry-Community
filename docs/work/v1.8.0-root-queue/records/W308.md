## 2. Decision: the Space body is not a warp target

**Design.** ADR-044 section 4 accepts a target that is "present, orbitable, known and not the current orbit", and
ADR-065 section 5.1 makes the warp controller reuse the same rules. The Space body passes only through ADR-031's legacy
decoder default `orbitable=true`. ADR-031 also says that "Shared Space remains a world host, not a newly landable
planetary surface" and that `orbitable` is "not permission to create a generic orbit instance". ADR-044 section 1 says
that every system is a label over the same Space Level, so the Space body names the place every station region is in,
not a body below one. ADR-033 keeps `space` as the legacy current-body alias that a station record resolves to its real
orbit body. The rest of the code already treats it so: the satellite bay refuses it as an orbit source, the rocket star
map leaves it out, and no route anchors an orbit of it.

**Why not fix the warp instead.** The warp itself is carried out correctly: the record, the charge and the disk write
are right. The faults are in what an orbit of the Space body means to every other system. Making it a real orbit would
need new routes, a sky rule and a satellite rule, which is new design, not a fix.

**Change.** `WarpTargetRule.offered(body)` is true for an orbitable body other than the Space body.
`StationWarpService.warpTargets` (the controller's list) and `StationWarpService.quote` (behind every request,
confirmation and commit) use it, so a request for the Space body is refused with the existing code
`WARP_TARGET_UNAVAILABLE` ("the target body is missing or cannot be orbited"), and a countdown cannot commit to it.
`StationWarpService.java` stays at 789 lines.

**Choices where the ADRs are open.**
- The existing code was reused, so the chat, screen and notice texts, the network enum and the translations are
  unchanged.
- A station that already orbits the Space body (warped there by an earlier build, or created around it by an operator)
  keeps its record and can still warp away. Section 4's evacuation rule and ADR-031's "closes new arrival/creation, not
  evacuation" both say so. Leaving costs the in-system price, because the Space body is in the Earth system.
- Operator station creation around the Space body (`/arce station create`, which checks only `orbitable`) is unchanged,
  because it is not a warp and the TASK excludes other paths. See "For Root".

### Draft ADR-044 implementation note (for Root to add; I did not edit the ADR)

> ### W308 implementation note: the shared Space body is not a warp target (2026-11-06)
>
> Section 4 offers a target that is present, orbitable, known and not the current orbit. The shared Space body
> (`advancedrocketrycommunity:space`) is orbitable only by ADR-031's legacy default, and ADR-031 keeps shared Space a
> world host; by section 1 every system is a label over that same Level. W308 warped a station there through the warp
> controller: the record, the charge and the checked write were correct, but no rocket route reaches or leaves an
> orbit of the Space body, the satellite bay refuses it as a source, the orbital laser has no table for it, and the sky
> showed the Space body as a planet below the station. The warp controller's list and the quote behind every request,
> confirmation and commit (section 4) therefore exclude the Space body and refuse it with `WARP_TARGET_UNAVAILABLE`. A
> station that already orbits it keeps its record and may warp away (section 4, evacuation). Nothing persisted changes,
> and the relocation decision, the schema and the checked commit are unchanged.

## 3. Tests

- `StationWarpSpaceGameTests.theSpaceBodyIsNoWarpTargetAndAStationInItsOrbitCanStillLeave` (batch `station_warp_space`,
  template `rocket_test`) replaces the observation test at `f92ebd062`:
  - An Earth-orbit station's warp screen lists the Moon but not the Space body. The command request (looking at a core)
    and a screen-context request for the Space body are both refused with `WARP_TARGET_UNAVAILABLE`. A confirmation
    finds nothing, no countdown runs, and the orbit and the 2,500,000 FE balance are unchanged.
  - A station created in the Space body's orbit is unreachable by rocket (`NO_ROUTE`), and its sky context names the Space
    body. These fixture checks fail if a route to that orbit is ever added, so that the exclusion gets reviewed then. Its
    own screen shows the Space body as the current orbit, offers Earth and not the Space body, and the real controller
    path (Request, in-system cost of 2,000,000 FE, Confirm, countdown, commit) moves it to Earth orbit. It is charged
    once, written to disk, reachable again (`READY`), and its sky context follows.
- `StationWarpStateTest.warpsOfferEveryOrbitableBodyButTheSharedSpaceBody` (unit): the Space body is still orbitable in
  the catalog but not offered; Earth, the Moon, Mars, the gas giant and Tau Ceti e are offered; the star Tau Ceti is not.
- `scripts/gametest_expected_log.json`: the existing `station-warp-energy-dropped` WARN expectation gets
  `"station_warp_space": 2`, because the guard deletes its two charged stations. No ERROR expectation was added, so the
  pinned ERROR total is unchanged.

## 6. Known risks and notes for Root

- **Existing stations in the Space body's orbit.** A world that warped a station there with an earlier build keeps it
  there until its owner warps it away. Its docked rockets stay unable to launch until then. Nothing is migrated.
- **Operator creation.** `/arce station create` still accepts the Space body (it checks only `orbitable`), giving the
  same unreachable orbit. Applying `WarpTargetRule` there, or setting the Space body's `orbitable` to false in a schema-2
  definition, would close it; both are outside this TASK.
- **Tau Ceti e.** It is an orbit-only body by design (ADR-043), and no route anchors its orbit either, so a station
  warped there also strands its docked rockets. The quote does not warn, because the Tau Ceti system has routes (Tau
  Ceti f and g). That is the per-system warning rule of ADR-044 section 4, not this TASK's target; a per-orbit warning
  would be a separate decision.
