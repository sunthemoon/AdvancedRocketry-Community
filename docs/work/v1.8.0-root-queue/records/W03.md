# W03 equipment implementation record

## Design before implementation

The write scope is equipment model/API, equipment persistence and workstation
adapters, the existing suit oxygen service, additive COMMON oxygen settings,
equipment registration, equipment client screen, equipment data generation and
tests, and this record. Status files, the ledger, build scripts, other tasks and
other worktrees are not edited. The starting commit is `1568699e` on
`codex/v1.8.0-equipment`, with a clean worktree.

The accepted ADR-066 D1 keeps the original active oxygen key and 2,000-unit API
bound. A single schema-1 equipment root owns installed component stacks and their
gas; the workstation persists only its two held stacks, never a module mirror.
Tank maxima use 1,000/2,000/4,000/8,000 times the 1..4 creation multiplier.
Missing tank metadata is initialized on the first authoritative use. Existing
supported maxima survive configuration reductions. The existing verified
`SuitReserveTransition` calculator is used on scheduled oxygen debits, not on
queries. Armor unrelated tags, enchantments and durability remain unchanged.

All workstation operations run on the logical server and revalidate the player,
loaded exact BlockEntity, menu, distance and permission. Edits are prepared on
bounded detached stacks and committed only after every refusal condition passes.
Removal uses the transfer slot or an empty player inventory slot; no partial
inventory insertion or resource spill is permitted. The menu exposes copies and
has no item capability. Fixed button IDs use the vanilla menu intent transport;
no custom resource/NBT packet is added.

Unsupported armor/component roots refuse edits and remain intact. Unsupported
workstation saves retain the raw root and prevent ordinary removal. Oversized
workstation data requires the already reviewed C16 chunk-save guard; any extension
of that guard will be explicitly documented before it is added. No new player-file
save rejection mechanism is introduced. Root must arrange the required independent
read-only persistence review before integration.

The registered enchantment ID is `space_breathing`, as specified by ADR-066.
It is unavailable from tables, books, trading and discovery. Native correctly worn
unclaimed armor with level 1 can seal a suit, with finite chest oxygen on its own
strict root; external registered providers take precedence. Chemical acquisition
belongs to the C16 recipe adapter and must not be replaced by generic enchanting.

Module effects, gas charge pads, HUD, propulsion, mining tools, C17 beacon item
registration, version acceptance and real-GPU validation are not implemented here.
