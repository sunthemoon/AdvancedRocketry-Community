## Design choices

`candidate.path` identifies the cell's installed **client** copy; the server copy has
the same basename and declared hash. `jei_jar.path` identifies the installed client
JEI copy, or the whole field is null. All recorded installed-file paths and all writes
are inside the output root; `runtime_root` is the external input. The remaining exact
schema-1 fields follow the TASK. Additional `mods.server` and `mods.client` arrays
contain `{path, sha256}` records for every mod file. `server_forge_args` records
`{path, sha256}` for the copied official `win_args.txt`. `version_id` comes from the
isolated runtime's matching Forge version JSON, not an account/launcher profile.

JEI is never installed on a server. Options explicitly select English, GUI scale 3,
master volume 1, windowed mode and 1280 by 720. EULA acceptance is explicit on creation;
replacement never changes it, even if `--accept-eula` is also supplied.

Replacement preflights all four existing manifests, both candidate copies, exact mod
sets, JEI hashes and Forge arguments before writing. Only candidate copies and
`cell.json` change; worlds, options and other settings remain untouched. Different JAR
basenames are supported; case-only renames and a candidate named `jei.jar` are refused.
Links/junctions/reparse points are rejected throughout the runtime/output and their
ancestors, including unrelated entries. Traversals have a 100,000-entry bound.
No ADR choice or exemption was required.
