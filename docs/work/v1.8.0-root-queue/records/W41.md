## What the tests do

`machine/classic/runtime/MotorTierFormationGameTests.java` has one GameTest per machine. Each test builds
the machine five times, facing north, through that machine's existing fixture. The first four builds use
`motor`, `advanced_motor`, `enhanced_motor` and `elite_motor` in every motor cell, and the fifth uses
`copper_coil`. Each build is checked while it stands and is then removed by the fixture's `close()`.

- For each tier, the test checks that every motor cell holds that tier's block, that `formed()` is true (the
  check the existing formation tests make), and that the controller kept no pattern diagnostic.
- For the copper coil, the test checks that `formed()` is false and the reason is `UNFORMED`, as the lathe
  and cutting-machine tests check. It also checks that the first diagnostic is a `BLOCK_MISMATCH` at a motor
  cell, expecting `tag=advancedrocketrycommunity:motors` and finding `advancedrocketrycommunity:copper_coil`.
  So the refusal comes from the motor cell and not from some other part of the fixture.
- The expected outcome is fixed in the test for each block. It is not derived from the motors tag, so a
  tier that dropped out of the tag would fail the test.

The copper coil was chosen because it is the motor's own crafting part and a member of the sibling
`coils` tag that the arc furnace accepts. It is a likelier wrong match than the dirt the older tests use.

**Formation path.** There is no wrench in this codebase, and using a classic controller only opens its
menu. A player's placement reaches formation through `ClassicRuntime` (the place, neighbour and break
events call `ClassicMachineManager.changed`), the controller's `onLoad` (`observe`) and the server tick
(`tick`, which calls `ClassicControllerBlockEntity.revalidate`). The fixtures place real registered blocks
with `Block.UPDATE_ALL` and then call `observe` and `tick` on the Level's own manager
(`ClassicRuntime.manager(level)`). That manager validates against the pattern catalog loaded from the
datapack and the real block tags. The lathe fixture's private catalog is used only for its fluid and
remote-power variants, and W41 uses neither.

**Fixture changes.** The lathe, arc/cutting, C16c and research fixtures each gained an overload that takes
the block for the motor cells. The new overloads of the first three fixtures do not assert formation, so a
refused build can be inspected. The existing constructors pass the base motor and keep their formation
assertions, so every existing test behaves as before. `ArcCuttingGameTests.Fixture` changed from private
to package-private, so the new class can use it. `ResearchGameTests.fixture` gained a matching overload, and
its origin calculation moved into a private helper that both overloads share. No fixture was copied.

**Batch and timing.** All six tests share the batch `w41_motor_tiers`. They are synchronous: they register
no `onEachTick`, `runAtTickTime`, `runAfterDelay` or `succeedWhen`, so the W28 rule is met trivially.
In the full run, the batch started at 09:33:02, and the next batch started at 09:33:03 with nothing logged
in between. The batch therefore took about one second of wall time, at the log's one-second resolution.

## Choices where the task or ADR was open

- The task names ADR-064 "section 2" for the legacy layouts. The sentence "A structure accepted any motor
  tier" is in the ADR's Context. The rules W41 tests are Decision §1.1 (a motor cell accepts any block of
  the motors tag) and §4.1 (four tiers; every machine accepts any tier).
- Every build faces north. The existing tests already cover the four rotations with the base motor, and
  the tag check does not depend on rotation.
- No runData was needed, because no generator or generated data changed.

## Not done, and risks

- Status files, the ledger and COMPLETION-PLAN were not touched. Root decides whether C16a-07b closes.
- No real-client check was made. This slice changes no client-visible behaviour.
- Risk: the six tests share one batch, and their fixtures may lie within a few blocks of each other. The
