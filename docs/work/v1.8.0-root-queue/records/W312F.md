### F1 and F3: the logout's own proof

R375 keeps R364's place: the save is still the exact dismount location, where LEAVE SEAT puts the rider. Only the check
changed. It asks whether the player would be hurt there after logging in.

`LogoutExitSafety.inspect` returns SAFE when either:

- the exact standing box is SAFE under the shared `BayExitSafety` proof; or
- the player settles at most three whole blocks straight down onto the first stable support. Every cell of the fall's
  shared window (body, support row and one-block collar) must be free of collision with the falling body, of fluid and of
  hazards, and the landing box must be SAFE under the shared proof. A fall of three blocks or less never deals fall
  damage in vanilla.

Each fall's window contains every shallower one, so the first SAFE landing is the first stable support, and an obstructed
or hazardous column refuses every deeper fall. A half-supported exit, a slab on the way down or a slab landing is still
UNSAFE.

Budget and loading:

- One window covers every candidate fall. The installed shared probe pays for it once, before any read: one candidate,
  at most 96 reads and 16 entity visits.
- The proof uses the deepest fall whose window fits the build height, the world border and 96 reads. For the usual exit
  (x on a block edge, z centred, whole feet) that is the three-block fall, exactly 96 reads; a box over both an x and a z
  block edge only fits a one-block fall.
- Column checks are the shared adapter's (`getChunkNow`, entities loaded, entity ticking). No chunk is loaded or ticketed.
- The landing boxes then go through the shared `BayExitSafety.inspect` over the snapshot alone. Its local allowance pays
  for no world access; every entity visit is charged to the shared probe.

`RocketLogoutExitWorld` applies two rules that differ from the bay exit selector's world, and only for the logout:

- `rocket_assembler`, `landing_pad` and `machine_casing` count as ordinary blocks (hazard NONE). Their real collision
  shapes still decide support; a GameTest checks that every state of all three is a full cube without fluid, and that the
  shared classifier still calls them unknown.
- Neither the rider's own rocket nor any other player blocks the exit or the fall. Since W311 the rocket's box covers
  its structure, but it is not a collision surface; players are not collision surfaces either. Mobs and other collidable
  entities (living entities, other rockets, `canBeCollidedWith`) still refuse the exit.

`BayExitSafety`, `BayPassengerExitWorld`, `BayExitBudget` and the bay exit selector are unchanged; the diff touches none of
them. All 59 `bay_exit_*` batches passed in the targeted run.

### F2: server stop

`RocketPassengerLogout.stopping` (`ServerStoppingEvent`, HIGHEST priority) runs in `runServer` before `stopServer`, and so
before its `saveAll`. For every online rider of a rocket it applies the same eligibility, the same proof and the same
native `unRide` as the logout hook. No rocket or seat input ticks after this event, so the seat stays assigned, as at a
logout. When any rider was examined it logs one INFO line, `ARCE_ROCKET_STOP_EXIT riders=<n> detached=<m>`, which Root can
use in the dedicated-server `/stop` check.

## Choices where R375 left room

1. **"Settle" keeps the exact save.** The player is saved at the exact exit and falls, at most three blocks, after
   logging in; the save is not moved onto the support. This follows R375's first sentence (the save keeps R364's place)
   and keeps the property that the hook saves exactly where native `unRide` puts the rider.
2. **Whole blocks only.** Candidate landings are the exact feet minus one, two or three blocks. If the exact feet are not
   on a whole block, a full-block landing never lines up and the fall is refused.
3. **One region, sized for the deepest fall that fits.** An eligible logout now reads 96 cells rather than W312's 60 to
   80, still within one candidate. If fewer than 96 reads remain in the tick, the logout is UNPROVED and keeps the seated
   save, where W312 might still have proved a supported exit.
4. **The landing uses the shared proof unchanged.** The column rule is the only new geometry rule, and it applies the
   shared proof's per-cell conditions to the swept body. The local evaluation allowance exists only because the shared
   proof's API takes a probe; it pays for no world access.
5. **Explicit block list.** Exactly the three blocks R375 names. Anything else outside `minecraft` stays unknown.
6. **Stop handler at HIGHEST priority.** It then runs before the rejoin data and the release owner close (LOWEST) and
   before the bay coordinator stops (NORMAL). It may run before or after the other HIGHEST stopping handlers (the
   journals' stop latches). It reads in-memory flight, fence, guard and receipt state, writes no journal and performs
   only the native detach.
7. **The guard catches `RuntimeException` only.** Errors such as out-of-memory still propagate.

## Known risks

- A server stop with more riders than one tick's shared allowance (128 candidates, 4,096 reads, so about 42 riders)
  leaves the remaining riders with the seated save.
- The stop pass detaches connected players a moment before the stop disconnects them; their clients see the dismount.
  Another mod that reacts to a dismount at stop would see it too.
- An exception thrown after `unRide` has begun (for example by another mod's dismount listener) is logged, but the
  detach cannot be undone.
- The settle relies on vanilla's fall damage rule (no damage for three blocks or less) and on the column staying as it
  was at logout. An offline world edit can still change the column; there is no login-time correction, as in W312.
- The red runs used an uncommitted patch (`red.patch`, SHA-256 below) that restores W312's hook and adds a no-op stop
  method so that the new tests compile. No commit disables the fix.
