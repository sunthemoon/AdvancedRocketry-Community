## Completed scope and design

- The coalesced/autosave test opens its measured window only when the registry writer has neither an in-flight
  capture nor a pending request, and the next periodic autosave lies beyond its entire measured budget.
- `SatelliteRegistryTestWindow` uses the existing `GameTestAutosave.ticksUntil` helper. A read-only test-support
  bridge exposes the existing package-private writer observations; it never requests, polls or awaits IO.
- The original assertions remain. The measured timeouts remain **300 ticks** for the coalesced/autosave test and
  **200 ticks** for the lifecycle coalesced-flush test. An independent per-tick assertion enforces each measured
  timeout after opening. Setup has its own hard limit: 601 and 401 ticks respectively. These allow one measured
  budget for an inherited write plus at most budget + 1 ticks to pass an autosave. The outer GameTest timeouts are
  the sums, 901 and 601; they do not enlarge either measured interval.
- The new cadence regression registers all callbacks and the measured sequence at test start. Only its capture
  setup is paced with the existing `GameTestTickPacer`; the measured request sequence is not paced or awaited.
  No production writer, cadence, protocol, save policy, asset or data generator changed. ADR-074 items 4, 6 and 9
  remain unchanged, and no ADR decision or exemption was added.

## Regression and development failure

The regression creates a dirty solar registration and calls the same `DataStorage.save()` entry as autosave. It
then makes a later mutation before the END-phase coalesced request, ensuring that publication of the first capture
cannot discard the later pending request. It observes the real writer with **busy = true and in-flight = false**
inside the ten-tick start cadence, then permits the unchanged measured test sequence to begin setup. It does not
wait for a periodic autosave or change either server clock.

- The old-window scratch patch removes only the idle predicate from the gate. With the final paced setup, the
  capture started at tick 140 and the pending-only observation/body occurred at tick 142. The original assertion
  failed: "The commit was not requested by the coalesced flush". The patch was restored before verification.
- With the idle predicate restored, all ten repeated runs observed the pending request at tick 382 after a tick
  380 capture, waited until tick 393 to open, and passed the original sequence: an additional 11 ticks after the
  pending-only observation. The full run likewise observed ticks 21,340 / 21,342 and opened at 21,353.
- The first combined development run, at `f1152bab1`, failed the new regression's setup assertion because ten
  unpaced GameTest ticks elapsed before the first capture published. `67c23e56a` gives only that setup wait the
  dedicated server's 50 ms ticks. Its ten-tick assertion, all measured assertions and all budgets are unchanged.
  The failed development log is retained separately from the ten successful final runs.
