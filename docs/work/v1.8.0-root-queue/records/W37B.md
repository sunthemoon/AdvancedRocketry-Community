A separate lifecycle-bound bed preserver snapshots all four native fields
after W37 admission at LOWEST. It attributes a setter by its exact arguments
and the direct native caller, identified by declaring class and JVM method
descriptor rather than development-only method names. Native sleep stack
depth separates nested operations; an early-return snapshot cannot classify
an unrelated same-tuple setter. It observes, never cancels, spawn events.
Restoration compares the complete tuple, writes fields directly and clears
the operation. The HIGHEST time-check listener is registered first by this
service; Forge guarantees precedence over lower priorities, not over
already-registered HIGHEST listeners. START, logout, orderly stopping and
command dispatch provide the amended fallbacks. R-036 persisted data is
never read or written by this preserver.

The v1.8 registry provider will register all six types once, retaining every
old field except natural. New native tests use connected players and actual
Levels. Existing W37 admission, restore and Overworld tests remain required.

### Ordinary bed operations and fallbacks

`ServerPlayer.startSleepInBed` posts admission at 7, checks natural at 60,
calls its native spawn setter at 122, then posts the time check at 127.
Daytime refusal is at 139, monster refusal at 258, superclass sleep at 261
and success at 308. Early refusals do not require a native write.

`BedRespawnPreserver` captures the native dimension, nullable position, raw
float angle bits and forced flag at LOWEST after W37's NORMAL admission. It
uses player-object identity, native call depth, direct caller descriptors and
the nearest Forge event dispatch, rather than an unscoped UUID token. Synthetic
events cannot borrow an enclosing bed call. Exact level/bed/not-forced arguments
attribute only vanilla's bed setter. Nothing cancels a spawn setter.

The preserver refreshes the pre-write snapshot after legitimate nested setters.
It also observes intervening native setters after the write or after a returned
failure, even when their tuples happen to equal the bed tuple. Final event
cancellation is consulted before restoration. Returned snapshots are retired
before another bed call. Foreign-event storage is folded by active setter depth,
not accumulated as an unbounded setter history.

The primary listener writes the four fields directly at HIGHEST time check,
only while the complete tuple still equals the attributed native bed tuple and
no committed foreign setter supersedes it. It then clears that operation.
START, logout, orderly stopping and CommandEvent apply the same comparison.
Reentrant commands before the native write do not consume an active snapshot;
commands during a native time-check callback can restore an already-written
operation before saving. Cancelled commands are observed too, because a later
listener may uncancel them.

The time-check listener is registered first by this service during common
atmosphere initialization. HIGHEST precedes every lower priority; it cannot
precede already-registered HIGHEST listeners. EventBus 6.0.5
`ListenerListInst.register` appends at 22. It offers no reserved first slot.
Its `post` invokes listeners at 107, runs its exception handler at 134 and
rethrows at 141. This is the practical registration limit requested by
Amendment 2, not a promise about foreign listeners.

There is no post-write setter callback: `setRespawnPosition` posts
PlayerSetSpawnEvent at 15, returns on cancellation at 21, sends its native
notification at 72, then writes position/dimension/angle/forced at 77/82/87/93.
The native notification is not suppressed by this change. The event contains
no angle argument; attribution samples yaw in our earliest HIGHEST callback.
Arbitrary foreign mutation of yaw before that callback or direct field/event
interference is not guaranteed to be transparent; an exact-match failure does
not overwrite a different tuple.

`PlayerList.remove` posts logout at 1 before save at 18. Orderly
`runServer` posts the stopping hook at 291 before `stopServer` at 303.
`stopServer` itself does not post that hook: it calls saveAll at 68 before
removeAll at 75. `Commands.performCommand` posts CommandEvent at 44 before
dispatcher execution at 120. `saveEverything` calls saveAll at 9, and
saveAll calls each player's save at 29. Player serialization occurs before
PlayerEvent.SaveToFile; that event is too late to protect the tuple.

The transient preserver neither reads nor writes the R-036 backup. Existing
W37 respawn validation and direct-field backup restoration remain in place.
The owner-open question about beds setting planet points with
`allowPlanetRespawn` enabled remains unimplemented.

### Proposed R-036 / ADR-066 risk text for Root

Ordinary admitted off-world beds temporarily pass through vanilla's native spawn
setter. The exact original native tuple is restored before the native time/day/
monster decision at the earliest practical HIGHEST time-check listener, with
START, logout, orderly stopping and command fallbacks. A foreign time-check
listener registered earlier at HIGHEST can throw before this restore. An Error
escaping the bed task can also interrupt it. There is no Mixin.

Residual A is `IntegratedServer.tickServer`'s pause save at 53, before its
superclass call at 115 and thus before any START. Residual B is crash cleanup:
`runServer`'s catch at 417 reaches `stopServer` at 525 or 647 without the
normal stopping hook at 291; stopServer saves players at 68 before logout via
removeAll at 75. Each native residual requires the earlier interruption plus
a pause or handled crash in the same inter-tick window. Contrary to Amendment
1's superseded crash assertion, crash cleanup can save the temporary tuple.
A third-party direct player save between the bed task and the first fallback
is also an accepted residual.

The bounded consequence is a saved off-world bed tuple displacing the prior
native point, a narrow D1 outcome 3 violation. W37/R-036 still validates that
point on respawn: under default options the Overworld fallback applies and the
point is kept. The pending backup is untouched. No inventory/player-file
deletion, save rejection, quarantine or new data migration is introduced.
Root accepted A and B in TASK Amendment 2 on 2026-10-14 and is responsible for
adding this text to R-036 and the ADR-066 note.
