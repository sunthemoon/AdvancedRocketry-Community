## 1. Design note (committed before any code change)

### 1.1 The defect

`ForceFieldProjectorBlockEntity.onLoad` reserves the projector's identity in the force-field cleanup root. A new block
entity's identity is the constructor's random projector UUID with the all-zero owner UUID, the internal UNBOUND
sentinel of the schema-1 root (W04F). Five paths call `load` on a block entity that is already in a Level, after
`onLoad`:

- `BlockItem.place` runs `updateCustomBlockEntityTag` after `placeBlock`; only a creative operator can apply a
  projector's `BlockEntityTag`, because the projector's `onlyOpCanSetNbt` is true;
- `StructureTemplate.placeInWorld` into a live Level loads the template's NBT after `setBlock`;
- `/setblock` with NBT (`BlockInput.place` loads after `setBlock`) and `/data merge block` on a live projector;
- the GameTest fixtures (`ForceFieldGameTests.Fixture`, line 59).

`load` swaps the identity and leaves the first entry without a block entity. The scheduler retires and forgets such
an entry only when its source chunk is loaded and the root is below capacity. When the load quarantines the projector,
it never does, because `ForceFieldService.work` stops at a quarantined source.

### 1.2 How an in-place load is recognised

Before `load` replaces the root, the projector records its previous identity if all of these hold:

1. its root is readable (not quarantined), and its own state has no owner and zero claims;
2. its Level is a `ServerLevel`, it is not removed, and it is the block entity registered at its position in a
   loaded chunk (read through `getChunkNow` and the chunk's block-entity map, so nothing is loaded or created);
3. the cleanup root is operational, and its entry under the previous key equals `Entry(previous, 0, false)`
   exactly: same projector UUID, the all-zero owner, the same generation, Level, position and direction, zero
   claims, and not an orphan.

A chunk load from disk never matches: `BlockEntity.loadStatic` calls `load` before the chunk gives the block entity a
Level, and the chunk calls `onLoad` afterwards. Worldgen (`ProtoChunk`) block entities have no Level either.

After the load, in that case only:

- if the root is readable and the identity is unchanged, nothing happens;
- otherwise the previous entry is released, through a new `FieldCleanupSavedData.releaseEmptyReservation` that checks
  the same exact-entry condition again and then calls the existing `forget`;
- if the loaded root is readable, the projector reserves the loaded identity with its claims, the same `reserve` call
  that `onLoad` makes. A quarantined root reserves nothing, as in `onLoad`.

Releasing that entry loses nothing. An unowned projector never projects (`ForceFieldService.work` returns when there
is no owner), so no field carries its identity, and the block entity no longer holds that identity, so no later
removal needs its slot.

### 1.3 Reserved at once

The loaded identity is reserved at once, in the in-place case only. The result equals what a save and chunk reload of
the block entity would give, minus the stray entry. Release comes first, so the swap never needs a second slot: at
4,096 entries the freed slot takes the loaded identity. Both entries have the same Level, position and UUID-sized
owner, so their encoded sizes are equal and the byte bound cannot refuse the swap either.

In the item path, `setPlacedBy` then runs as before: `reservePlacement` re-puts the same entry, and `bind` by a
connected placer finds the loaded UNBOUND reservation and binds it in place (`bindEmptyReservation`) instead of taking
a second slot. Structure templates and commands have no `setPlacedBy`; without the immediate reservation their
projector would stay unreserved until its chunk reloads.

### 1.4 Refusals (the existing rules hold; a bound entry is never dropped)

- **Root not operational** (a refused file): `reserve` refuses there, so no previous entry can exist. The step does
  nothing: no release, no reservation, no `setDirty`. The retained raw root saves unchanged.
- **Root full:** if the previous entry exists, the swap reuses its slot. If `onLoad` was refused because the root was
  full, there is no previous entry, the load is not recognised, and nothing changes; the loaded identity is reserved
  at its next chunk load if there is room, as today. Item placement into a full root is still refused earlier, by
  `getStateForPlacement`.
- **Collision:** the loaded identity's key holds another identity's entry (for example a copy of another projector's
  NBT placed elsewhere, or a structure template of it) or an orphan tombstone. `reserve` refuses as today and that
  entry stays byte-identical. The previous empty entry is still released, because the block entity no longer holds it.
  The projector stays readable without a reservation, as it would after a chunk reload today.
- **Quarantining load:** the previous empty entry is released and nothing is reserved. Today that entry stays for as
  long as the projector is quarantined.
- The release requires the all-zero owner and zero claims on an exact, non-orphan entry, so a bound or claimed entry
  is never released.

### 1.5 Cases that must not change

- **Chunk load from disk** (and worldgen): not recognised (1.2); `onLoad` reserves as today.
- **A projector that has claims**, in its state or in its entry: no release and no immediate reservation. The
  scheduler retires the old entry to an orphan and cleans its claims, as today.
- **A bound reservation** (the block entity has an owner): no release. A `/data merge` on an owned projector keeps the
  old bound entry for the scheduler to retire and clean, and the new identity is reserved at its next chunk load.
- **A different owner:** the entry under the previous key belongs to another identity, for example one bound to an
  owner by `bindReservation` while the block entity still holds the UNBOUND identity (the pattern of the power and
  snapshot fixtures). No release and no reservation.
- A load that keeps the identity, a load into a quarantined block entity (a repair by NBT is reserved at its next chunk
  load, as today), and every force-field block entity: unchanged.

### 1.6 Tests

A new GameTest class `ForceFieldReservationGameTests` in batch `force_field`:

1. a creative operator places a projector from an item whose `BlockEntityTag` carries another, owned identity: the
   root gains exactly the loaded entry and no other entry at that position; a file round trip of the root and a
   chunk-reload-equivalent of the block entity (`loadStatic`, then `setBlockEntity`) keep it byte-identical;
2. capacity: the same tagged placement at 4,095 entries takes exactly the last slot; a projector placed into a full
   root (so `onLoad` was refused) and then loaded in place leaves the root byte-identical;
3. a refused root: byte-identical and not marked dirty;
4. collisions with another projector's claimed entry and with an orphan of the loaded identity: those entries stay
   byte-identical and the previous empty entry is gone;
5. a quarantining load releases only the empty entry;
6. the unchanged cases of 1.5: the root stays byte-identical;
7. no fixture leak: for each of the six directions, `ForceFieldGameTests.Fixture` adds exactly its loaded entry, and
   `close()` returns the root to the key set it had before.

A unit test covers `releaseEmptyReservation`'s refusals: bound, claimed, orphan, foreign and missing entries and a
refused root.

### 1.7 Proposed ADR and risk-register wording (Root applies it)

The cleanup root belongs to ADR-065: section 6.2 defines it
([ADR-065](../../../decisions/ADR-065-CLASSIC-PROPULSION-STATION-CONTROLS-AND-SOLAR.md) lines 818-828), and its W04
implementation note (lines 830-850) documents its save protection. R-022
([risk register](../../../11-RISK-REGISTER.md) line 92) points to that note. ADR-064 does not mention the root.
ADR-054 lines 79-80 define unowned devices as inert.

**ADR-065, a new paragraph after line 850, titled "W59 implementation note: empty reservations of unowned
projectors":**

> This note documents reservation mechanics, not a changed decision. Since W04F every readable projector in a loaded
> Level reserves one cleanup-root entry, unowned ones included. An unowned projector's entry uses the all-zero owner
> UUID as an internal sentinel and has zero claims; it grants no ownership or effect, and binding by a connected
> player replaces it in place without another slot. When NBT replaces a live projector's identity (an operator's item
> `BlockEntityTag`, a structure template placed into a live Level, `/setblock` or `/data`), the projector releases its
> previous entry only if that entry is exactly its own non-orphan, zero-claim sentinel entry, and then reserves the
> loaded identity under the ordinary admission rules. A refused root, a full root without that entry, and a loaded
> identity whose key holds another entry or a tombstone refuse as before. A bound, claimed or foreign entry is never
> released. Chunk loads from disk are unchanged. No save refusal is added.

**R-022, appended to the mitigation column:**

> W59：未绑定投影器的空预留（全零所有者哨兵、零声明、非孤儿）在原地 NBT 载入（物品 `BlockEntityTag`、放入已加载
> Level 的结构模板、`/setblock`、`/data`）替换身份时立即释放，载入身份按普通准入规则预留；已绑定、带声明或属于其他
> 身份的条目不释放，清理根不可用、已满或冲突时照旧拒绝。此项不新增拒存机制，见 ADR-065 的 W59 实施说明。
