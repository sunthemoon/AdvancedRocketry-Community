## Method and checks

- Scripts: `D:/GitHub/ARCE-Task-Evidence/root-queue/W60/scripts/`; logs: `.../W60/logs/`. Their
  hashes are in `D:/GitHub/ARCE-Task-Evidence/root-queue/W60/W60-SHA256SUMS.txt`, SHA-256
  `c53bf1be455215e0ab65b77039413cf08974a4841f4dc7af63260339263e21b9`. Nothing there is committed.
- `linkscan.py` finds links the way `markdown_link_errors` does: the same regular expression,
  code-span removal, fence handling and target normalization. It found the same 704 entries as the
  validator.
- `rewrite.py` applies rules 1 to 3 and logs every change. It skips the excluded files and stops
  for hand review on any unusual target; there were none.
- `verify.py` reads each changed file at the base commit and in the tree. With the logged link
  snippets removed from the old line and their replacements removed from the new line, the rest
  must be identical. Each replacement must have exactly the rule's form, the set of changed files
  must equal the logged set, and every manifest link must resolve. Result: 0 failures in both
  phases (501 and 161 links).
- `punct_check.py` does not use the log. It removes `[`, `]`, `(`, `)`, backticks, whitespace and
  the two fixed phrases from the old and new files and compares them. Rule 1: 0 differences in 153
  files. Rules 2 and 3: one difference in 69 files, the intended single code span of choice 3.
- I read samples of each phase by hand, including every link with an unusual form (text equal to
  the target, fragments) and paragraphs with several links.
