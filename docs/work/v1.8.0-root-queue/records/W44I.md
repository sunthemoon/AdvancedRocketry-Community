### N1: the first ordinary station save is staged (`66a2130e`)

**What was wrong.** After W44J, the first ordinary save of a PROVEN_ABSENT station registry was an in-place
`NbtIo.writeCompressed`, which creates or truncates the target before it writes. A failure after that open left the
session's own partial file. The next save saw an entry, the root became UNREADABLE, and the pre-start validator then
refused every later startup until an operator deleted the file. The W44J text above calls this "the inherited
in-place-write tear risk". That understates it: the tear is inherited, but the inability to rewrite the session's own
torn file was introduced by W44J. This section supersedes that wording.

**What changed.** `StationOrdinaryWriter` now writes every ordinary save of a proven-absent root that has no known
commit yet through `StationCheckedWriter.write`, the station's existing checked writer. It stages
`advancedrocketrycommunity_stations.dat.arce-pending`, forces it, reads it back, re-checks absence through the root's
guard immediately before the atomic move, moves, and then forces the data directory.

- A failure before the move leaves the target untouched and removes the pending file. The absence proof is not
  consumed, so the next save proves absence again and writes the registry.
- Ownership still begins only at a known commit (W44J F2): a normal return, or a failure reported after the move whose
  readback is the exact candidate. The second case is the station writer's existing rule and logs one WARN.
- A move whose readback finds no file or a different file, and a move whose readback cannot be read, are not commits.
  The next dirty save re-checks: an absent target is written, and a present one makes the root UNREADABLE as before,
  without overwriting it. If the session's own move did land, the target is a complete file from an atomic move, so a
  restart reads it normally.
- An entry that appears between the save's admission check and the move is caught by the guard. Nothing is written
  and the root becomes UNREADABLE, exactly as for checked writes.
- Dirty handling stays vanilla's: dirty is cleared even after a failed attempt, and a later mutation retries. The
  payload is the ordinary-save encoding (live clock, or the floor while quarantined) and does not raise the checked
  clock floor.
- A failed attempt logs one `Could not save data` ERROR, the same message and count as before. An entry caught by the
  guard also logs the existing `ARCE_MANAGED_ROOT_UNREADABLE ... stage=first_write` line once.

**Later ordinary saves keep the in-place path.** I chose this over reusing the staged path. The staged writer also
applies the station type's compressed-size bound and requires every ancestor of the data file to be a real directory.
Station checked writes, the journal and the progression root already require both, but extending them to every
ordinary save of a loaded registry would change more than N1 needs. The in-place path is unchanged and every existing
assertion holds. The staged first save now has the same two requirements as the checked writes.

### N2: a failure before the committer keeps the UNKNOWN candidate digest (`19671ad8`)

`RocketJournalFirstWrite.beforeMove` now records whether this attempt proved the target absent. `completed` clears the
retained UNKNOWN candidate digest on NOT_COMMITTED only when it did, and resets the flag after every completion. A
NOT_COMMITTED that comes from a failure before the committer (a staging open or write error, ENOSPC, an ancestry stat
error or a staging readback mismatch) keeps the digest. The per-attempt flag is safe because the writer runs one
attempt at a time and publishes each completion before it starts the next attempt.

**Test** `RocketJournalFirstWriteTest.aStagingFailureAfterAnUnknownMoveKeepsTheCandidateForItsRetry`. The first move
lands and then fails with an Error, so the outcome is UNKNOWN. A directory at the `.arce-pending` path then makes the
retry fail before the committer: the outcome is NOT_COMMITTED, the committer is not called, the target's bytes are
unchanged and the root stays operational. After the directory is removed, the next retry resolves COMMITTED for the
session's own identical candidate: the acknowledgement is current, the root is operational and its presence is still
PROVEN_ABSENT, not UNREADABLE.

The test was run on the unfixed code first: 7 tests, 1 failure, "expected COMMITTED but was NOT_COMMITTED", because

## Changes to the design forced by the code

None of these changes the commit, receipt, award or DELIVERED order, an absence proof or a hold.

1. **N5 wording for `foldWarpCredits`.** Design section 10 says the changed
   `StationWarpRelocationTest` asserts that `foldWarpCredits` and `addMember` "throw as they do for a
   registry that is not operational (`requireOperational`)". In the code, `foldWarpCredits` never
   throws for a registry that is not operational. It refuses every credit and returns
   `WarpCreditFold(0, offered)`, because the warp service calls it from the server tick, where a
   throw would escape the tick. Implemented: under the committed override, `addMember` throws (as
   `requireOperational` does), and `foldWarpCredits` refuses every credit exactly as for a registry
   that is not operational. The test asserts the full refusal.
2. **Size bound.** Besides `StationCheckedCandidate` and `StationCheckedWriter`, two more small
   classes were extracted from `StationRegistrySavedData` so that it stays at or under 800 lines
   without an ADR: `StationWarpEnergyFold` (the existing fold loop, unchanged) and
   `StationRootPresence` (the section 3.6 bookkeeping). The root encoder moved to
   `StationRegistryPayload.encodeRoot`.
3. **The first-write re-check.** `AtomicSavedData` gains a `beforeCommit(Path)` hook beside
   `writable()`. It is how the first write of a proven-absent progression root re-checks absence
   immediately before the atomic move, for the barrier and for ordinary saves alike (section 3.6,
   item 3).
4. **A1 isolation.** Detached roots need the delivery service and the Moon completion to take their
   sources and dispositions as parameters (`FirstEventSources`, `FirstEventDispositionSource`).
   Production passes the world's. GameTest fixtures (classes named `*GameTests` or
   `*GameTestSupport`) are excluded from the A0 check that only the warp service builds an electing
   request.
5. **Directory force for named station operations.** Named station operations now force the data
   directory after the replacement, as design section 1.3 asks ("both root-only and named station
   operations call the same one writer ... R1 directory-force policy"). On Windows this is the
   existing no-op.
6. **GameTest log expectations.** Two expectations were added to `scripts/gametest_expected_log.json`:
   - `w44-first-moon-landing-startup-baseline`: at most one WARN
     `ARCE_FIRST_EVENT_HELD kind=first_moon_landing reason=SOURCE_UNCONFIRMED` per start. The journal's
     startup baseline is not yet confirmed at the delivery service's first END tick, so the Moon kind
     logs its one temporary-hold WARN and then one INFO when the hold clears (section 3.3).
   - `w44-a1-refused-first-warp-replacement`: exactly one ERROR
     `ARCE_STATION_UPDATE_WRITE_FAILED ... stage=replace` in the `classic_first_event` batch. The A1
     fixture refuses the detached registry's replacement on purpose.
7. **Seam details the design leaves open.**
   - The participant seam returns the fixed list [P1, P2] for any active cut, not only for named
     rows. Every M and WARP row uses it, and only the release-test gate can reach it.
   - FP7a, FP7b, FP9, FP10 and FP11 halt at the first delivery step after startup
     (`first_step`). FP7a's "election attempt" is therefore approximated by the first step, which is
     where the unavailable progression root first refuses.
