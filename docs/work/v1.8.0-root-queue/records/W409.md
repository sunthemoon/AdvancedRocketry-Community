The benchmark access class is a test helper in `src/test`, not `src/main`. Its mutation methods count

tenth admitted mutation, not every tenth attempt. Therefore the old 21-attempt schedule could finish
without ten publications on a slow runner. This confirms the cause described in the task.

## Change and non-goals

The test retains its 20-tick cadence, staggered roots, 2 ms sleeps, and 2,000-tick final drain.
It attempts mutations until both roots have at least `READBACK_EVERY` publications, bounded by
100 attempts per root. Failure to reach that target reports both attempt counts and both result maps.
Final checks use the actual attempt counts and additionally require each root's readback count to equal
`published / READBACK_EVERY`. All previous assertions remain, including publication/mutation equality,
receipt refusal/outcome checks, operational/drained state, composition, and decoded file checks.

No product/helper logic, save format, protocol, asset, or central file changes. No assertion is
removed or weakened; sleeps, existing timeouts, and performance budgets are unchanged.
No upstream content is copied and no ADR choice is needed.
