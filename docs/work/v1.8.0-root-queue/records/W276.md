## Design decisions and files changed

The importer already provides the necessary review overlay: `record_for(core, previous)` validates and preserves
the previous review only while its content digest binds the regenerated core. No separate overlay file or new
import command was needed. `tools/import/import_v010_assets.py`, shared by the v1.8 importer, and
`docs/provenance/schema-v1.json` now permit an optional, nonblank `review.basis` on completed reviews. Pending
reviews still cannot prefill a decision, approved reviews still cannot retain unresolved findings, unknown fields
are rejected, and a changed core resets the review. The byte-for-byte verifier and all transformation checks are
unchanged. The basis records a decision; it is not cryptographic authentication of a reviewer or an origin finding.

For L1, `scripts/validate_v180_content_ledger.py` and
`docs/work/v1.8.0-w268-review-closure/adopt_findings.py` require a string with a strict date full match before the
preparation-date comparison. They no longer accept a final newline or coerce another type to a string.

Changed test areas are:

- `tests/test_import_v010_assets.py` and `tests/test_import_v180_assets.py` cover basis preservation, invalid or
  pending basis data, digest invalidation, retained findings and byte-format tampering.
- `tests/test_validate_v180_content_ledger.py` and new `tests/test_adopt_v180_origin_findings.py` cover malformed
  dates, including `2026-11-03\n`, and refusal without creating or changing the output file.
- New `tests/test_v180_d7_approvals.py` checks the exact 30-file cohort against the reviewed commit, all review
  metadata and digests, and W275's continuing pending status.
- Five existing Java classes, `V180ArtRedrawProvenanceTest`, `V180ClosureProvenanceTest`,
  `V180FluidFuelLoaderProvenanceTest`, `V180PresentationProvenanceTest` and `V180LandingPadTextureImportTest`, now
  check the exact authorized approval through new test helper `V180OwnerReviewAssertions`. Existing content,
  digest and resource assertions remain. No assertion was changed to accept an unspecified review status.
- `docs/work/v1.8.0-w268-review-closure/test_proposal.py` updates only the synthetic fixture and adds negative date
  cases. Its original assertions remain unchanged.

The remaining changed files are the 30 provenance records named in the TASK and this record. No runtime Java,
resource, DataGen provider, asset plan, allowlist, origin-findings data, ledger, status, QUEUE, build or workflow file
changed. No open ADR choice required a new decision.
