## Implementation and verification log

The plan was committed as `7d474027` before Java changes. W119-1 is implemented-unverified:
the composed writer, session-local watches and immutable identity acknowledgements now cover every
write entry. The shared base is unchanged. Added `SatelliteRegistryProofTest` and
`SatelliteRegistryEpochTest`; their first execution is queued behind another worker's Gradle process.
No test result or delivery is claimed by this implementation checkpoint.

W119-2 is implemented-unverified. The server-bound registry uses the live receipt index for all
three entry points; detached codec/domain fixtures have no world and use an empty fence. NOT_LOADED
and a missing/stopping runtime fail closed. REGISTERED permits normal decommission only at its exact
receipt acknowledgement. Added separate index and registry-fence tests. The registry was already
798 lines, so launch admission was extracted into `SatelliteLaunchAdmission` rather than crossing
the 800-line threshold; its dry-run and commit share the same validation and budget checks.

W119-3 is implemented-unverified. `SatelliteLaunchService` takes a UUID owner, validates FRESH versus
REPLAY, and revalidates the branch before registration. The terminal retains ownership and durability
checks, and lets package replay reach the service even with no selectable target. Its historical
blocked-registry diagnostic/result is preserved; the shared service returns REGISTRY_BLOCKED. The
two new result codes are appended, never inserted into persisted ordinals. New unit and GameTest
coverage pins N8; no pre-existing expected result was changed. Language generation is still pending.

W119-4 is implemented-unverified. Only the production bay checkpoint requests the platform directory
force, including after replace-then-throw resolves to an equal file. Directory-force failure is exposed
in the completion; it does not undo a COMMITTED replacement's S2 proof (design section 3). Other write
entries retain their original file-only durability policy. No deployment entry or coordinator permit
was added.

Static review added full account/codec-byte quota fixtures, individual count-quota checks, restore
sequencing, raw blocked-root transport checks, and detached S2 receipt/registry ordering cuts. It also
keeps a refused idle launch's clock unchanged, retains the original write exception for diagnostics,
and derives the exact-acknowledged receipt set once per index rebuild instead of scanning the full
store once per receipt. These additions remain unverified while W118's GameTest owns the JVM slot.

The clock-path audit found that domain refusals/replays and backward observed time can update the
persisted clock without a state-result change. Their adapters now sequence that clock observation in
`finally`, mark only ordinary dirty state, and leave E and `flushPending` unchanged. Dedicated checks
cover these paths; this implements section 3's requirement to sequence every clock mutation without
changing the clock algorithm or the coalesced-write policy.
