The write scope is the gas-table parser and record-fit helper, `SatelliteItemData`,
`LaserDrillTableCodec`, `BlackHoleCodec`, `BoundedItemIngredientCodec`, their regression
tests, this record, and `D:/GitHub/ARCE-Task-Evidence/root-queue/W180/` for commands and logs.
No upstream files or assets are copied. No status file, ledger, ADR, risk register,
build script, protocol, saved schema or registry decoder is changed.

Gas table file IDs keep their existing effective maximum of 176 canonical characters:
the `gas-v1` prefix, two separators and 16-character hash consume 24 of the existing
200 reward-version characters. The parser will reject longer file IDs with its existing
identifier diagnostic. The fit helper will also return its existing non-fit sentinel
for an oversized derived version, so directly constructed tables return the catalog's
existing file-identifying error instead of throwing. No 128-character restriction is
introduced on otherwise working gas file IDs.

The item identity reader will apply its existing 128-character bound to canonical
definition/component IDs, returning `INVALID` without mutating the source NBT. Schema 1
and 2 writers remain unchanged. This is the item-NBT normalization correction expressly
requested by W180-R2, not a change to saved satellite registry decoding or load policy.
The three adjacent content parsers will preserve their existing diagnostics and bounds.
