**Choices where the documents are open** (conservative):
1. The capacity guard covers every state-changing registry entry, not only stamped ones: at r = MAX nothing is
   admitted, and the scheduler only advances the clock (a clock-only write keeps E).
2. A capture needing an unrepresentable epoch is refused: the request is dropped, one diagnostic per streak, the work
   stays dirty, nothing retries.
3. Detached registries (no server) await IO on the calling thread for `flush(Path)`, `checkpoint(Path, ...)` and
   `save(File)`. A live server never waits, except a GameTestServer (test-only) or an empty release-test server.
4. The pending table lives in the service package, held by `SatelliteManager` for one server lifetime.
5. While a terminal has an entry, every state-changing button there answers REGISTRY_PENDING before any mutation;
   target selection, paging and reward withdrawal stay available.
6. A mismatch at completion keeps a diagnostic hold until the session ends.

### Choices where the documents were open

The plan's six choices hold. Added during implementation:

7. A conflicting action for the same satellite at another terminal, or a full table, answers REGISTRY_BUSY; a second
   state-changing press at a terminal that already waits answers REGISTRY_PENDING. Both refuse before any mutation.
8. A chunk save of a waiting terminal stores the entry's RAM result (SUCCESS or IDEMPOTENT), never REGISTRY_PENDING,
   which is session-local.
9. Research's same-target failure seam (`failOneWriteForTests`) fails before replacement through a committer that throws
   `SatelliteRegistryTestAwait.InjectedFailure`; the writer reports it at INFO, not as a failure streak, so W21c's
   no-ERROR harness rule still holds.
10. The release-test hooks `releaseTestLaunch`, `releaseTestBatch` and `releaseTestClaim` keep awaiting their write, but
    only on a release-test dedicated server (`SatelliteRegistryTestAwait`), as their native harnesses expect.
11. An await on a GameTest or release-test server pumps the writer on a millisecond clock. The writer adds those
    milliseconds to the tick count it reports, so a cadence or backoff that starts late in an await still ends after
    its number of server ticks (commit `79f2653a`). A production server never awaits, so nothing changes there.
12. A replayed receipt whose mission the registry lacks is answered MISSION_NOT_FOUND without a request (commit
    `ecbbf19a`).
13. The GameTest batch fixtures that swap in their own registry await the original's write before the swap and await
    and close the fixture's writer before restoring the original, because both write the same file.
14. The native seams hold a terminal's effect and the discovery replay only through release-test commands; the hold
    flags are read on the server thread and are false in production.

### For Root: protections, holds and log lines (not registered here)

These belong to the new registry-writer entry (R-041) and the R-039 change of design section 5.3. I did not edit the
risk register or any ADR.

- **Terminal waits.** One server-lifetime table, at most 256 entries, one per terminal (Level and position) and one per
  satellite. While a launch or decommission waits, the package and chip slots refuse insertion and extraction through
  the item handler (so menus, hoppers and droppers), the terminal refuses player breaking and leaves explosion block
  lists, and every other state-changing button there answers REGISTRY_PENDING. Scope: one terminal. Duration: until a
  published commit covers the change and its effect runs at a loaded terminal (normally a few ticks); through FAILED and
  UNKNOWN writes and the 200-tick backoff; while the terminal's chunk is unloaded; and, after a slot mismatch or a
  missing terminal, a diagnostic hold until the session ends. Shutdown discards every entry without its effect; after a
  restart the package replays as IDEMPOTENT or the chip is inert (ADR-049 section 6), also after an ordinary stop.
  Log: one WARN `ARCE_SATELLITE_TERMINAL_HOLD level=... pos=... kind=... satellite=... reason=SLOT_MISMATCH|TERMINAL_MISSING`
  per held entry. `/setblock`, `/fill` and raw third-party replacement stay operator residuals.
- **Discovery** waits for the commit of its paid receipt (PENDING_DISCOVERY plus a request; the replay queue retries).
- **Data actions** show REGISTRY_PENDING until a commit covers their token; the admin cancel says
  `ram_result=... durable=after_next_registry_commit`.
- **Write failures.** One ERROR `ARCE_SATELLITE_REGISTRY_UNACKNOWLEDGED outcome=FAILED|UNKNOWN sequence=... epoch=...
  durable=...; retained dirty state` at the first failed or unknown write of a streak, and one INFO
  `ARCE_SATELLITE_REGISTRY_ACKNOWLEDGED ... after an unacknowledged write` at the commit that ends it. The core logs
  one ERROR `ARCE_CHECKED_WRITER_THROWABLE root=satellite_registry` per unexpected writer `Throwable`, one WARN
  `ARCE_CHECKED_WRITER_DRAIN_INCOMPLETE root=satellite_registry target=... committed=... attempts=... reason=...` when a
  stop drain gives up, and one INFO `ARCE_CHECKED_WRITER_DRAINED` when it succeeds. No total cap.
- **Epoch capacity.** At r = MAX every state change is refused before it mutates (CAPACITY_REACHED), with one ERROR
  `ARCE_SATELLITE_REGISTRY_EPOCH_EXHAUSTED durable=... reserved=... in_flight=... sequence=... dirty=...` per streak; the
  data stays and stays dirty, and fixing storage does not repair it.
- **Stop path.** One three-attempt budget per shutdown across save, drain and close; the join before world storage
  closes can block as long as the filesystem does; a watchdog end before coverage leaves only the last committed or
  unknown whole file (verified by R7_INTERRUPTED).
- **R-039.** D3's proof becomes an asynchronous completion, so INTENT lasts at least one registry write longer (W27d2's
  callers are not in this slice).

**Operator backup note (design section 4.5), for Root to place.** While the server runs, autosave, `/save-all` and
`/save-all flush` only request the satellite registry's write (and the transaction journal's) and return at once; the
write finishes on its own thread and is published on a later tick. So after `/save-all flush` returns, the registry
file on disk may still be the previous one. Atomic replacement keeps each file whole, but a live copy of the world can
still combine an older registry with newer chunks. For a consistent backup, stop the server normally, wait for the
log's `ARCE_CHECKED_WRITER_DRAINED root=satellite_registry` (and the journal's), and copy the world afterwards. A stop
that logs `ARCE_CHECKED_WRITER_DRAIN_INCOMPLETE`, or one ended by the watchdog or a kill, is not that guarantee: the
files are then the last committed or unknown versions, and RAM changes after them are lost. This slice adds no
synchronous command drain; a consistent live snapshot would need its own design.
