# W300: stale stationary seats

## Design (before implementation)

The base is `ee35242f2` on `codex/v1.8.0-w300`. The write scope is the
rocket passenger tick and shared seat-release service, the narrow reconnect
query needed by that tick, one operator command, focused GameTests and their
log expectations, and this record. Rider positioning, flight/transfer seat
policy, assets, schemas, the ledger, status files, and QUEUE are excluded.

Each loaded rocket owns a transient, seat-limit-bounded absence tracker. Only
operational ASSEMBLED, FUELED or LANDED rockets without an active transfer are
eligible. A connected, living, non-fake assigned player who is not riding that
rocket accumulates 40 consecutive eligible rocket ticks. Riding, logout,
replacement of the online player instance, rejoin protection, an internal move,
or a pending reconnect attempt resets the observation. Death keeps the seat
until the player is alive/respawned. Spectator mode is eligible for absence
cleanup, unlike the existing sneak-input path. No world search or chunk request
is performed. The existing synchronous login reconnect precedes entity ticking;
the pending reconnect query also protects retries delayed by journal or chunk
readiness. Offline seats are never removed by this policy.

`BayPassengerExitService.heldLeave` intentionally performs a physical-only
exit: `RocketEscrowGate.idle` rejects membership mutation while a bay claim or
blocking/released receipt holds the logical rocket. Keep the seat and reset
the timer throughout that hold; start a new grace period after it ends. Do not
change any claim, receipt, transfer manifest, or descent capability.

Move the shared LEAVE mechanics out of the near-limit flight service into a
small seat-release helper. Sneak, absence, and operator release use its existing
release/escrow/journal checks and `updateFlightData`; they never detach a player
from another vehicle. Evaluate `sealedFrozen` lazily, once per rocket tick,
before its first attempted release. Catch update refusals, retain the seat, and
include the exception in `ARCE_SEAT_RELEASE_HELD`. Successful removals emit one
INFO `ARCE_SEAT_RELEASED` with SNEAK, ABSENT, or OPERATOR as the cause. Reuse
`RocketFlightService.stationary` rather than maintaining another state list.

The permission-level-2 command is `/arce rocket release-seat <rocket> <player>`.
Its entity argument resolves only an already loaded rocket in the source level.
The player argument identifies one cached profile by name (including offline
players) or UUID, without a remote profile lookup. Recheck permission during
execution; refuse ambiguous/missing profiles, unavailable rockets, in-flight or
active-transfer states, protected riders, frozen roots, and held membership.
Report success or a concrete refusal without changing other assignments.

No new saved field, ID, or migration is needed. Only the existing entity
passenger assignment changes. The crash boundary remains the next native entity
save, just as for menu LEAVE: a crash before that save can restore the old seat.
Tests will cover native departure stimuli, grace/reset boundaries, offline and
reconnect preservation, internal/rejoin/frozen/held guards, old saved seats,
operator validation, and refusal handling. The existing seat, bay, loader and
transfer suites remain intact. Delivery requires the task's automated commands;
real clients, native restart, independent review and v1.8 Gate approval remain
Root/owner work.

## Delivery

Implemented on `codex/v1.8.0-w300`; nothing was pushed or merged. The final
tested production commit is `e452d7142440abb1bc2391c07eae1a06ffd8e84e`, from
a clean worktree. The final record commit changes documentation only.

- `42d8b72c9` committed the design before implementation. `ac569ac28` added
  bounded absence reconciliation, shared release validation, the command and tests.
- `ea1d6983a` starts fresh grace after thaw. `a98e0a2ed` keeps reconnect
  readiness in its recovery owner and the transfer service below its 800-line limit.
- `50a2ec547`, `a7631aa3e` and `d82c1238b` correct fixture lifecycle details:
  incidental fall damage, native spectator changes, local profile caching,
  committed landing authority and held claims without deployment IO.
- `a1b2ddc5e` preserves the explicit player passed to menu LEAVE, including
  server-side callers not registered in the online player list.
- `e452d7142` resets absence throughout the shared escrow/journal/release
  mutation guard. A returned rocket can look stationary before F8 retires its
  transfer authority; those protected ticks must not consume the grace period.

There is no new schema, public ID, packet, asset, configuration or save-refusal
mechanism. Held bay exits remain physical-only until the hold ends. Cached
offline names are supported without authentication requests; UUID is the fallback
when a name is missing or ambiguous. Only this task's files were changed.
