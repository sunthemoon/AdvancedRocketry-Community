## Completed scope and decisions

- The [design note](W256-design.md) was committed before implementation.
  The stateless `saw_blade` block uses an ordinary `forge:obj` model and its
  block item inherits the same mesh with explicit P1-style camera transforms.
  There is no facing, block entity, custom renderer, runtime fallback,
  network change, saved-data change or registry-ID change.
- Four S1 sources were inventoried before copying in the
  [coverage table](W256-asset-coverage.csv) and
  [LF import plan](../../../../tools/import/v180-w256-plan.json).
  The importer records `mtllib sawBlade.mtl` to `sawblade.mtl`, the identity
  `usemtl Material` mapping required by the transformer, and `map_Kd
  advancedrocketry:models/cuttingmachine2` to
  `advancedrocketrycommunity:block/cuttingmachine2`. Both PNGs are byte copies
  into stitched singular folders. The assembly icon is the item's particle
  sprite, not a separate GUI mesh or fallback. The
  [provenance record](../../../provenance/v1.8.0-w256-saw-model.json) stays
  `PENDING_HUMAN_REVIEW`: 720 budget vertices and 17,789 imported bytes.
- Placement uses the upstream identity north/inventory transform. The
  vertical YZ blade keeps its tooth overhang, less than 0.095 model pixels,
  rather than fitting the mesh by eye. `flip_v: false` follows P1's Forge
  blockstate route, not K2's LibVulpes route. The legacy Forge V-coordinate
  premise remains unverified and is explicitly part of V1.
- Only the saw registration gains `noOcclusion()`. Collision, support,
  sealing and the cutting pattern remain unchanged; the new GameTest checks
  these properties and light transmission with an opaque iron control.
- The existing W246 provider-consumption regression needed an exact-set
  update: it still pins W246's sixteen imports and now additionally requires
  S1's two named sprites. No assertion, test, timeout or budget was weakened.
  The existing packaged atlas walk checks the actual OBJ/MTL dependencies.

## Root decisions after the independent review (R285, 2026-11-02)

The review `D:/GitHub/ARCE-Task-Evidence/root-queue/W256-review/REVIEW.md` (SHA-256
`d21bc787b9ff44637655ef1d1ecdc924b1c1c1cb4a344f27f0882930cbe23842`) approved with changes. Root decided:

- **W256-R1.** The saw block keeps no facing. Its axle runs east to west in every machine rotation, so in two of the
  four rotations it points away from the motor. This is accepted as a known visual limitation; adding a facing would
  need a migration for placed saw blocks. V1 checks the axle against the motor in all four rotations.
- **W256-R2.** A formed cutting machine draws both the K2 hull's `Saw` object and the placed saw block. V1 checks the
  formed state in all four facings (crossing, parallel or z-fighting blades) before Root decides whether the hull
  stops drawing its saw.
- **W256-R4.** `saw_blade_classic.png` is bound only as the shared saw item model's particle, a nominal consumer: the
  legacy flat item look is replaced on purpose by the shared mesh, as in P1. "Uses the upstream identity
  north/inventory transform" applies to the placed block; the 1.12 item probably used its flat item model instead.
- **W256-R5.** The target keeps the name `saw_blade_classic.png`, after the saw block it belongs to; this is a
  deliberate exception to the keep-the-upstream-name rule, recorded here.
- **W256-R6.** Root's asset-plan edit names the provenance record and the targets in the three rows.
- **W256-R3.** The `saw_occlusion` GameTest was not run red first. A follow-up runs it once on a scratch tree with the
  saw registration reverted and records the failure.
