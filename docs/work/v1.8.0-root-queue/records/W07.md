### Persistence

- **Record schema 3.** The record carries a strict five-key `orbital_controls`
  compound: distance 4..190, three phases 0..359,999 milli-degrees, three rates -60..60
  as bytes, and a nonnegative epoch.
- **Registry root 5.** The root (format epoch `v1.8.0-station-orbital-controls`) adds a
  two-key `orbital_clock`. Roots 1 to 4 migrate to 5 in one step: tick 0, distance 4,
  zero rates, epoch 0, and an EAST phase equal to the stored sun angle. Every other
  field, the warp balances and unknown extra tags stay as they are.
- **What blocks a root.** Each of the following blocks the whole root, which is kept
  verbatim:
  - a missing, malformed or future clock;
  - a clock on an older root;
  - an epoch after the saved tick;
  - malformed controls.
- **The clock.** `StationOrbitalClock` lives in the registry SavedData and saturates at
  `Long.MAX_VALUE`. `StationManager` advances it once per server END tick, but not
  while the registry is quarantined.
- **Checked writes.** Every checked write names its transition and carries one clock
  sample into the candidate. Validation requires the decoded clock to equal the sample,
  and a known commit raises the checked-commit floor.
- **Saves.** A healthy ordinary save writes the current tick. A quarantined one writes
  the floor. While a rate is nonzero, the registry is marked dirty every 20 ticks.
- **Transitions.** `StationState` gains `ALTITUDE_ONLY` and `ORIENTATION_ONLY`; growth,
  gravity and relocation now also require unchanged controls.

### Network and sky

- `StationSkyContextPacket` is payload schema 2 (167 bytes at most, bound 256) and
  `celestial_snapshot` moves to protocol 4 (fixture and pin test updated).
- The server chooses the sky kind: `SINGULARITY` comes only from the ADR-057 profile
  (`BlackHoleData.at`), `PLANETARY` from the current catalog, and `SPACE_FALLBACK`
  otherwise.
- The pass sends on a change of basis, and a heartbeat at most every 20 ticks per player
  while the context rotates. It sends NONE while the registry is blocked or
  quarantined.
- The client extrapolates at most 40 local ticks, then holds the last phase. The cache
  clears on NONE, a Level change and logout.
- The renderer turns the stars, the sun and the orbited body by one rotation
  (yaw from UP, roll from EAST minus 270°, pitch from NORTH). The disc radius is
  `asin(900 / (900 + altitude))`, exactly 30° at distance 4.

### Controls

- **Shared context validator.** `StationActorContext` is either a command (the existing
  rule, with the server ray pick on a core) or the exact controller block from the
  server menu: its Level, position and block. `StationLocalActor.locate` checks that
  the controller is loaded and is still the same block, and that the actor is a living,
  non-spectator connected player within 8 blocks of it, in the same committed region.
  The warp service uses the same validator. For a controller, a loaded core of the
  station must stand within 5 blocks of the controller.
- **Orbital control service.** `StationOrbitalControlService` sets distance, rates,
  STOP and fixed phases with one clock sample per change, in this order:
  1. the observed-station check;
  2. the unchanged no-op;
  3. the elevator guard;
  4. the per-station 100-tick cooldown, shared with gravity;
  5. the server-wide write budget.

  Gravity screens use `StationGravityService` with the same checks.
- **Blocks and menus.** The four controllers are plain blocks with no BlockEntity. The
  menus send only vanilla button IDs, show values through short data slots, and allow
  one change per player per 10 ticks. The warp screen sends an index into the server's
  own target list, sent when the screen opens.
- **Commands.**
  - `/arce station altitude <4..190>`;
  - `/arce station orientation rates <e> <u> <n>`;
  - `/arce station orientation stop`;
  - `/arce station orientation phases <e> <u> <n>`.

  `/arce station environment` and `admin inspect` show the controls on their existing
  line.
- **Code keys.** Every `StationManagementCode` has a stable key,
  `station.advancedrocketrycommunity.code.<code>`.

## Choices where the ADR was open

- **No `classic_controls` channel.** The controller menus use the vanilla menu-button
  transport and data slots, as W03 does. ADR-065 section 11.1 freezes a three-message
  `classic_controls` channel, but its index 2 belongs to C17c. Registering a partial
  channel now would change the pinned table again later. The task's network scope names
  only the celestial channel. The section 11.2 checks still apply: sender, main thread,
  open menu, distance, exact block, permission, observed station, value range and
  rate. Root should decide whether a later slice registers the channel.
- **No BlockEntity.** The controllers store nothing, so they have no BlockEntity. The
  "exact FULL-loaded BE" check of section 11.2 becomes the exact loaded block at the
  server-side menu position.
- **Observed revision.** The menu keeps the station it last broadcast. A click is refused
  as `STATION_CHANGED` when the live station differs, even in a field that screen does
  not show.
- **Cooldown.** Gravity, altitude and orientation share one 100-tick per-station cooldown,
  the most conservative reading of "the 100-tick station cooldown".
  `GRAVITY_COOLDOWN` now reads "gravity or orbit".
- **Elevator guard.** `orbitalControls` defaults to the deletion rule: a pair names the
  station, or a transit endpoint stands in its region. This is the ADR's "pair bound or
  ride pending".
- **Sky reference.** EAST equal to 270° (the BASIC_SPACE sun angle) is the ADR-047 sky, so
  migrated and new stations look unchanged until turned. The disc radius uses a nominal
  900 km body radius, so distance 4 keeps 30°.
- **Ordinary saves.** A healthy ordinary save does not raise the checked-commit floor,
  because it is not a disk barrier. A quarantined save writes that floor.
- **Language namespace.** The §5.3 code keys are in the v1.8 language namespace
  (`advancedrocketrycommunity_v180`). `runData` now writes only `src/generated/v1.8`,
  and a second `advancedrocketrycommunity_v150` lang file would duplicate a resource
  path. The keys use the established `station.advancedrocketrycommunity.*` form.
- **ADR-047 quarantine rule superseded.** ADR-065 section 5.2.1 replaces it: a quarantined
  registry now sends NONE. `StationCheckedUpdateTest` was updated to assert the new
  rule, and that ordinary reads still resolve.
- **Refused data.** No new save-refusal mechanism is added. The new clock and epoch checks
  reuse the existing blocked-root preservation that ADR-065 section 5.2.1 specifies: the
  whole root, kept verbatim, until offline repair from a backup. The encode-time epoch
  check is an invariant guard, like the existing size guard, and cannot fire with the
  model invariants. For that reason no risk-register entry was added; Root may want one.

## Known risks

- **Size guidance.** `StationRegistrySavedData` (about 710 lines) and `StationWarpService`
  (about 620 lines) were already over the 500-line guidance and stay under 800. The new
  code is the same authority's clock and the controller entry points of the same
  actions.
- **Changed descriptions.** `ELEVATOR_BOUND` and `ENDGAME_UNAVAILABLE` now also mention
  orbit changes. Tests read descriptions from the enum.
- **Clock-dependent display.** The orientation screen shows whole-degree phases at the
  server's tick. A stale context on the client holds its phase after 40 ticks until the
  next heartbeat.
