## Signal, sources and decision

The second signal is the global cursor visibility returned by Win32 `GetCursorInfo`.
Only a desktop clip contained in the client area needs it. Every previously decidable clip
keeps its original answer and makes no extra Win32 calls.

Primary sources read on 2026-11-27 (URLs are code spans under WORKER-RULES):

- GLFW 3.3.8, `src/win32_window.c`, `updateCursorImage`, `updateClipRect`, `disableCursor`,
  `enableCursor`, and `_glfwPlatformSetCursorMode`:
  `https://github.com/glfw/glfw/blob/3.3.8/src/win32_window.c#L221-L301` and
  `https://github.com/glfw/glfw/blob/3.3.8/src/win32_window.c#L1995-L2006`.
  Disabled mode sets a null cursor image and confines the pointer to the client. Returning
  to normal mode removes the clip and restores the cursor image. This is a source reference,
  not a new claim about the version of the running campaign's GLFW binary.
- Microsoft, `GetCursorInfo`:
  `https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getcursorinfo`.
  It reads global cursor state; `cbSize` must be initialized and a zero return means failure.
- Microsoft, `CURSORINFO`:
  `https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-cursorinfo`.
  Flags 0 mean hidden, 1 means showing, and 2 means suppressed for touch/pen input.
  Suppressed is not accepted as evidence of game capture.

The fullscreen interpretation follows from these sources and Minecraft's existing normal/disabled
cursor convention; it is not a direct query of Minecraft screen identity. Let `inside` mean the
clip is wholly contained in the client, and let the desktop be the virtual-desktop rectangle:

| Clip and client | Visibility flags | Captured result |
|---|---|---|
| Any invalid rectangle | Any | Refuse, unchanged. |
| Clip differs from desktop, `inside` | Ignored; not read | `true`, unchanged. |
| Clip differs from desktop, not `inside` | Ignored; not read | `false`, unchanged. |
| Clip equals desktop, not `inside` | Ignored; not read | `false`, unchanged. |
| Clip equals desktop and client | Exactly integer 0, hidden | `true`. |
| Clip equals desktop, `inside` | Exactly integer 1, showing | `false`. |
| Clip equals desktop, client strictly contains it | Exactly integer 0, hidden | Refuse: GLFW capture would clip the entire client, contradicting this clip. |
| Clip equals desktop, `inside` | Missing, suppressed (2), combined (3), unknown or malformed | Refuse. |

Omitting the optional signal still raises a `ValueError` subclass for the formerly undecidable case.
The Win32 adapter catches only that subclass, checks foreground, initializes `CURSORINFO.cbSize`,
reads visibility, rereads the clip, and checks foreground again. Missing APIs, failed reads,
changed clips or lost foreground refuse before the screen gate can send input. This fallback
neither focuses a window nor sends any input. Diagnostic `status.pointer_captured` remains null
when unreadable; `require_screen` and conditional `close_screen` retain their existing behavior,
timeouts and pacing. Fullscreen on one monitor of a larger desktop stays clip-only.
