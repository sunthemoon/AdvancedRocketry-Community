## The predicate and the retirement proof's limit

The rejecting request guard is:

```java
!stepping && result == null && !recovering && !retentionSubmitted
    && (port.now() - requestedAt > 200 || !port.requestCurrent())
```

It is in [SealedDisassembly.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/sealed/SealedDisassembly.java),
lines 79-94. It ends an unretained request as REJECTED, even while other work is
backed off. [SealedWorkScheduler.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/SealedWorkScheduler.java),
lines 23-26, checks that guard before proof/work scheduling. The rejection is
not the ordinary proof's `slots=2` verdict.

`port.requestCurrent()` requires both the original authorization and the sealed
entity binding: [SealedDisassemblyWorld.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/SealedDisassemblyWorld.java),
lines 70-73. [RocketDisassemblyRequest.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketDisassemblyRequest.java),
lines 59-76 and 119-123, requires the same alive, operational entity, unchanged
snapshot/flight/position/consent, original request age and no release fence.
[SealedEntityView.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/SealedEntityView.java),
lines 59-65 and 131-142, additionally requires a live loaded binding and the same
flight/snapshot object references. [RocketTransferEntities.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketTransferEntities.java),
lines 55-58, defines loaded entity as alive, added to the world, in loaded entity
sections and still the Level's exact entity object. An unloaded saved entity
does not satisfy these predicates, although its complete disk image survives.

The ordinary retirement proof checks the frozen survivor, complete entity-slot
readback, redundant-copy absence, crew, guards and current proofs **before** T is
removed: [RocketOrdinaryRetirement.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketOrdinaryRetirement.java),
lines 512-534. Its acknowledgement callback calls `drop`, which releases flight
tickets, before invoking the landed continuation (lines 543-570).
[RocketDestinationRetirement.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketDestinationRetirement.java),
line 107, and `RocketTransferEntities`, lines 576-589, release both ends' recorded
ticket sets. It does not transfer a destination ticket to the sealed executor.
The standalone sealed entity adapter explicitly owns no tickets (`SealedEntityView`,
line 19). The two ordinary slots prove entity persistence, **not** continued
loaded authority, empty restoration terrain, a retained U, or completed disassembly.

The already-loaded-end check and preparation are separate again:
[RocketI6Entry.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketI6Entry.java),
lines 75-105 and 115-136, and [RocketI6Retirement.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/RocketI6Retirement.java),
lines 39-62. Completed preparation only leaves its finite ticket to expire;
it neither authorizes future destruction nor makes that ticket permanent.

There are other REJECTED branches, which must not be conflated with this guard.
`SealedDisassembly`, lines 120-125, rejects a nonempty preflight cell;
[SealedTerrain.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/SealedTerrain.java),
lines 75-82, defines EMPTY as air with no block entity. A preparation exception
before U exists and before restoration also rejects in
[SealedDisassemblyCoordinator.java](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/SealedDisassemblyCoordinator.java),
lines 379-394. C6 does not emit a per-branch rejection subreason. Attribution to
the lost loaded binding is a **control-flow inference** from the unload readbacks,
short request age, empty native landing cells, unchanged payload and the
destination-only controls, not a fabricated internal trace.

The `ARCE_ROCKET_SEALED_DISASSEMBLY` line merely reports the result
(`RocketDisassemblyRequest`, lines 97-116). `ARCE_DISASSEMBLY_DURABILITY_COMPLETE
... reason=REJECTED` is not success or a terrain-restoration certificate:
