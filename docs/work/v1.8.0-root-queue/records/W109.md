# W109: cargo C-A fluid devices

## Implementation scope and design

The assigned worktree is `D:/GitHub/arce-v180-w109`, branch
`codex/v1.8.0-w109`, initially clean at `e76492113c9114a1be354db9c0231ff1bde628f0`.
Only this record, new fluid cargo device/codecs/menu/screen/protection classes,
linker roles, their tests, appended registration/data-provider entries and
generated v1.8 output are writable. Other worktrees and processes remain untouched.

The implementation follows [W11CD](W11CD-DESIGN.md) sections 5 and 7 and the
existing ADR-065 cargo implementation note. The two block and block-entity IDs
are `rocket_fluid_loader` and `rocket_fluid_unloader`. The block fixes LOAD or
UNLOAD; schema-1 `arce_rocket_fluid_cargo` validates that role and the corresponding
SOURCE or DESTINATION escrow marker. Existing tank, binding, linker-selection,
carrier and native container-exchange codecs are reused without changing them.
Placement generates a fresh identity and applies W11b3's carrier-owner rule.

Local capabilities are direction-specific and lifecycle-bound. The owner's
container exchange is bidirectional and does not start escrow. The menu exposes
only scalar display data. Binding uses vanilla interactions, the existing linker
selection format and shared ten-tick item cooldown. Unsupported roots stay raw;
only observed native incompatibility invokes the existing terrain-save guard,
with its unchanged 256-coordinate Level saturation. Operational oversize is not
a save refusal. The native preflight reuses the bay's existing bounded check.

Admission, escrow mutations, C-P2 preparation/publication, C-E integration, C-D
art/models/recipes/provenance, item cargo, S2 cuts and shared status/ledger/build
files are not part of this task. No upstream code or assets are imported. No Gate
is marked passed. Root's independent read-only persistence review is still due.
