## Implementation and decisions

- Commit `a8085125b673618ec1e75a31aba5864ba879a860` makes assembly a continuation.
  It waits for the origin's entity section, assembles once, waits for the UUID to
  become visible, fills fuel and invokes the caller. Origin readiness and
  visibility share 20 ticks. Both discovery-test assemblies share one deadline,
  keeping its 230- and 21-tick delays inside the unchanged 280-tick timeout.
- Transfer waits use the existing `GameTestTickPacer` and loaded entities only.
  All original assertions execute on readiness or deadline expiry. The existing
  270-tick landing windows, 190-tick rollback windows, recovery retry limits and
  every existing test timeout are unchanged.
- Commit `7d4ae2ee6ea4b5afaadf14bd730375ddbf08f26d` corrects the Earth predicate to
  use the Overworld and waits for the installed station warp authority to report
  no motion before requesting the Tau Ceti warp. Bounded, read-only diagnostics
  remain inside the original 270-tick window. Native runs demonstrated that
  `LANDED` alone precedes the production warp guard's landing margin.
- No ADR decision, production code, registry, configuration, generated resource,
  status file or content ledger changed. These conservative fixture choices use
  the existing pacing design, rather than changing production timing.
