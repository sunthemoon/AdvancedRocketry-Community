## ADR choices where ADR-066 was open

1. **Impulse message.** The channel also carries an S2C `JetpackImpulsePacket`. Vanilla's motion packet replaces
   the whole client velocity, and the server has no horizontal player input. A server-set velocity would
   therefore erase horizontal momentum on every tick. The server computes and pays for the increment; the
   client adds it with the same capped arithmetic, and rejects values outside the server bounds.
2. **Motion estimate.** The server estimates motion from the player's last accepted displacement
   (`x - xo`). No ARCE packet carries velocity or height.
3. **HOVER.**
   - HOVER also needs a live heartbeat: it is hold-to-hover, with no autonomous hovering.
   - The target is 0.25 of the distance below the reference, per tick, within ±0.6.
   - The reference also resets when the intent expires or is released, in addition to the ADR's resets.
4. **`flight_speed_upgrade`.** It adds 20% of the paid increment along the accepted horizontal motion, and never
   pushes the horizontal speed above 0.8.
5. **Fall distance.** An upward paid correction resets the server fall distance, as vanilla slow falling does.
6. **Vehicles.** Thrust is refused while riding any vehicle. This includes every rocket seat.
7. **Intents.**
   - Switching the jetpack off is always allowed. Switching it on needs `equipment.classicEnabled` and a worn
     jetpack.
   - `CYCLE_MODE` is allowed while the jetpack is off.
   - If the worn jetpack, or HOVER's `hover_upgrade`, disappears, the jetpack is switched off rather than
     moved to another mode.
   - A respawn drops the session.
8. **Client input.**
   - The default key is J. Sneaking with the key cycles the mode.
   - Thrust is the jump key held in a suit chestplate. The client sends a heartbeat every 3 ticks, so at most
     7 per second.
   - The server window accepts at most 10 packets in any 20 ticks, and counts only accepted packets.
9. **Bionic legs.** One `MULTIPLY_TOTAL` 0.2 modifier with a fixed UUID. It is re-evaluated every server tick
   and on a LEGS equipment change.
10. **Padded boots.**
    - They act for `ServerPlayer` only, by cancelling `LivingFallEvent`. Ender-pearl damage is not a fall
      and is not cancelled.
    - The ARCE multiplier is read from `CelestialGravityController`'s transient gravity modifier.
11. **Configuration names.** The names follow the ADR coverage table. `equipment.lowGravityBoots` is registered
    as a server switch, so GameTests can override it in memory.
12. **Log expectations.** The `equipment` section already counted `classicEnabled` under the generic rule. So
    the rule excludes the two exact new keys rather than the whole section.
13. **Visors.**
    - The client reads its own worn helmet through the bounded codec; there is no S2C summary.
    - Anti-fog skips ARCE's fog-distance override outside the Space Level, and keeps the fog colour.
      `effects.atmosphericNausea=false` disables that override for everyone.
    - ARCE has no nausea visual yet, so there is no nausea to remove.
    - Earthbright lifts the lightmap with strength 0.7 through Forge's `adjustLightmapColors`, whatever the
      sky-override setting.

## Known risks

- **Flight kick.** Vanilla kicks a player who floats for more than 80 ticks unless `allow-flight=true`. This
  affects dedicated servers only, because the integrated server allows flight. The jetpack does not bypass this
  check; operators need `allow-flight=true` for sustained flight.
- **HOVER at high latency.** HOVER is a proportional controller fed by a displacement up to one round trip
  old, so it may oscillate at high ping. This needs V1/V2 evidence.
- **Client trust.** The client applies the paid increment itself. A modified client can ignore it, or move as
  it likes, which is the usual vanilla movement trust. The server still controls payment and permission.
- **Visors and the server switch.** Visor effects follow the client's view of its own helmet. They cannot see
  the server's `equipment.classicEnabled` switch.
- **Warning budget.** On a cold start the generic configuration-warning rule is now exactly at its maximum of
  99. Any further new COMMON key needs its own exclusion, as W02's ROCKET section has on its branch.
- **Merge conflicts.** Root will need to resolve conflicts with W02 in `CommonConfigTest` (exact count),
  `gametest_expected_log.json` (the generic rule's exclusion list) and the network protocol table.
