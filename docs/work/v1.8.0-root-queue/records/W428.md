## Design decisions

Schema 1 remains compatible with the original manifest. The extended form requires
both `mods` and `server_forge_args`; partial extensions, unknown fields, malformed
records and non-integer/unknown schema versions are refused. Each side has 1–256
unique mod records matching exactly its installed JAR inventory. Every listed file
must resolve inside the cell, exist and match its SHA-256. Candidate and optional JEI
records must identify listed client files. Forge arguments must match both the
declared hash and the selected server/Forge's `win_args.txt` location. External runtime
inputs remain permitted. Relative paths and uppercase SHA-256 values are normalized.

JEI detection parses only actual `mods` declarations with standard-library `tomllib`,
following the parsing rule reviewed in W425's unmerged `declared_mods` function.
There is no import from or dependency on W425's script. Optional dependency entries
and filenames do not establish installed JEI. A JAR without `mods.toml` does not
declare JEI; present but malformed metadata is refused. The metadata limit remains
1 MiB, with a maximum of 256 valid mod declarations. No ADR decision or exemption
was needed.
