enum to be `READY`, and `check_settlement` also requires `READY` for every head after the launch. In contrast,
the existing `EscrowFlightAuthority.finish` (lines 79-96) stores the terminal outcome `HANDED_OFF` in that head,
and `prune` (lines 100-104) preserves it. `EscrowGovernedHandoff.request` uses that production transition. The
existing `EscrowFlightAuthorityTest.readyHandoffReplacesThePositiveIdentityWithoutEditingAnyReceipt` covers
the terminal successor and a subsequent launch. The task row requires a governed launch, not a reset of its
terminal enum to `READY`. This source conflict is established; the aggregate assertion does not identify every
live value, so it cannot prove that this is the only failed conjunct or that native cargo was correct afterwards.

The runner correctly rejects a server that exits without its result marker even though Minecraft returned
process exit code 0. However, its wait-failure branch exits before raw decoding and before restart 2. Consequently
the failure retains the restart log but **not the restart-1 raw world files or crash report**; the owned server copy
was deleted by the required `finally`. That is an evidence limitation and a runner follow-up, not a recovered
state or acceptance claim. The first-cut failure remains intact. Neither oracle nor production code was changed
