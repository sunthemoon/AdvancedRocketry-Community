**Method.** One cut is one forced stop (the runner kills the JVM inside a fixed 30-second pause) followed by two
restarts, so three JVM starts. Each cut pins the source commit, the JAR's SHA-256 and the hook and harness files, and
an independent Python oracle decodes the raw ledger, journal, region and entity files after every start. The fixture is
W11CD section 6's: a rocket whose one pressurized tank holds 5,000 mB of water and an empty unloader (1,000 mB moves),
or the reverse for a load; the rocket also carries 1,000 mB of rocket fuel so that it can fly. A gated probe
(`EscrowCargoCutProbe`, inert unless the release-test hooks, a scenario and an `FS_` or `FF_` case are set) saves only
the BEFORE baseline and, for a held state, saves once before the operator previews, as an autosave would; between that
and the cut only production entry points act. An after-write cut stops after the file replacement and before its
callback, never at a graceful stop.

**C-S4, settlement (20 cuts),** for an unload with ACCEPT_CURRENT unless named. Scenarios: *applied* (the ordinary
executor is held right after both sides published, then the manual conflict), *neutral* (held at PREPARED, so the rocket
is the neutral survivor), *named* (neutral, with a COMMITTED landed record, so O3J removes it).
