## Implementation and design decisions

Part B is implemented first so the before/after workloads use exactly the same root-3
native-loader fixture. The base JAR is also exercised unchanged in normal mode; that
mode is known from W390 to lack its accounting baseline. Its failure is retained, not
treated as a valid timing run. The comparable before run uses only the benchmark
fixture/report correction on top of the base; no Part A production change is present.

The native-loader path retains the exact 1,000/4,000 resource checks, C0-C8 retirement,
operator O1-O4 and endpoint pruning checks. The obsolete unaccounted fixture is removed
from this gated benchmark. Attribution remains opt-in and uses the same fixture.

Part B is commit `09e671e0b7d04475d006fdc99c0d463ac90a16aa`. Its compilation, five
targeted Java tests and 15 Python runner tests passed. The unchanged base JAR failed
before measurement with `Legacy fluid component has no accounting baseline`. The
Part B-only normal start/recover run completed with all workload and performance checks.

Part A keeps a stack-local result, record/entity identity, observation, binding identity
and both server and Level clocks. A missing or HELD result, changed identity, observation,
clock or binding recomputes. The small binding witness reads the existing map only; it
does not capture, serialize, move, acquire authority or issue a permit. Landing, terminal
authority and the first-event completion seam are unchanged. A package-local execution
seam lets the GameTest count calls to the real arrival executor and place observation
cuts immediately after the real F4 or F5 action; no global probe or product counter is added.

The three new unit tests passed alone. The new `escrow_arrival_single_call` GameTest
passed alone on its third development attempt. It drives the real governed dispatcher
with installed bays, checks one warm computation, two after each F4/F5 serialization
cut, two after a real HELD attempt, and one for LANDED. It checks that the binding
witness neither captures nor serializes, then completes first-event acknowledgement,
landing and F8/pruning. It reuses the existing single-Level governed-flight fixture on
the Moon, with a plan that changes logical body, as the existing Earth fixture does.
The first two attempts had invalid fixture plans (source location mismatch, then no
logical-location change); neither was an executor failure or an assertion relaxation.
