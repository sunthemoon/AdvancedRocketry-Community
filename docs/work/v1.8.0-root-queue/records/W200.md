# W200: residual I6 admission and write-back cost

## Design note, before implementation (2026-10-29)

This worker starts from `2256044ad51e31a7b46d4f164555353422ae85a6` on
`codex/v1.8.0-w200`. Its write scope is I6 admission/preflight pacing, transfer
insertion validation/put, their tests, measurement runner support, and this
record. No other worktree, ADR, status file, ledger, build configuration,
numerical proof bound, request lifetime, timeout or budget will change. No
upstream code or assets are imported.

The existing bounded ordinary-retirement queue will retain a confirmation's
original request, not new consent. Its I6 destructive demands receive at most
one admission/preflight work turn per server game tick, including repeated
coordinator visits. The expensive sealed-plan and restoration preflight checks
move from the confirmation callback to that turn, before the destination scan
can discard anything or capture a proof. Existing record/identity/authorization
checks still guard enqueueing, and the tick rechecks current request, identity,
record, world availability and interlocks before work. Deferred work neither
loads chunks nor holds a reservation between ticks. A failed preflight ends the
request without mutation; the terminal preflight and retained-executor recheck
remain independent, fresh checks. The 64-pending limit, four-attempt limit,
100-tick proof deadline and original 200-tick request age remain unchanged.
For players, a burst returns pending immediately; invalid terrain/plan feedback
may arrive asynchronously, and expired requests still require fresh consent.

Write-back validation will retain only a journal-local, single-use checked
candidate witness, bound to the exact immutable record object and mutation
sequence. The checked encoding is produced once by the existing codec and all
record/root bounds still run. `put` may reuse that check only for the same
candidate, unchanged journal and canonical-resident witness established by
W199. A different candidate, intervening mutation or failed validation falls
back to ordinary encoding. Identity/conflict/capacity checks still run at put;
this witness is not durable acknowledgement, a reservation or removal authority.
Loaded unproven residents still require the exact full-root validation. Nothing
changes for players except reduced synchronous serialization cost; there is no
new saved format, save refusal or recovery policy.

The W197 before/after runs use its unchanged real 64-command burst, native
whole-tick measurement and maximum fixtures under the heavy-JVM lock. New
tests will fail against the old behavior first, then run alone; the entire unit
suite and three I6/sealed batch runs follow. Hosted full GameTest and independent
review remain Root's work, and no performance or version Gate is approved here.
