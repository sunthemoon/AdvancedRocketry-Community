# W200: residual I6 admission and write-back cost

## Design note, before implementation (2026-10-29)

This worker starts from `2256044ad51e31a7b46d4f164555353422ae85a6` on
`codex/v1.8.0-w200`. Its write scope is I6 admission/preflight pacing, transfer
insertion validation/put, their tests, measurement runner support, and this
record. No other worktree, ADR, status file, ledger, build configuration,
numerical proof bound, request lifetime, timeout or budget will change. No
upstream code or assets are imported.

The existing bounded ordinary-retirement queue will retain a confirmation's
original request, not new consent. Its I6 destructive demands receive at most
one admission/preflight work turn per server game tick, including repeated
coordinator visits. The expensive sealed-plan and restoration preflight checks
move from the confirmation callback to that turn, before the destination scan
can discard anything or capture a proof. Existing record/identity/authorization
checks still guard enqueueing, and the tick rechecks current request, identity,
record, world availability and interlocks before work. Deferred work neither
loads chunks nor holds a reservation between ticks. A failed preflight ends the
request without mutation; the terminal preflight and retained-executor recheck
remain independent, fresh checks. The 64-pending limit, four-attempt limit,
100-tick proof deadline and original 200-tick request age remain unchanged.
For players, a burst returns pending immediately; invalid terrain/plan feedback
may arrive asynchronously, and expired requests still require fresh consent.

Write-back validation will retain only a journal-local, single-use checked
candidate witness, bound to the exact immutable record object and mutation
sequence. The checked encoding is produced once by the existing codec and all
record/root bounds still run. `put` may reuse that check only for the same
candidate, unchanged journal and canonical-resident witness established by
W199. A different candidate, intervening mutation or failed validation falls
back to ordinary encoding. Identity/conflict/capacity checks still run at put;
this witness is not durable acknowledgement, a reservation or removal authority.
Loaded unproven residents still require the exact full-root validation. Nothing
changes for players except reduced synchronous serialization cost; there is no
new saved format, save refusal or recovery policy.

The W197 before/after runs use its unchanged real 64-command burst, native
whole-tick measurement and maximum fixtures under the heavy-JVM lock. New
tests will fail against the old behavior first, then run alone; the entire unit
suite and three I6/sealed batch runs follow. Hosted full GameTest and independent
review remain Root's work, and no performance or version Gate is approved here.

## Native measurements and remaining cost

Both runs used Windows 11, Ryzen 5 5500, 32 GiB, Forge 47.4.10, Java 17.0.7 and
`-Xms512M -Xmx4G`. Both retained 64 maximum snapshots, 2,048 blocks and 128 barrel
payloads per snapshot, 1,048,576 serialized bytes, 32,768 volume, 16 discovery
columns per end and a 20-slot downstream sealed plan. All 64 were prepared and
handed off across four fresh-consent rounds; both had 140 confirmed captures,
zero refused captures and 84 expired/not-current requests. Accepted handoff is
not completed terrain restoration: the same four downstream `REJECTED` results
remain, outside W200's terrain scope.

All values below are whole server-tick milliseconds, including early journal
callbacks, not only observed port time. Columns show mean / P95 / P99 / maximum.

| Window | Before | After |
|---|---|---|
| Cold preparation | 11.423 / 17.413 / 40.030 / 40.030 | 12.199 / 20.015 / 48.698 / 48.698 |
| First proof round | 8.832 / 14.443 / 51.194 / 267.051 | 8.405 / 17.278 / 36.462 / 166.668 |
| All proof rounds | 8.794 / 15.310 / 42.183 / 287.813 | 7.843 / 15.577 / 40.426 / 166.668 |
| First-round substantive work, 42 ticks each | 17.987 / 42.183 / 97.883 / 97.883 | 18.253 / 29.235 / 93.039 / 93.039 |

The actual first-round 64-command admission tick fell from **97.883 to 23.338
ms**; its commands occupied 91.689 versus 16.253 ms. The harness did not spread
the commands. Expensive admission work now runs inside the existing tick queue,
with at most one observed `prepare` invocation per tick. The new deterministic
unit bound also covers repeated same-tick visits and invalid preflights.

The largest write-back/proof-window tick fell from **287.813 to 166.668 ms**.
The after maximum is tick 1306: 8 of its 10 server-thread JFR samples include
`validateWriteBack`/`validateInsert` and NBT sizing, with 15.988 ms of overlapping
GC pause. These are sampled stacks, not exact CPU attribution. **Five proof
ticks still exceed 100 ms**, versus seven before. The requested duplicate
candidate encode is removed, but validation/callback cost is not eliminated.
No claim is made that every worst-case tick is now below 100 ms.

Against [docs/17](../../../17-V1PLUS-QUALITY-BUDGETS.md), the measured cohorts
meet mean 25 ms, P95 50 ms and P99 100 ms numerically; neither run exceeds the
500 ms spike target. These are percentile targets, not a new universal 100 ms
maximum. Peak RSS was 4.020/4.198 GiB before/after, with no native ERROR/FATAL,
watchdog or OOM. Each run had one setup overload warning. Other-process CPU
mean/P95 was 11.69%/37.86% before and 2.54%/5.34% after, so this pair is not an
isolated causal speedup measurement. Proof-attempt P99/max changed from 25/25
to 23/23 ticks; admission-to-terminal P99/max stayed 184/184. Peak active proofs
were 4 and 3, still within the unchanged limit of 4.

The ordinary proof census has two origin slots, not a maximum duplicate-entity
census. The synthetic flat-world fixture forces its warm proof columns and does not
qualify unexpected-loading behavior, a Debian reference node, the full
player/device/station/satellite load, periodic restart or four-hour soak.
**The current version's complete Required Gates are not satisfied or approved.**
Root's independent review, hosted full regression, and a decision on the
remaining v1.8 validation/callback cost are still required; W198 owns terrain.

## Root's correction at merge (W200-R1)

The statement above that the measured cohorts meet the mean/P95/P99 targets applies only to the selected cohorts, not to all residual callback work. The after-run work classifier excludes every one of the five proof ticks above 100 ms: tick 1306 = 166.6683 ms, 2071 = 161.6724 ms, 2159 = 100.6112 ms, 2822 = 119.1069 ms, and 3557 = 146.6983 ms. Their only step samples are `releaseTickets`, which is absent from the inherited `substantive` set; consequently none enters the 42-tick first-round or 148-tick all-round work cohort. Whole-tick proof windows retain them. This is a coverage limitation, not a W200 harness change or missing raw measurement.

As a sensitivity supplement only, the union of work and observed `releaseTickets` ticks has 165 samples across all rounds, with mean/P95/P99/max of 20.2467/65.8756/161.6724/166.6683 ms; the first-round union has 46 samples at 22.5176/65.8756/166.6683/166.6683 ms. This is not exact write-back attribution and does not replace the original summaries. Docs/17's 100 ms is a P99 target, not a universal maximum; one 166.6683 ms tick alone cannot establish a P99 failure, while the supplemental P95/P99 exceed 50/100 ms numerically. Residual callback cost remains open, and neither cohort closes R-035, G7, or any version Gate.
