The [fixture README](../../../../intent-test-mod/README.md) contains build and
trigger instructions, 15 case definitions, authoritative R/C/M/L readbacks,
all 28 menu IDs, all three C2S matrix rows and the four block-use rows, and
explicit NOT_COVERED branches with existing test references. It distinguishes
A0 unit references from A1 GameTests and identifies missing A1 coverage rather
than inventing a test result.

The eight-channel pin actually contains only three C2S messages. The product
already registers/negotiates all eight; cached Forge 47.4.10's `NetworkRegistry`
rejects duplicate registration. The fixture therefore uses the existing
registrations through standard client custom-payload packets, with the exact
discriminator and independently encoded pinned fields. The other five channels
remain S2C-only. It imports no product classes, not even API classes, and adds
no access transformer or server hook. This conservatively resolves the TASK's
"registers for eight" wording without breaking normal product registration or
inventing a C2S channel. No product protocol or persistence format changed.

F8 captures one real menu/target; F9 queues one packet, at most 156 bytes, with
UTC/monotonic time, player/menu/target identities, fields and payload hex in the
client log. A capture expires after 120 seconds and is consumed on send. All
cases share a two-second cooldown and 32-send connection cap. Disable/re-enable
does not reset that cap. Logout clears the connection state; dimension changes
invalidate the retained capture. There are no automatic sends/retries/bursts.

The implementation deliberately reports the actual early menu refusal for
stale/range flight probes, not an inner ENTITY_UNAVAILABLE/OUT_OF_RANGE that
normally cannot be reached. It does not call client queueing a server receipt.
Server messages/logs are expected only where the source emits them; unchanged
protected server state and loaded-chunk readback remain campaign obligations.
No upstream assets/code were imported and no save-refusal mechanism was added.

## Remaining scope and risks

Client/server qualification is not part of this task and was expressly not
started. The fixture is never shipped. Normal menu slot/button/block-use
operations, intentional malformed packets, server rate-limit bursts, callback
faults, client cache/S2C injection and G03 same-tick claim proof are not added.
Their README entries remain NOT_COVERED (or NOT_APPLICABLE for self-only motion
distance/foreign-target cases), not implicitly passed by builder tests.

The probing account's actual ownership, operator level, station membership,
equipment state and forbidden-target properties must be established by the
campaign. Local guards cannot establish server authority; incorrect negative
setup could perform a legitimate action. Silent drops cannot be established by
absence of a log. No-extra-loaded-chunks requires a real server observer, not
client render distance. Development version equality is not a substitute for
pinning the tested product JAR/hash. Any missing late-S2C/cache A1 subbranch is
recorded as a gap, not mislabeled as GameTest coverage.

This does not satisfy all v1.8.0 Required Gates G0-G9 and changes no Gate status.
The next work is Root review of these local commits and K18 qualification in
the current v1.8.0 campaign, retaining actual client receipts and authoritative
server readbacks for each reached branch.
