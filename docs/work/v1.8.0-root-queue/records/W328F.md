- **Hint tests** (`PresenceUnknownHintTest`, 7 tests). They use real refusals from the migration service and the same
  injected status check:
  - an unknown rejoin presence;
  - an unreadable data directory (every status under it unknown), with and without a ledger, which keeps the rejoin
    precedence;
  - an unknown data directory alone, in a plain world and in a ledger world;
  - an unknown ledger or receipt presence, and an unknown stations presence in a ledger world (escrow hint);
  - an unknown stations presence in a plain world (migration hint).

  Each line is compared in full: the storage hint, then today's hint. Malformed stations, stations-with-ledger and rejoin
  files keep exactly today's line, compared with literal strings.
- **Lookup guard** (`EscrowLedgerLookupTest.offTheServerThreadOrWithoutAnOverworldTheLookupNeverTouchesStorage`). Off
  the server thread, with or without an Overworld, and on the server thread without an Overworld, the answer is
  NOT_LOADED, and neither the storage supplier nor the runtime supplier is called (both throw). On the server thread
  with an Overworld, storage is read once per lookup, and the runtime only for a missing root.

## Choices where the task left room

- **Read seam (item 1).** The TASK allowed a read seam. It is a parameter added to the existing package-private test
  constructor chain, so production behaviour is unchanged. Hashing still reads each file after decoding, as before.
- **Diagnostic order (item 1).** The unsafe-path and regular-file checks moved into the preflight. So a world with a
  malformed earlier file and a symbolic or non-regular later managed path now reports the later path's `UNSAFE_PATH`
  first. Both refuse startup without a write, and no existing test depended on the old order.
- **Hint text (item 2).** The storage instruction is one sentence followed by "If repair is still needed after that:",
  and today's hint follows unchanged. It is added in all three branches (rejoin, escrow and migration). The hint is now
  computed once per refusal instead of up to three times; the text is the same. An escrow line with the storage hint is
  one fixed line of at most 540 characters and still has no stack trace. The older escrow-line test's 512-character
  check covers refusals with a free-form reason, not this fixed one.
- **Lookup (item 3).** Off the server thread, a lookup now answers NOT_LOADED even when a root is loaded; before, it
  answered LOADED there. Every production caller runs on the server thread, so nothing changes in production.
  `server.overworld()` is read only on the server thread.
- **Fence test (item 5).** For ordinary records, the paths into the private `fence` method (`joined` and
  `actionAllowed`) need a `MinecraftServer`, because `classify` calls `RocketEscrowGate.logicalLocked(server, ...)`. The
  test therefore reaches `fence` through the package-private `classifyGoverned` with the governed fixture, as existing
  tests do, and the reevaluation path through `reevaluate`. No production seam was added.

## Known risks

- **Off-thread lookup.** A future off-thread caller now always gets NOT_LOADED, the protective answer, even with a
  loaded root.
- **Diagnostic order.** An operator may now see a later file's refusal first (an unknown presence or an unsafe path)
  while an earlier file is also malformed. The next start after the fix then reports the earlier file.
- **Fence WARN volume.** The code is unchanged and now described correctly. Under NOT_LOADED the WARN repeats with joins
  and leaves of a fenced rocket, at most two WARNs per record per 1,200 ticks, with no per-session total (R397).
- **File size.** `WorldDataMigrationService.java` is now 556 lines (523 before), over the 500-line review mark of
  AGENTS.md section 3.4. It still holds one responsibility, the pre-start migration transaction; the growth is the
  preflight and the seam.
