## Step 0 findings

W123 extracted the replacement and exception-time readback algorithm into
`CheckedJournalCheckpoint`. `RocketJournalCheckpoint` remains its transfer-specific
adapter and `RocketJournalWriter` remains a fixed-target asynchronous writer. The
sidecar can compose the shared checkpoint without rebinding either journal or
introducing a new general writer framework. Staging force, bounded readback,
atomic replacement and directory force remain as specified; normal completion
and exception-time exact-candidate readback are distinct acknowledgement paths.
Only the owner publishes asynchronous results. An UNKNOWN result clears proof;
a later pre-replacement failure does not establish new proof.

`RocketJournalFirstWrite` now retains the attempted digest across an UNKNOWN
first write, allowing reconciliation of its own appeared candidate but never an
unrelated file. The sidecar must use the same ownership distinction. Startup
`WorldDataMigrationService.discoverSources` still uses `Files.exists`, unlike the
checked writer's three-state presence test; explicit sidecar presence handling
is needed to implement the frozen unknown-presence refusal. The migration event
already runs at `ServerAboutToStartEvent`, before level/recovery/login work.

Journal root remains 3 with epoch `v1.8.0-first-moon-landing`. Migration adds an
EMPTY outbox only for roots 1 and 2. Governed per-record schema 3 does not change
the journal root, and W11b2 does not provide a sidecar writer or enable W80.
No storage-contract change has been identified. The existing recovery hint is
also insufficient for a sidecar-only world: it must require whole-world repair,
not restoration of the managed-file migration backup alone.
