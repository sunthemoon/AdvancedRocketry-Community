## What the tests check

- **N1.** `broadcastChanges` now calls `planPacket(navigation)`, which reads `activePlan()` and `padName(plan)` and builds
  the same `RocketFlightPlanPacket` as before. The call order is unchanged (`navigation()`, then `activePlan()`, then
  `padName`), and so are the equality check, the send and the catalog sync. In the remote unloaded case, the GameTest now
  calls `menu.planPacket(RocketNavigation.empty())`. It asserts that the packet's plan is the player's recorded choice and
  that its `padName()` is `"Venus Dock"`. The navigation is passed in as `empty()`, so the test does not depend on
  whether the unspawned fixture rocket counts as a valid console.
- **N2.** The test encodes a named-pad frame with an empty name, then replaces the name with two over-long strings: 33
  characters (inside the 96-byte encoded bound, over the 32-character bound) and 97 bytes (over the encoded bound). Each
  frame stays within `MAX_ENCODED_BYTES`. The test expects `io.netty.handler.codec.DecoderException`, which only
  `readUtf(LandingPadEntry.MAX_NAME_LENGTH)` throws here. The record constructor's `checkedName` would throw
  `IllegalArgumentException` instead, so a loosened read now fails the test even while the constructor check remains.

No production behaviour, packet layout, protocol version (`rocket_flight` stays 10), network channel or expected-log
entry changed.
