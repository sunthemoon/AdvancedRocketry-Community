- `cba71b458`: [flight runner](../../../../scripts/run_v100_flight_forced_stop.py)
  and [line-backed tests](../../../../tests/test_run_v100_flight_forced_stop.py).
  `--journalled-launch-receipt` defaults off and leaves the shared legacy helper
  unchanged. The pending receipt must match the refuelled physical and logical
  rocket, route, checkpoint and fuel. Its subsequent `ARCE_TRANSFER_PREPARE`

  Both waits share the original 30-second launch budget. The pause, recovery,
  fuel, authority and disassembly checks remain required.
- `e3789e1ff`: make the default-mode test actually emit the pending answer after
  the command, asserting the original launch refusal rather than a missing log.
  No product source or existing assertion was relaxed.

C6's `RocketOrdinaryLaunch.prepare` submits the PREPARED transfer through
`RocketTransferSavedData.afterAcknowledged`. On the owner-thread acknowledged
callback it starts countdown, then invokes `RocketTransferService`'s prepared
consumer, which calls `RocketTransferAudit.auditPrepare(...SUCCESS)`. This is
the accepted-launch confirmation, unlike the immediate admin command answer
`Release-test launch failed: JOURNAL_PENDING`. A refusal or mismatched outcome
before that confirmation fails the opt-in mode. The isolated admin fixture has
one request; this is not a general concurrent-launch log oracle.

No new ADR decision, source import, save schema or network protocol is introduced.
No `src/`, build script, state file, ledger, sealed source, other worktree or
other task file is changed. No subagent, client, push, merge or tag is involved.
