The supplied hosted log has the expected SHA-256
`5ac00747e2f6dccc431c54bd6623bebd3657bfcdd741bb7ca238f67baba68274`.
The batch starts at 16:25:08.890 UTC and reports the failure at 16:25:21.990 UTC.
There are 1,800 progress bars before line 14113, followed by the failure at line
14115 and progress bar 1,801. `GameTestServer.tickServer` prints progress at each
20th overworld tick, and this fresh-world run has no GameTest that changes game
time. This reconstructs a 36,000-tick autosave boundary at 16:25:20.690 UTC and a
refusal by tick 36,020. `MinecraftServer.tickServer` calls `saveEverything` every
6,000 ticks; `ServerLevel.save(..., false, ...)` invokes entity-manager `autoSave`.

That autosave is a strong candidate for the superseding writer. Entity autosave
calls `storeChunkSections` for loaded slots, including empty loaded slots, without
the terrain cooldown. `EscrowEntityStore.storeEntities` observes those stores even
when vanilla suppresses an empty disk write. The existing terrain precondition
therefore cannot protect the entity barrier. The old comment also assumed that a
10-second wall-clock cooldown covered both proof windows. The batch lasted 13.1
seconds, but the log does not show when the pre-save or either capture occurred;
batch duration is not proof-window duration, so cooldown expiry is not established.

The historical log records neither the failing endpoint kind nor a save stack.
Accordingly, this record does not claim a uniquely observed terrain-versus-entity
writer for that historical failure. Temporary test-only tracing compiled, but its
baseline GameTest never started because the machine lock was occupied. The trace
was removed before the implementation commit. Its patch/helper remain development
diagnostics, not acceptance evidence.

The other `escrow_core` tests do not directly save the failing slot: the positive
joint test uses block position `(530001, 100, 530001)`, the negative tests use their
template positions, and reconciliation fixtures use positions starting at
`(681008, 100, 681008)`. None invokes a Level-wide save. The failing fixture is in
chunk `(32500, 32500)` at block position `(520001, 100, 520001)`; terrain and entity
generations are separate monitor slots. Reconciliation already uses product retry
scheduling. `EscrowGovernedReturnGameTests` and `RocketSettlementIdleGameTests`
already re-request proofs rather than requiring one-shot confirmation; their
existing retry policies were not changed. The joint terrain positive case can
