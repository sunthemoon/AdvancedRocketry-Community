**B3-U.**
- `EscrowAdmissionAuthority.Delegate` is one consumer's registered index, with the states NOT_LOADED, NO_FILE and
  LOADED. NOT_LOADED reports `Index.loaded` false, so `tryReserve` returns UNAVAILABLE for every consumer. NO_FILE is
  loaded and empty. LOADED reads the attached store's index. `register(consumer)` creates a delegate through the
  unchanged `registerIndex`, so a second registration still throws. The authority still sees only `Index`.
- `retarget(store)` attaches a store, or with null returns to NO_FILE. It returns false, and changes nothing, while
  a different attached store holds queued, captured or UNKNOWN work (the coordinator's queue is not empty or its
  writer is not idle).
- `EscrowRuntime` owns the authority and registers the one PROPULSION delegate. At `ServerStartingEvent` it runs the
  load-only `ResourceEscrowSavedData.existing` and binds an existing ledger at once; with no file it sets NO_FILE.
  The runtime tick's own lookup and bind are unchanged and now find the coordinator already bound.
- `EscrowCoordinator` takes the delegate and attaches its index (the ledger's records, the queue and the writer's
  captured operations, as the old constructor gathered them). It never registers. `ResourceEscrowSavedData.bind`
  passes the runtime's delegate.
- `EscrowRuntime.replaceLedgerForTests(server, ledger)` is the only path that replaces the ledger SavedData. It is
  gated by `EscrowTestEndpoints.requireEnabled`, retargets the delegate on the owner thread, and returns false
  without throwing while the attached coordinator holds work. `forTests` creates its ledger through it, and the
  swap and restore in `RocketJournalInterlockGameTests.noLedgerLandedBoardAndRefuelSurviveAnotherTransfersWrite` use
  it (the test now asserts that both succeed).
- The Javadoc now says "runtime-owned" for `EscrowRuntime` and the authority, and "ledger-owned" for the coordinator.

**`prepareFill`.**
- `Fill prepareFill(EscrowNativeBinding.Admission capture, Consumer<Boolean> completion)` takes the validated,
  immutable native capture. It refuses, as a typed `Fill` result, a closed or unavailable ledger (UNAVAILABLE); an
  operation that is not a fresh `FLUID_PROPULSION_FILL` with a complete `FUEL_VECTOR_V1` binding (INVALID); a
  sequence other than the next one or an ID that is already queued, captured or durable (STALE); a frozen frontier,
  a pending flight write or any ARMED entry for the rocket (ENDPOINT_BUSY); then the pure check's refusals; then the
  authority's SERVER_FULL, ROCKET_FULL and IDENTITY_CONFLICT. Only then does the shared queue core run.
- `fillRefusal(root, queued, capture)` is the pure check: a capture whose section names another ledger is STALE;
  `requireAdmission` (the five-marker limit against the same capture) gives ROCKET_LIMIT; the candidate preflight
  `preflight(prospective, candidate)` gives ESCROW_FULL. It is static and mutates nothing, so the first-fill path
  of B3-E can run it against `EscrowLedger.empty(id)`. It uses W11b2's checks as merged and adds no capacity rule.
- `prepareTest` keeps its checks and exception messages; only its last three lines moved into the shared
  `enqueue`. `productionAdmissionEnabled()` still returns false, and nothing calls `prepareFill` outside tests.

## 6. Choices where the design was open

- **Registration time.** The delegate registers at `ServerStartingEvent`, or at an earlier ledger bind if one
  happens: several existing paths (`RocketEscrowAudit.observe`, `RocketEscrowGate`) bind lazily, and an entity
  loaded or saved while the Levels prepare could reach them before that event. The authority is created on the
  server thread in both cases, and there is still exactly one registration. If such a bind happened, the startup
  lookup finds the delegate already LOADED and does nothing more.
- **A ledger file that did not load.** Vanilla's `DimensionDataStorage` logs and returns null for a file it cannot
  read. Then the delegate stays NOT_LOADED, so admission refuses, and the runtime logs one WARN line,
  `ARCE_ESCROW_LEDGER_NOT_LOADED`. The pre-start check normally refuses such a file before this point, and
  GameTest worlds start without a file, so the line is not expected in any current run.
- **"Holds work".** Queued admissions, or a writer that is not idle, which covers captured and UNKNOWN candidates.
  Durable records of a detached test ledger leave the union while it is detached and return when it is restored;
  only test hooks detach a ledger, and the replaced coordinator stays open, as before.
- **Direct construction.** A coordinator constructed on a delegate that another ledger's work holds throws; this is
  an invariant, not a control path. The runtime method checks first and returns false, so it never throws. The
  two-argument constructor, now package-private, gives a detached coordinator its own authority, for unit tests and
  the gated `EscrowReconciliationGameTests` fixture, as before.
- **`prepareFill`.** It is package-private, because no device calls it; B3-E decides its final visibility. It
  requires a complete `FUEL_VECTOR_V1` binding, because a fill always targets a rocket's fuel vector; it cannot yet
  check that the source is the loader, whose signature kind B3-E registers. The typed result maps the authority's
  ALREADY_HELD to STALE, because `prepareFill` has already refused an ID that any index holds. `fillRefusal` maps
  every refusal of `requireAdmission` to ROCKET_LIMIT and every refusal of the preflight to ESCROW_FULL, including an
  ineligible merged component; B3-E maps these to the player statuses.

## 8. Known risks

- The early bind runs the writer's baseline check at `ServerStartingEvent` instead of the first tick. A failure there
  still only marks the ledger unavailable with the writer's one existing WARN line. Native restart cuts that inspect
  the first tick were not rerun here.
- `replaceLedgerForTests` refuses rather than drops held work, so a test that swaps the ledger while another test in
  its batch holds work now fails with "Ledger removal refused while escrow work is held" instead of silently dropping
  reservations. `RocketJournalInterlockGameTests` runs alone in its batch.
- `fillRefusal` classifies refusals by which check threw, not by message. If W11b2's checks add a new refusal reason,
  it is reported under the existing category until B3-E maps it.
