## Design decision and changed files

[ADR-024](../../../decisions/ADR-024-STATE-BASED-ATMOSPHERE-BOUNDARIES.md) explicitly
defines extension callback timing. Those limits remain unchanged: 5 ms per returned
callback and 1 second accumulated per registration. No ADR decision, API signature,
API version, timeout or performance budget was changed.

- `compat/atmosphere/ConstantAtmosphereBoundaryProvider.java` is a final record
  containing one non-null boundary enum. It cannot contain an arbitrary callback.
- `compat/atmosphere/AtmosphereBoundaryRegistry.java` expands that exact internal
  value directly, without invoking a provider or consulting the clock. Existing
  ownership, claim, provider/block/state caps, atomic publication and lifecycle
  checks still apply. Other provider implementations retain all timing and failure
  checks. There is no owner-namespace exemption.
- `forcefield/ForceFieldBoundaries.java` registers its existing `SEALED` rule using
  the constant value. The existing common-setup event flow remains unchanged on
  both physical sides; the startup caller needed no edit.
- `AtmosphereBoundaryRegistryTest.java` adds three tests. The actual force-field
  registration succeeds with injected delays exceeding either timing threshold and
  never reads the clock. Additional checks cover constant-rule state caps, atomic
  claims, compiled values, null rejection and timing enforcement for arbitrary
  callbacks using the host's own IDs. All thirteen existing tests are unchanged.
- [The API guide](../../../PUBLIC-API-GUIDE.md) explains the internal optimization
  and the unchanged extension contract. This record is the only task documentation
  added; no status file, ledger, queue or build script was changed.

This approach bounds the host's constant expansion by state count rather than
machine speed, without trusting arbitrary code merely because of its namespace.
