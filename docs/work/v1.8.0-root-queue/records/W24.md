The legacy selector's `available` check is now a wrapper over a new
`unavailable` method that returns a reason. After the existing terrain, bounds,
chunk and support checks and the existing entity-box query, it runs W13F's
bounded discovery and compares the arrival region with every discovered
rocket's snapshot extent. Both the initial selection and the pre-spawn recheck
in `RocketTransferService.spawnDestination` use this method, so both see a wide
parked rocket whose entity box misses the arrival.

The legacy selector's contract is kept and stated as follows:

- **Fixed surface pads (`select`)**: an overlap skips the candidate, and the next
  of the eight fixed pads is tried, as before. If every pad fails, the existing
  generic `LANDING_PAD_UNAVAILABLE` message is shown.
- **The station's own pad (`selectStation`)**: there is one candidate, so an
  overlap is a refusal with the translated reason
  `message.advancedrocketrycommunity.pad.reason.occupied`.
- **Pre-spawn recheck**: an overlap returns the rocket to its source with the
  existing `destination_pad_blocked` outcome. No destination entity is created,
  and the source keeps its undebited fuel.
- **Discovery budget**: W13F's 64-rocket bound applies. Exceeding it refuses
  with the translated `...pad.reason.entity_budget`. Fixed-pad selection stops at
  the budget rather than trying the remaining pads, because all eight pads lie
  within 64 blocks of each other and share nearly the same discovery region.

The legacy path never creates pad claims. A refusal before preparation creates
no transfer journal record; a pre-spawn refusal removes the prepared record.

To show the translated reason, `RocketLandingPadSelection.refusalKey()` returns
the detail only when it is a `message.advancedrocketrycommunity.pad.reason.*`
key, and `prepareLaunch` passes that to the result for both paths. Named-pad
details are always such keys, so named behaviour is unchanged. Other legacy
details remain English audit text and are still not sent to players.

## Reuse of W13F's code

`NamedLandingPadOccupancy` now serves both paths. Its existing method and the
`discoveryBox` signature are unchanged for named pads. Two additions:

- an overload taking a predicate for ignored rockets, which keeps the legacy
  `allowMatchingRocket` parameter working (an ignored rocket still counts
  against the budget);
- a null station, which leaves discovery unclipped horizontally for surface
  levels that have no station region.

The class keeps its name so W13F's unit test compiles unchanged.

## Tests

The GameTests use R1's geometry: a three-wide, one-deep, three-tall arriving
rocket, and a parked rocket whose origin is ten blocks west of the pad centre and
whose structure runs sixteen blocks east (X=0..15), so it covers the arrival
while its 1.5-block entity box does not. Each test asserts that geometry.

1. `wideParkedStructureRefusesUnnamedStationPadButNearMissIsAccepted`: a really
   scanned and assembled, never-flown wide rocket on a station's own pad. An
   unnamed station flight through `prepareLaunch` is refused with the translated
   `occupied` reason; no journal record or Space rocket is created; the source is
   unchanged. The same structure relocated to end one block before the arrival is
   then accepted.
2. `wideParkedStructureAppearingAfterPreparationRefusesUnnamedPreSpawn`: the pad
   is empty at preparation; the wide rocket is assembled afterwards. The recheck
   states `occupied`; the real `spawnDestination` returns the rocket to its source
   with its undebited fuel, creates no destination entity and removes the record.
3. `unnamedStationDiscoveryAcceptsItsLimitAndRefusesOverflowWithoutLoading`:
   exactly 64 non-overlapping rockets are accepted; the 65th makes `prepareLaunch`
   refuse with the translated `entity_budget` reason, with nothing created and a
   cold chunk in the station region still unloaded.
4. `fixedPadSelectionSkipsAWideOccupantAndStopsAtTheDiscoveryBudget`: on the
   Overworld fixed pads, a wide occupant over the first available pad makes the
   recheck state `occupied` and selection choose a later pad that does not
   overlap it. With at least 65 rockets in range, selection stops with the
   translated `entity_budget` reason.

Loading waits use `GameTestTickPacer`. As in W13F, an owned test-only region
ticket keeps the fixture chunks loaded and is removed during cleanup.

## Choices where the task was open

- **Discovery reach on surface levels.** W13F's reach (`MAX_BOUNDING_VOLUME - 1`,
  32,767 blocks) is reused unchanged. Outside Space there is no station region to
  clip to, so the box spans that reach horizontally around the arrival, clipped
  only by height. The lookup still visits only loaded entity sections and never
  loads chunks.
- **Space rechecks.** `selectStation` and the pre-spawn recheck both clip
  discovery to the committed station whose region contains the arrival (found
  with the existing `StationRegistrySavedData.findAt`). If no station contains it,
  discovery is unclipped, which is stricter.
- **The old entity-box rule is kept.** A rocket whose entity box intersects the
  arrival still blocks it, now with the `occupied` reason. Removing that rule would
  have relaxed other pad behaviour.
- **Budget on fixed pads stops the search** (see above).

## Known risks

- **Budget on busy surfaces.** On a surface level, every loaded rocket within
  about 32,767 blocks of a fixed pad counts towards the 64-rocket budget. A server
  with more than 64 loaded rockets in that range, for example many rockets parked
  in the spawn chunks, refuses every unnamed landing on that level with the
  translated budget reason until fewer rockets are loaded. This fails closed (the
  rocket stays at its source), but it can block Earth returns on large servers.
  A tighter reach would need a proven per-axis bound for legal rockets. Scans are
  connected and capped at 2,048 blocks, which suggests 2,047, but the snapshot
  model does not enforce connectivity. That decision is left to Root.
- **Reach assumption.** Like W13F, discovery assumes a snapshot's origin lies
  within its bounds, which holds for scanned rockets but is not enforced by the
  snapshot model.
- **Station clipping.** Like W13F, Space discovery is clipped to the owning
  station's region. A rocket based in another station's region whose structure
  crosses into this one would not be found. Station regions are at least 256
  blocks apart.
