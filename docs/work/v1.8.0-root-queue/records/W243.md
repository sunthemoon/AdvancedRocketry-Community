### W238-R2 in detail

- **O1 (`EscrowCoordinator.beginSettlement`).** W238 added an early `checkReserve` before the "Floor changed since
  preview" guard. Moved after the floor-retirement and tombstone checks, it would sit directly before the final
  `tryReserve`, with the same operation, owner and rocket. `tryReserve` already returns a normal refusal and changes
  nothing when it refuses. I therefore removed the early check instead of duplicating it. The order is now the
  pre-W238 order: busy checks, floor changed, receipt room (RECEIPTS_FULL), FLOOR_FULL, tombstone creation, then
  pending capacity (`return false`).
- **The command (`EscrowSettlementOperator.floorAdmission`).** The floor admission now starts with the preview's
  tombstone-count check (shared as `requireReceiptHeadroom`), and the static admission check runs floorPreview's
  receipt-room check for one new member before `checkReserve`. I added the second check, which the task did not
  name, because a ledger can hold its 64th permanent receipt in a decided record while it has only 63 tombstones.
  With the tombstone-count check alone, that ledger would still show the transient refusal first. Both checks are
  pure and throw the same RECEIPTS_FULL text as the preview, which the command reports as
  `Settlement intent refused: …`. The confirm path runs the same floor admission first, so it keeps the same order.

### W238-R3 in detail

- `rocketFullTakesPrecedenceOverOwnerPendingFullWhenBothApply`: owner A holds 16 bay receipts, 8 on each of two
  rockets. A request by A on a full rocket gets ROCKET_FULL from `checkReserve`, from a real bay admission (reason
  `ROCKET_PENDING_FULL`) and from `tryReserve`. The test also shows that each condition applies on its own, and it
  checks that the receipts, the sequence and the count do not change. I swapped the rocket and owner checks in
  `EscrowAdmissionAuthority` for one run, and this test failed (`expected: <ROCKET_FULL> but was: <OWNER_PENDING_FULL>`).
  The file was then restored from HEAD.
- `restartWithAnOverCapEscrowLedgerRefusesOnlyThatOwnerAndRecoversWithoutANewSlot`: a checked ledger file with 24
  PROPULSION records for one owner is loaded. The delegate reports UNAVAILABLE until the coordinator attaches. Then
  that owner gets OWNER_PENDING_FULL and owner B gets RESERVED. A reason change and an accept-current decision move
  one record to SETTLING_ACCEPT. An exact ordinary retirement, with frozen proofs, removes a second record. Neither
  step takes a slot: the count stays 24, then drops to 23. The saved file then loads again with 23 pending and the
  same refusals. The decision and the retirement act on different records, because ordinary retirement refuses a
  record in SETTLING_ACCEPT.

### W238-R8 in detail

- `EscrowSettlementIntent.floorOperation(long, long)` was public and is removed. The three-argument form is
  package-private and rejects a null owner.
- The four-argument `EscrowSettlementCapacity.floorRetirement` is removed.
- The two-argument `EscrowCoordinator.beginSettlement` now accepts only accept-current and abandon decisions. It
  refuses a floor intent with "A floor retirement is charged to its checked journal owner". The operator passes no
  owner for those decisions, where the owner was always unused.
- I removed the overloads rather than making them package-private, because the production classes share the
  `resourceescrow` package with the tests, so package-private would not keep production code away from them.
- The floor fixtures pass `EscrowTestFixtures.FLOOR_OWNER`, which is `id(700)`, the operator id every floor fixture
  already used. Encoded operations, receipts and counts are therefore unchanged.
- `W238OwnerPendingTest` asserts the refusal, and that `EscrowSettlementIntent` has no public `floorOperation`.
