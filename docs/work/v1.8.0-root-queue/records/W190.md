## Choices made where the task was open

- **Per-process count in the celestial smoke.** `validate_log` is called once per process on its complete log, so
  the scanner's at-most-once count already covers the whole process. A hold after any reload still uses the same
  single allowance, and a second hold still fails the exact comparison.
- **Per-process count in the guard's save slices.** A slice gets no fresh allowance. Its findings are taken from a
  scan that counts from the process start, so a hold that the process has already used blocks again inside a
  later slice, as an unexpected WARN. The tests show this in the slice itself, not only in the final audit.
  Example: a host with no startup hold and one hold per save fails in its second save slice.
- **The station-registry change in the celestial smoke.** The task names only the log propagation. However, the
  smoke cannot pass on v1.8 without this change: v1.8 writes root schema 5 (`StationLimits.REGISTRY_SCHEMA_VERSION`),
  and the old check required 2. I followed W101's `2a23e011` for the v1.3 environment smoke, including the clock
  exception, and limited it to the exact v1.8 build. In this run the saved clock was `logical_tick` 2 at all
  three captures (after creation, and at both stops). The root-schema change was required; the clock exception
  was not exercised. I kept it because W101 saw the clock advance across a restart, and the S1 campaign runs longer.
- **Which celestial mode ran natively.** The script has three modes, and the task allows one run of each
  script. I chose `--check-joint-reload`. It has the most intentional reload ERRORs (six rejected candidates),
  so it exercises the interplay between the startup allowance and the exact rejection list most. The default
  mode and `--check-bindings` were not run natively.
- **Guard inputs.** I used the same Tank06 runtime template, source world and fixture JAR as SETUP05
  (`D:/ARCE-Task-Evidence/v1.8.0/integration-072fbcf821ce4ceb9fbcb3d98ec27d41/tank-native-06/server`). The
  fixture JAR is `arce-adapter-compat-test-1.0.0.jar`, SHA-256 `765735d1…6fa4`, checked by the driver before
  the runs. Only the host JAR is new.
