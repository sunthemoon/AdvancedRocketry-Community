Cargo reuse currently takes an internal lock. The new driver will provide a
visible child-dispatch mode that replaces only that orchestration with an
already-owned-lock adapter, forwarding the unchanged wrapper argument form,
candidate checks, hook/harness pins and existing `run_cut` calls. It will not
replace an oracle or alter a cut or timeout. The lock owner passed to each cut
will be the campaign owner. Reuse uses the existing Temp parent; only runners
create and remove their token-owned child servers. G2 additionally needs an old
JAR and its source commit; these will be explicit optional CLI inputs, required
before native execution if G2 is selected. A new campaign-local start-counter
path will be supplied. Dry runs show unresolved historical inputs without
inventing a historical pin or starting anything.

### Preconditions, failure handling and verification

Before each selected family, and again after waiting for the lock, verify JAR
bytes, production equality under the task's five paths, unchanged clean source
HEAD and more than 10 GiB free on both C: and D:. Resolve candidate and source to
full commits. Acquire the fixed backslash heavy-JVM lock using `cmd /c mkdir`,
with a unique owner token, a three-hour wait/stale-lock bound and a minimum
90-second post-release delay. Release only the matching owner's own lock files;
never recursively remove foreign contents. The driver never deletes a server.

Every family gets an invocation record, including preflight refusals and
NOT_RUN entries. A failed family blocks subsequent families of its underlying
runner; cargo's wrapper is a dispatcher, not a shared oracle. Independent
runners continue. Update campaign JSON after every family and write a done
marker carrying the final outcome; dry-run evidence is explicitly not a pass.
Reject occupied evidence directories. Preserve all failed attempts.

Tests use fake git, disks, clock, atomic lock creation and runners. Verify matrix
and inventory coverage, pins/refusals, lock ownership and cooldown, failed-runner
isolation, summary persistence and dry-run non-execution. Run all existing bay
and cargo Python tests unchanged, escrow inventory and strict repository
validation. Save a placeholder-JAR dry run against committed HEAD outside Git.
The task-specific no-server rule excludes native runs and GameTest. No Java
change or new asset is expected.
