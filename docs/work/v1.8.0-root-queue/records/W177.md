## Choices where the design left room

- **"Count canonical identifiers."** The fillers already had 128 canonical characters. The check undercounted only
  because a definition ID could have 138, which step 2 removes. I tied the fillers to the shared 128-character
  constant and made an over-bound reward item not fit, so the check no longer depends on how its caller parsed the
  items. A 138-character filler would have refused tables that are accepted today, which step 5 forbids.
- **The instance fit (`instanceBytes`) is unchanged.** An asteroid type's instance and mission checks use the same
  item list, so an over-bound item already refuses the type through the mission check; gas tables have no instance.
- **Spelling checks kept.** Every parser still rejects a spelling over 128 before parsing. The canonical form is never
  shorter, so the new check covers it, but the early reject avoids parsing long strings.
- **`SizedMissions` in `GroundPreflightTest`** extends the benchmark's `CountingSizer` and sizes missions through
  `missionBytes`. With delegation it would have lost that size, so it now overrides `missionReservation` with the same
  proven value it inherited before; `fillReservations` already checks each size against the codec sizer.
  `DecoderPreflightTest.ProofCountingSizer` overrides the same four methods the same way and is unchanged; its
  overrides are now redundant.
- **`GroundSurveyScaleTest`'s inflated satellite reservation** stays proven, as the default made it, because that test
  measures the reservation sum, not the proof.

## Known risks and observations

- **Compatibility.** A datapack with an identifier of 129 to 138 canonical characters is now refused at reload, and on
  the initial load the world does not start, with the catalog diagnostic. Such a datapack previously produced a world
  that refused to start once a satellite of that definition had been saved. A world that already saved such a
  satellite stays refused at load (W173 option A's case), with or without the datapack. Component and table items
  must also name a registered item, so they reach this bound only if some mod registers an item with such an ID.
- **Gas table file IDs have no length bound (pre-existing, not changed).** A gas table's ID is its file ID, which the
  codec does not parse. By reading: a file ID over 176 characters makes the reward version
  (`gas-v1/<id>/<16 hex>`) longer than its 200-character bound, so the `MissionState` constructor in
  `resourceMissionBytes` throws outside its `try`, and `ResourceTables.create` throws instead of returning an error,
  which the reload listener does not catch. The reload is then refused without the aggregated diagnostic. That
  version is a free string, not an identifier, so it is outside this task. An asteroid type's ID equals its file ID
  and is now bounded at 128 canonical characters, so its version has at most 157.
- **Item NBT identifiers.** `SatelliteItemData` bounds the definition and component identifiers it reads from item NBT
  by spelling, like the registry decoder. Every writer stores the canonical form, and no content path can now create a
  longer canonical ID, so I left it.
