### U's unresolved byte-preservation requirement

Both valid file types produce `VANILLA_VALIDATE=[]`, actual presence UNKNOWN, `isPresenceUnknown=true`, the correct
managed type and `ARCE-BETA-2000`. The native start then emits the exact typed refusal with the storage instruction
first, without READY or a receipt-index line. All six expected refusal/shutdown diagnostics and exception identities
are audited, including pinned vanilla's pre-Level shutdown NPE. This path exits with code 0, as the existing W157
runner already documents; an arbitrary successful exit is not accepted without the complete refusal evidence.

The handle is cleared and closed, and each managed file's SHA-256 matches S0 after restoration and after both clean
recovery starts. **Nevertheless, `level.dat` changes and `level.dat_old` rotates.** Decoding those two retained metadata
files shows `/Data/LastPlayed` as the only changed NBT field. Vanilla writes that metadata before the Forge refusal.
The runner does not exclude those files, reset the baseline after the write, restore bytes manually or claim PASS.
Both U cases therefore remain NOT_COVERED for the requested whole-world invariant, despite observed refusal/recovery.

`round2/smoke-U/native/U_BAY-observations.json` and `U_LEDGER-observations.json` retain S0/S1/S2/S3, actual marker/type,
diagnostic audits and recovery hashes. Their before/after manifests and S1 raw snapshots retain the failure evidence.
The `unchanged` field in the restoration JSON is whole-world manifest equality, not a claim that the restored file
changed. `round1/smoke-U` also retains the initial failed native attempt; it is not reported as a pass.
