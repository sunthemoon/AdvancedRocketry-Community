# W202: exact write-back sizing and callback-inclusive measurement

## Design note, before implementation (2026-10-30)

This worker starts from `9820b18c9addb583ba53dc2077abe6aea23c1681` on
`codex/v1.8.0-w202`. The worktree was clean. Its write scope is
`RocketNbtSize`, `RocketTransferJournalCodec`, `RocketJournalInsertionBudget`,
their focused tests, supplemental W197 measurement analysis/tests, and this
record. No other worktree, admission path, terrain fixture, ADR, risk register,
status, ledger, build configuration, numerical limit or deadline will change.
No upstream code or asset is imported. Root owns review, integration and push.

The codec will expose the byte count from its existing final root-size check.
The ordinary encoding API will still return the same caller-supplied root;
insertion validation will consume the count directly from that same encoding
invocation, rather than serialize its returned root again. No count/root cache
or mutable NBT witness escapes the invocation. Per-record and nested snapshot
checks, canonical-resident fallback, ordering, outbox framing, exceptions and
all thresholds remain unchanged. Repeated calls, including calls after target
mutation, must encode and check anew.

Separately, sizing will continue to call `NbtIo.write` with a `DataOutputStream`,
but its sink will discard bytes rather than allocate and grow an unused byte
array. The stream's byte counter counts the actual writer calls, not an
approximate NBT walk or UTF-8 calculation. Modified UTF, root headers, list
framing, array widths and writer exceptions consequently retain their existing
semantics. The int counter is exact for representable NBT sizes; its documented
saturation at `Integer.MAX_VALUE` remains above every existing NBT threshold,
so an oversized value cannot wrap into an accepted size. Allocation and exact
boundary equivalence tests will accompany this change in its own commit.

W200-R1 is addressed by a separate, explicitly callback-inclusive summary:
the union of the historical substantive-work ticks and observed `releaseTickets`
ticks. Those release calls identify the continuation ticks missed by the old
classifier; the whole tick, not just release CPU, enters the supplemental view.
This is a conservative observed-callback cohort, not exact attribution of all
write-back CPU. Full phase windows remain authoritative for unobserved work.
The historical summary module and existing summary files remain unchanged;
both views will be reported with identical nearest-rank percentile arithmetic.

Each sizing change gets a failing regression first and an isolated green run.
The whole unit suite, three I6/sealed batch runs, and W197 before/after native
measurements follow. Heavy runners use the existing detached entry points,
atomic machine lock and ownership-checked cleanup. No extra W202 JVM will run
during its native measurements. Docs/17 comparisons retain mean 25 ms, P95
50 ms and P99 100 ms; a maximum over 100 ms alone is not a P99 failure.
If residual cost remains, this record will describe a separately reviewable
write-back work allowance, without implementing it. No Gate is approved here.

## Execution
