### The product-side landing failure

New-strip repeat 2's maximum is **landing tick 520**, not its 93.2340 ms relaunch
tick. It measures 166.0006 ms: core 8.4466, END 157.5540, transition observer
zero, column observer 1.8586 ms. Its paired timing-only landing tick is
25.3327 ms. A JFR `jdk.FileForce` on the **Server thread** is wholly inside the
full tick and lasts **139.8039 ms**, forcing
`advancedrocketrycommunity_classic_progression.dat.arce-pending`.

The recorded stack is
`ClassicFirstEventDelivery.onServerTick -> tick -> step -> barrierStep ->
ClassicProgressionSavedData.barrier -> AtomicSavedData.flush ->
CheckedSavedDataPolicy.replace -> CheckedSavedDataFile.replace ->
FileChannelImpl.force`. The duration event attributes real blocking product
save latency; there are no execution samples during that blocked window and
no overlapping server-thread GC/park event. It is an overlay inside W212's
unassigned remainder, not an extra amount added to the tick. A missing event
in another run is not zero I/O: JFR's existing thresholds remain unchanged.

The [progression barrier](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/progression/classic/firstevent/ClassicProgressionSavedData.java)
explicitly confirms captured receipts only after the checked synchronous flush
and directory force. Extra relaunch preloading or hashing caches cannot remove
that required force. Save ticks were not excluded or reclassified to claim a
checkpoint P99 pass. This failure prevents an observation-only disposition.
