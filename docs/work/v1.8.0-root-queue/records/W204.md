## W204-fix design, before implementation (2026-10-30)

Root decision R176 and `TASK-W204-FIX.md` in the shared queue authorize this
follow-up on clean baseline `ce16502de0b0085edb3d48ee2bd9a7206dfba445`.
This supersedes the earlier production-fix exclusion only for the absent
transfer branch of named-pad claim reconciliation. Write scope is
`LandingPadService`, the journal's absence query and existing bounded transfer
history, focused regression fixtures/tests, the W204 native probe, W91K runner
and its tests, and this record. External helpers and new results belong under
`D:/GitHub/ARCE-Task-Evidence/root-queue/W204/`, with native rows in `native-02`.
No other worker owns this worktree. W206 and its heavy-JVM lock are not touched.

An old claim may be reconciled for an absent transfer only when that transfer
is absent both in RAM and in acknowledged journal authority. During a live
session this means the last published checked writer generation excludes T
and its sequence covers T's latest mutation. The existing bounded transfer
history supplies that comparison, including its conservative overflow floor;
an older empty generation cannot authorize a later insert/remove. Unrelated
transfers need not stop an already acknowledged absence. UNKNOWN, blocked or
unreadable roots and stopped lifecycles do not authorize reuse. A failed or
still-pending removal retains the original claim. The contender receives the
existing false result and can retry; neither its failure nor repeated retries
erase or replace the old claim.

A successfully validated disk load also proves the loaded absence of T before
the first writer acknowledgement, provided T has not changed since that load
and no failed/UNKNOWN attempt has invalidated that proof. Record the load
sequence in RAM only. A new/proven-absent root is not a successful load and
waits for the existing baseline writer. This narrow pad-absence proof does not
turn a load into a whole-root checkpoint, first-event acknowledgement, lease
or permission to run other dependent effects. Existing W44 baseline writes
and all schemas remain unchanged. A restart that reads T retains the claim;
a restart that reads no T may reconcile the saved stale claim on demand.

Reconciliation stays lazy and local to the requested index entry: no world
scan, ticket or new background sweep. The existing claim-ID-checked release
and claim operation run in one owner-thread call. A delayed old callback or
a repeated request cannot release a successor's claim. Native evidence will
observe the old-to-new ownership transition and retry with the same contender
and a different contender; it will distinguish lazy restart reconciliation
from the normal same-session completion callback instead of expecting an
automatic restart sweep that the product does not provide.

The recorded `live=0` is correct and is left unchanged. `liveTransfers` drives
forward flight dispatch, not durable ownership. Once T leaves RAM the absent
branch stops dispatching it; the ordinary retirement operation still owns its
reservation, survivor proof and acknowledgement continuation independently.
That continuation releases the pad and reports completion only after the
checked removal. Refused admission never reaches this branch and must retain
live membership as before. Crash recovery reconstructs authority from native
storage and the loaded journal, not this transient set.

Verification starts with a red regression against the real claim decision,
then checked-write, UNKNOWN, restart, stale-callback and history-overflow
coverage. Run isolated new classes, the full unit suite, runner oracle tests,
and station/pad/scheduling/return GameTests three times. Native `N2_PAD_MOVED`
and `N2_PAD_UNKNOWN` each get two restarts and one observed acknowledged
release/reconciliation; repeat `N2_REFUSED` and `N2_STOPPED` controls. Each
attempt is three counted starts (12 planned; at most one reproduction per
failed row, stopping after two failed attempts). Use committed-source JARs
under the owned heavy-JVM lock with disk-space checks and cleanup. Root owns
the independent read-only review and hosted full regression. Cancellation,
offline crew, other pad policy, default limits, budgets, timeouts, ADRs,
status files and the ledger are unchanged. No version or Gate is approved.
