## Conservative readings for Root

Endpoint identity, transfer/hash authority, hint-cache ownership, one handle per
actual detach, player-instance ownership and the final pre-application validity
check belong to S2. S1 receives only an already checked optional anchor/hint and
a current-context predicate. A hint is checked for identity, never assumed safe.
A Level string is an opaque comparison token here,
not a new public or persisted ID; S2 must derive it from the existing Level key.

The snapshot adapter must prove collision and full-footprint support against the
exact box using only its bounded pre-read state. S1 does not map Forge block
classes to those observations or claim that a simulated port proves actual
world geometry. The entire enclosing integer window, including support and
collar, must fit the border/build bounds. This is conservative at fractional
border coordinates. Read units reserve the entire window before any read, even
if a later unknown observation prevents using all of it.

A recursive read of the same still-running selection returns `PENDING`, with
zero additional work, rather than manufacturing a final position before one
exists. It is explicitly not an instruction to place or apply fallback. After
selection the same handle returns its identical cached final result. A different
nested detach immediately caches `REENTRANT_REFUSED`. Root should preserve that
distinction in S2's adapter.

Unapplied synchronous reservations remain occupied through the whole END drain,
not just until their own earlier capture entry is visited. Completion applies
each delayed result synchronously, and actual entity occupancy must be observed
before `applied` removes a reservation. New captures during a drain refuse to
extend it; the snapshot has at most 1,024 contexts. Stale entries consume no
attempt or work units. No next-tick search/retry is scheduled.

The budget cannot advance while a decision, validity check or END completion
callback is running, even between probes. A context can bind its own safety port
for the exact passenger and Level while retaining the one server arbitrator,
reservation set and budget. S2 need not create per-player budgets or a mutable
global current-passenger pointer to adapt the loaded-state port.

### Completed scope and design decisions

Code and regression tests are committed as
`1c7b8d3d5c608f18f02e1071d677246520f1ae71`
(`fix(rocket): guard bay exit validity callbacks`). The write scope is
`BayExitSelector.java`, its existing `BayExitSelectorTest.java`, and this record.
The selector now has 219 lines and its test has 381; all four main classes remain
below 400 lines, totaling 486 lines. The four test classes total 662 lines.
These counts supersede the earlier implementation snapshot's counts above.

The selector checks and acquires its active-decision guard before invoking
external validity code. The existing `finally` releases it on stale, successful,
exhausted and exceptional exits. An attempt sequence is assigned only after
successful validation. Same-context recursion returns an uncached zero-work
`PENDING`; another uncached context receives cached zero-work
`REENTRANT_REFUSED`, without invoking its validity callback. Cached final results
still take precedence. A thrown initial validity callback propagates its error,
while the same fail-closed result caching used for exceptional decisions prevents
a later repeat attempt; it has sequence zero and zero work.

The callback audit found the same unguarded validity boundary in the END drain's
preflight. It now acquires `active` around that predicate and releases it in
`finally`, before application/release or selection continues. No callback is
removed and normal FIFO completion behavior is unchanged.

The rest of the four-class callback audit found:

- The safety port, reservation check and post-probe validity predicate run
  inside the active decision, open probe and budget work scope. The
  `LoadedState` methods and snapshot-cell callbacks in `BayExitSafety` are
  synchronous descendants of that safety call. Reentrant selection cannot
  allocate another decision through them. A standalone loaded-state probe has
  no selector-owned mutable state; its open probe prevents budget advancement.
- END completion callbacks run only after selection has cached its result and
  reserved its box. They intentionally run without `active` so that synchronous
  application and release remain possible, but the drain flag and budget work
  scope prohibit a nested drain, new live capture or tick-budget reset. Cached
  selections spend nothing; reservations persist until application or cleanup.
  Existing tests cover completion/reset refusal and exception cleanup.
- `BayExitBudget` invokes no external callback. `BayExitCandidates` uses only
  internal lambdas over immutable model values; it has no decision callback.
  No additional instance of the initial-entry reservation-corruption pattern
  was found beyond the two validity preflights corrected here.
