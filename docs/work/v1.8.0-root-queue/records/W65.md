## Summary

- [`scripts/check_client_bytecode.py`](../../../../scripts/check_client_bytecode.py) reads the class
  files of a built JAR with only the standard library. It fails when a class outside the client packages
  references a client-only class, either directly or through client-bound mod classes. A reviewed pair
  in [`scripts/client_bytecode_allowlist.txt`](../../../../scripts/client_bytecode_allowlist.txt) passes.
  Each entry gives a reason.
- [`tests/test_check_client_bytecode.py`](../../../../tests/test_check_client_bytecode.py) has 20
  tests. They run over class files that the test assembles byte by byte. All pass.
- The real run used a JAR built from `98e41378`. It passes with no violations: 2,991 classes and
  91 allowed references. The allowlist has six entries. W62 proposed four of them, the `DistExecutor`
  sites. The other two are Forge client hooks: the fluid texture extension and the data-generation
  providers. W62 did not list them, because its proposal looked only at `net.minecraft.client`.
- With an empty allowlist, the same JAR fails with 3,744 violations. 87 are direct references, and
  they all come from the two Forge groups. The other 3,657 are transitive: 955 of the 2,991 classes
  become client-bound, the mod's main class among them.
- No production defect was found, and no production code changed.

## 2. What the checker does

- **Client-only classes.** A class is client-only when its name starts with `net/minecraft/client/`,
  `net/minecraft/realms/`, `com/mojang/blaze3d/` or `com/mojang/realmsclient/`, or with Forge's
  `net/minecraftforge/client/`.
  - The four Minecraft prefixes are exact. Mojang's 1.20.1 `client_mappings.txt` lists 1,976 classes
    that `server_mappings.txt` does not. All 1,976 are under these four prefixes, and no class under them
    is in the server mappings. The server mappings list no class that the client mappings lack.
  - The Forge prefix is a conservative choice. In the mapped Forge 47.4.10 JAR, the package holds
    344 classes. Of these, 239 reference client-only Minecraft classes directly, and 290 do so
    transitively within the package. The other 54 classes are treated as client-only too.
  - Library classes are matched by prefix only, never transitively. Sixteen Forge classes outside
    `net/minecraftforge/client/` reference Minecraft client classes, `SimpleChannel` and
    `PacketDistributor` among them. They guard those references themselves, so they are not roots.
- **Client-bound classes.** A class of the JAR is client-bound when it references a client-only or a
  client-bound class through an edge that the allowlist does not hold. A breadth-first search from
  the client-only classes gives each hit its shortest chain.
- **Client packages.** A class is in a client package when one of its package segments is `client`,
  the rule that `check_client_imports.py` uses. Such a class may reference anything. A client-package
  class that is not client-bound is data only, and common code may use it.
- **Failures.** Each reference from a class outside the client packages to a client-only or
  client-bound class fails, unless the allowlist holds the pair. The check also fails on:
  - an allowlist entry that matches no reference;
  - an unreadable class, a duplicate entry, or an entry whose path does not match the class it
    declares;
  - a malformed allowlist: a missing reason, a duplicate pair, a source in a client package, or a
    name that is not a class name or pattern.
- **References.** The checker counts:
  - every class constant;
  - every class in a descriptor: the class's own fields and methods, and its `NameAndType` and
    `MethodType` constants.

  It walks the bytecode, the exception tables and the `StackMapTable` frames. A nested or enclosing
  class that only the `InnerClasses`, `EnclosingMethod`, `NestHost`, `NestMembers` or
  `PermittedSubclasses` attributes name is therefore not a reference. Generic signatures, annotations
  and string constants are not references either.
- **Output.** One `[INFO]`, `[ALLOW]` or `[FAIL]` line per finding, and a `[PASS]` line at the end.
  `--report` also writes the full result as JSON, with the JAR's SHA-256.
- **Limits.** At most 100,000 class files of at most 4 MiB each.

### Choices where W62 left the design open

1. **An allowlisted pair does not propagate.** Otherwise every class that names an allowlisted
   packet would become client-bound again. Most of the 3,657 transitive hits of the empty-allowlist
   run would then return.
2. **Unused entries fail.** This keeps the allowlist exact as the code changes.
3. **Patterns.** A name ending in `/*` matches the classes of one package, nested classes included.
   A name ending in `/**` also matches subpackages. The data-generation entry uses `/*` on both sides,
   instead of 86 single pairs.
4. **The Forge client package counts as client-only.** The TASK names Forge client-only classes, and
   Forge marks none of its classes as client-only. The whole package is the conservative reading.
   This choice brought in the two entries beyond W62's four.

## 7. Known risks

- **The allowlist works per class, not per call site.** An entry allows every reference from its
  source class to its target. Suppose a new, unguarded call from `EquipmentEnabledPacket` to
  `SuitVisorClient` outside the lambda. It would pass. A new target or a new source class is still
  caught. A per-method check could use the bytecode walk that already exists; it is not built.
- **`DistExecutor.unsafeRunWhenOn` keeps the client class in the source class's synthetic lambda
  method.** The verifier checks every method when it links the class, and it can load a class for an
  assignability check. The scan cannot tell whether that happens. The `DEDICATED_SERVER` GameTest run
  and the packaged smoke remain the runtime checks.
- **The Forge prefix is coarse.** The 54 Forge client-package classes that reach no client class
  still need an entry if common code ever uses them. The data-generation pattern also covers future
  providers, as long as they target only `net/minecraftforge/client/model/generators/*`.
- **The data-generation classes ship in the release JAR.** They are safe only because the data launch
  alone posts `GatherDataEvent`. Moving them out of the JAR would be a build change, so it is Root's
  call.
- **At 553 lines, the script is over AGENTS.md section 3.4's 500-line mark.** That rule is written
  for classes. The script is one module with three parts: the class-file reader (about 210 lines),
  the allowlist and scan (about 130 lines) and the command line (about 60 lines). I kept it in one
  file because the TASK's write scope names one script.
