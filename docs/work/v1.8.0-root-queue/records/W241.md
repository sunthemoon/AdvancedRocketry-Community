## Pre-implementation projection design and proposals for Root

Reuse each owner above; do not establish another formation validator. Add only
the existing canonical transient `formed` byte via vanilla update tags and
packets. Only byte 1 decodes true; missing, null and malformed values clear
presentation. Decode never mutates the server formation, inventory, root,
process, ownership or persisted schema. Publish only formation transitions,
including invalidation and unload. Existing operation projections remain.

The following conservative design choices are proposals for Root's review,
not owner approval or Gate acceptance. A separate session's read-only review
is required before merge.

1. Keep the K3 convention: reflect legacy placement across pattern width,
   about the controller, then rotate with facing. Keep scale one and source
   bytes unchanged. Several v1.7/v1.2 patterns were redesigned and are smaller
   than legacy hulls. A render-only box encloses the static mesh and existing
   effects; collision, world blocks and required cells do not grow. V1 must
   assess overlap and placement; containment alone is not visual acceptance.
2. The surface elevator anchor is a symmetric 5 x 2 x 5 pattern with no facing.
   Use canonical NORTH and the legacy disconnected ground Anchor, not the
   508-block source Tether, Door or Capsule. Keep the existing bounded tether
   and capsule renderer. Do not attach the legacy orbital hull to the modern
   single-block terminal; it keeps its existing JSON/effects.
3. The precision assembler's mirrored alternative stays functional. Until a
   mirrored mesh presentation is separately designed, expose formed=false for
   that display variant and retain its JSON/world-block fallback. The normal
   variant uses the existing formation state. This adds no mirror packet field.
4. Rolling's original renderer draws Roller_2 twice and never draws roller_3.
   Prepare bounded static parser input with those exact idle instances; pin
   every drawn source position/instance against that transcription in four
   facings. All six full sources retain format/reference/budget checks before
   adaptation. Recheck adapted geometry and count any increased vertex budget.
5. Compose hull rendering with existing laser, accretion and elevator effects
   rather than registering a second renderer that overwrites them. Fallbacks
   are existing NEW/project textures, never newly copied vanilla art.

Import plan/provenance must precede copying upstream resources. Missing MTLs
are authored in a separate commit so importer NEW-source blobs are immutable.
All twelve upstream histories and derivations must remain CLEAR; human
provenance review remains PENDING_HUMAN_REVIEW.

### Failures retained and corrected

The first plan attempt used the wrong case for a source name. Initial import
attempts rejected an invalid Forge material texture identifier and duplicate
main/imported material resources. An initial compile rejected duplicate lifecycle
overrides. The first K4 orientation run had six failures because its oracle
paired positions by face order despite the required mirrored winding reversal;
it now pins position-reference sets and compares every drawn source position in
all four facings. No geometry limit or tolerance was increased.

The unfiltered GameTest run exposed all twelve integration failures above:
optional-cell fixtures were incomplete, constructing a vanilla packet with a
null supplier result was invalid, the rolling test expected the stored formation
to be immediately projected after load, and the old capsule decoder rejected the
new anchor flag. Corrections preserve exact privacy assertions and all existing
timeouts/ride/geometry limits. The twelve affected tests then passed together,
including all newly added break/repair, unload and reload stages.

There has been **no post-fix unfiltered GameTest run**. Root's scheduled sharded
regression must establish whole-suite acceptance; the focused pass does not
