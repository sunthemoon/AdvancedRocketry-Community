How the parts map to W85:
- **M0** (`RocketDisassemblyService.playerCode`, `RocketLandedDisassemblies.begin`). With a P the request runs the
  actor, range, identity and permission checks and answers DISASSEMBLY_PENDING (N6). Without a P and without T,
  today's one-tick path runs. With T, schema-2 non-native landed authority, the bay gate, `canQueueEffect()`, the
  64-entry bound and the shared preflight must hold, or the request answers its code and keeps T. S
  (`RocketLandedDisassemblyRules.Snapshot`) accepts zero fuel; a confirmed request's quote must equal S; `Quote` and
  its positive-fuel test are unchanged (N5).
- **M1** (`RocketLandedDisassemblies.release`): record P, `journal.remove(T)`, queue the continuation, answer
  DISASSEMBLY_PENDING. While T is absent from RAM, P adds T's region to `prepareLaunch`'s reservations and counts
  toward `MAX_ACTIVE_TRANSFERS`; in WRITE_BACK it is not counted again (N2). `resourceMutationAllowed` and the
  escrow reconciliation boundary refuse while P exists.
- **M2** (`removalAcknowledged`): audit and drop the session sets; restore only within 200 ticks, with E equal to S
  and the bay gate allowing; set the one-way latch before `execute`; classify SUCCESS, certified clean rollback
  (not ROLLBACK_FAILED, equal counts, E still equal to S) or uncertain; return true in every handled case (N1).
- **M3** (`writeBack`): the only step that puts T back, only with the latch unset or a certified clean rollback;
  a refused insert logs `ARCE_LANDED_RESERVATION_NOT_RESTORED reason=<journal|full|overlap|mismatch>` and ends P;
  a queued write-back keeps T, P and every interlock until its exact acknowledgement, with no time limit; under a
  stop or abort only `put(T)` runs. The removal's discarded callback never calls `put` once the latch is set
  without certification (also while an `Error` unwinds).
- **Reporting**: at most one `ARCE_LANDED_DISASSEMBLY_UNACKNOWLEDGED logical=<L> stage=<removal|write_back>` per P
  and stage, from the transfer tick before its early return.

## 4. Choices where the design was open

- **Where P lives.** `RocketTransferService` had 800 lines. P and M0 to M3 live in the new
  `rocket/server/RocketLandedDisassemblies` (with the pure decisions in `RocketLandedDisassemblyRules` and the
  service side in `RocketLandedDisassemblyPort`); the transfer service owns one instance and keeps 798 lines. W44's
  FM12a hook keeps today's plain removal, moved unchanged into `RocketLandedDisassemblies.releasePlain`.
- **Refusal codes at M0.** A T that is not schema-2 landed authority (record 3, a native transfer, a changed
  arrival), a refusing bay gate, a full continuation queue and the 64-entry bound all answer REGION_BUSY, the code
  that today's release answered. A preflight failure answers its own code.
- **The answer to a release.** The player sees DISASSEMBLY_PENDING in the action bar. `confirmDisassembly` and the
  confirm command return success (1) for it, because the request was accepted and its token spent; the release-test
  command prints "Release-test disassembly pending" and returns 1. A spent token whose rocket already has a P sees
  only DISASSEMBLY_PENDING, not also `disassembly_confirmation_invalid`; a replayed or unknown token still sees the
  latter.
- **Notifying the requester.** M2 notifies the requester's current session if online, otherwise the requesting
  player object while it is still connected (a fake player is never in the player list). The release-test hook
  logs its `ARCE_RELEASE_TEST_DISASSEMBLY` receipt once, when M2 classifies the result or M3 starts.
- **Uncertain mutation.** When a `RuntimeException` leaves the action after the latch and no result exists, the
  requester sees ROLLBACK_FAILED ("needs recovery"). A throw after a certified clean rollback still writes T back,
  as the removal callback does (M3's rule: latch unset or certified).
- **The 200-tick limit** is "at most 200 ticks after the request" on the overworld clock: restoration requires
  `0 <= now - requested <= 200`.
- **Write-back queue refusal.** If the write-back's continuation cannot be queued (stop, abort), P ends and T stays
  in RAM for the final capture, as W85 (c) describes.
- **Escrow reconciliation boundary.** `escrowReconciliationBoundary` also refuses while P exists, so that "E's
  resources stay locked in every stage" holds for the governed reconciliation entry as well as for
  `resourceMutationAllowed`.
- **Native probe placement.** K1 pauses on the journal writer just before the removal's atomic move (a committer in
  the gated policy); K2, K4 and K5 pause on the server thread at the start of the removal continuation, at the start
  of the write-back continuation and right after SUCCESS. `LANDED_REMOVAL` refuses the first landed removal once per
  process, so that the K9 retry succeeds and K10's drain commits the removal before the final capture.

  insert, and a process stop while disk lacks T (K2, K3) leave T released; K5, K6 and K11 are the unchanged v0.5

- A written-back T that keeps failing holds the rocket and, while F3 is open, every flight, with no time limit; this

  GameTestServer. The executor's fault injector and the `begin` overload are package-private; production always
  passes `RocketFailureInjector.NONE` and the world journal.
- The asynchronous completion keeps a reference to the requesting `ServerPlayer` until P ends (at most 64 entries,
  cleared at server stop) and uses it only while it is still connected.
- W91 (P1-F3, N2) also changes the journal. This leaf adds only `validateWriteBack` beside `validateNewRecord` and
  test helpers in `RocketJournalGameTestSupport`; `pollWriter`, `queueEffect` and the acknowledgement order are
  unchanged.
