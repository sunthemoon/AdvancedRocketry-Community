not a whole-root lease. An unrelated mutation does not revoke that lease during the barrier or ledger write.

This is intentional R17 item 3, implemented in `45388d8d` and documented in
[continuation 47](W11B2-C47.md). The existing tests pin it:
`EscrowFlightJournalGovernedTest:30-35` keeps the absence lease after another rocket's phase change;

### Related integration boundary: the existing off-thread lease service

[RocketJournalLeases](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/flight/persistence/RocketJournalLeases.java)
already tracks per-logical change sequences and publishes immutable views read by the ledger writer.
Its checked exclusion includes records removed from RAM but still potentially present in the last
acknowledgement. Continuation 49 added that protection in `4b19dcdf`; see
[its record](W11B2-C49.md). It retains up to 1,024 change entries and 1,024 removed instances, with
conservative overflow floors. This is not W86's proposed owner-thread scheduling lease or its
129-slot bookkeeping bound.

The revised instructions need to distinguish or integrate these two lease roles, preserve the
off-thread publication and T/serial exclusion, and say how queued continuations and held reservations
affect R17 consumers. Replacing this service with an owner-thread-only scheduler lease would not
preserve the merged contract. W86's 128-continuation bound has not been changed or implemented.
