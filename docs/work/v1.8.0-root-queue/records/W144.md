## 关键设计决定

- Keep all Java additions under test sources. The init script exports the test
  classpath only; central build files and production artifacts are unchanged.
- Use the existing test-only ticket fixture. It bypasses live admission and uses an
  unstarted server; it does not bypass the production cursor's work accounting.
  Capture suppliers copy already encoded synthetic envelopes: these timings do not
  include a real Entity/BlockEntity save. Recomputation repeats the production
  preparer, not the full live apply/settlement lifecycle. Readback hashes a detached
  synthetic native slot on another thread, without disk IO. Visual encoding does not
  publish packets or rebuild a client's cache.
- Each fixture has one addressed tank/chest, 127 vanilla chests holding three tagged
  stone stacks each, and 1,920 iron blocks. It is a synthetic stored snapshot, not a
  world-assembled rocket. The moved resource is 1,000 mB water or 64 stone items.
- Bisection finds the largest eligible aggregate **in this fixture family** through
  the complete eligibility predicate, including O1 capacity; the adjacent byte is
  refused. Unexpected refusals are errors, not permission to shrink the fixture.
  The full 1 MiB aggregate remains a separate rejection fixture, never silently
  relabelled as admitted. No limit, assertion, timeout or cadence was relaxed.
- The detached PowerShell driver owns the atomic machine lock and releases only its
  token in its own `finally`. It waited behind W142, took the lock once for the final
  run, and released it. The earlier successful lock acquisition preceded the final
  attempt by more than 90 seconds. No foreign JVM was present during measurement.
- Five warm-up operations and 50 measured operations per device; warm-up samples are
  retained separately. Percentiles use nearest rank without outlier removal. Only
  owner-thread phase/tick samples are compared to the 25/50/100/500 ms thresholds;
  background hashing is never labelled MSPT. Native gaps always prevent a pass.
