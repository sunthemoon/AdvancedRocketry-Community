## 关键设计决定

- `w144NativeJar` is an opt-in diagnostic artifact. The init script combines main
  output with only `CargoNative*.class` from test output, then reobfuscates that
  artifact. The normal mod jar contains none of these classes; no production source
  or normal source set is modified.
- The reference stage composes the existing governed load (two connected
  release-test players, 16 oxygen providers, 10 stations, 100 satellite tasks, eight
  governed flights and a 2,048-block assembly) with four maximum and four small real
  cargo devices and two real fuel loaders. Two item fixtures have 355 tag keys:
  their stack/frame fit, while the microbenchmark's full O1 check rejects that
  adjacent node boundary. Native observation of those fixtures remains unverified.
- Device origins stay inside the stationary Moon player's existing two-chunk view
  distance. Maximum snapshots remain 2,048 blocks and 128 payloads; overlapping
  visual extents do not alter explicit device bindings.
- The packet observer forwards existing outbound messages unchanged and records
  initial/updated content hashes. It never manufactures a visual send. The dispatch
  wrapper delegates to the unchanged production driver. Publication timings,
  dispatch timings, complete ticks and isolated micro-phase timings are distinct.
- The native runner audits a quiet JVM inventory, C:/D: space and free RAM, records
  RSS, preserves failures, and deletes only its new marker-owned server copy.
  Detached PowerShell owns the atomic `cmd /c mkdir` lock and releases only its
  matching token in the same script's `finally`. Successive W144 acquisitions wait
  at least 90 seconds. The verification run also voluntarily uses this lock.

host is not the docs/17 reference node.
