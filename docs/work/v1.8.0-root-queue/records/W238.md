# W238: per-owner pending admission cap (R244)

## Design note (before implementation)

Root decision R244 selects 16 pending operations per stored, server-validated owner across the existing unique
PROPULSION/BAY union. The authority checks identity, availability and exact repeats before server, rocket and owner
capacity, in that order. The cap is a constant and is not a codec validation rule: existing over-cap saves remain
loadable and saveable, and existing operations can recover, change phase or retire without a new slot. Retained
receipt capacity remains independent. Device preflight checks reserve nothing and precede native capture; final
admission rechecks before charging. Floor-retirement preview and confirmation report a typed capacity refusal rather
than throwing the coordinator's reservation assertion.

The write scope is the escrow authority/adapters and floor command, appended bay/loader/cargo display values, their
v1.8 language providers and generated language resources, related unit/GameTests (including applicable W231 tests),
and this record. ADR/risk changes are drafts only under `D:/GitHub/ARCE-Task-Evidence/root-queue/W238/`.

Out of scope are bay production enablement, W230 safe exit, configuration or schema changes, status files, the
content ledger, build scripts, ADR edits, the risk register, pushes and merges. This branch starts at
`362ce414506fecb5a0fe5e72ed61c0c27099c705`; no other worktree or process is modified.

### Files and design decisions

- `resourceescrow` contains the constant and unique-union owner check, appended coordinator outcomes, non-reserving
  loader/fluid-cargo/item-cargo preflights, typed floor-command refusal and stored-owner floor publication. Existing
  identity, unavailable and exact-repeat handling precedes the unchanged 64/server and 8/rocket checks, then 16/owner.
- Bay, loader and cargo status/reason adapters append `OWNER_PENDING_FULL` without moving old codes. The v1.8 bay,
  cargo and receipt language providers and only the v1.8 generated English/Chinese dictionaries add W231's four exact
  messages. Historical generated roots, schemas, configuration, retained limits and byte budgets are unchanged.
- A new floor operation uses the owner of the matching checked transfer-journal record, not the command actor.
  Its existing operation-owner field stores that identity; the settlement still audits the actor separately. Existing
  historical floor operations are not reassigned. Compatibility overloads remain for existing fixtures; production
  supplies the checked owner. Pending-capacity refusal returns normally, while permanent receipt-budget assertions
  remain tested. Existing recovery and phase changes do not acquire another owner slot.
- New unit classes are `W238OwnerPendingTest` (nine tests), `W231BayFairnessTest` (three) and `W231BayCapacityTest`
  (one), with `W231BayCapacityFixture`. The W231 imports come from this repository's `986e11fa7`, not an upstream
  asset source. Measurement cases keep 100 samples and 10,000 coordinator ticks per distribution. One-owner cases
  above 16 load valid historical saves instead of requesting forbidden new admissions; they are local A0 measurements,
  not reference performance or release evidence.
- Existing global-pressure fixtures now distribute 64 operations across four owners. Global, rocket, retained,
  receipt, byte and timing assertions are not reduced. The combined-reservation test separately retains the permanent
  receipt-room exception assertion while checking the required normal pending-capacity refusal.
- `BayLoaderSaturationGameTests` adds the real 16-owner-slot/no-loader-capture case and retains global saturation.
  `EscrowFloorAdmissionGameProbe`, called by the existing native settlement-completion fixture, exercises the actual
  Brigadier preview with a full owner index and verifies unchanged cache, ledger, sequence, writer, counts and loaded
  chunks. It is release-test-hook guarded, not another registered GameTest.
