## Scope and design

This work is confined to the W358 worktree and TASK write scope. It adds gated release-test commands and a sibling
native runner; production admission, persistence schemas, budgets, existing case selections, registration, build,
workflow and shared status files are not changed. No upstream content is copied. Candidate acceptance and version
Gate approval are not part of this task.

The B6.8 fixture parks the existing two-bay rocket with room for 1,000 mB, fills it through a real fluid loader and
waits for its operation to retire before launching. CAP.3 uses the same loader probe beside the seeded owner-full
root and compares both native envelopes and admission/queue counts around its visit.

B10.6 extends `seed-repair` with an explicit incoherent variant. Its REPAIR receipt has a valid schema but a package
signature different from the immutable transfer snapshots. This exercises `BayReleasedAuthority.payloads`: an
unconsumed package must match its receipt's `packageSig`. The oracle requires PREPARED/TRANSIT, both original bay
signatures, the same acknowledged unreleased REPAIR operation, no registration and unchanged receipt-file authority.

B11.8 fills and removes only the fixture's own owner receipts using the real receipt store. Two relaunches exercise
the refused re-arm and the later same-operation consumption. The existing REJECTED receipt takes priority in the
menu, so the refusal proof uses the real admission authority, unchanged receipt and unconsumed packages, not a
replacement menu reason.

B11.9 uses the TASK's permitted typed-ledger seed: structurally valid PREPARED records with absent fixture endpoints,
a checked file write/readback and the real runtime index. The 63rd live admission was refused by settlement byte
headroom at 62; that policy is unchanged. Seeds combine 63 escrow plus one bay and the reverse. Both consumers'
checks must refuse at 64. These cases establish loaded mixed capacity, not live admission of 63 fills.

B11.7 uses a new mode of the existing gated committer: UNKNOWN is injected before replacement on every retry until
explicit release. The receipt writer, its retry schedule and authority union are unchanged. The case crosses a
normal retry with one durable/captured/UNKNOWN operation and a different successor, beside 62 escrow operations.
The shared count must be 64, retained bay count 2, and both consumers must refuse a further reservation. A hard kill
ends the held writer; both restarts read only the acknowledged file.

## Feasibility and exclusions

B6.8 remains NOT_COVERED, contrary to W331's reachability assumption. The real loader filled 1,000 mB and retired its
operation, leaving a real ledger binding, epoch 1, zero markers and zero operations. Its subsequent launch selected
governed flight. `RocketTransferService.tick` skips legacy `tickLive` for a record with `nativeTransfer`, whereas the
bay ascent callback is in `tickLive`. No bay claim was made. The rocket landed with both original package signatures
and no consumption or registration; both menu reasons were NONE, including after the forced stop and two restarts.
The new family therefore returns FAILED, not PASS. Its complete observation is preserved in
`smoke8-B6/campaign/forced-W358-B6-BOUND-smoke8-B6/native/W358_B6_BOUND-observed.json`. No forged legacy transfer or
direct D0 call is substituted for a production launch. The direct D0 guard is covered by
`BayDeploymentGameTests.anEscrowBoundSourceIsRefusedWithBaySourceProtectedAndKeepsItsPackages`.

B17.3 remains NOT_COVERED. The existing commands can renew production discovery tickets or remove a test forceload,
but cannot prevent the coordinator from renewing its own source/destination tickets. Selecting a different unloaded
dimension or corrupting an end would test an invalid group instead of the requested unloaded-end scheduling case.
A deterministic control would need a production ticket/readiness seam or a coordinator scheduling change, neither
of which is in this task's gated-class-only scope. No native result is inferred from a race.

B11.2 is unreachable through production admission and bay launch. Live fill admission reserves a five-marker
settlement allowance, and active escrow work prevents launching that logical rocket. Even granting a historical
seven-operation root, legacy D0's `RocketEscrowGate.bayNeutral` check precedes D1 and refuses a non-neutral source.
`BayAdmissionRowGameTests.mixedConsumersShareGlobalAndRocketLimits` exercises the authority boundary directly
(seven escrow plus one bay, ninth refused); it is not native launch evidence.

B17.5 is unreachable for one production claim without forged receipts. A repair hold stops subsequent D1/D2;
in-session registration conflicts hold without writing a REPAIR receipt. On restart, INTENT can become REPAIR, but
the hold prevents D3/D4 publication. REGISTERED members publish together in one receipt generation only after the
group is proved. A REJECTED receipt is not a pending restart member. Thus the normal producers do not create the
requested REGISTERED/REJECTED/REPAIR live group. No GameTest covers that exact triple-phase group. The relevant guard
tests are `BayDeploymentGameTests.aClaimHeldForRepairBeforeD1WritesNoIntent` and
`BayDeploymentFlightGameTests.aClaimHeldForRepairBeforeD2RegistersNoSatellite`; both ran in the full GameTest suite.
