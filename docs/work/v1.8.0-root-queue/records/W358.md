# W358: native satellite-bay gap fixtures

## Scope and design

This work is confined to the W358 worktree and TASK write scope. It adds gated release-test commands and a sibling
native runner; production admission, persistence schemas, budgets, existing case selections, registration, build,
workflow and shared status files are not changed. No upstream content is copied. Candidate acceptance and version
Gate approval are not part of this task.

The B6.8 fixture parks the existing two-bay rocket with room for 1,000 mB, fills it through a real fluid loader and
waits for its operation to retire before launching. CAP.3 uses the same loader probe beside the seeded owner-full
root and compares both native envelopes and admission/queue counts around its visit.

B10.6 extends `seed-repair` with an explicit incoherent variant. Its REPAIR receipt has a valid schema but a package
signature different from the immutable transfer snapshots. This exercises `BayReleasedAuthority.payloads`: an
unconsumed package must match its receipt's `packageSig`. The oracle requires PREPARED/TRANSIT, both original bay
signatures, the same acknowledged unreleased REPAIR operation, no registration and unchanged receipt-file authority.

B11.8 fills and removes only the fixture's own owner receipts using the real receipt store. Two relaunches exercise
the refused re-arm and the later same-operation consumption. B11.9 queues typed PREPARED escrow operations through
the real ledger writer, with absent fixture endpoints, and combines 63 escrow plus one bay and the reverse. Both
consumers' capacity checks must refuse at 64.

B11.7 uses a new mode of the existing gated committer: UNKNOWN is injected before replacement on every retry until
explicit release. The receipt writer, its retry schedule and authority union are unchanged. The case crosses a
normal retry with one durable/captured/UNKNOWN operation and a different successor, beside 62 escrow operations.
The shared count must be 64, retained bay count 2, and both consumers must refuse a further reservation. A hard kill
ends the held writer; both restarts read only the acknowledged file.

## Feasibility and exclusions

B17.3 remains NOT_COVERED. The existing commands can renew production discovery tickets or remove a test forceload,
but cannot prevent the coordinator from renewing its own source/destination tickets. Selecting a different unloaded
dimension or corrupting an end would test an invalid group instead of the requested unloaded-end scheduling case.
A deterministic control would need a production ticket/readiness seam or a coordinator scheduling change, neither
of which is in this task's gated-class-only scope. No native result is inferred from a race.

B11.2 is unreachable through a production bay launch: seven live escrow operations lock the logical rocket. D0's
`RocketEscrowGate.bayNeutral` check rejects every bay with BAY_SOURCE_PROTECTED before D1 can reserve the eighth
mixed slot. `BayAdmissionRowGameTests.mixedConsumersShareGlobalAndRocketLimits` exercises the authority boundary
directly (seven escrow plus one bay, ninth refused); it is not native launch evidence.

B17.5 is unreachable for one production claim without forged receipts. A REPAIR member prevents writing any later
INTENT for that claim, so a single group cannot accumulate REGISTERED, REJECTED and REPAIR members by ordinary
deployment. The partial two-phase native case does not establish a three-phase group. The exact GameTest mapping
and executed results are to be recorded after verification.
