**Order and the stop rule (Q6).** The first code commit is measurement only: `SatelliteRegistryBenchmark` and
`RocketTransactionCheckpointBenchmark`, standalone `main` classes under `src/test` (the `RocketJournalBenchmark`
pattern), run with Xmx4G under the heavy-JVM lock through an external init script. The registry is loaded through
`SatelliteMissionSavedData.load` from a root of at least 16 MiB minus the samples' margin. Each sample: (a) 32 real
`launchIdle` registrations, their watches, then one timed `checkpoint` that must prove all 32 (the registrations are
decommissioned untimed afterwards, so the root stays at size); (b) one mutation, then a timed coalesced `flush`; (c) one
mutation, then a timed autosave `save(File)`. (d) A transaction journal filled to its checked bound, one mutation, then
a timed `saveChecked`. Each reports P50, P95, P99 and maximum per operation; an operation is a whole tick of
server-thread work, so its P95 must be at most 50 ms and its P99 at most 100 ms (docs/17 section 4). If any misses, this
slice stops there: the record reports the measurement, and no coordinator code is written until Root decides.

**Placement.** Pure-Java domain in a new package `rocket/bay/deployment`: the reason enum (the `BayReceipt` reason
grammar, with menu codes), the round-robin step queue keyed by L (32 steps per tick, shared by restart work), the claim
book and member state machine, and the runtime rejection map (4,096 entries, oldest evicted, cleared at stop). The
Forge adapter `rocket/server/BayTransferRecovery` implements `RocketTransferBayRecoveryGate`; `RocketManager` owns it
for one server session (created at `ServerStartingEvent` at LOW priority, after `EscrowRuntime.starting`; dropped at
`ServerStoppingEvent` and on the crash path). `resourceescrow` gains no dependency on it: `BayReceipts` issues one
session handle (put, remove, find, acknowledged, issued sequence, the claims predicate, the rejection map and the
registry permit), and a second request for it throws. New classes stay below 500 lines; `RocketTransferService`
gains exactly one line, `recovery.bays().checkpoint(server, journal, record, source)` before the existing
`recovery.classify` at `ascent_complete`, which reaches a new default `ascentComplete` method of the gate interface.

**D0 (all on the server thread; admission only on the GameTest server and the gated release-test server).** At the
checkpoint the coordinator reads bays from T's source snapshot by adapter ID (at most 128 block-entity visits, cached
per snapshot ID and hash), keeps those holding a package, and enqueues L with a HELD claim at once (Q1); no package, no
claim. Group steps, in order: checked T (`journal.actionable(L)`, `logicalGuard(L)` naming T with a record digest, T
PREPARED; otherwise wait); the live source current at its altitude in TRANSIT, otherwise the claim ends
RELEASED_TO_ORDINARY; the neutral wrapper (epoch 0, no markers, no ledger binding, `escrowIdle`, no escrow logical lock,
floor or tombstone for L and T), otherwise every bay BAY_SOURCE_PROTECTED; writer availability and a blocked registry
(BAY_RECEIPTS_UNAVAILABLE, REGISTRY_BLOCKED); F5 on `plan.sourceBody()` for every kind (legacy `space`, missing or
non-orbitable body: TARGET_NOT_ALLOWED; no catalog: CATALOG_UNAVAILABLE); B14 `absenceStatus(L, snapshot, entity)`:
PROVED continues, PENDING rejects every bay, otherwise one timed checked `checkpoint` and a re-query on the next step,
whose failure rejects every bay with ASSEMBLY_JOURNAL_UNPROVED. Then one step per bay in position order (the first 8;
the rest ROCKET_DEPLOYMENT_LIMIT): package decoding (its availability reasons), bay, package and T owner agreement
(BAY_OWNER_MISMATCH), X already registered (DEPLOYMENT_UNAVAILABLE, Q4), the receipt for X (a blocking, released or
other-package receipt, or a stale REJECTED one at this key: BAY_CONFLICT; an unacknowledged REJECTED one:
RECEIPT_PENDING), and replay-first `SatelliteLaunchService.validate`, whose refusal keeps its code as the reason. Every
D0 refusal is a runtime reason in the rejection map; nothing durable changes.

**D1 and D2.** D1 puts INTENT (new `op`), or re-arms the acknowledged REJECTED receipt of X with the same `op`, new key
and new T context, through the store's `put`, so `tryReserve` and `tryRetain` of the real authority decide; each refusal
maps to its own reason (DEPLOYMENT_CAPACITY, ROCKET_PENDING_FULL, RECEIPTS_FULL, OWNER_RECEIPTS_FULL,
RECEIPT_IDENTITY_CONFLICT). FAILED_BEFORE_REPLACE gives runtime RECEIPT_WRITE_FAILED (the store restores the prior
state); UNKNOWN waits while the writer retries the exact candidate. Completions only mark state and enqueue; they never
write. D2, a queued step after the exact INTENT acknowledgement, revalidates through a new registry permit: the session
handle issues it for an `op` whose RAM receipt is INTENT for X, and `SatelliteMissionSavedData` honours it only inside
one scoped validation call and only for the validation previews; `launch`, `launchIdle` and `decommission` ignore it,
and no public caller can construct one. Every outcome becomes REJECTED: a refusal keeps its code (B9), SUCCESS or
IDEMPOTENT becomes DEPLOYMENT_UNAVAILABLE (Q4). A definitely failed REJECTED write is requeued; nothing times out.

**Exits (Q1).** When no member of L is INTENT or awaiting its REJECTED acknowledgement (D0 rejected every bay, an
INTENT write failed definitely, or the last REJECTED was acknowledged), the claim ends: READY_SOURCE(S) while S is
loaded and current, otherwise RELEASED_TO_ORDINARY; each is reported once by `claim`, which then forgets L. While held,
the coordinator renews T's recorded flight tickets on both ends each tick, without loads. **Restart rows**, classified at
`ServerStartingEvent` before the first tick: INTENT with T present, PREPARED and matching the receipt's owner and before
hashes, and X absent, becomes REJECTED (INTERRUPTED), then RELEASED_TO_ORDINARY once no blocking receipt names L; a
differing tuple becomes durable REPAIR (REGISTRY_SIGNATURE_CONFLICT); a blocked registry holds as runtime
REGISTRY_BLOCKED; an equal X, a REGISTERED or a released receipt waits unchanged at runtime; INTENT whose T is missing
or different holds as runtime REPAIR (TRANSFER_AUTHORITY_CONFLICT) with no write; REPAIR holds; REJECTED claims nothing.

**Gate lock (Q3, Q8).** `RocketEscrowGate.idle`, `logicalLocked` and `resourcesIdle` add a bay part; `escrowIdle` and
`escrowLogicalLocked` stay escrow-only. The bay part is `BayReceipts.holdsRocket(server, L)`: a coordinator claim on L
(including a pending handoff), or a blocking or released receipt naming L in any state; while the index is NOT_LOADED
after startup, every PREPARED transfer record of L (and every L if the transfer journal is not operational); before
`ServerStartingEvent` it is false, because no login, command or tick runs then and the first classification after
installation supersedes it. `claim` and `beforeAction` answer HELD exactly when this part is true, so an UNCLAIMED
record never meets it (N1). Production call sites whose result changes for a held L: `RocketEscrowInterlocks` (mount,
teleport, spread, dimension travel), `RocketEntity` (resource-changing `updateFlightData`, `/data` load, `kill`),
`RocketFlightService.passengerMutationAllowed` (board, leave), `RocketTransferService` (`cancelCountdown`,
`resourceMutationAllowed`, so launch, loaders and disassembly), `LoaderEligibility`, `RocketCargoPreparations`,
`RocketCargoBindingChecks`, `RocketFluidCargoLinker`, `RocketItemCargoLinker`, `EscrowFluidCargoAdmission`,
`EscrowFlightCheckpoint`, `EscrowGovernedPreparation`, `RocketTransactionRecoveryService` (two sites), and the gated
`EscrowTerminalLeaseCut` probe (four); `RocketTransferFences` (three) and `RocketTransferEscrowRules` (two) are reached
only by UNCLAIMED records. A new GameTest class covers these rows for an INTENT-held rocket at rest and in TRANSIT.

**Status, audit and native cuts.** `SatelliteBayStatus` gains the phases INTENT, REGISTERED, REJECTED and REPAIR and
one reason per name above, each with EN and zh text; a world bay shows its package's receipt, else its runtime
rejection, else NONE with DEPLOYMENT_UNAVAILABLE. One `ARCE_BAY_CLAIM transfer= logical= state= reason=` line per claim
transition (INFO; WARN for REPAIR). The harness `scripts/run_v180_bay_forced_stop.py` (with Python tests) runs B1, B9,
B11, B12 at D1, B13's first-tick refusals, B14, B18, B10's INTENT hold and B17 without registered members, two restarts
each, through `releaseTestHooks` and `bayCheckpoint=<cut>`; its probe only pauses the receipt or transaction committer
(staged-only or replaced-before-callback) and prints `ARCE_RELEASE_BAY_PAUSED cut=<id> op=<uuid>`.

**Not in this slice.** Registration, D3 to D7, reconstruction, copies, released flight, W27e admission, ADRs, the risk
register, status files and the ledger. No saved format beyond the receipt store's, and no bound, budget or timeout
changes. Choices made where the design is open are marked "(choice)" in the implementation log below.
