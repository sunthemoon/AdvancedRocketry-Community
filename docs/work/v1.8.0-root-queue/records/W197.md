## Fixture and measurement decisions

The geometry starts from W164's unqualified R156 draft, SHA-256
`b464a7859ff512d4ab5eac880deeae1d71430117317777bc55190c99ee691d3f`.
The qualified fixture has 64 distinct, nonoverlapping source/destination pairs;
each snapshot has 2,048 unique blocks, 32,768 bounding volume, 128 real barrel
payloads, exactly 1,048,576 serialized bytes and 16 discovery columns per end.
Tests cover every pair, codec round-trip, real barrel-adapter capture/restore,
and refusal one byte beyond the ceiling. The downstream sealed plan has 20
slots. The ordinary I6 proof census has two origin slots, not 20; this is not a
maximum-duplicate-entity census experiment.

The native benchmark uses the installed journal, preparation, player-confirmed
command and I6 port. A proxy attached after real admission delegates all results
unchanged. It times server-thread calls and their completion callbacks; async
readback validators are untouched. Per-step statistics are exclusive sums per
method per invoked tick, with call counts and inclusive single-call maxima.
Nested callback time is not counted twice. Percentiles use nearest rank.

The cold preparation queue reaches 64 and all 64 become ready without changing
their journal records. Proof uses a separately forced, warm set of 2,048
discovery columns. Setup, forced warmup and offer construction are excluded;
preparation/confirmation admission is included. Forced columns stay loaded for
proof, so this is not a production-ticket-lifetime or unexpected-chunk-load test.

The unchanged consent window is 200 ticks. Proof rounds admit 64, 46, 28 and 10
fresh confirmations, yielding 18, 18, 18 and 10 accepted terminal submissions to
the real handoff. All 64 unique rockets are covered; 84 not-current outcomes
remain visible rather than extending consent. There are 140 confirmed captures,
zero refused captures and a peak of four active attempts. All accepted proofs
finish on attempt 1. Their start-to-terminal latency is P50/P95/P99/max
**22/23/25/25 ticks**; admission-to-terminal latency is **84/184/184/184 ticks**.
Inclusive tick counts are used, not wall-clock seconds.

Accepted terminal submission is not successful block restoration. Four downstream
sealed disassemblies log `REJECTED`; W197 does not claim 64 completed disassemblies
or close the combined terrain matrix. Those downstream operations and journal
continuations remain in whole-tick samples while the ordinary queue drains.
The raw events also retain `BUSY` and `SLOT_UNLOADED` release reasons.

## Native results and docs/17 comparison

The authoritative run used Windows 11, Ryzen 5 5500 (6 cores/12 threads), 32 GiB,
Java 17.0.7, Forge 47.4.10 and `-Xms512M -Xmx4G`. It ran once, exited 0, and passed
fixture and timing-integrity checks. The detached runner owned the heavy-JVM lock
from 16:42 to 16:49 local time; it waited for W196 rather than breaking its lock.
No other JVM appears in the before-native process snapshot. Other resident work
included Claude, W196/W197 Codex, MCP, a localhost Python HTTP server and a Python
repository validator. No extra Gradle job was launched by W197 during measurement.

Whole-process two-second samples, including startup/setup, show other-process
CPU mean/P95/max **4.22%/14.26%/20.31%** of host capacity. The host was not perfectly
idle; these numbers do not establish isolated reference-machine performance.

68.778 ms. There were zero native ERROR/FATAL, watchdog or OOM entries. Five
overload warnings remain: one during setup and four during proof windows.

Against the numeric targets in [docs/17](../../../17-V1PLUS-QUALITY-BUDGETS.md):

  `keepLoaded` alone exceeds a 50 ms tick at its median; cold loading is a concrete finding.
- Full-queue proof round 1 **exceeds mean and P99**; P95 holds numerically.
  Pooling smaller later queues must not hide that first-round P99 failure.
- All-round proof **exceeds mean**; P95 and P99 hold numerically. Ten proof-window
  ticks exceed 500 ms, with maximum **5,795.134 ms at tick 2,093**. Its native core

- This synthetic Windows run lacks docs/17's Debian reference node, connected
  player/device/station/satellite/transfer load, periodic restart and soak. It
  cannot approve the reference performance Gate, even where numeric targets hold.
