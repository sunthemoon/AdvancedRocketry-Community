## Timer correction after the first native run

The first native run from `a5877e142` reached all 64 preparations and proof
handoffs, four simultaneous attempts, and 140 confirmed captures without a
capture refusal. The unchanged GameTests passed 1,534/1,534 and their checker
passed. All original outputs remain in `native-01/`.

Review found a timing boundary omission: `RocketJournalLifecycle` polls and
runs continuations in an earlier `HIGHEST` START listener. The first observer
started after it and reset its accumulated costs. The Forge 47.4.10 source
patch confirms that vanilla's native timer begins before START and is recorded
before END. The corrected benchmark therefore sums `MinecraftServer.tickTimes`
for the current tick and a separate HIGHEST-to-LOWEST END interval, without
double counting the core. It clears method totals at END, preserving earlier
START callbacks. It retains both components and the old late-START interval
in the CSV for comparison. A fifth fixture test checks the addition and invalid
durations. No production file or budget changes. The first run's whole-tick
figures are superseded by a new committed-source run, not silently corrected.
