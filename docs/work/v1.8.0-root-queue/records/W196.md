**Write scope.** Bay coordination and released-flight adapters, their existing transfer/entity/passenger boundaries
(excluding `RocketTransferService`), receipt locking, associated unit/GameTests and native harness, exact log
expectations for new tests, and this record. No upstream assets, ADR, risk register, status, ledger, build or workflow
file is in scope. Root supplies the risk-register update and independent review before merge.

**Eligibility and durable release.** A coherent REPAIR or REGISTRY_BLOCKED claim must name one checked legacy T,
one L and owner, with matching end snapshots, package signatures and existing consumed markers. Unknown authority,
protected wrappers, another T, or unrecognized copies remain held. Finish the existing REGISTERED group's D5 on the
source, journal and recognized copies before any delegation. Preserve INTENT/REPAIR packages byte-for-byte and do not
register or retire receipts during released recovery. Publish `withReleased()` for the unresolved group through the
existing grouped receipt writer. Delegate nothing until every exact candidate is current and acknowledged; FAILED
retries and UNKNOWN retains the writer's exact candidate. Pending and retained charges remain unchanged.

**Exact delegated actions.** A session-owned authority binds the receipt group, L/T/owner, snapshot IDs, dimensions,
origins, full hashes, source/destination UUIDs, neutral wrappers, manifests/resources and checked old/next journal
digests. Only one-step legal phase successors are admitted. `TICK_SOURCE` and `SPAWN_DESTINATION` use the existing
dispatch; journal continuations must validate both before publication and immediately before their acknowledged
effect. Passenger movement has its own synchronous assigned-player/endpoint scope, never a global `idle()` bypass.
Endpoint/save/movement changes invalidate pending permits; current physical authority must be checked again.
Ordinary source settlement and PREPARED journal removal are refused. Destination publication, passenger transfer,
source removal, descent and completed-reservation handling retain all escrow and checked-writer checks. A failed
destination cannot silently roll the released flight back to a stationary source.

**Restart and completion.** Released receipts are claimed before ordinary recovery. Only the checked phase's exact
source or destination authority may resume, with loading restricted to the existing recorded-end census and existing
budgets; no registration, new operation or receipt retirement is inferred. Missing T is an offline-repair hold,
including after a previously completed flight, never permission to rebuild or redeploy. Completion leaves receipts,
the shared 64/8 pending charge and the rocket's launch/disassembly/resource/package locks intact. R49 Q2 remains:
dismounting is not cancelled. Because released receipts can now name landed rockets without T, NOT_LOADED must hold
all logical rockets until the receipt index is available; the former PREPARED-only inference is no longer sound.
This availability change belongs in Root's R-042/R-043 update before merge.

**Saved structures.** Intended writes use only existing fields: the receipt root's `released` flags; existing journal
record snapshots/checksum for REGISTERED consumption and its phase/destination identity for flight; existing rocket
entity snapshots, flight data, UUID/owner/logical ID, position and entity removal; vanilla passenger position,
dimension and vehicle state; and existing landing/reservation/first-event state reached by ordinary completion.
No new schema, field, persistent token or file is planned. Existing 8-member, 32-step, claim, snapshot-work,
64-match, 16-column/end, writer, ticket and barrier limits remain unchanged. Any need for a new format, bound,
budget, quota, timeout, or any line in `RocketTransferService` is a stop-before-code condition, not authorization.

**Verification.** Run each new unit class alone and the whole suite, all bay batches three times, and B10 release
native cuts with two restarts each, at most 60 counted starts per tranche. Heavy runs use the atomic machine lock,

under `D:/GitHub/ARCE-Task-Evidence/root-queue/W196/`, below 100 MB. No existing assertion, timeout or budget is relaxed.
