## Completed scope and design decisions

Every review/decision date guard found in `scripts/`, `tools/` and the W268 helpers now requires a string matching
exactly `[0-9]{4}-[0-9]{2}-[0-9]{2}`, followed by `date.fromisoformat(value).isoformat() == value`. Invalid dates are
rejected before preparation-date comparisons. There is no trimming, Unicode normalization, type coercion or new
chronology restriction. The canonical W268 preparation date is still refused for its existing adoption cohort.

The v1.8 importer already reuses the v0.1 importer's review validation, so both use that corrected implementation.
Otherwise, existing standalone validators keep local helpers rather than gaining new cross-module dependencies.
The repository validator shares its local helper between identity review dates and date-only Gate approvals;
its existing timezone-qualified timestamp forms remain supported with explicit ASCII digits. No ADR choice was
open, no exception was introduced, and no review authorization or provenance clearance was granted.

The search also found date guards in the older release, bootstrap and manual-evidence validators. Their ASCII
and round-trip requirements are now explicit. In particular, identity review parsing no longer accepts impossible
dates, and bootstrap review validation no longer accepts compact or ISO-week dates. Remaining `\d{4}` matches
are log timestamps and log/crash filenames, not review or decision-date guards.
