## Item 1: the six tests reach the structure discovery again

- **The helper.** `LandingOccupancyGameTestSupport.leaveToDiscovery` is test-only code. It:
  - asserts that the occupant's base box (the type's fixed 1.5 by 4 box, its whole entity box before W311) stays clear of
    the arrival;
  - asserts that its structure-sized box reaches the arrival, which is why the test narrows it;
  - narrows the entity box to the base box with `setBoundingBox`, without moving the rocket;
  - asserts that the selector's quick check (the same `getEntitiesOfClass` query) then finds no rocket at the arrival.

  W311's two box assertions moved into this helper unchanged in meaning. Every refusal assertion is unchanged.
- **Why the narrowed box holds.** The server rebuilds the box only when the rocket's snapshot or flight data changes, or
  when it is reloaded. A parked occupant's server tick does not touch its box (`RocketEntity.tick` and `refreshSyncedData`).
- **The five occupancy tests.** Each narrows the occupant right after its geometry checks, before the first refusal:
  - `LegacyLandingPadOccupancyGameTests`: the station pad refusal, the pre-spawn refusal and the fixed-pad refusal;
  - `NamedLandingPadOccupancyGameTests`: the preparation refusal and the pre-spawn refusal.
- **The arrival-footprint test.** The parked rocket is unloaded and reloaded before the refusal, and a reload restores the
  structure-sized box. On each due visit with the rocket loaded, the test narrows it again before `tickLive`. It then
  asserts that the visit which logged the refusal naming the rocket had the base box.
- **Named pads never ran the quick check.** `NamedLandingPadStaging.unavailable` goes straight to
  `NamedLandingPadOccupancy.unavailable`. Selection, recheck and `spawnDestination` all use it. So the two named-pad tests
  reached the discovery even after W311, and the TASK's premise holds only for the four other tests. The two named-pad
  tests narrow the box anyway, so that they keep W13 R1's premise if the staging ever gains an entity-box check.

## Item 2: the quick check's own refusal

`LandingPadQuickCheckGameTests.quickCheckRefusesAWideOccupantThroughItsStructureBoxAndNamesIt`, in a fresh station's
Space column:

- R1's wide occupant (X=0..15) has its origin on a section's west edge, and the arrival lies at X=9..11 in the same
  section. Vanilla's search therefore visits the occupant's section, and only the entity box decides.
- The test asserts that the occupant's base box misses the arrival, and that the quick check finds exactly that occupant.
- `RocketLandingPadSelector.unavailable` returns `occupied` and logs exactly one `ARCE_PAD_OCCUPANCY_REFUSED` line. The line
  names the occupant's UUID, position and arrival, with `snapshot=readable`. The quick check returns before the discovery
  runs, so that line is the one from W311's commit `373e3e274`.

## Item 3: a tall occupant and vanilla's section margin

- **The margin.** Read from the Forge 47.4.10 bytecode with `javap`:
  - `EntitySectionStorage.forEachAccessibleNonEmptySection` visits sections from 4 blocks below the searched box up to its
    top, with no margin above, and from 2 blocks beside it;
  - `EntitySection.getEntities` then keeps the entities whose box intersects the searched box;
  - `Level.getEntitiesOfClass` adds no margin of its own.

  A rocket is indexed in the section of its position, its origin block.
- **The quick check can miss.** It misses an occupant whose origin section lies below the section that contains the
  arrival's lowest block minus 4, even when the occupant's structure-sized box covers the arrival. The GameTest
  `tallOccupantBelowTheSectionMarginEscapesTheQuickCheckAndTheDiscoveryRefusesIt` builds this case:
  - an eleven-block column with a two-block arm at its top, its origin 12 blocks into section 4 (y = 76);
  - a one-block arrival under the arm, at y = 84, so vanilla's search starts in section 5;
  - the test asserts that the occupant's box covers the arrival, and that the quick check finds no rocket;
  - a search that starts at the occupant's base finds it, so the miss comes from where vanilla starts searching.
- **The discovery refuses it.** `NamedLandingPadOccupancy.discoveryBox` reaches `RocketLimits.MAX_BOUNDING_VOLUME - 1`
  (32,767) blocks in each direction, clipped to the build height, and to the station region horizontally. Its search
  therefore starts at the bottom of the world (`LegacyLandingPadOccupancyTest` asserts this) and always visits the
  occupant's section. In the GameTest the selector returns `occupied` and logs one line naming the tall occupant.
- **No production gap.** The quick check is only the first of the two steps, so item 4's condition is not met and no
  production code changed.
- **The same mechanism elsewhere.** The quick check also misses an occupant whose origin lies above the arrival's top
  section, and one whose origin lies more than 2 blocks beside the arrival in another section column. The discovery's
  reach covers both. They were reasoned from the same bytecode and are not tested separately.
- **A non-operational occupant** keeps the type's fixed box, because its snapshot cannot be read. The quick check sees only
  that box; the discovery refuses every unreadable rocket that it visits.

## Choices

No ADR was open for this task. Where the TASK left room, the choices were:

- **Test-only narrowing.** The tests narrow the box with the public `Entity.setBoundingBox`, so no production hook was
  added.
- **All six tests, the named-pad tests included.** This keeps them alike and holds W13 R1's premise (see item 1).
- **An existing batch.** The new tests use `legacy_pad_occupancy`, so no batch name was added, and each test has its own
  fresh station and ticket.
- **W311's assertions kept.** The base-box and structure-box assertions became preconditions of the helper.

## Not done and known risks

- **Test-only box writes.** The helper calls `setBoundingBox` on a parked rocket. That changes only that rocket's entity
  box, until its snapshot or flight data changes or it is reloaded; the fixtures discard it at the end. The narrowing
  relies on the server not refreshing a parked rocket's box on its own, as is the case today. Each refusal in the six
  tests runs in the same tick as the narrowing and its quick-check assertion, so a future per-tick refresh would not let
  the quick check refuse unnoticed.
- **W311's premise kept as a precondition.** The helper asserts that the structure-sized box reaches the arrival before
  narrowing it. A later change that shrinks the entity box fails these six tests at that precondition, with a message
  that says so.
- **The station clip.** Outside this task, and not tested: for a Space arrival inside a station, the discovery is clipped
  horizontally to the station region. An occupant whose origin lies outside the region, more than 2 blocks beyond its
  edge and in another section column, is visited by neither step. This could happen only if its structure reaches into
  the station over the arrival. The quick check misses it through the margin, and the clipped discovery does not visit
  its section. This was already so before W311, because the old base box lay outside the region. W311 changes nothing
  here.
- **Batch count.** Both new tests use the existing `legacy_pad_occupancy` batch, so this task adds no batch name. It
  therefore cannot push the batch map past its resize threshold, which W311 recorded as reached.
- **Open full-run failure.** `sleepisdeniedinvacuumonaplanetandinspace` failed in the local full run, and so the local
  checker failed. As described above, it follows the batch order that W309's batch changed, and W314's run shows it
  without this task. The hosted sharded regression decides.
- **Not done.** No real-client check, because nothing visible changed.

This record approves no version or Required Gate. Root's diff review and the hosted sharded regression remain.
