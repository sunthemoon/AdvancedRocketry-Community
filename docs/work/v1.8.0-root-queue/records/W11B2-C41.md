## Scope and design

This worker owns the governed retry adapters, their tests, the governed-flight
benchmark and this record. Continuation 40's reconciliation files, all other
worktrees, status files, the ledger, ADRs and log expectations are not edited.
Production admission, W27f, W11b3 and version/Gate approval are excluded.
Commits stay local; Root performs review, integration and pushing.

Retry scheduling belongs to the logical rocket's runtime lifetime, not an
individual terminal proof capture. Replacing an invalidated capture must release
its proof watches without discarding the retry count or due tick. F6 proof and
F7 definite-write failures use the existing 100/400/1,200-tick schedule. UNKNOWN
remains owned by the checked writer with its exact candidate and 200-tick gate.
The scheduling state supplies no action authority and changes no stored schema,
proof, acknowledgement order, replay rule or resource lock.

The terminal adapter retains an invalidated in-flight capture until its exact
callback has released its watch and recorded the failure. Definite F7 refusal
uses the same logical history; queued/UNKNOWN F7 never replaces its Work or
candidate. Only acknowledged terminal success, checked journal absence or runtime
closure clears terminal history. Both maps are bounded by 64 active flights.

Failed public successor classifications retain a logical retry schedule across
record/serial changes. The existing hard/manual authority checks still decide
the hold. R10/R11/R14 acknowledgement/lifecycle waits remain silent and do not
become failed attempts. Final action permits still repeat their original checks.
The hold tuple now includes the logical UUID explicitly, in addition to ledger,
transfer, serial, phase, reason and backoff; the F1 call-site edit only supplies
that identity, without changing its writer policy.

### Wait audit and implementation choices

at most the existing landing-column bound and never constructs an envelope.
Flight tickets still refresh only after positive ACTIVE classification, using
the same two recorded origins and expiry. Backing off ticket refresh itself
would expire a healthy flight's tickets, so no cadence change is made there.

Unresolved passengers now short-circuit before complete envelope capture. The
dispatcher's landed-successor and recognized-return hints only suppress work;
they never grant authority. F1's pre-countdown source is not mistaken for a
returned survivor. Reconnection still requires the original full boundary,
survivor validation, own-store/force/readback and exact writer acknowledgements.

validators; the barrier's final reservation remains mandatory. R10/R11/R14
acknowledgement and lifecycle waits stay silent. No schema, proof, hold effect,
acknowledgement order or replay exclusion is changed.

replaceable capture. Return absence/F6 and F8 prune failures use the common
