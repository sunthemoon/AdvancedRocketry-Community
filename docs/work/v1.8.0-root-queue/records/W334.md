## Scope, source commits and design

The implementation changes only the three bay-exit test sources below and this record.
Their common directory is `src/main/java/io/github/sunthemoon/advancedrocketrycommunity/rocket/server/`.

- `BayPassengerExitGameTestArea.java` selects a BE-free origin inside this test's own
  16x16 columns. Sealed cases retain their radius-5 window: 36 relative `(x, 4, z)`
  positions with x and z in 5..10, each with at most 7,139 cells, or 257,004 checks.
  Unsealed cases use their actual radius-3 footprint: 100 positions in 3..12, each with
  at most 2,891 cells, or 289,100 checks. Both check the full -3..55 height, not just
  vanilla's cleared portion. They read loaded chunks only and add no ticket or force.
  Rejected candidates are logged at INFO with the obstructing position.
- `BayPassengerExitGameTestFixture.java` uses that selection after its existing setup
  tickets become ready and before creating players or flights. All scenarios, including
  the shared descent enclosure, receive bounded preflight. The ambient-fluid setup also
  uses radius 5 because its water writes reach that far. A later sealed-area `prepare` still
  validates every cell before its first write and refuses every BE, regardless of owner.
- `BayPassengerExitAreaGameTests.java` seeds a chest above vanilla's cleared ceiling,
  checks the original refusal's no-write behavior, prepares an avoiding window, and
  checks the same chest object and three diamonds before and after restoration. It also
  checks allocation bounds and unchanged loaded/forced chunk counts. A second test puts
  a BE in every full-size candidate's common footprint and verifies a no-write refusal.
  A third verifies that the smaller descent footprint can avoid an obstruction that
  blocks every full-size window. The inventory-bearing seed is emptied before its owned
  chest is removed, preventing cleanup drops.

The source commits are `b0837abb5` (selection and regressions), `9e3e997e1` (seed inventory
cleanup), `90020a6eb` (geometric rather than ordinal assertions), `48f10b568` (absolute
template-coordinate bounds) and `093b17a4e` (actual per-scenario footprint and third
regression). The final source is `093b17a4efd10490ec1e63498a46fee139a486f4`.

Avoidance was chosen instead of deleting supposedly stale BEs. It needs no retrospective
ownership classification, preserves running-test and terrain BEs alike, and refuses if
all windows for that scenario are occupied. The ground/local/gantry shapes, candidate ordinals, existing
assertions, test timeouts and production budgets are unchanged. No production logic,
save schema, network protocol, asset, provenance entry or ADR decision changed.

## Failure investigation

Hosted run `42612205968` at `8d22b9ba7` failed only
`unassignedridergetsonlylocalplacement` in shard 3. Attempt 2 repeated the identical
failure at `(186, -2, 189)`; its other three shards passed. The second job log was read
through GitHub's API using the repository's existing noninteractive credential helper.
No credential was printed or written to evidence.

An export of committed `c27d81f9e` replayed all 188 historical shard-3 batches, preserving
vanilla's order and hooks. It reproduced that exact failure: 411/412 tests passed. A
temporary external observer recorded the native registry, test positions, and the BE
without changing blocks, tickets, schedules or assertions. Its reporter delegates the
normal vanilla reporter.

The object is `minecraft:chest`, with unopened loot metadata
`LootTable:"minecraft:chests/simple_dungeon"` and
`LootTableSeed:-1691400596937156819L`. It was first observed during the **first** batch,
`bay_deployment_matrix`, while `theCapturedSourceBodyIsTheOneTheDataReceiptRecords` was
active, and remained present when `bay_exit_local` started. That test name identifies
the observation context, not a writer. Subsequent startup diagnostics in the mutation
runs identify a `NoiseBasedChunkGenerator`, seed 0, with the target chunk not yet loaded;
they do not establish pre-test BE presence in the historical run. The loot metadata and early
observation support generated dungeon terrain, not a BE left by a completed earlier
batch. No BE-creation stack was captured.

The native registry and pinned Forge 47.4.10 `javap` layout agree with the historical
anchors: `bay_exit_2` starts at `(145, -60, 182)`, `bay_held_proof_retire` at
`(165, -60, 182)`, and `bay_exit_local` at `(185, -60, 182)`. Vanilla advances by
template X size minus one plus five. The failing cell is therefore **relative
`(1, 58, 7)`**, inside this test's horizontal columns. Vanilla clears through template
max Y plus 20, or relative +35, whereas the bay window reaches +59. The chest is 23
blocks above vanilla's cleared ceiling. The original two-column low-side overreach is
real but is not the cause of this particular collision. Moving the origin inward alone
would not fix the full-height precondition.
