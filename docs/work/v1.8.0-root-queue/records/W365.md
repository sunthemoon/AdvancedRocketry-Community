central status files, build scripts and pushes are excluded.

The reader design preserves NBT types for row bounds and canonical digests. Root 2
and receipt 3 retain their legacy semantics. Root 3 validates bounded rows and their
operation, receipt and frozen-group references before any oracle uses them. Fresh
fluid cases require accounted operations/receipts in root 3; item receipts remain
schema 3 UNKNOWN. A single-member KNOWN row is recomputed per key; a shared
adjustment has one validated owner and is not summed across receipt references.
Native observations and later flight consumption remain separate from the frozen
transfer account. Commands, results, caller inventory and commits follow below.

## Implementation and conservative choices

The shared `escrow_accounting.py` reader checks the closed row fields and native
types, R443's 2,048 bytes / depth 5 / 65 nodes / 14 members, ordered fluid keys,
checked signed-long arithmetic, masks, ownership and knowledge. It recomputes
each single-member KNOWN identity per key, including signed gains and losses.
Operation baseline digests, receipt row digests, intent commitments and complete
frozen group membership are checked. Each key's adjustment must belong to its
first eligible member; shared references are not counted as additional losses.
The native ledger reader also checks the amount-free key using the original
native Tag types. This diagnostic reader is not a substitute for the production
codec's full endpoint, capacity and durable-proof validation.

Root-2 native files require the old epoch and legacy forms. Root-3 native files
require the new epoch and account list; there is no fallback after an error.
Historical oracle-only JSON projections that omit root framing still take the
unchanged legacy checks. Explicit root-3 fluid fixture cases require accounted
operations and receipts rather than silently claiming a migrated legacy row.
Item receipts remain schema 3 UNKNOWN, including inside root 3. Missing-endpoint
receipts remain UNKNOWN. Cargo `payload_amount` remains zero, and fuel's payload
diagnostic remains 1,000 in these fixtures. No quantity is reinterpreted as cargo
or as later flight fuel consumption.

The loader oracles compare complete versioned expected receipts derived from O1,
not from the observed receipt. Private legacy resource projections are used only
after validating the original accounting authority, so an orphan row cannot be
hidden by a projection. Both synthetic restarts retain the frozen account and
digest. S4/S5 checks retain account history through PRUNE and governed flight.
Ordinary L2 may remove its planned row; frozen receipt-backed rows may not vanish.
The three gated comparisons in `EscrowCargoSettlementCuts` (two sites) and
`EscrowSettlementProbe` (one site) share an exact row/status/digest predicate.
Their result logging now reports the actual receipt status. Item probe comparisons
and all family/case selection tables are unchanged.
