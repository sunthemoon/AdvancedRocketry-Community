# W104: Journal and escrow drain clock

## Design note (before implementation, 2026-10-19)

The clean starting commit is `b5684eb951e909a2660852cffa8cc23a09537cf5` on
`codex/v1.8.0-w104`. The write scope is the two writers, their tests, a temporary
matrix timing probe, new test fixtures, and this record. No scheduling rules,
timeouts, generated cases, save formats, ADRs, risk entries, status files, or
ledger entries will change. No upstream code or assets are imported.

The unchanged targeted run reproduced the generated matrix timeout at 30.032 s;
the acknowledgement table took 25.568 s. The two escrow unknown-drain tests took
6.326 s and 6.372 s. A standalone Java 17.0.7 sleep probe averaged 1.718 ms without
synthetic load and 1.688 ms under the W102 two-process, two-CPU load. That is not
representative of the bootstrapped test JVM: its temporary 400-sleep probe measured
15.597 ms mean, 15.579 ms median, and 16.143 ms p95. Individual failed matrix saves
took 6.326-6.581 s for three completions, with last-write IO times of 5.728-227.521 ms.
The unchanged drain sleeps at least 400 times between three failures, accounting
for about 6.24 s at the measured mean. Both writers have the same costly loop.
Further loaded measurements and exact artifact hashes are recorded below.

The change will derive the drain's owner tick from monotonic elapsed nanoseconds
at one millisecond per drain tick, instead of counting one overslept wait as one
tick. The starting tick remains `max(owner tick, retryAt)`. After each pump the
owner sleeps until the next millisecond boundary; an oversleep advances over
empty ticks on the next pump. No gameplay or queued journal effects are pumped.
A 200-tick retry therefore still requires 200 owner ticks, approximately 200 ms
plus wakeup and IO delay, rather than 200 independently rounded sleeps. Escrow's
ten-tick start cadence uses the same continuing owner clock.

The existing tick methods retain sole ownership of completion validation,
publication, successor capture, retry deadlines, and the three-unknown-attempt
limit. Callback order and rejection of requests while draining remain unchanged.
Owner checks, interruption restoration and exception messages, close/join and
abort semantics remain unchanged. Injectable package-private clocks/waits and a
journal executor seam will let tests simulate coarse timers and nanosecond-counter
wraparound without depending on the host timer period; ordinary constructors
will still use real IO threads. Existing high-uptime drain tests remain intact.

A Windows dedicated server with persistent write failures gains a shutdown retry
budget near 0.4 s for the two backoffs rather than about 6.2 s per failed candidate.
Disk IO and scheduling can still delay shutdown; this is not a shutdown deadline
or permission to release world ownership before IO joins. There is no new save
refusal, data discard policy, or migration. Root must arrange the separate
read-only persistence review before merging.

## Execution

The pre-implementation design was committed as `ddf684f6`. The loaded probe also
confirmed the cause: mean sleep 15.608 ms, median 15.630 ms, p95 17.436 ms. The
acknowledgement-table test took 27.483 s; the generated test timed out at 30.029 s.
These measurements used W102's unchanged `cpu-load.py`, two processes, affinity
mask 3, and `-XX:ActiveProcessorCount=2`. The no-added-load measurements were not
an exclusively idle host: other workers remained active and were not interrupted.

Both writers now derive their drain ticks from elapsed monotonic time. Six new
tests use real IO threads with a virtual 25 ms wakeup clock. They cover both
journal failure outcomes, escrow unknown retries, successor ordering, continued
high owner ticks, escrow cadence, drain request rejection, interruption, abort,
join, and signed nanosecond-counter wraparound. Three of the six tests failed
with the old counter loop plus only the injection seams; all six pass with the
fix. Each new class also passed alone (three tests each). The temporary matrix
probe has been removed, leaving that source file unchanged.

Committed-source repeated, full-unit, and GameTest acceptance runs are pending.
The version's Required Gates remain unapproved. No ADR choice or contract change
was needed; Root's separate read-only persistence review remains required.
