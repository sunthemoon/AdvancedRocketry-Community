## Design choices and manual checks

The suit is one non-dyeable NEW set. The three overlay/base pairs share NEW
targets; the helmet overlay row receives a complete NEW helmet icon, and
the trouser overlay row receives a complete NEW layer-2 base. The NEW
leggings icon completes all four existing item IDs. This produces 16 PNGs
for 18 audit rows, not 18 unrelated files. No legacy file was opened or
traced. `SpaceSuitMaterial` preserves helmet/chest/legs/boots protection
2/6/5/2 and durability 165/240/225/195, enchantability 9, toughness and
knockback resistance 0, iron equip sound and iron-ingot repair. Existing
oxygen and module code, IDs, attributes and saved payloads are unchanged.

Only the orbital laser's model parent changes to provide its dedicated bottom.
Other model IDs and native geometry stay the same. Unmodified project casing
and the existing legally referenced vanilla top textures remain where outside
these audit rows. Current source-root model bindings are regenerated in place,
not duplicated across resource roots. An unexpected DataGen output layout is
rejected before the provider writes any sibling root.

Human originality and V1 checks remain open. On the reviewed build, inspect
all six machines, both electrolyzer states, the orbital laser bottom, the two
solar icons and all four suit icons. Equip each suit piece alone and as a set,
inspect helmet, torso, cuffs, trouser knees and boot sole UVs in third person,
and install the existing tanks, visor and jetpack to check attachment overlap.
Reload resources, test GUI scales 2/3/4, and record the GPU, build SHA,
screenshots and observed results. Compare all machine faces by eye with the
native counterparts named by ADR-061 section 4.5. A code-generated contact
sheet is not a Minecraft real-GPU or originality approval.
