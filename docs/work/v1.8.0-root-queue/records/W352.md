## Completed scope and design

Only the gated R1 fixture changes behavior. Both `R1_255` and `R1_256` now call
`EscrowCargoRecoveryProbe.r1Record`, which supplies
`RocketFuelState.empty(recorded.propulsion().orElseThrow())` with a 1,000 mB
`minecraft:water` bank to the existing record builder. Its 500 mB plan, transit,
arrival and `land(200)` flight data retain C1's construction. The existing
five-argument builder is package-private instead of private; both it and the new
helper call `EscrowTestEndpoints.requireEnabled`. The public current-fuel wrappers
and `landedRecord` keep their behavior.

The new unit guard starts with an ASSEMBLED rocket containing no fuel. It confirms
that the current-fuel wrapper refuses that input, then compares the R1 builder's
complete plan, transit, arrival and landed NBT with an independently constructed
C1 synthetic-fuel result. It also checks the committed destination binding,
500 mB remaining fuel, no mutation of the live rocket while building the record,
and rejection outside the fixture gate. It uses the existing `UnstartedServer`
test support and calls `MinecraftBootstrap.initialize()` before Minecraft types.
The native runs exercise the complete R1 placement and persistence flow.
