# W282: suit refill data and empty-canister return

## Design note (before implementation)

The assigned worktree is `D:/GitHub/arce-v180-w282`, branch `codex/v1.8.0-w282`,
starting at `be8c262df`. Write scope is the normal oxygen-canister use adapter,
its suit-service hand return, focused equipment tests, and this record. No asset,
ledger, status, queue, build, workflow, accepted ADR or other task file changes.
There is no push, merge or delegation.

ADR-066 sections 4 (W226 alternative), 5.1 and 9 D1, W174-DESIGN sections 2.4/9,
and W226's design distinguish normal oxygen use (active buffer) from sneaking
oxygen use (installed tank). The reported active 1,000 and EMPTY auxiliary zero
match that design. The balances remain separate; no oxygen migration is needed.

The persisted module `kind` is the shared `ModuleKind` family discriminator,
not the component's registry ID. All four tank items map to PRESSURE_TANK, whose
existing stable discriminator is `low_pressure_tank`. `stack.id` preserves the
actual tier and `TankData.maximum` its capacity snapshot. This is not a saved
pressure_tank item being converted into a low-pressure item. Preserve the stable
discriminator and test the four tiers and old data explicitly. No saved field,
schema, public ID, decoder or migration changes are planned.

W226 permits replacement of a single held canister in its source slot, and the
existing `CanisterStackSwap` already applies that convention to the finite tank
route. Apply it to normal survival oxygen use as well, in either hand. Keep the
existing stacked-canister inventory return and creative exemption unchanged.
The item adapter must return the actual post-use hand stack so vanilla item-use
publication cannot overwrite the replacement. This changes no persistence owner,
save policy, automatic charger behavior or cross-store durability claim.

## Execution

### Completed scope and commit

Implementation, tests and the initial design note are committed as
`7686174f88ade0100fcf4c8726c7d1a90f564b9d`. All final source verification uses
that commit; this completion-record update changes documentation only. Execution
spanned 2026-11-05 and 2026-11-06 local time. Nothing was pushed or merged.

1. **Active-buffer oxygen matches the design.** Normal use directly credits
   `arce_space_suit_oxygen`; it does not first fill and then drain the auxiliary
   tank. The installed EMPTY tank correctly stays EMPTY/zero. Sneaking oxygen
   use remains the separate O1 installed-tank operation. Both balances and
   existing saves are unchanged, so no oxygen migration is introduced.
2. **The saved kind matches the shared family model.** ADR-066 requires a shared
   module-kind table and preservation of existing IDs; neither it nor O1 requires
   `kind` to equal `stack.id`. `low_pressure_tank` is the existing stable family
   discriminator for all four tank tiers, not a claim that the item has the lowest
   tier's capacity. Keep it rather than rename a saved ID without a behavioral
   correction. Old values continue to load unchanged; the item ID, saved maximum,
   stored gas and foreign tags survive round trips. No decoder alias is needed.
3. **A single consumed canister's return deviated from vanilla convention.**
   Vanilla `ItemUtils.createFilledResult` returns the replacement when the source
   becomes empty. The suit service now uses that helper in its existing
   non-creative branch, and `OxygenCanisterItem.use` returns the actual post-use
   hand stack so `ServerPlayerGameMode.useItem` retains the replacement. Main
   hand slot 7 and offhand both work, including with completely full storage.
   Stacked sources still keep their remaining filled canisters in hand and
   return the empty to inventory; the normal-use creative exemption is unchanged.

No schema, saved-field format, module identifier, active-buffer location, save
protection, network contract or charger behavior changed. The design note above
was written before the production changes; a migration design was not necessary.
