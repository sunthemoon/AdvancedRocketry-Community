**Scope and classes.** Extract the checked replacement/readback core of
`RocketJournalCheckpoint` into `CheckedJournalCheckpoint`, retaining the transfer-specific
acknowledgement adapter and its existing off-thread `RocketJournalWriter`. Compose that
same core into `RocketTransactionSavedData`. Add transaction proof unit tests and A1
GameTests. Write scope is these persistence classes, their direct tests/GameTest support,
and this record. Existing transaction, assembly and disassembly tests are read-only.
`RocketTransferService`, central status, ledger, ADRs and risk register are unchanged.

**Write path.** Transaction autosave `save(File)` and an explicit `saveChecked`/server
checkpoint use `CheckedSavedDataPolicy` for `ROCKET_TRANSACTIONS`: bounded encode, forced
staging file, staging readback, atomic replacement without fallback, directory force
where supported. Reuse the transfer journal's exception-time exact-candidate readback
and previous-root digest comparison. Transaction writes remain synchronous, matching
their existing save cadence; no second executor, queue, tick hook or deployment caller
is added. W27d can request one checkpoint and keep the rocket waiting until its next
query. Encoding-only `save(CompoundTag)` and loading never acknowledge durability.

**Proof.** Session-local immutable acknowledgements contain mutation sequence, canonical
root digest and transaction-ID-to-record-digest map, using the shared streaming NC1
digest and existing journal depth envelope. Every dirty mutation advances sequence;
only an exact successful capture clears dirty. A bounded query checks the logical rocket's
assembly transaction ID, snapshot ID and entity ID against remaining records, so both
assembly and disassembly records refuse with `ASSEMBLY_JOURNAL_PENDING`, even if saved.
No record plus current acknowledgement proves absence; stale/unacknowledged state requests
one checked write; a definite failure or UNKNOWN refuses with `ASSEMBLY_JOURNAL_UNPROVED`.
The caller's waiting/rejection of all bays remains W27d, not an implementation here.

**Failure and recovery.** A definite failed replacement keeps old disk proof and dirty RAM;
it cannot prove a newer capture. Ambiguous replacement/readback or directory-force failure
clears proof and remains UNKNOWN until a successful checked write. A later pre-replacement
failure cannot turn UNKNOWN into proof. Blocked future/invalid roots are preserved, never
overwritten by checked saves, and never acknowledged. Refusal affects this journal only,
does not discard RAM records, does not throw as normal save control, and adds no logging
loop. Recovery is the existing legitimate transaction recovery/removal followed by a
successful checked write; restart discards session proof. Root owns required ADR/risk notes.

**Compatibility and exclusions.** Schema 2, format epoch, stable filename, quotas, transaction
count, timeout and all saved fields stay unchanged. Existing assembly/disassembly mutation
and recovery ordering is unchanged; only their eventual file persistence is checked.
No upstream imports, W27d deployment, W27e admission, protocol or asset changes.
