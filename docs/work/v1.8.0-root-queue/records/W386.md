## What was done

- `07a1a2f69` changes `BoundedSavedDataIo.read`. A file of 0 bytes is now refused with `INVALID_SCHEMA`
  (`ARCE-BETA-2000`) and the message `<data name> file is empty (0 bytes)`. A file above the type's compressed limit

## The staging path

`WorldDataMigrationService.stageMigrations` validates each staged file with `BoundedSavedDataIo.read`. It rethrows
`OVERSIZED_DATA` as it is and wraps every other refusal as `STAGING_FAILED` (`Cannot stage and validate every migrated
SavedData file`).

- Before W386, an empty staged file reported `OVERSIZED_DATA` from the staging step.
- Now an empty staged file reports `STAGING_FAILED`. Its cause is the `INVALID_SCHEMA` refusal with the empty-file
  message. This is the same result as for any other invalid staged output, such as a truncated staged file.
- The originals stay byte-exact, the staged file is deleted, and no commit runs. The pre-migration backup already
  exists at that point, as before, because the backup precedes staging.

`WorldDataMigrationServiceTest.emptyStagedFileReportsStagingFailedAndKeepsTheOriginal` pins this with a stager that
leaves an empty file.
