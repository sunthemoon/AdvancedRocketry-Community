## Implementation and decisions

- The terminal target and status occupy the 160-pixel column between the arrows,
  with separate rows and gaps before the action row. The bay hatch's top edge moves
  below its notice; no inventory slot moves. The builder's complete insertion hint
  wraps into two rows inside the existing 180-pixel column, clear of the charge slot.
  Valid blueprint statistics and the builder's status keep their original rows.
- `BodyDisplayNames` extracts the drill's body-name formatter. The drill, generator,
  railgun, elevator and star map share it through `EndgameViewText` where appropriate.
  The existing celestial snapshot maps Level IDs to logical bodies; the fixed
  Overworld/Earth alias works before a snapshot arrives. Coordinates, endpoint
  identity prefixes and selection counts are retained, not translated as IDs.
- The built-in black-hole fuel table had no name key. The v1.8 language generator
  supplies `black_hole_fuel.advancedrocketrycommunity.default` in English and Chinese.
  Custom tables can supply `black_hole_fuel.<namespace>.<path>` (slashes become dots);
  missing names retain their canonical ID. No fuel-table data or behavior changes.
- ADR-035 asks for localized body/environment details, not a visible raw-ID suffix.
  The star-map detail line therefore keeps only the translated name. Shared Space is
  removed from the display layout after the complete graph is validated. Other gas
  bodies and any datapack descendants remain inspectable. Selection is normalized
  against visible nodes, including when inspecting an existing station target.
  Existing stations around Space do not require this node: W308 establishes that
  no rocket route reaches or leaves that orbit. Evacuation through the warp controller
  remains unchanged. No catalog entry, station record or navigation packet is removed.
- The elevator Bind rule cannot be named from the data the client already receives.
  `ElevatorMenu.apply(BUTTON_BIND)` takes only `.code()` from `ElevatorPairs.bind`;
  `EndgameDeviceMenu.clickMenuButton` calls `EndgameIntentGuard.statusLine`, which sends
  only the translated `EndgameCode` and its name. The view's `pair` line describes the
  existing pair, not the rejected Bind; an unbound terminal has `NOT_BOUND`, so it
  cannot identify that Bind failure. A later task would need to preserve the returned
  `Check.rule()` and pass its translated explanation through the action notice,
  or explicitly extend the view/menu protocol. This task does neither. The railgun's
  notice lifetime and device-status meaning are unchanged, as Root requested.

These are presentation choices within the task; no accepted ADR is changed.
