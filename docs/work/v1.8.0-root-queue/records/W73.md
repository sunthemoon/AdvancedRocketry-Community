## Part 1: clearance

The chemical reactor (two null cells), centrifuge (one) and planetary beacon (32) reuse the arc
furnace's closed optional clearance matcher. Crystallizer and etcher have no null cells.
`runData` changed exactly these three generated pattern files. An independent JSON comparison
against `07c4b379` verified that removing only their 35 wrappers restores the original JSON.

`ClearancePatternDataTest` checks every affected null cell in all four rotations with untagged
air, tagged decoration, a non-air untagged block-entity observation, and an unloaded observation.
It derives the air flag from actual block states; the pure world-observation model does not carry
a BE class. Thus it tests the same matcher boundary as `ArcCuttingDataTest`, not a separately
installed third-party mod. Solid untagged machinery still mismatches and unloaded cells still wait.

`PackagedRecipeGraph` already handles optional cells from W55. Its existing exact C16c structural
prerequisite checks pass without changing the graph. The full unit suite exposed the centrifuge
OBJ fixture's old pattern hash. Only that hash was updated; the exact-hash assertion, geometry,
orientation, collision and rendering expectations are unchanged. The research/observatory fixture
was not changed.

## Part 2: reproduction and fixture lifetime

The existing `await` already retains a `GameTestTickPacer` across continuations. Adding another
pacer or extending the 80-tick readiness deadline would not address the uncovered lifetime gap:
the remote pad was loaded only by `getChunk`, whose UNKNOWN ticket expires after one tick, without
any fixture-owned retention during asynchronous entity loading. This was checked against the
local pinned Minecraft/Forge classes. A readiness predicate does not reload an unloaded chunk.

Three isolated baseline runs used committed source `a23e91e0` and eight CPU-busy threads in another
JVM. The first reproduced exactly `cancellationReleasesExactlyOneTransferClaim` failing with
"Pad fixture/flight did not become ready"; the other two passed. The third run's non-loading
observations showed the source ready while the pad's entity data was false at tick 0 and true at
tick 1. The failed run did not have that observer, so it does not identify its precise unload tick.

The fix retains at most the four chunks intersecting the five-by-five pad, using a unique station
UUID as the test ticket key. Radius 0 requests FULL only, not ENTITY_TICKING. Production transfer
ticking tickets and readiness checks remain responsible for flight. A terminal listener removes
the fixture tickets on success or failure; their 400-tick expiry also bounds their lifetime. All
existing timeouts, readiness predicates, cancellation assertions and pacing are unchanged.

The external diagnostic launcher registers the six original test methods with their original
batches, timeouts and assertions, using a byte-identical template under an isolated namespace.
It also runs one observation-only fixture-lifetime case. Its sources and logs are outside Git at
`D:/GitHub/ARCE-Task-Evidence/root-queue/W73/`. It is not part of the full-suite launch or the mod.
