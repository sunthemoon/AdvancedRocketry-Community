## Pre-implementation design

All four legacy renderers require `canRender()`: none is a single-block
always-visible model. The analyser is the modern `astrobody_data_processor`
3-by-2-by-2 classic multiblock; the observatory is a 5-by-5-by-5 classic
multiblock. Both reuse W233's canonical transient `formed` byte and fixed
render footprints. The planetary beacon has its own 3-by-5-by-3 multiblock
controller; the solar array has its own fixed 3-by-1-by-22 loaded-only layout.
Their existing block entities will expose only that same formed byte via
vanilla update tags/packets, publish only state transitions, and keep
projection decoding separate from server formation and persistent state.
No channel, variable payload, save schema, registry identity, matching,
collision, ownership or generation rule changes. Missing/null/noncanonical
flags clear the client presentation. Root must obtain a separate read-only
review before merging these projection changes.

Every OBJ names an MTL absent from the pinned upstream. NEW MTLs will bind
the three K3 textures and the already generated NEW planetary-beacon
controller front texture. Upstream RenderBeacon actually binds
`advancedRocketry:textures/models/beacon.png`, outside K3; it is not silently
imported or represented as history-cleared here. The beacon's existing NEW
controller texture is an explicit substitution, also its fallback. All
other models use their own NEW controller faces as fallbacks. Source OBJ/PNG
bytes remain unchanged; idle-only geometry changes are checked parser-input
adaptations. The observatory uses its closed idle shell, and the beacon's
spin groups are translated to their legacy idle socket. Animation is not
projected. Geometry and material/reference budgets are checked on full
sources before any idle adaptation. Provenance remains PENDING_HUMAN_REVIEW.

The importer requires every material texture inside its plan. The existing
NEW front PNG is therefore byte-copied to `textures/models/beacon_new.png`
in the authoring commit, then imported under that unique location, without
overwriting the generated original. Its fallback still references the
original generated front texture. This adds no new pixels or upstream asset.

New GameTests use disposable fixtures in isolated distant
regions, outside vanilla's template forced-chunk offsets -1 through +3,
with cleanup on every terminal outcome. They create no connected players.
Research and solar tests are synchronous; beacon tests use one callback
registered at setup and a mutable break/reform stage, respecting the shared
validation budget without nesting vanilla schedule registrations.

the existing x mirror; the observatory keeps a centered closed shell.
Scale remains one. The solar OBJ is only the front controller/plug row;
it does not fabricate any optional collector panels. The observatory's
source base extends 0.005001 below its pattern, so only its render box gains
that exact lower allowance. Matching and collision do not grow. Light
samples are +1Y for analyser/array, +4Y for observatory and +5Y for beacon,
outside occupied or optional pattern cells. The first real fixture run
