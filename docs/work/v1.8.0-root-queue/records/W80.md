## Choices made where the TASK left room

- **Scope.** The command covers both holds. It refuses governed (schema 3) records, so it adds no input or
  acknowledgement order to W11b2's flights.
- **Storage.** The rejoin table lives in the transfer journal root, because the checked writer has one
  fixed file. This bumps the root schema to 4. The note recommends implementing it after the W11b2 merge.
- **Retirement.** A rejoin entry retires only after an observed player save. The command also requires a
  Level save before it removes the record. That narrows R-032's unobservable entity-write window but does
  not close it, and the note says so.

## Known risks

- **Unobservable entity write (R-032).** A crash after the record's removal can still leave an orphaned
  rocket entity if vanilla's entity write did not land.
- **Stale seats.** A seat can survive if a crash lands before the entity's next save and the player is
  placed and saved before that rocket loads again.
- **Downgrade.** A root-4 journal holds every transfer on an older jar.

All three are written into the proposed R-035 text for Root.

### Choices where Root's decisions left room

Each choice is the more conservative reasonable one, and Root may change it when it checks the note.

- **Admission classification (N2).** Root allowed either refusing or leaving out a player seated elsewhere. The note
  refuses the command when that player is also still seated in L, because one player in two seats is a repair case,
  and leaves the player out of placement (NOT_REQUIRED) when they are no longer in L.
- **NOT_REQUIRED.** A third placement value keeps the existing entry structure and its four-per-player bound, instead
  of adding a second list to the batch. The note stores no manifest digest, because no stage compares one after S1.
- **B0.** B0 must finish within 200 ticks. A failure drops the admission rather than retrying, because nothing
  durable exists yet and the operator can simply rerun the command.
- **B1 tickets.** B1 uses its own ticket type with the flight ticket's 400-tick expiry, at most three tickets per
  batch and six in total, matching the scheduler's two batches per tick.
- **Deletion.** The generation that makes an entry's second state final also deletes the entry and, when it is the
  last one, the batch. This needs no separate cleanup generation.
- **Readback ceilings (N5).** The note sets 64 MiB on disk, 512 MiB inflated, depth 512 and 10 seconds. Depth 512 is
  the limit at which vanilla's own `CompoundTag$1.load` refuses a file; the byte ceilings are judgement values far
  above common player files.
- **Readback thread (N5, N10).** Decision 5 requires the scan to run off the server thread, so the note takes the
  review's NIO option for Windows sharing, not the server-thread option. A Windows test that holds a scan open across
  two saves must pass, or the rejoin leaf is blocked.
- **Exact position (N10).** The note compares exactly and re-pins at logout, because `PlayerList.remove` fires the
  logout event before it saves. It does not use a tolerance.
- **Status (N13).** The guard records the player's effects when it starts and removes only harmful types that were
  not in that record. Harmful effects the player had when they logged off are left as saved.
- **Function level 2 (N7).** This case needs a dedicated server, because GameTest compiles functions at level 4, so
  the note plans it as one native start.
- **Length (N12).** The TASK asks to keep the note's structure, so Appendix A stays in the note rather than moving to
  this record. A stage table and lists replace the slash lists, and the new rules make the note about 740 lines, up
  from about 400.
