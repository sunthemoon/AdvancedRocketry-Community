### Measurements and oracle

Record request result and synchronous duration, source flight/fuel and ARMED/journal
absence before F1, selected Level/origin/region/columns, warm-up start/deadline/state,
first READY tick, fresh request/BOUND, phase transitions, F2 handover and F8 release.
Record each owned ticket by type, key, level and column, plus all loaded/ticketed columns
and entity-ready columns at transitions and their measured-window unions. Ticket absence
is an independent assertion; loaded chunks may remain after release.

Tick timing uses the native `MinecraftServer.tickTimes` core plus the Forge END interval,
as established by W200, so early START callbacks are included. Keep all ticks, non-idle
ticks (requests, live warm-ups or flights), and callback/checkpoint-bearing ticks as
separate cohorts. Never dilute active work with setup or idle ticks. Record the exact
callback/checkpoint observation boundary, async IO events separately, request-to-READY
ticks and wall time, request-to-F2/F8, phase latency, RSS, GC and process IO counters.
Percentiles use nearest rank. Compare mean/P95/P99/max to 25/50/100/500 ms and RSS to
5.5 GiB, without calling this Windows short-run workload the Debian reference node or
four-hour soak. Readiness timeout, cold generation failure and unfinished phases remain
failures/unmeasured results; 600-tick warm-up and 400-tick flight ticket lifetimes do not
change. A production/persistence cause is reproduced and reported to Root, not fixed here.
