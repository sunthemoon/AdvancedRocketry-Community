## Scope and fixture design

The write scope is new W63 release-test fixture classes under `rocket/command`,
`scripts/run_v180_resource_restarts.py`, its Python tests, and this record.
External execution evidence belongs to `D:/GitHub/ARCE-Task-Evidence/root-queue/W63/`.
Production recovery, admission, persistence schemas, data generation, central
status files, ADRs and the ledger are not changed. No push, merge or delegation
is performed.

The fixture uses the installed server lifecycle, native entity/player/journal
storage, and separate dedicated-server JVMs. Only the initial session constructs
the transfer checkpoint; later sessions inspect and operate on loaded state.
The MONO checkpoint is a landed COMMITTED arrival with 2,000 mB remaining. The
PREPARED checkpoint has 2,000 mB hydrogen and 1,000 mB oxygen, with one or two
offline recorded passengers. Hand operations use production container exchange;
the loader uses its production inventory and server tick. Journal acknowledgments
come from the normal asynchronous writer, never a GameTest acknowledgment seam.
Embedded-channel players provide native login/save handling, not real-client V2
evidence. The two-passenger variant uses distinct nonoverlapping JVM sessions.

Hooks require both the existing release-test property and a W63 stage property,
an empty dedicated server, and the runner's disposable world-name prefix. They
are lifecycle-cleared and time-bounded. Evidence records the committed source,
packaged JAR hash, command lines, full process logs, live assertions, saved NBT,
inventory and hashes. A production failure stops the matrix without changing
production behavior or relaxing assertions.

Execution is in progress. No Required Gate or version acceptance is claimed.
