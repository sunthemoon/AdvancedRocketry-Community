## Tests

**Unit.** `EscrowLedgerLookupTest` (5 tests) uses real admission delegates. It covers UNCLASSIFIED before the startup
classification, without reading the delegate; NO_FILE only for a NO_FILE delegate; NOT_LOADED for a NOT_LOADED or a
LOADED delegate; the record's invariant (only LOADED carries the ledger); and the test seam, which returns to NOT_LOADED
so that every consumer is UNAVAILABLE, refuses while the store holds work, and restores to NO_FILE or LOADED.

**GameTest.** Each batch changes the server-wide state, so it runs alone. The first test that finds the PROPULSION
delegate idle, the transfer journal empty and no assembly transaction installs the state. It waits up to 150 ticks and
then fails with the reason, so that no leftover record is fenced meanwhile. The batch's `@AfterBatch` restores the
ledger it found through `replaceLedgerForTests`. NOT_LOADED is vanilla's cached miss for the ledger, which a ledger
that did not load leaves, with the delegate back at NOT_LOADED. So the shared authority answers UNAVAILABLE, as in
production, and the status test checks that for every consumer. NO_FILE detaches any ledger. Each rocket and device is
ordinary, with no escrow history in RAM: the rocket whose history would live only in the unloaded ledger.

## Choices where the task left room

- **Before ServerStartingEvent the reads keep today's answers** (UNCLASSIFIED). Rocket joins while the spawn chunks load
  read `idle` and `logicalLocked`. Protective answers there would fence each legacy record with a WARN on every world,
  including every NO_FILE world, and hold its recovery for 1,200 ticks. Design note, section 3.
  **Correction (W328F, 2026-11-09):** the release manifest filter is an exception to "every action rechecks later"
  (review check 5). `RocketReleaseAccess.joined` updates the flight data at once when it removes passengers whose release
  the rejoin sidecar already records, and nothing rechecks that change. It moves no fuel or cargo and grants no transfer.
  See the design note's correction in section 3.
- **Off the server thread, or without the runtime, a missing root is NOT_LOADED** (fail closed), like
  `BayReceipts.blocksInsertion`. Every current caller runs on the server thread.
  **Correction (W328F, 2026-11-09):** the delivered lookup read vanilla storage before it checked the thread (review
  check 5). Since W328F item 3, off the server thread or without an Overworld it answers NOT_LOADED without touching
  storage, even when a root is loaded.
- **A LOADED delegate without a root in storage counts as NOT_LOADED.** Only a proven absence keeps the no-ledger answers.
- **The loader shows `ESCROW_PENDING`**, not `LEDGER_UNAVAILABLE`, whose text claims that no fuel moved.
- **The status command is changed too**, although it protects nothing, because `ledger=absent` would tell an operator
  that no ledger exists. `inspect` and the settlement commands already refuse; their "No escrow ledger" message is
  unchanged.
- **The test seam is a package-private delegate transition** (`Delegate.unloadForTests`), called only after
  `EscrowTestEndpoints.requireEnabled`. So the lookup has no test branch in production reads, and the GameTests use the
  real production state: the cached miss and a NOT_LOADED delegate.
- **No ADR or register edit.** The hold refuses work, not saves. The TASK assigns the register to Root; the proposed
  text is in the design note, section 5.

## Known risks

- **The hold is server-wide** (design note, section 4). While the ledger is NOT_LOADED, no rocket can launch, board or
  leave through the seat actions, take or lose fuel or cargo, be disassembled, retired, killed or teleported by command,
  or change its flight data. Legacy flights pause where they are. Every fuel loader and cargo device holding a root is
  locked. Players can still dismount with the vanilla control. This lasts until a restart that loads the ledger or
  proves it absent. After W328 it is reachable only when a status check or load fails after the pre-start check.
- **`updateFlightData` throws while frozen.** Every production caller I found checks `idle`, `resourceMutationAllowed`
  or the legacy flight rule first, and those refuse first under NOT_LOADED (design note, end of section 1). A caller
  that skips them would throw, as it already would for an armed flight. The full GameTest run found none, but it
  exercises NOT_LOADED only in the new batch.
- **Relaunch first use was not remeasured.** The new lookup classes are listed as existing dependencies, not preloaded.
  They are small (a record and a four-constant enum) and are normally loaded earlier by rocket joins and boarding.
