## Completed scope and design

Commit `51332841945703b26550de305c11b87dcba03206` adds a fixture-owned
`GameTestTickPacer` to `BayDeploymentHoldGameTests.Restart` and
`BayDeploymentGameTests.Checkpoint`, pacing every non-closed tick in `finally`,
as `BayHeldProofGameTests` already does. These are the only Java files changed;
this record is the only documentation change. No production code, assertion,
stage, timeout, wait bound, retirement constant, log expectation, checker, asset,
status file or ledger changed. No new ADR choice, upstream import or delegation
was needed. Nothing was pushed or merged.

`RocketOrdinaryRetirement` starts its 100-tick attempt deadline when entering
`PROVING`. Its per-tick `prove()` checks the deadline even with an outstanding
capture. `RocketRetirementWorld.capture()` uses `EscrowBarrier.beginOrdinary()`;
the barrier waits for the own-store future, batches a force within 20 ticks,
waits for `IOWorker.synchronize(true)`, then submits Anvil readback to its
single-threaded reader. The owner-thread callback and remaining census/final
checks must also finish within the original attempt. This is not merely a
deadline for scanning additional census slots: both reproduced returns had just
one slot. A deadline retry releases the
proofs/reservation and waits the unchanged 200 ticks.

The hold fixture keeps its 1,150/380 wait bounds and 1,200/400 timeouts. At
20 TPS those are nominally 57.5/19 seconds versus 60/20 seconds; the first pacer
call is free. The ordinary checkpoint keeps 560 waits and its 600-tick timeout.
No bound was enlarged. The paired stalled run completed well within them.
