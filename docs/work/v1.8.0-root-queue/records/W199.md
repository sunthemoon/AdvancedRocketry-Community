# W199: I6 preparation and proof-window cost

## Design note, before production edits (2026-10-29)

The baseline JFR run at `93cb0aff8` reproduces ten proof ticks over 500 ms.
The largest is tick 1264, 4,342.657 ms: 190 of its 191 server-thread execution
samples include `RocketTransferSavedData.validateInsert`, called by I6's
acknowledgement-triggered write-back. GC overlaps 438.230 ms; blocking is not
the dominant cost. This is repeated serialization/sizing of all journal
records, not vanilla generation or saving. The native-core timer includes
earlier Forge START callbacks, which explains why W197's named port costs
did not account for it. Cold preparation separately reaches 327.416 ms and
samples synchronous `loadOrigin`/chunk scheduling beneath `keepLoaded`.

The bounded remedy has two parts. Cold I6 preparation receives at most one
ticket step per server tick (at most 32 recorded columns, still 16 per end),
within the existing shared four-start allowance. Its port only places the
finite tickets and waits for the unchanged complete entity-ticking readiness
predicate; it does not synchronously get the old origin. Deferral consumes no
ticket opportunity. Other destination sites retain their existing behaviour.
The 64 pending limit, three opportunities, 200-tick retry/consent, 100-tick
proof deadline, storage/authority guards and 400-tick ticket expiry remain.

Insertion validation can establish journal fit compositionally: existing
immutable records have already passed the record-size bound at admission;
the candidate is encoded and checked once, and the actual empty root/outbox
framing plus `record count * MAX_TRANSFER_RECORD_NBT_BYTES` bounds the whole
encoding. Compound list entries omit their standalone type/name header, so
this is conservative. If that conservative bound ever fails, retain the old
full-encoding check rather than refuse a record that would fit. This changes
no saved format, writer, acknowledgement, capacity/identity check or refusal
policy, and adds no cache/lifecycle state. Tests will pin the candidate-only
fast path, compare framing with actual encodings, and retain the existing
write-back/stop/conflict tests. Root's separate persistence review is required.

The fresh flat world amplifies cold chunk activation: old origins were never
generated, unlike the origin of a real completed flight. It does not explain
the proof spikes, which serialize the deliberately maximum-sized snapshots.
Both costs remain measured findings, not exempted Gate results.
