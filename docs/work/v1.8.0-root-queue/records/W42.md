## Projection design

The server projects successful recipe progression to one transient boolean
`active` in the vanilla block-entity update tag. It sends a block update only on
a transition; completion, failed progression, invalidation and reload are silent.
The update tag contains no inventory, identity, job or persistence root. The byte
codec accepts only values 0 and 1; missing flags, wrong tag types and other byte
values decode as inactive. Disk schemas and custom network channels do not change.
Client code reads that projection through W16's existing loop manager, preserving
its discovery budgets, distance hysteresis, nearest-first selection, shared cap
and unload/reload cleanup.
