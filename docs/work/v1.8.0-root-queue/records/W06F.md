## Design choices and boundaries

The TASK's Root decisions govern these fixes. The AT uses the
[Forge-documented](https://docs.minecraftforge.net/en/1.20.x/advanced/accesstransformers/) SRG field
directive (`f_9737_`) and changes only visibility; its resource was verified inside the JAR.
Vehicle counters do not apply because every passenger is refused before payment.
With `allow-flight=true`, vanilla trusts client flight regardless of this mod's paid-counter resets.
With flight disabled, unpaid floating still uses vanilla's existing conditions and 80-tick
tolerance; this is not a general movement anti-cheat or immediate displacement enforcement.

Worn identities are opaque objects in the pure Java session, rather than persisted IDs or
NBT hashes. Replacement preserves the selected mode and enabled toggle but ends the previous
intent/reference. A fresh heartbeat can begin a new session reference. The one-correction-per-tick
claim is not reset by replacement. An ordinary debit modifies the same worn stack.

The added S2C message is index 2 on the existing required channel, with exact protocol-2
admission; protocol-1 peers are incompatible. Authorization is connection-scoped and false
until received. Reload/Level changes clear effects but retain that connection's authorization;
join/logout clear authorization too. The independent CLIENT `atmosphericNausea` opt-out is
unchanged. Switch synchronization occurs at the next server START tick, without per-player caches.
