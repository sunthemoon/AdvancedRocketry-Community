## Cause, client information and decision

[W490](W490.md), E04 step 10, reports Venus showing `ATM // VACUUM` alongside
high-pressure exposure. `LifeSupportHud` is the only HUD/screen consumer of
`LifeSupportClientCache` and the `life_support.state.*` protection labels. It
appended the server status's diagnostic key, so every `EXPOSED` case selected
the historical English `VACUUM` or Chinese `真空暴露`. There is no second screen
consumer to change.

The life-support snapshot contains protection, breathability, suit-piece count
and oxygen, but no pressure. The already synchronized `CelestialSnapshot.Entry`
does contain ambient pressure and the mapped Level ID. No payload addition is
necessary. Following [ADR-066 section 3.1](../../../decisions/ADR-066-CLASSIC-LIFE-SUPPORT-EQUIPMENT-RESEARCH-AND-PRESENTATION.md)
and the distinction already used by [W294](W294.md), the display now selects:

| Exposed player's actual Level profile | English | Chinese |
|---|---|---|
| Pressure equals zero | `VACUUM` | `真空` |
| Pressure is positive | `NON-BREATHABLE ATMOSPHERE` | `不可呼吸大气` |
| Catalog absent or Level unmapped | `NO AIR` | `无可呼吸空气` |

Selection uses the actual Level mapping, not the logical body ID or the body a
station orbits. Space therefore uses Space's pressure. The neutral fallback
asserts only the server-known lack of breathable air; it does not invent a
pressure measurement. All other protection labels and the server's decisions
remain unchanged.

The active v1.8 language provider publishes three new keys. The old v0.4
`AtmosphereLanguageProvider` and its generated output remain byte-identical;
the HUD no longer selects their ambiguous `exposed` key. This follows the
historical-output rule without duplicate definitions or a build-script change.
No network payload, save schema, service rule or persistent identity changed.
