## Verdict

**Merge after one named fix (F1).** The decision function is correct, fails closed on every input it is given, and
changes no earlier answer. The gap is in the adapter: it trusts the cursor visibility whenever the game window is the
foreground window, but Windows reports the visibility of the window under the pointer, which can be a different
window. F2 to F5 are low or informational and do not block the merge.

## Findings

### F1 (medium, fix before merge): the visibility belongs to the window under the pointer, not the foreground window

- **Where:** `scripts/campaign_client/windows.py` lines 141 to 153 at `77dbcf42b`. The fallback checks
  `GetForegroundWindow` before and after `GetCursorInfo` and nothing else about who owns the cursor.
- **Evidence:** the probe below showed a 24 x 24 topmost, non-activating window of another process under the pointer.
  `GetCursorInfo` flags went from 1 to 0 and back while the foreground window never changed.
- **Input that goes wrong, unsafe direction:**
  - The game is fullscreen on a single monitor and holds the pointer, so the pointer sits at the client centre.
  - A topmost window that does not take the foreground (an overlay, a tooltip, an input-method or notification
    window) lies under that point and shows its own cursor.
  - The clip equals the desktop and the client, the foreground is the game, and the flags are 1.
  - `cursor_captured` returns `False`, so `close_screen` (`session.py` line 272) posts ESC with no screen open and
    the Game Menu opens. `require_screen` with `open: true` passes, and the request's clicks go to the world.
- **Input that goes wrong, other direction:** a screen is open, the pointer rests on such a window, and that window
  hides its cursor. The flags are 0, the gate reads "captured", `require_screen` with `open: false` passes, and the
  request's keys go into the open screen.
- **Named fix:** in the fallback, also read `WindowFromPoint(info.ptScreenPos)` and refuse unless it is the game
  window's handle. This is read-only, uses the position that the same `GetCursorInfo` call returned, and needs one
  binding, one comparison and tests for "other window under the pointer" in both flag states. GLFW creates no child
  windows, so the handle comparison is exact.

### F2 (low, optional): flags 0 has no corroboration in the fullscreen case

- **Where:** `scripts/campaign_client/gates.py` lines 50 to 52. The check "a hidden cursor needs clip equal to client"
  is always true for a window that exactly covers the desktop, so "hidden" alone decides "captured".
- **Input that goes wrong:** a machine with no pointing device (`GetSystemMetrics(SM_MOUSEPRESENT)` is 0), or a tool
  that hides the system cursor globally. The flags are then 0 while a screen is open, and the gate reads "captured".
- **Note:** `hCursor` cannot corroborate it. The probe showed `hCursor` null both for `SetCursor(NULL)` and for
  `ShowCursor(FALSE)`.
- **Suggested fix:** refuse the fallback when `SM_MOUSEPRESENT` is 0. The campaign machine reports 1.

### F3 (low, optional): remote sessions are not covered by the cited GLFW behaviour

- **Where:** the fallback in `windows.py` and the README paragraph.
- **Input that goes wrong:** the client runs in a Remote Desktop session. Later GLFW versions set a transparent
  cursor instead of a null one there (my recollection of GLFW's 3.3.9 and 3.4 change notes, not re-read today), and a
  transparent cursor reads as flags 1 while the game holds the pointer. That is the unsafe direction of F1.
- **Suggested fix:** refuse the fallback when `GetSystemMetrics(SM_REMOTESESSION)` is non-zero. The campaign machine
  reports 0.

### F4 (low, pre-existing class): `close_screen` decides on one sample

- **Where:** `session.py` line 272, unchanged by this commit.
- **Input:** a request begins just as the window regains the foreground. GLFW re-applies the null cursor when it
  handles the focus message, so one sample taken before that reads "screen open" and ESC is sent. The clip reading
  has the same window in windowed mode, so this is not new, but the fallback now shares it.
- **Suggested handling:** no change in this commit. The first fullscreen cell should begin each request with
  `require_screen`, which polls, before any `close_screen`.

### F5 (informational): the cited GLFW tag is not the running binary, and no live client has confirmed the reading

- **Where:** `scripts/campaign_client/README.md` line 172 cites tag `3.3.8`. Minecraft 1.20.1 ships LWJGL 3.3.1,
  whose GLFW build is a different snapshot. W494's record says so and makes no claim about the running binary.
- **Reviewer's check:** the probe confirmed on this machine (Windows 11 build 26200) that a null cursor set by the
  window under the pointer reads as flags 0 and the arrow as flags 1. That supports the signal, but it is not a
  Minecraft client.
- **Suggested handling:** before the first gated fullscreen input, Root reads `status` once in each state (in the
  world, and with a screen open) and checks `pointer_captured` is `true` and `false`.

## Task checks

### 1. Fail closed

| Case | Result at `77dbcf42b` | Assessment |
|---|---|---|
| Desktop of several monitors, window on one | The clip decides as before; visibility is not read. | Safe. |
| Window spanning the whole virtual desktop | Falls into the ambiguous case; flags decide. | Safe except F1. |
| Borderless window covering the single monitor | Flags 0 gives captured, flags 1 gives released. | Safe except F1 and F2. |
| Window larger than the desktop | Flags 0 is refused as contradicting the clip; flags 1 gives released. | Safe except F1. Captured can never be confirmed, which fails closed. |
| `CURSOR_SUPPRESSED` (2), 3 or any other value | Refused with `ValueError`. | Safe. |
| Flags of a non-integer type, including `True` and `False` | Refused. | Safe. |
| Cursor hidden by another program | Flags 0 is taken as captured. | **F1** (window under the pointer) and F2 (global). |
| Change between the reads | A changed clip or foreground is refused; a failed read raises `OSError`. | Safe. See the note below. |

Note on the re-read: in the case the fallback serves, the clip is the same whether the pointer is held or shown, so
the second `GetClipCursor` cannot detect a capture change. It detects only a change of window mode. This is not a
defect, because the decision then rests on one `GetCursorInfo` sample, which is a single consistent reading.

### 2. No other case changes

- `git diff --exit-code ada5c3367 77dbcf42b -- tests ':!tests/test_campaign_client_pointer.py'` exits 0: no existing
  test changed.
- A differential script loaded `gates.py` from both commits and compared `cursor_captured` over 242,064 combinations
  of clip, client and desktop, including malformed rectangles. Without flags, no return value or exception class
  differs. In the 34 ambiguous combinations the old code raised `ValueError` and the new code raises its subclass
  `CursorVisibilityRequired`, with a longer message that still contains "undecidable". Flags never change an answer
  outside the ambiguous case.
- In the adapter, the non-ambiguous path makes the same Win32 calls as before. `status` still reports null for an
  unreadable state, because `Session.pointer_captured` catches `OSError`, `ValueError` and `AttributeError`.
- The one intended change is that the adapter no longer always raises for a desktop-covering window.

### 3. Tests

- The suite passes on an export of `77dbcf42b`: 156 tests, of which 22 are new.
- Linux safety, by reading (this machine has no WSL, so there was no Linux run):
  - the new test file imports only `ctypes`, `unittest` and harness modules, as `tests/test_campaign_client_gates.py`
    already does for `scripts.campaign_client.windows`;
  - `Windows.__new__` avoids `WinDLL` in the adapter tests, and the binding test patches `WinDLL` and `WINFUNCTYPE`
    with `create=True`, the pattern `tests/test_campaign_client_session.py` already uses;
  - `adapter.require` is replaced, so `ctypes.WinError` is never called;
  - `ctypes.wintypes` imports on Linux, and the tests compare `cbSize` with `sizeof` of the same structure, so the
    different `DWORD` size there does not matter.
- Gap: no test covers a different window under the pointer, because the code does not read it (F1).

### 4. README

The paragraph matches the code: when the fallback runs, the two flag values, the refusal cases, the unchanged
one-monitor-of-several case and the `status` null. The cited GLFW tag is covered by F5.
