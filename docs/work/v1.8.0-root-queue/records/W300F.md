# W300F: stale-seat review fixes

## Scope and design

The base is `d21bc8f3c` on `codex/v1.8.0-w300f`. The write scope is
`RocketSeatInput`, its existing reconnect-query bridge through `RocketRuntime`,
`RocketManager`, `RocketTransferService` and `RocketTransferRecoveryService`,
the operator-command success text, the new `RocketSeatReviewGameTests`, and
this record. The accepted W300 design
and R348 remain the authority. No schema, saved ID, network, asset, configuration,
save-refusal mechanism, rider positioning, flight/transfer seat policy, grace
duration, ledger, status file or QUEUE changes are included.

A player riding any loaded copy with the same assembly transaction ID resets
logical absence. Only the actual physical vehicle consumes sneak input. Login
retry and logical transfer-fence checks apply only to absent riders, preserving
W287 ground-sneak behavior when the transfer journal is unavailable. The fence
lookup uses the journal's existing bounded logical-record query and the owning
recovery service's fence table, without world scans or chunk loading. The
existing bridge is extended, not supplemented: `RocketTransferService` stays
at 798 lines. Absence observations weakly reference the player session, retaining
identity-based grace resets without keeping a logged-out player alive.

## Accepted limits and review notes

- F2: a stationary rocket without a transfer journal record reseats nobody at
  login. This includes assembled or fueled rockets that never launched and
  landed rockets whose record was retired. Offline membership is kept; after
  login, an online player who remains unmounted loses the seat after the
  unchanged 40-tick grace and can use BOARD again. A reconnect that expires
  after `MAX_WAIT_TICKS` (200 ticks) is followed by the same absence release.
- F4: the operator command intentionally dismounts an online target riding the
  selected stationary rocket; it does not detach a target from another vehicle.
  The success reply now explains that physical dismount, covered by a regression.
  No new command mode is added.
- F5: a freeze wholly within the first 39 absent ticks can count toward grace.
  Fresh grace after thaw applies when the freeze was observed at a release
  attempt. The release itself still cannot mutate a frozen rocket. No change
  to freeze sampling or grace duration is made.
- F6: weak references preserve same-session comparisons and remove strong
  retention. A regression checks both the reference type and fresh grace after
  replacing the online player instance.
- F7: the new tests cover a non-operational journal and recordless login. The
  existing IN_FLIGHT test's entity-replacement limitation, fixture-driven login
  ordering, fake-player exclusion, absence-path refusal backoff and
  cross-dimension absence are not expanded here: those are additional test
  scenarios, not one-line production fixes. Existing assertions and budgets
  remain unchanged. Targeted verification includes the actual
  `rocket_seat_roster_refusal` and `rocket_stale_frozen` batches.
- F8: no service split is needed for this change because the bridge replacement
  does not increase the transfer service's line count. Future additions still
  need a responsibility split before reaching the architecture limit.
