## Runner defect and design decisions

The registry's injected rename exception occurs inside the committer, before
`SatelliteRegistryWriterCuts` reaches R3's `MOVED` pause. Readback resolves the
registration COMMITTED, so no retry reaches the pause. The original attempt
injected correctly but timed out waiting for that marker and never restarted.
This was a runner/cut mismatch, not evidence of lost production data.

The correction selects existing R4 only for registry `MOVE_AFTER`. R4 holds the
terminal effect after publication, requires the same one-satellite durable file,
and retains both existing restart checks for the package and idempotent replay.
The new test fails against the old runner and pins every other registry fault's
unchanged selection. No existing runner, oracle, assertion, timeout, budget or
production file changed. No ADR decision changed.

The `ZERO_LENGTH` result retains W379G's deliberately conservative declaration:
only typed `ARCE-BETA-2000` counts. Both starts actually refused the zero-byte
registry with `ARCE-BETA-2002`, before readiness, and left its bytes unchanged.
This is not evidence that production accepted that file. Widening the declared
marker list is not part of this correction; Root should explicitly disposition
this limit before interpreting S5's residual totals.
