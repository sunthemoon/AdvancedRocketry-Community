# W46: elevator capsule and departure update-tag carrier

## Pre-implementation design

The vanilla departure block-entity update tag keeps `tether` unchanged and adds
`capsule_rides`, a list of compounds with exactly two integer fields:
`entity_id` and `remaining_ticks`. The list limit is
`min(8, ElevatorRules.PENDING_RIDES_PER_ENDPOINT)`, currently four, matching the
actual server admission limit rather than inventing eight ride slots. Countdown
values are 0 through `ElevatorRules.RIDE_COUNTDOWN_TICKS` (100). Missing, wrong-type,
oversized, duplicate, out-of-range or unknown-field projections decode as empty.
There is no saved schema change, UUID, name, pair, arrival, inventory or energy
in this transient carrier. Projection truncation never changes server rides.

`ElevatorRides` notifies the already-loaded, identity-matching departure after
insertion or removal. Removal covers cancellation, unbinding, commit, arrival
wait expiry and server stop. The notification uses `sendBlockUpdated(..., 3)`,
like W42, without dirtying persistence. Ordinary countdown/wait ticks never
notify. Serialization derives the remaining time from the authoritative pending
ride at send time; it does not cache or decrement server ride state. Existing
tether transitions and initial chunk synchronization remain unchanged.

Each client endpoint owns a bounded transient countdown, advanced by its client
block-entity ticker. A newer snapshot replaces membership immediately. An entry
ends at local countdown zero or a 300-tick lease from its first uninterrupted
observation; repeated snapshots cannot renew that lease. Removal and chunk unload
clear the endpoint state. No client class is referenced from common/server code.

The physical-client renderer resolves a network entity ID only through its own
current Level. An absent entity, a non-player, a dead player or a player no longer
on that endpoint's platform is discarded, without loading or retaining an entity.
A later server transition can provide a fresh observation. The code-drawn capsule
is stationary around the rider's interpolated position; its colour can brighten
with countdown progress, but it has no collision, passenger, movement, teleport,
reward or server callback. No texture or legacy asset is imported.

Existing endpoint render callbacks offer candidates for the frame. A bounded
nearest-first selector keeps at most 64 endpoints by camera distance, with packed
position as a deterministic tie breaker, and emits at most one effect per entity
ID. Only loaded, in-range, frustum-visible endpoints with live countdowns qualify.
Candidates are cleared after rendering, on disconnect, client clone/Level change,
and Level unload. The render pass rechecks the loaded endpoint and player so a
cancel, commit or unload between collection and drawing cannot leave a stale
effect. There is no unbounded discovery scan or world-object cache.
