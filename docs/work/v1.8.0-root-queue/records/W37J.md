# W37J: logout save reconciliation and original-player supersession

## Implementation design after Amendment 2 (2026-10-14, before production code)

Root's Amendment 2 (`fa5e0e21`) replaces the shutdown stop condition. F1 will use the existing
logout listener at LOWEST for both ordinary disconnect and shutdown. A small service-owned helper
will copy only into the exact cleared old tuple with a readable backup, or into its own previous
copy on that exact old/replacement/connection identity pair. It will follow later changes on END
and logout, and discard its transient record on adoption, identity/tuple mismatch, logout and stop.
Losing this record on a crash does not promise durability of unsaved changes. Periodic `saveAll`
already saves the listed replacement; the shutdown seam will save that replacement first, then
invoke its shared listener's disconnect callback to save the old player without an intervening END.

F2 will inspect the original at Clone and retain the original identity through the respawn event
only when the backup remains pending. A non-cleared original releases the old envelope before
replacement restoration. The record expires at respawn, logout, the next END or server stop, so
normal tick restores cannot accidentally reuse a stale original. A fresh replacement's default
tuple is never used to decide whether a pre-read original superseded the envelope. No Mixin,
capability save side effect, post-save overwrite or save refusal is added.

New native tests cover the four specified logout/shutdown cases with direct file assertions before
reconnect and native readback, plus two original-player supersession cases. Additional tests will
check END follow-up copies and refusal to overwrite a foreign old tuple. Existing tests and their
budgets remain intact. F1 and F2 will have separate commits, then the whole unit suite and locked
native regression will run. F3's corrections remain; the earlier blockers below are historical.

This design was committed in `60ac16bc` before production edits. The final tested source is
`c32bc96be77e909a7fcf0e9212b633b213794ff2`. F1, F2 and F3 are implemented/documented, with the

### F1: reconcile the player that native logout actually saves

`SleepRespawnService.onLogout` runs at LOWEST, before native serialization. It reconciles only when
the departing object is the shared listener's old player and the PlayerList contains a different,
same-UUID replacement on that exact connection. A first copy requires a readable pending backup
and the exact cleared old tuple. Later copies require the old tuple to equal this service's last
copy for the same old/replacement/connection identity. The latest non-cleared replacement tuple is
copied verbatim, including raw angle bits and forced status. Completion removes the active envelope
or returns its opaque retained root. A foreign old tuple is never overwritten.

`RespawnSaveReconciler` owns the identity-based transient copy records. END follows later changes
even after the backup was completed; pruning rejects adoption, identity/connection changes and
foreign changes to the old tuple. Logout forgets the record, and server stop clears the helper.
The logout identity regression posts a same-UUID event for an unrelated object sharing the envelope
and verifies that it cannot authorize copying into the connection's old player or completing that
envelope. No new durable state, schema, save rejection or Mixin is introduced.

The shutdown GameTest uses the explicitly permitted seam: `PlayerList.saveAll()` saves the listed
replacement, then the shared listener's native `onDisconnect` removes and saves the old object,
without an intervening END. Both file reads contain the same latest complete tuple; the later file
has completed the active envelope. This is not an actual host-server stop or an S2/V2 claim.

### F2: decide from the original, not the replacement's defaults

The LOWEST Clone listener reads `event.getOriginal()` after native `restoreFrom` shares
`PlayerPersisted`. A non-cleared original releases the readable pending envelope before it can be
restored into the fresh replacement. The original identity is also available for rechecking at the
respawn event, then removed. Logout, the next END and server stop expire any unfinished dispatch
record. These records do not govern normal later tick restoration.

The corpse-removal tests use a real END decision, native KILLED removal, `/spawnpoint` on the
original, and the native respawn packet. One cancels the replacement's native setter, and one
prevents an arrival at the newer point. Both prove that the old Moon backup is absent immediately
and after the following END. The veto case also verifies arrival at the newer point.

## F3: corrected risk and recovery text for Root

Root still owns publication in ADR-066 and the risk register. This text supersedes the inaccurate
qualifications in W37I's proposed text; it does not rewrite the historical W37I record.

The backup protects one player's respawn tuple, not a chunk or a Level. Its schema-1 core has eight
fields and is bounded to 1 KiB and nine NBT nodes. **That bound does not cover an optional opaque
`retained` root or the complete envelope.** Validation preserves the pre-existing opaque root
without traversing or truncating it; completion returns it to
`ForgeData.PlayerPersisted.arce_planet_respawn_backup`. The existing oversized-root fixture and
the new logout/file-readback case cover this distinction. No whole-envelope size bound is claimed.

An unreadable or future root **does not imply an empty native point**. It can coexist with a valid
native point, or be retained inside a readable envelope protecting a later point. That later point
can be restored and the opaque root returned unchanged. World-spawn/no backup-restoration-message
behaviour applies only when the native tuple is empty and no readable active backup is available,
assuming no other mod supplies a point. A WARN alone does not determine native arrival.

Losing W37H's removed foreign-setter flag cannot change the tuple-only supersession rule. This does
not promise durability of unsaved tuple changes or crash-atomic saving. The implemented last-copy
records are transient too; an abnormal stop loses them and any updates vanilla has not saved.
Saved readable backups remain available to the reader. No packaged restart/S2 evidence is supplied.

No save is refused or controlled by throwing an exception. Diagnostic frequency remains at most
one WARN per player, per case, per server session. A foreign exact null clear still leaves the
backup governing; restoration can undo another mod's explicit reset of an already-refused point,
as Root decided. The specified immediate-logout, later-copy and clone resurrection gaps are covered
by this implementation and passing native tests; arbitrary throwing-mod lifecycle repair is not.

Offline recovery, for a readable validated schema-1 envelope only:

1. Keep the player offline and stop server writes to their file. Back up
   `world/playerdata/<uuid>.dat` before editing.
2. Inspect `ForgeData.PlayerPersisted.arce_planet_respawn_backup`. Use a compatible reader for an
   unreadable/future root; do not assume schema-1 fields or discard it.
3. Copy the validated core's `dimension` into `SpawnDimension` and exact integer `x`, `y`, `z`
   into `SpawnX`, `SpawnY`, `SpawnZ`.
4. Convert `angle_bits` with Java `Float.intBitsToFloat`, store `SpawnAngle`, and copy the byte
   `forced` into `SpawnForced`, preserving the complete tuple.
5. Complete the repaired envelope: remove its key only if it has no `retained` child; otherwise
   put that same opaque child back under the key, unchanged.
6. A non-compound `PlayerPersisted` belongs to another mod. Coordinate repair with its owner;
   replacing it can lose unrelated data.
7. Save, reconnect and verify all four native tuple components and the next saved-file readback.
   Verify completion of the repaired active envelope. The key must be absent only if no opaque
   child was retained; otherwise verify that the retained root is present unchanged.

This recipe is a documentation correction, not an executed offline player-file repair.

  Independent persistence review is for Root to arrange before integration; none is claimed here.

  transient copy authority does not provide crash-atomic durability of unsaved changes.
- A later-registered LOWEST END or logout listener can still run after this service. Inter-tick
  tasks and the configuration watcher retain the existing freshness limits. A mod replacing native
  respawn/tick/credits handling can bypass these Forge boundaries.

  world reads remain bounded. Opaque retained roots are not newly bounded.

  and Level. This slice preserves the save tuple; it does not repair connection adoption. Copies
  also change the old object observed by mods retaining it after respawn.

  dedicated-server restart or V1/V2 verification. No manual client/GPU acceptance was performed.
