## Implementation design (before code)

The preferred power strategy is used: both controllers extend the existing
`ClassicControllerBlockEntity`. Research profiles have no recipe process or
inventory banks. The existing power plug remains the physical FE owner, with
unchanged claims, exclusivity, generations, stale-claim retirement and Forge
extraction refusal. A package-private kernel transaction checks every live
binding and aggregate FE before a checked registry advance, then debits plugs
on the same server thread. This does not make FE crash-atomic.

Registry jobs are the only progress/claim/credit authority. START and CLAIM
use the existing save-epoch barrier and coalesced flush. A server-lifecycle
directory and fair scheduler live in an overworld capability, not static world
collections. Only block-entity tickers enqueue work; there are at most 32 paid
advances and 64 inspections per server tick across Levels.

Physical identities have a schema-1 root containing owner/device UUIDs, immutable
home Level/position and a sticky collision flag. The additional home fields are
needed to reject an idle copy even when the original is unloaded. Retained jobs
(including READY/PROCESSED and credited processor claims) validate the canonical
home; otherwise a loaded canonical home is authoritative. An off-home copy is
quarantined at the device-root scope only. It cannot start, claim, rebind or pay;
the original job, instance, progress and research balance are not rewritten.
Reload cannot clear the copied root's quarantine. Moving active work requires an
explicit owner-authorized registry rebind to a fresh, formed, idle identity.
Unsupported roots remain raw and inert; oversized retained roots reuse the
existing whole-chunk save guard. Recovery is backup plus offline repair.

Menus use exactly 16 short-safe slots: status; packed phase/analysis/owner;
progress low/high; duration low/high; aggregate FE low/high; required FE;
diagnostic x/y/z and role; selection index/count; machine kind. All wide halves
are masked, including signed wire halves. Buttons are existing container intents,
with loaded physical identity, player, Level, distance, permission, owner and
10-intents-per-second validation. No network channel is introduced.

The frozen patterns are reproduced by deterministic DataGen, with original
code-drawn art and English/Chinese text. Proposed controller recipes use steel
plates, machine casing, motor, glass/lens and the existing control board. No
upstream code or art is imported.

## Proposed Root-owned ADR/risk text

ADR-066 implementation note: The physical identity authority consists of the
schema-1 immutable home Level/position and owner/device UUID, corroborated by
every retained registry source/processor claim, including READY and PROCESSED.
The bounded server directory tracks at most 16,384 loaded devices independently
of live-work indexes. A conflicting/off-home copy receives a persistent device
root collision flag. Isolation affects that copied BlockEntity only; the
canonical original and its valid jobs, instances, progress and credited account
remain unchanged. A retained authority disagreement refuses that device until
offline repair. No job is completed, transferred, deleted or credited by collision
detection. Normal movement of ACTIVE/RUNNING work is an owner-authorized rebind to
a fresh formed idle device. Collision flags are not cleared by unload/reload or
online release. Back up the world and repair the conflicting device root offline.
Collision detection emits no per-tick log; menus expose the refusal. Quarantined
ACTIVE job/PENDING instance pairs and duplicate RUNNING claims remain the existing
offline-repair-only registry cases, shown by inspect/release and menu text.

R-027 scope addition: Include `arce_observatory` and
`arce_astrobody_data_processor`, at 4,096 bytes/depth 8/64 nodes each. Unknown or
malformed bounded roots are retained unchanged and inert. An unsafe retained
root uses the existing sticky whole-chunk `GuardedChunkSaves` refusal. It retains
256 rejected chunk coordinates; a 257th distinct coordinate saturates that Level
and refuses all subsequent terrain writes. Existing retry ERROR pairs and stacks
have no total log limit; this slice adds no new save-guard logging guarantee. The
refusal lasts until backup/offline repair and restart; this root scope reuses the
existing exception-based save policy rather than introducing another mechanism.
The saved kernel checkpoint/resource roots remain under the existing classic
root guard. No new chunk/Level save-refusal policy or budget is introduced.

Proposed physical-collision risk entry: Device copies with duplicate identities
are isolated at the conflicting BlockEntity-root scope. The immutable home plus
retained registry authority prevents an unloaded idle copy, completed survey copy
or credited processor copy from starting new work or rewriting a source. Owner
work can be moved only by checked rebind to a new identity. The collision flag
survives save/restart; recovery is backup and offline device-root repair. There
is no per-tick log, no account/instance mutation and no global registry refusal
from a physical collision. The existing ACTIVE-pair/duplicate-claim recovery
limitations still apply independently.
