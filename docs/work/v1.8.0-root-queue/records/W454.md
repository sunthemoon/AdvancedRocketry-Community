## Not covered

- **J05, a 34-column census and 64 claims.** The gated fixture rocket is three blocks wide and has one owner. A
  wider census needs a real rocket with packaged bays, and the packages need a player (R638).
- **J05 waits 1 to 9, 13 to 16 and 18 to 22.** They are C6's ten timing profiles and forced-stop families. They
  run on REF through `scripts/run_v180_w336_timing.py`; K12 adds no fixture for them. That runner is the Windows
  wrapper (it starts `win_args.txt`), so REF needs its Debian start line; K12's procedure names `unix_args.txt`
  for K12's own fixtures only.
- **J08 steps 1 to 4** (largest admitted, oversize, 64 synthetic records, capture and hash costs). They are built
  by `CargoNativeFixtures`, a test-only class absent from C6's release JAR, as W434 found.
- **J09 step 4.** No packaged command starts an F1, W98 or sealed-disassembly capture against the shared quota.
- **J10 steps 2 to 10.** The four checked-margin rockets in two terrain cohorts were not built, and the capacity
  cases need connected players.
- **J11's flush interval.** K15's raw sample is vanilla's tick time plus the satellite runtime's post-tick time.
  The receipt barrier runs in another END-tick handler and I could not show that the sample includes it: the
  largest candidate tick was about 4 ms, against the 139.804 ms development sample. REF needs K15's JFR file
  events or a wall-clock bracket for the flush. This entry was added to the driver after the seals, so the
  sealed manifests lack it; `DELIVERY-AUDIT.json` says so.
- **J11's participant.** The qualification used the gated launch hook with nobody aboard. An eligible player's
  product-route launch belongs to the REF sitting.
- **J17 execution.** No debugger, client or stop was run. The W-thread stop names the writer thread and the
  move, not a line number.

## Choices, risks and open points

- **Fixture commands.** The bay fixtures and the cells are made by C6's gated `arce bay release-test` commands,
  which load fixture roots inside the product. That is how C6's campaign families make them. No `data merge`, no
  offline edit and no other NBT-writing console command was used. If Root reads R638 as excluding these gated
  commands too, the four built worlds are void and only `first-event/` and the recipes stand.
- **Wait-23 isolation** is by construction: one claim, no player, no forced chunk (checked in every dimension's
  `chunks.dat`), a census far from spawn. The console cannot list ticket owners, so this is not an observed
  absence of other tickets.
- **Journal hold.** C6 bounds the startup hold at 60 seconds (`bound_ms=60000`); a REF driver must arm and
  release inside it. The readback read every status inside the hold.
- **Driver size.** `k12_queues.py` is about 1,050 lines in one module, because the TASK named one tracked
  script. It mixes the planner, the readers, the recipes and the native runner; a split is a follow-up for Root.
- **Storage.** The K12 folder is about 105 MB, of which the five source worlds are 83 MB. It is external and
  must not be committed. The superseded `wait23` world (14 MB) can be deleted if Root does not want it.
- **Windows only.** Nothing here ran on Debian. The readers are pure Python and tested on this PC only;
  governance runs the tests on Linux after Root pushes.
