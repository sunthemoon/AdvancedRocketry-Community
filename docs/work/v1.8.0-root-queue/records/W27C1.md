**The managed type.** `ManagedSavedDataType.BAY_RECEIPTS`, file `data/advancedrocketrycommunity_bay_receipts.dat`,
schema 1, epoch `v1.8.0-bay-receipts`, no legacy schema, a 4,195,328-byte bound. `BayReceiptSavedData` is the
Overworld root; it holds no static state, its `save(File)` never writes, and it is never marked dirty, so autosave
publishes nothing and therefore never a queued intent. The pre-start check (`ManagedSavedDataPayloadValidator`) decodes
the root and reads the file back twice as the baseline, as RESOURCE_ESCROW does; a future or invalid root refuses
whole-world startup and the file is never staged or rewritten. `BetaWorldMigrationEvents.recoveryHint` now also gives
the whole-world hint when a receipt file exists.

**The codec.** `BayReceipt` (the 24 fields), `BayReceiptRoot` and `BayReceiptCodec`. UUIDs are int[4], hashes and
`package_sig` byte[32], `bay` int[3], `kind` the exact `SatelliteKind.id()`, `definition` and `orbit` canonical IDs of
at most 128 characters, `reason` an upper-case name of at most 40 characters, flags 0 or 1, `attempts` 0 to 1,000.
Every envelope is checked before any copy or decode: a receipt at most 1,024 bytes, depth 3 and 40 nodes; the
receipts list at most 4,194,304 bytes; the root at most 4,195,328 bytes, depth 4 and 131,072 nodes; at most 4,096
receipts. The invariants refuse: unique `op`, unique key, one receipt per satellite, every sequence issued, REGISTERED
needs all four hashes, unknown fields and wrong types. The generation digest is `CanonicalNbtDigest` at depth 4.

**The writer.** `BayReceiptWriter` is `EscrowLedgerWriter`'s state machine with a typed candidate, as a new class; the
escrow writer is unchanged. The server thread captures an immutable root (at most 4,096 references, no NBT). The IO
thread encodes, checks the round trip through the decoder, digests, stages, forces, reads back and replaces under
`CheckedSavedDataPolicy(BAY_RECEIPTS, committer)`, then calls `forceDirectory`. The first attempt fixes the bytes and
digest; a retry moves exactly those bytes, and the owner thread refuses a completion with another digest. One captured
generation and one successor; an unknown outcome is resolved by bounded readback or retried every 200 ticks; three
unresolved failures make the store unavailable (BAY_RECEIPTS_UNAVAILABLE) until an exact commit; writes start at most
once per 10 ticks; the stop drain uses W104's elapsed-time clock and gives up after three unknown outcomes; the crash
path joins the IO thread and publishes nothing.

**The store and its index.** `BayReceiptStore` keeps the durable root, the writer's captured generation (active or an
exact unknown candidate) and the RAM root (queued mutations and a successor's contents). Its cached index answers from
all three, so it answers while the writer is unavailable:
- pending: an op whose receipt is INTENT, REGISTERED, REPAIR or released in any state, with the newest such identity;
- retained: every op in any state, REJECTED included;
- blocking: a satellite whose receipt is INTENT, REGISTERED or REPAIR in any state.

A put checks the retained and pending results without charging (`checkRetain`, `checkReserve`) and charges both only
when both pass, so a refusal changes nothing. A definite failure before replacement cancels the generation's mutations
that nothing later superseded, before the successor captures, which releases a never-applied admission; an unknown
outcome keeps everything. A released receipt keeps its flag, never re-arms and cannot be removed online.

**The authority.** `EscrowAdmissionAuthority.Index` gains `retained` (only the BAY index may carry it), and
`tryRetain(op, owner)` returns RESERVED, ALREADY_HELD, IDENTITY_CONFLICT, SERVER_FULL, OWNER_FULL or UNAVAILABLE
against 4,096 per server, 128 per owner and the byte reservation, which charges every retained op at its 1,024-byte
ceiling against the 4,194,304-byte section. There is no release call: a queued retention, like a queued reservation,
moves into the BAY index's ownership at the next refresh and ends only when the op leaves every state. `tryReserve` keeps
its results and order.

**The runtime.** `EscrowRuntime` creates the authority once with both delegates, PROPULSION and BAY, NOT_LOADED. At
`ServerStartingEvent` it keeps the PROPULSION lookup, then `BayReceipts.start` runs the load-only lookup: an existing
root binds (writer at the root's generation, baseline readback) and attaches (LOADED); a proven-absent file gives
NO_FILE; a file that exists but did not load stays NOT_LOADED with one WARN. The runtime ticks the store, drains it at
`ServerStoppingEvent` and aborts it on the crash path. The first admission from NO_FILE creates the root; its first
generation creates the file.

**The insertion refusal.** `SatelliteBayBlockEntity.admissible`, the one check behind the menu slot, hoppers, droppers
and the item capability (simulated and actual), now also refuses while `BayReceipts.blocksInsertion` is true: an
INTENT, REGISTERED or REPAIR receipt for the package's satellite, or an index that is not loaded or a missing runtime
(fail closed). A REJECTED receipt never blocks.

**The N5 command.** `/arce bay receipt retire-rejected <satellite>`, permission 2 like `/arce rocket recover`.
`BayReceiptRetirement` refuses unless the receipt is REJECTED, not released, exactly acknowledged (identical in every
state with no pending mutation), no INTENT, REGISTERED, REPAIR or released receipt names its rocket, and both journals
are readable and hold no record for that rocket. It writes the removal through the receipt writer; the retained slot
ends at the exact removal acknowledgement; one INFO audit line `ARCE_BAY_RECEIPT_RETIREMENT` names the operator, the
key and `op` at the final outcome. Every message has EN and zh text.

**W95's loader cut probe.** Its N3_FULL and N3_NOT_LOADED cuts registered their own BAY index on the runtime authority,
which now throws because the runtime registers BAY. They substitute a synthetic BAY index through a gated runtime seam
and restore the store's attachment afterwards; the oracle does not parse the changed `bay=` field.

## 5. Choices where the design was open

- **Package.** The new classes live in `resourceescrow`, beside the runtime that owns the authority, so `Store`,
  `retarget` and `noFile` stay package-private.
- **Writer.** A new class with `EscrowLedgerWriter`'s state machine rather than a change to the escrow writer, whose
  contract encodes and validates on the owner thread and whose tests must pass unchanged. `RocketJournalWriter` lacks
  exact completions, the unavailability count, the cadence and the guard. On a definite failure the store cancels the
  generation's mutations before the successor captures (the escrow writer captures first and cancels after); so a
  successor never carries a cancelled mutation.
- **The key.** "Unique key" is read as unique `(rocket, bay)`: section 6 speaks of X "keyed to another `(rocket,
  bay)`", and with one receipt per satellite the full triple would be unique anyway.
- **Hashes.** `src_before` and `dst_before` are required in every phase (D1 always has the checked T); the two after
  hashes are optional, and REGISTERED requires both. `reason` is an upper-case name (`[A-Z][A-Z0-9_]`, at most 40).
  Ticks and the registry epoch must not be negative; no order between ticks is required, because the server tick
  count restarts with each session. Sequences need only be issued, not unique.
- **Released receipts.** The flag never goes back to 0, a released receipt never becomes INTENT from another phase,
  and it cannot be removed online (the store refuses, and so does the command).
- **The byte reservation** charges each retained op at its 1,024-byte ceiling, a separate check; since 4,096 times 1,024 is
  4,194,304, its boundary coincides with the count, so it never refuses alone under these constants. SERVER_FULL
  answers before OWNER_FULL, as SERVER_FULL does before ROCKET_FULL.
- **Non-mutating checks.** `checkReserve` and `checkRetain` were added so a put can check both results and charge
  neither on refusal; the frozen `tryReserve` and `tryRetain` results and the no-release rule are unchanged.
- **Registration time.** BAY registers, NOT_LOADED, when the authority is created: at `ServerStartingEvent`, or at an
  earlier ledger bind (W93's case). It loads in the startup handler either way. In that early window PROPULSION
  admission answers UNAVAILABLE until BAY loads.
- **Startup states.** A file that exists but did not load, or whose presence cannot be proven absent, keeps NOT_LOADED
  with one WARN. The first admission from NO_FILE creates the root; its first generation creates the file. If that first
  write fails definitely, the store stays LOADED and empty with no file until the next start, which finds NO_FILE.
- **The command.** Permission 2, as `/arce rocket recover`, for any source; the audit operator is the player's name and
  UUID, or the source's text name, bounded to 80 printable characters. A transaction-journal disassembly record names
  the physical entity rather than the logical rocket, so any disassembly record refuses (TRANSACTION_RECORD). An
  unreadable journal refuses. The command answers at once; the final result follows the exact acknowledgement.
- **Insertion** also fails closed while the runtime is missing or stopping.
- **Recovery hint.** A world with a receipt file gets the whole-world hint at a refused start, as one with a ledger does.
- **GameTests** use their own batch, `satellite_bay_receipts`, so no concurrently running test can plant a journal
  record or read the shared counts while a fixture receipt exists.

**R-039 and ADR-065's W27c1 note.** What I built matches both. Two notes for Root, neither a contradiction: BAY can
register before `ServerStartingEvent` when a ledger binds early (it still starts NOT_LOADED and loads in that handler);
and R-039's "可重试的失败每 200 tick 以同一候选重试" is implemented for unknown outcomes, while a definite failure before
replacement cancels the attempt, as W27A section 4's D1 row states.

## 7. Known risks

- The store's index is rebuilt after each change from up to three roots of at most 4,096 receipts, and a capture copies
  up to 4,096 references; neither was measured at the 4 MiB bound (the W27d benchmarks).
- A drain that gives up after three unknown outcomes at stop publishes no outcome, so a retirement in flight then has
  no audit line; the file stays authoritative and restart reads it. (Superseded: W27c1F writes the audit line when the
  removal is queued.)
- The command's conservative journal check can refuse a valid retirement while any disassembly record exists.
- The command reports the final outcome to the source that ran it; an operator who left meanwhile sees only the log.

### Choices where the decision was open

- **Order.** R2 was committed before R1, as explained above.
- **BUSY first.** BUSY is checked right after STORE_UNAVAILABLE, before RELEASED_LOCKED and the uniqueness checks, so
  those run only on a settled op and satellite. A removal also answers BUSY, rather than INVALID, while the op's own
  removal is in flight.
- **R1 timing.** The first recovery generation starts 200 ticks after the failed write that made the store unavailable,
  and each later one 200 ticks after the previous failure. The generation carries the store's issued-sequence counter,
  which may be higher than the durable one after cancelled puts; the receipts are unchanged. If the store was created
  from NO_FILE and no write ever committed, the recovery generation creates the file with no receipts. No new log line
  was added: the existing WARN at unavailability and INFO at availability bound the volume.
- **R6 logging.** Each writer logs one ERROR line with the cause when its IO task throws an Error. No GameTest reaches it,
  so no log expectation was added.
- **R7.** Refusing was chosen over remembering the prior state, because `retarget` cannot return to NOT_LOADED.
- **R8.** A mismatch throws. The authority has no release call, so a mismatched charge that did reserve cannot be undone;
  this cannot happen with the current authority.
