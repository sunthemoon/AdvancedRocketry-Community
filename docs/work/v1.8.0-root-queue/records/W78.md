## Cause and design

The original test did not guarantee its claimed one-production-tick observation window:

1. `roomWithBed` calls `placePreparedVent`, which manually observes the new vent once. The first atmosphere tick
   can therefore supply a room whose chunk has not yet loaded the entity sections needed for native block-entity
   ticking. This is the false readiness described in [W74](W74.md).
2. On that false readiness, the test called the small-room sleep checks and placed the large room, even though its
   own vent chunk was not live. On subsequent atmosphere ticks, unobserved vents were pruned and the large scan
   disappeared. The diagnostic logs show its air changing from PENDING to VACUUM.
3. Every later callback first waited for BOTH small rooms to become supplied again. Thus it skipped the actual
   next-tick PENDING sample and eventually checked a later state. The two original-code runs sampled after four
   and five service ticks, not one. Each callback advanced the service counter by one; the extra ticks came from
   this readiness loop, not multiple production scans in one callback.

The historical W11B2 C09/C14 failures reported no active scan and only the small room's 18 indexed cells. That is
consistent with a cancelled/unavailable large-room scan, not a successfully supplied large room. These old logs
do not include per-tick readiness, so their exact scheduling cannot be reconstructed.

The fixture now reuses W74's `NaturalBedFixtures.Room.live()` for the two supplying chunks AND the pending room's
chunk, and excludes atmosphere state from the setup tick's manual observations. After placement it never waits
on readiness again: it asserts that exactly one server tick and one atmosphere service tick elapsed, and that
the supplying rooms stayed live and supplied. It then runs the existing admission, incomplete-provider, PENDING,
and pending-sleep refusal assertions. The existing admission loop still runs on both qualified callbacks.
There is no new synchronous setup wait, extra manual atmosphere tick, timeout increase, or test split. No ADR
choice or exception was needed.
