## Design choices and boundaries

The server-scoped service is an overworld capability; no global static world collections are
introduced. The schema/format epoch and managed data ID are explicit. Native FluidStack
round trips, UUIDs, canonical resource IDs, contiguous epochs, counts, NBT types, unknown
fields, depth, nodes and byte envelopes reject rather than normalize malformed input.

Only the current fluid-fill model is supported. Floors and tombstones have structural codecs,
but this slice does not install production floors, reservations, settlement intent or operator
commands. Test signatures represent the fixture's amount/identity, not rocket snapshot hashes.

The ledger has one background writer and a bounded owner-thread completion queue. A checked
success publishes authority before successor capture; definite-failure cancellation follows
successor capture. Unknown replacement freezes the exact candidate and retries at 200 ticks.
Three unresolved failures make admission unavailable; only an exact later acknowledgement
clears it. Shutdown pumps only writer callbacks and joins its thread while world storage is
open. New barriers quiesce before drain, but previously delivered proof tokens remain valid until
the writer finishes (`R/EscrowRuntime.java:100-106`, `R/EscrowBarrier.java:142-148`). Native G3L2
first exposed a real early-invalidation bug; the corrected run preserves L2 through shutdown.
Permanently unresolved IO can prevent clean shutdown; a hard stop is not called a drain.

The barrier serializes at most one endpoint chunk per tick, retains its own store future,
forces each original worker once in a Level's 20-tick batch, and reads disk with one bounded
reader. It limits pending attempts, terrain/entity batch counts and charged capture bytes.
Anvil proof checks the header, compressed bytes and file attributes twice; it never uses an
IOWorker pending read. Oversize/external data is refused, never truncated into a vanilla save.
Windows lacks portable directory-channel forcing, so directory force is omitted there; this
is not a power-loss guarantee.

## Open acceptance items and risks

1. The saturated 256-region terrain **and** entity cache benchmark is not implemented/run.
   There is no accepted main-thread/IO/vanilla-load-queue latency, allocation/GC, reference-load,
   both `sync-chunk-writes` settings or soak result. Empty fixture servers are not performance evidence.
2. The reason enums/codecs and retry intervals are implemented, but there is no automatic fair
   reconciliation scheduler or persisted three-failure STALLED recovery. E5's blocked/unloaded
   work, recovery and multiple-restart fairness matrix is not implemented/run.
3. E1/E3 remain **diagnostic, not PASS**. No OS-level failure was injected into the original
   vanilla worker, and no additional AT seam replacing its RegionFileStorage was introduced.
   An own completed failure cannot be inferred from a later synchronize result. A failed
   unrelated eviction close or an external-file move can be unobservable to vanilla's caller.
   The design review's residual applies; its risk entry is pending Root. Existing unit reader
   refusals and injected ledger failures do not prove these original-worker failure cases.
4. Native E2 tests observed supersession, not every header/external/bounds case; those reader
   checks are A0 native-file fixtures. Native E4 covers definite/ambiguous replacement, while
   autosave/explicit overlap and successor cancellation are covered in A0/A1, not a complete
   native overlap/stale-callback matrix. Some runtime capture/scheduling bounds and codec-specific
   count/byte combinations still lack explicit at-limit tests, including native at-limit runs.
5. A later own capture invalidates an earlier same-slot proof. The chain fixture deliberately
   uses separate source chunks. Joint proof/retirement for several endpoints in one terrain
   slot, and pruning retired markers when only an earlier chain prefix retires, require further
   adapter work. The native chain retires both operations together; it tests refusal of a later
   link alone, not successful partial live-marker retirement.
6. Direct writes by other mods/tools bypass the event/decorator monitor. Unobservable vanilla
   write failures after confirmation, including between confirmation and L2 or after L2, can
   lose/regenerate/omit a chunk with no retired escrow diagnosis remaining. These are not
   guaranteed by stopped-process S2 tests. No hardware/OS crash, per-file rollback or real
   production resource interlock is covered here.
7. An independent actual-diff persistence review has not occurred in this worker. Root must
   perform it and add the C3 risk/ADR note before integration. W11b2/W11b3 and production
   admission must not proceed on an assumption that all W11b1 acceptance items are complete.
8. Root cleanup of the ignored generated GameTest server directory remains necessary because
   the tool rejected recursive deletion. It is not a source world or committed evidence.

## Proposed Root risk entry / ADR-065 implementation note

This text is a proposal for Root's record, not an accepted ADR or allocated risk ID:

> RESOURCE_ESCROW is a schema-1, lazy managed root. While production admission is disabled,
> an absent root remains absent; only gated fixtures create one. An existing future or invalid
> root refuses the **entire world's startup**, preserves its raw bytes and performs no online
> deletion, fallback or per-file restoration. The refusal persists across restarts until a
> compatible offline whole-world repair succeeds. One bounded startup diagnostic and its
> exception stack are emitted per failed startup; repeated launches have no lifetime log cap.
> Recovery requires stopping the server, backing up all Levels' terrain/entities/POI plus
> global data/journals/ledger, player data and metadata together with hashes, repairing only a
> copy or restoring one consistent complete backup, preserving malformed originals, then
> native validation, conservation checks, two save/restart cycles and fresh endpoint proofs
> on the copy. Never delete or restore only the escrow root. No online command repairs this
> startup refusal. Unresolved records share the server-wide capacity of 64; exhaustion refuses
> new admissions. The separate endpoint chunk/Level save-veto scope and unobservable vanilla
> writer residual need their own explicit integration risk entries, without accepting R-021
> or claiming that stopped-process S2 covers storage faults, power loss or arbitrary rollback.

### Choices where the design or ADR left room

- **Shutdown bound.** Design section 6 says that stuck IO means shutdown has not completed.
  Root's decision is that shutdown must always finish. The drain therefore stops retrying one
  unresolved candidate after three further unknown outcomes (`DRAIN_UNKNOWN_ATTEMPTS`),
  logs one WARN and joins the IO thread. For the ledger this is the same as a hard stop:
  restart validates the target file, which holds either the old or the new generation, and
  both are covered by the S2 model. Vanilla's final save still runs. An IO system call that
  never returns still holds shutdown, because releasing world ownership while a rename may
  land is unsafe.
- **Durable generation match.** Before this session commits, the writer knows only the
  loaded generation number, so the match uses ledger ID and generation. After a commit it also
  requires the payload digest.
- **Crash hook.** The fallback runs on the overworld's `LevelEvent.Unload`, which comes before
  storage is released, instead of only on `ServerStoppedEvent`, which comes after.
- **Freeze refusal.** `freeze()` throws, like its existing prefix check; callers check
  `admitting()` first. A chained credit therefore waits for its L1 acknowledgement (at most
  one 10-tick cadence) before its endpoint can be frozen.
- **Log levels.** INFO for backoff and recovery lines, WARN for STALLED, repair,
  unavailability and abandoned shutdown retries.
