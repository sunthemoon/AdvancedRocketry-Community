## Choices where the task was open

- **Exact rows or patterns.** R295 allows one row per file or per exact pattern. Narrow patterns that match exactly
  their group's files and nothing governed earlier (`space_*.png`, `jetpack*.png`, `sawBlade.*`) are converted in
  place; the four broad wildcards, which would otherwise become unused rules, are replaced by exact rows.
- **Owner trimming.** Owners were only removed, never added: the active face drops `block:blastbrick` (its sole
  upstream consumer is `blockstates/arcfurnace.json`), and the split item meshes name only their own motor or tank
  unit. The block tank rows keep the existing `block:fuelTank`, though upstream also used them in three other tank
  blockstates.
- **U1 reason.** Upstream drew the four slot icons in its suit HUD, not in the workstation, so the reason names both
  R292's workstation slots and `LifeSupportHud`'s module text.
- **Validator fixtures.** Three tests used the active face as an unimported IMPORT fixture. They now restore its former
  row first, the pattern the nuclear-model test already uses; the assertions and the IMPORT precondition are unchanged.
  `test_model_textures_do_not_land_after_their_model` still sets the owner of `models/block/models/*`; that call was
  already a no-op at the base (W260 set the same owner) and matches no rule once the draft removes the wildcard, while
  its assertion still holds through the exact nuclear rows. It was left unchanged.
- **Upstream checkout.** W229's shared upstream checkout has CRLF working files (`core.autocrlf`), which made the
  content-inventory check fail on a Java hash in a stopped first run. The final run uses this session's LF clone
  `D:/GitHub/ARCE-Task-Evidence/root-queue/W267/upstream-lf` of the same pinned commit, as CI's Linux checkout does.
  W229's checkout was not changed.
