## Findings, most severe first

### M1 — Medium: decoding a subsequently refused workstation root changes its original armor tag

**Location:** [SuitWorkstationSave.java:41](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/equipment/workstation/SuitWorkstationSave.java#L41), with quarantine publication at [SuitWorkstationBlockEntity.java:127-130](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/equipment/workstation/SuitWorkstationBlockEntity.java#L127).

**Concrete input:** load this small, bounded workstation root (Count is a byte; Damage is deliberately a string):

```snbt
arce_suit_workstation: {
  schema_version: 1,
  armor: {
    id: "advancedrocketrycommunity:space_suit_helmet", Count: 1b,
    tag: {
      Damage: "keep-verbatim",
      arce_suit_equipment: {schema_version: 2, future_data: "retain"}
    }
  },
  transfer: {id: "advancedrocketrycommunity:future_module", Count: 1b}
}
```

The first slot passes the stack-envelope checks and is passed directly to `ItemStack.of(saved)`. The native constructor retains the supplied `tag` compound by reference. Because the helmet is damageable, it reads the nonnumeric Damage as zero and writes integer Damage=0 into that same compound. The loop then encounters the unknown transfer item and returns null. `load` copies the now-modified raw root into `refused`; a later save emits Damage=0, not the original string. The nested future equipment payload is not edited, but the promised verbatim preservation of the refused workstation root is broken, and the original malformed field cannot be recovered from the new save.

**Checked by reading**, including the local Forge 47.4.10 ItemStack patch, mapped ItemStack/CompoundTag bytecode, Forge's default damage reader/writer, and the actual iron-material suit registration. No native reproduction test was run. The existing future-workstation GameTest uses root schema 2, which short-circuits before slot deserialization and does not cover this case.

**Fix/check:** preflight both slot envelopes before native deserialization, and deserialize bounded detached copies rather than the retained raw compounds. Add a refusal round-trip test that snapshots this input before `load` and compares the entire saved raw root afterward. Also check an invalid second slot after a first slot with missing or noncanonical Damage.

**Post-merge safety rationale:** this example is already unsupported/malformed; it cannot install/remove modules or permit ordinary workstation destruction. Supported integer durability, component counts and finite gas roots are not altered by this particular failure. The follow-up must preserve the original raw input, not normalize it or weaken the refusal assertion.

### L1 — Low: the save-guard trigger documentation excludes below-budget noncanonical NBT

**Location:** [ADR-066:118-119](../../../../docs/decisions/ADR-066-CLASSIC-LIFE-SUPPORT-EQUIPMENT-RESEARCH-AND-PRESENTATION.md#L118) and [R-026:5](../../../../docs/11-RISK-REGISTER.md#L5). Actual admission is [SuitWorkstationProtection.java:32-34](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/equipment/workstation/SuitWorkstationProtection.java#L32), using [BoundedNbt.java:47-48](../../../../src/main/java/io/github/sunthemoon/advancedrocketrycommunity/persistence/BoundedNbt.java#L47).

**Concrete input/state:** an unsupported schema-2 workstation root contains an empty list whose binary element-type byte is TAG_Compound (10), with length zero. This root can be far below 64 KiB, depth 16 and 1,024 nodes. Native NBT loading preserves that empty list's declared type. `BoundedNbt.fits` nevertheless returns false for the non-TAG_End empty list, so the workstation retains the raw root and its next chunk-save event calls `GuardedChunkSaves.refuse`. Terrain writes for that chunk are then denied until the Level ends, despite none of the three advertised numeric limits being exceeded.

**Wrong documented outcome:** the implementation note says the guard is used "only" above the numeric limits, and R-026 lists only those limits as triggers. An operator following that statement would incorrectly exclude a small retained root as the cause of a save denial. The guard's prevention of native normalization is appropriate; this finding requests documentation, not a weaker guard.

**Checked by reading** the guard, its bound helper, and the local mapped `ListTag$1.load` bytecode, which retains the read type when constructing an empty list. No save event was executed.

**Fix/check:** document that native-write/noncanonical-NBT refusal is also a trigger, including typed empty lists (and the helper's other representability checks). Keep the existing whole-chunk/Level scope, lifecycle, unlimited retry-log warning and offline backup/repair procedure.
