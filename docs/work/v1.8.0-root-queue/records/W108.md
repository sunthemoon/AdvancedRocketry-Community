## Implementation

The command's `create` action assembles without launching. The shared Java `create()` helper
and all adapter GameTests are unchanged. The runner checks the assembled package is present,
waits for at least ten observed game-time ticks, then sends the existing launch command and
checks package consumption. The reinstalled claim and replay receive the same tick-based gap.
Polling sleeps only pace queries; they never satisfy the tick condition. Each wait has a ten-second
deadline and refuses a backwards clock. The phase result records the two observed endpoints.

The original replay assertion remains exactly code 9. The TASK calls this an IDEMPOTENT result,
but the production enum names ordinal 9 `MISSION_NOT_FOUND` (ordinal 1 is `IDEMPOTENT`): a successful
data claim clears `current_mission_id`, so the next terminal claim has no current mission. The
smoke's no-duplicate-reward checks and operator `ALREADY_CLAIMED` replay are preserved.
