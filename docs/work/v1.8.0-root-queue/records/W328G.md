## Design choices and evidence limits

- R397's production deduplication is unchanged. Reevaluation remains limited to once per record per 1,200 ticks and
  twice per server tick, with at most one join/leave reason transition between successive reevaluations. Joins and
  leaves do not share that throttle; the three boundary WARNs are compatible with these budgets.
- The boundary test uses W328F's existing `classifyGoverned` route into the shared private `fence`, and `reevaluate`,
  with the governed fixture and traced reasons. It is not a native join-scheduling or event-rate measurement.
- The new join test is **structural evidence, not cold-start evidence**. Its approved direct calls contain no resource
  transfer, admission or ledger write. It does not establish callee behavior, branch execution or a real
  UNCLASSIFIED join end to end. It reads bytes without loading Minecraft classes, so it needs no Minecraft bootstrap.
- No ADR choice was open or changed. No production code, save schema, network protocol, assets or provenance changed.
