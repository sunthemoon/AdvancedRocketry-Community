# W216: ground-survey START preflight

## Design before implementation (2026-10-30)

The assigned worker starts from `31099ce8488aab0520e7effa3c494c42275d527f`,
clean on `codex/v1.8.0-w216`. Root remains Claude. The write scope is satellite
registry sizing and its mutation hooks, related satellite unit tests, this record,
and external diagnostics in `D:/GitHub/ARCE-Task-Evidence/root-queue/W216/`.
No upstream material, format, schema, budget, bound, timeout, measurement sample
count, ADR, status file or ledger changes are included. No push or delegation.

`groundMutationFits` currently encodes every original resident before replacing
the touched job, instance and account, advances the candidate epoch, writes the
payload inside the native `data` wrapper, and compresses/reads it back. It proves
canonical per-record encodability, payload bytes <= 16 MiB, compressed/expanded
wrapper quotas, native reader depth/declaration/heap quotas and NBT equality.
It does **not** run the domain decoder or prove semantic reload compatibility,
cross-record invariants, section capacity, or durability. The caller separately
checks capacity, reservations, both original/candidate invariants and epoch
overflow, in that order. START needs the same answer, not compression itself.

Keep numeric measurements for each resident immutable record, owned by its
registry: list-element encoded bytes and native reader heap charge. Compute them
from the unchanged canonical encoder and a native uncompressed read/equality
check at the actual record nesting depth. Include the list's per-element heap
charge; derive fixed root/wrapper framing from the existing empty-root encoder.
Maintain totals and an unknown count on insertion, replacement and removal.
Mutation/load must never fail merely because eager measurement fails: catch a
runtime sizing failure, mark that resident unknown and retain the old whole-root
fallback. No mutable NBT or serialized record buffers survive measurement.

When all residents are known, subtract the old touched measurements and add only
the candidate job, instance and account measurements. The original residents
must all be encodable even when one is being removed/replaced, as before. Fixed
width clock/epoch edits do not change sizes; still evaluate the existing epoch
checks. Native NBT equality is compositional for these canonical compounds and
homogeneous lists. Exact raw bytes and exact accumulated reader charges retain
the inclusive byte/heap bounds. Canonical records have bounded strings/arrays,
no duplicate compound keys or arbitrary tags, and shallow depth; the native
round trip checks the record shape. The reader's individual declaration guard
is backed by the serialized elements, with its existing fixed slack. At <=16 MiB,
the fixed wrapper and gzip stored-block overhead fit the unchanged 64 KiB file
margin. Thus compression adds no separate START decision for these encodings.
Tests will compare both native reader charge and the actual whole-root oracle,
including exactly-at-bound and +/-1-byte roots; no quota is substituted or raised.

Restore/migration reconstruct measurements from decoded canonical records, not
raw file lengths. Repairs replace the corresponding measurements before the
registry is exposed. Every satellite, mission, instance, ground-job and account
mutation/removal must update the index, including retention and account recovery.
Unknown measurements keep fallback eligibility until replacement/removal; a
transient failed sizing is retried by the unchanged oracle, so it cannot turn
into a new refusal. Failed preflight retains all records, counters, clocks and
epochs. Existing STORAGE_BUDGET, CAPACITY_REACHED and INVARIANT_FAILED ordering,
section reservations, loaded over-budget acceptance and writer behavior stay.

Extra retained state is bounded by the existing 20,480 resident-record cap:
identity keys plus two numeric counts per record, estimated below 2 MiB with
compressed references. Removed/replaced versions are released. Work per ordinary
mutation is bounded to its changed records; no deferred root encode on the first
START after load. Loading pays the bounded per-record measurement once. Unknown
resident sizing remains the exceptional whole-root path, not a new save refusal.

## Implementation

The design was committed as `b42f6e228`. Failing-first tests were committed as
`8175812`, with the second survey fixture's admission timestamp corrected in
`493c93c88`. Production and final tests are committed as
`7fc12970b258ddf09c07fa5ec7ab2235c5e1d1d2`. Nothing was pushed or merged.

`RecordEncodingIndex` holds identity-keyed numeric measurements and running byte,
heap and unknown totals. `SatelliteMissionRegistry` and `GroundSurveys` update it
at all resident insertions, replacements and removals, including load repairs,
account recovery, ordinary mission/satellite changes and retention. The registry
remains 799 lines; the separate index and preflight helper keep measurement out
of its existing scheduling/admission responsibilities. `StorageBudget` and every
lifecycle reservation are unchanged.

`ExactGroundPreflight` writes and natively reads only a changed record, at depth
3 in the real wrapper/list structure. Its measurement excludes the three-byte
named header and includes the containing list's four-byte heap charge. The fixed
framing is measured from the existing encoder, not a duplicated field-size
formula. Unit tests compare both sums with complete native encodings and actual
`NbtAccounter` charges. No NBT or serialized bytes are retained.

The individual-declaration proof is stronger than just valid record shape: a
root within 16 MiB leaves almost 64 KiB of the expanded reader limit unused, and
the compressed estimate also includes 64 KiB of inflated slack. The largest
section declaration is 8,192 * 4 = 32,768 bytes; record declarations are bounded
by their <=4 KiB encodings. Both are below the guard's four-times-remaining-byte
allowance. The fixed wrapper and gzip overhead fit the existing 64 KiB margin.
Native equality and depth are checked per record; accumulated heap quota is
checked exactly. Compression/readback therefore adds no further answer for a
known canonical candidate. Unknown eager sizing retains the original fallback,
including its retry, refusal and arithmetic-exception behavior.

At 20,480 residents, an `IdentityHashMap` with 65,536 reference slots is about
256 KiB with compressed references, and 20,480 two-long measurement records are
about 640 KiB. Allowing object/table overhead remains below the design's 2 MiB
estimate. Existing resident objects are shared, and removed versions are not
retained. This is an estimate, not a heap-dump measurement. Eager load/mutation
measurement is the deliberate trade-off; exceptional unknown roots remain costly.

be reduced to a fitting candidate, as the old oracle allowed. The near-bound
allocation check includes the first START after reload, without cache warm-up.

## Remaining scope, risks and acceptance

No open ADR choice was exercised and no new save-refusal policy was introduced.
The change derives admission evidence from the same canonical record encoders;
the actual save writer and recovery policy still run unchanged. There is no
on-disk migration or public/persistent ID change to roll back.

The cache depends on immutable resident values and complete mutation hooks.
Future registry mutation paths must update it; the exact-total/lifecycle tests
cover all existing paths. Loading and publication now pay small eager native
record measurements, and the index retains bounded numeric state. Roots with an
unknown measurement deliberately retain the old expensive fallback until that
resident is replaced/removed. Existing normalized-record encoding failures are
not repaired or newly admitted by this optimization.

The task's implementation, local unit verification and host measurements do not
approve v1.8.0 or any Required Gate. No full `clean build`, `runData`, native
restart, real-client visual/multiplayer, soak or Debian reference-host run is
claimed here. There are no generator/asset/client changes; TASK-W216 explicitly
assigns complete GameTest regression to Root's hosted run. The independent
read-only review and that regression remain required before merge. No status,
ledger, version tag or shared branch was changed, and nothing was pushed.

The next work is Root's independent review of this committed v1.8.0 slice and
hosted regression, including the original near-bound START incident. The local
performance evidence alone does not close that hosted observation.
