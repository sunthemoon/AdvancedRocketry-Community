## Design decisions and tests

The original 34 families keep their names, order and command arguments. The
driver now has 51 families. Families 35-44 follow the timing runner's `CASES`
order: `B12_D4`, `B12_D7`, `B13_FAILED`, `B13_UNKNOWN`, `B16_MOTION`,
`B10_BLOCKED`, `RECONNECT`, `TURNS` with two claims, `TURNS` with three claims,
and `D6_RETRY`. Their names begin with `w336-timing-`; the two proof-turn names
end in `TURNS-2` and `TURNS-3`. Families 45-50 are `w336-saturation-` followed
by `bay`, `item-load`, `item-unload`, `fluid-load`, `fluid-unload` and `fuel`.
Family 51 is `w336-downgrade`.

Only the original bay runners receive `--stop-on-failure`. No command receives
`--smoke`. W336 commands retain all required common arguments and use the
runners' unchanged window and timeout defaults. An underlying timing failure
stops later timing families, but independent runners continue.

`--downgrade-old-jar` and `--downgrade-old-jar-sha256` are independent of G2's
`--old-jar` and `--old-source-commit`. Missing requirements are listed only
when their family is selected; native mode refuses them before any lock or
runner. When downgrade is selected, every preflight verifies its old JAR bytes
against the supplied hash, including before and after lock acquisition. The
unchanged downgrade runner additionally enforces W176's exact historical pin.

Downgrade invocation records retain the actual `exit_code` and the raw
`runner_status` from `native/results.json`, if produced. Missing or non-PASS
status cannot become a passing downgrade, even if the exit code is zero. A
nonzero exit remains failed. W176's failed whole-world verdict is not waived,
and does not block any other underlying runner.

The real-CLI parse test now constructs and exercises each target runner's own
parser for all 51 commands, faking only execution. Coverage checks exact timing
case multiplicities, the two proof-turn claim counts, all six saturation kinds,
and the single downgrade family. Other checks cover distinct G2/W176 inputs,
missing inputs, invalid hashes, pre-lock and post-lock refusals, timing failure
isolation, and failed downgrade status/exit preservation with independent
runners continuing. The existing driver family-count pins changed from 34 to
51 in the plan total and both dry-run totals because 17 families were appended.
Driver fixtures now include the new optional inputs and expected requirements;
no existing runner test or assertion was weakened. No ADR decision, schema,
network protocol, migration policy or save protection changed.
