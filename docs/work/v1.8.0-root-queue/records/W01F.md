# W01F: independent review fixes

## Implementation design (2026-10-12)

The worktree started clean at `83fcf0ba` on `codex/v1.8.0-hatch-kernel`.
The complete assigned review was read and its SHA-256 matched the TASK.
The write scope is the W01 runtime, its tests, the R-021 classic-root extension,
the labelled ADR-064 section 11 implementation note, and this record. No other
machine, GuardedChunkSaves implementation, status file, ledger, build script,
upstream asset, or other worktree will change. No agent will be dispatched and
no commit will be pushed or merged.

Missing hatch roots become empty, unbound instances. Missing required controller
roots become fresh, unformed checkpoints, provided every present retained root
can be written unchanged. Present oversized, structurally unbounded or
nonrepresentable roots still use the existing sticky whole-chunk refusal; bounded
unsupported roots remain quarantined and are preserved verbatim. This does not
promise conservation of unrelated resources during the remaining refusal cases.
R-021 and ADR-064 will describe their duration, saturation, logs and offline repair.

Claims are retired only after loaded-only lookup establishes that the physical
controller position has no matching machine UUID. A matching unsupported owner
and an unloaded owner remain protected. Retirement clears binding/facade epochs,
not the plug's FE. Formation will reconcile generation skew only for an exact
loaded owner identity, without changing shared kernel binding policy or transferring
Item/Fluid ownership. Item-bank removal will spawn its drops at the controller.
Each finding has its own implementation/test commit. The final automated checks
are targeted classic JUnit, locked runData, locked GameTest and the log checker.

`ClassicControllerBlockEntity` and `ClassicHatchBlockEntity`. The writable-root

position assertions. Its existing foreign-claim test now creates an actual loaded
controller with the claimed UUID: an absent alleged owner is intentionally stale
under R2. No assertion, timeout, budget or log expectation was weakened.

Documentation changes are this record, the R-021 scope extension and the labelled
ADR-064 implementation note. No upstream file or asset was imported.

### Evidence, conservative choices and remaining work

Local unsealed supporting files are `build/w01f-tested-commit.txt`,
`build/w01f-unit-committed.log`, JUnit XMLs under `build/test-results/test/`,
`build/w01f-runData.log`, `build/w01f-datagen-diff.log`,
`build/w01f-gametest-server.log`, `build/w01f-gametest.log`,
`build/w01f-gametest-checker.log` and `build/w01f-cleanup.log`. Development unit
logs are retained separately with the `w01f-r1`, `w01f-r2`, `w01f-r3` and
`w01f-unit-final` names. These ignored outputs are not a sealed release packet.

A missing required controller root intentionally creates a new UUID and empty
checkpoint; this is not companion-root salvage or legacy migration. Present
unsafe companions prevent that reset. Claim retirement does not infer an identity
from an unsupported controller. Generation reconciliation advances only older
bindings. The reverse-save-order test covers an immediate successor through the
unchanged kernel gateway; parts more than one generation ahead of the loaded
controller still fail closed. No shared gateway policy was expanded.

The constructors and public/protected runtime shape remain unchanged for W05.
W05 should retain these inherited load/removal/rebind behaviours when integrating
its controllers and include its new BlockEntity IDs in its save-admission coverage.
Foreign-claim tests must represent an actual owner or an unavailable position,
not an absent loaded alleged owner that R2 deliberately retires.

Remaining risks are the documented whole-chunk/Level refusal, unbounded retry/log
volume, independent-store divergence, and indefinitely unavailable or unsupported
owners. The chest/player test shows admission and NBT transfer conservation when
missing roots no longer cause refusal; it does not prove conservation during a
remaining unsafe-root refusal or native writer/crash durability. Plug FE retains
the existing external/per-tick crash-atomicity exclusion.

All assigned W01F automated checks passed. **The complete v1.8.0 Required Gates
are not satisfied or declared passed.** No `clean build`, packaged dedicated-server
restart, forced crash, administrator repair/writer proof, GPU V1/V2 or hosted CI
regression was run here. Root still needs independent integration review and its
full regression/acceptance evidence within v1.8.0; no later-version feature is
recommended or implemented.
