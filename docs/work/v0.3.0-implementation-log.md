## Goal

Deliver an Earth/Moon/Space celestial slice with bounded data definitions,
stable `ResourceKey<Level>` identities, fixed Moon and Space worlds,
schema-versioned global state, safe operator commands, a finite client display
snapshot, and a secure import-only legacy XML adapter.

## Scope and non-goals

In scope: three definitions, parent/orbit/atmosphere validation, immutable
reload catalog, Overworld `SavedData`, basic gravity/vacuum profile services,
fixed Level JSON, bounded safe-platform teleport, diagnostic commands, S2C
display snapshot, XML DTO/parser/export/report, DataGen, unit/GameTests,
packaged-server restart, two-player consistency, and visible client evidence.

Explicit non-goals: runtime Level registration, random planets, rocket travel,
space stations, atmosphere damage, life support, custom sky rendering, legacy
world loading, or support for every legacy XML tag.

## Decision log

- `2026-08-31`: accept ADR-001. Only the fixed Moon and Space Levels are data
  registered; catalog reload never changes the loaded Level registry.
- `2026-08-31`: use a project-owned Codec reload listener instead of a custom
  dynamic registry so invalid catalogs can be rejected atomically while fixed
  Level JSON remains vanilla-compatible.
- `2026-08-31`: keep legacy numeric dimension IDs in import diagnostics only.
  Runtime definitions, snapshots, commands, and SavedData use namespaced IDs.
- `2026-08-31`: create a bounded platform during operator `goto` rather than
  force-loading or populating arbitrary Space chunks continuously.
- `2026-08-31`: represent vacuum/gravity as profiles in v0.3; atmosphere damage
  and life-support enforcement remain v0.4 scope.
- `2026-08-31`: keep the legacy parser on bounded StAX DTOs and fail closed when
  DTD/entity support cannot be disabled; no DOM type enters the public adapter.
