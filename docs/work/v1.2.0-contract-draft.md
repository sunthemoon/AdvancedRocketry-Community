# v1.2.0 machine kernel contract draft

> 状态：`DRAFT`。本文件没有冻结任何 Java API、注册 ID 或 schema；前置
> Gate 未满足时不得据此实现生产代码。

## Dependency direction

```text
machine model
  -> process simulation and commit plan
  -> persistence / recovery + pattern validation
  -> Forge capability and BlockEntity adapters
  -> menu summary + optional client integrations
```

model/process/multiblock 核心不引用 `net.minecraft.client.*`。Minecraft 类型
在 Forge adapter 边界转换为稳定 `ResourceLocation`、数量和只读快照。

## Process contract

### Definition

`ProcessDefinition` 草案字段：

- stable recipe ID and `schemaVersion`;
- bounded `durationTicks` and `energyPerTick`;
- bounded lists of Item/Fluid requirements and products;
- no callbacks、world reference、BlockEntity 或客户端计算结果。

候选限制（冻结前需基准复核）：单类输入/输出列表各不超过 8，单 ingredient
variant 不超过 32，ID 不超过 128 字符，单定义编码不超过 64 KiB，
`durationTicks` 为 1–72,000，`energyPerTick` 为 1–16,384，累计能量使用
checked `long` 且不超过 `Integer.MAX_VALUE`。

### State and result

状态至少区分 `IDLE`、`RUNNING`、`WAITING_INPUT`、`WAITING_OUTPUT`、
`WAITING_ENERGY`、`REDSTONE_DISABLED`、`INVALID_RECIPE`、
`UNSUPPORTED_DATA` 和 `RECOVERY_REQUIRED`。失败返回稳定 reason code 与可选
诊断参数，不把本地化文本持久化。

`simulate(snapshot, definition)` 只产生不可变 `ProcessPlan`；它不能改物品、
流体或能量。`commit(plan, mutablePorts)` 必须比较 plan 捕获的 revision/fingerprint，
任何输入或输出变化都使提交失败并重新模拟。

### Recoverable atomic commit

完成批次使用独立 schema 的 journal：

1. `PREPARED` 保存 transaction ID、recipe ID、before/after bounded snapshots；
2. `APPLYING` 在实际 mutation 前持久化；
3. 同一 server thread 内应用完整 after snapshot；
4. `APPLIED` 后清除 journal并进入下一批。

恢复时：资源匹配 before 则应用 after；匹配 after 则只完成 journal；两者都
不匹配则进入 `RECOVERY_REQUIRED` 并停止处理。重复恢复必须幂等，不以清空
未知数据来继续运行。逐 tick 能量和 progress 单独保存；最终 Item/Fluid
扣料与产出只能由上述一次 commit 改变。

## Port contract

- Kind：`ITEM`、`FLUID`、`ENERGY`。
- Mode：`INPUT`、`OUTPUT`；只有明确机器需求时才允许 `BIDIRECTIONAL`。
- Side：使用 controller-local `FRONT/BACK/LEFT/RIGHT/TOP/BOTTOM/UNSIDED`，
  在 Forge adapter 中按 block facing 转换为世界 `Direction`。
- 每个 port 声明 channel、slot/tank range、过滤器和 insert/extract 权限。
- capability view 在 `reviveCaps` 创建一次，在 `invalidateCaps` 全部失效；
  查询不得分配新 wrapper 或触发结构扫描。
- 外部 capability 操作也遵守 process lock 与 transaction revision；输入锁定
  时不允许管道替换正在处理的资源。

## Pattern contract

### Definition and transforms

`MultiblockPatternDefinition` 包含 stable ID、schema、三轴尺寸、唯一 controller
anchor、完整 cells 和允许的水平旋转/镜像集合。cell matcher 支持：

- exact block/resource ID;
- block tag;
- air;
- controller;
- typed port;
- optional wrapper over one bounded matcher。

不支持任意 predicate、脚本或运行时类名。候选上限为每轴 16、总 cell 4,096、
port 64、一次返回 diagnostics 32；冻结前以 Arc Furnace 5×5×5 和三台代表
机器为下界复核。

坐标以 controller-local right/up/back 为正轴。只支持绕 Y 的 0/90/180/270°
旋转和 local-X 镜像；不允许把机器竖直翻转。transform 必须可逆并保持 anchor。

### Validation result

结果为结构化枚举：`FORMED`、`MISMATCH`、`WAITING_UNLOADED`、
`LIMIT_EXCEEDED`、`INVALID_DEFINITION`。diagnostic 至少含 reason code、局部
坐标、世界坐标以及 expected matcher 摘要；actual block ID 仅在已加载时读取。

validator 在读取 block state 前检查区块是否已加载。任何 cell 未加载时返回
`WAITING_UNLOADED`，不强制加载、不误解体、不部分绑定。一次验证最多访问
定义声明的 cell 数，不从相邻世界 flood fill。

## Controller and part lifecycle

- controller 保存独立 machine instance UUID、generation、formation state、
  selected transform、part positions 和 schema。
- part binding 保存 `ResourceKey<Level>`、controller `BlockPos`、instance UUID、
  generation 和 schema；不使用数字维度 ID 或全局静态集合。
- formation 先完整验证，再以有界 transaction 绑定全部已加载 part。
- 方块变化只标记 dirty；控制器按去重队列和 tick budget 重验证，不每 tick
  扫描结构。
- 区块卸载为 unknown/waiting，不是 disassembled。确认 mismatch、控制器删除
  或维度移除才解绑；解绑不得清空 port 内资源。
- stale generation、伪造坐标和跨维度 binding 必须拒绝且不得加载区块。

## Save and migration contract

- Electrolyzer 的 `arce_machine` schema 1 decoder 在 1.x 支持周期保留。
- 首次升级只转换状态，不运行 recipe、不扣资源、不生成结果；重复迁移幂等。
- future schema 原样保留并阻止运行，invalid data 提供可读错误且不覆盖副本。
- 新 process、journal、controller 和 part 各有独立 schema；不能用一个全局
  “machine version”替代对象级迁移。
- 单机器持久化 NBT 继续以 64 KiB 为默认硬上限；超限停止处理并报告。

## Menu and JEI boundary

- 菜单同步只包含 progress、duration、energy、formation state、reason code 与
  有界端口摘要；服务端库存仍通过标准 container/capability 处理。
- 不接受客户端提交 progress、完成状态、产出、结构匹配或最终配方。
- 打开菜单需要服务端校验玩家、距离、权限、controller generation 和已加载
  区块；重复/远程请求不加载区块。
- common 提供不可变 display view；JEI 实现仅在 client compat 包加载，JEI
  absent 时无类链接失败。v1.2 不冻结 v1.3 公共第三方 API。
