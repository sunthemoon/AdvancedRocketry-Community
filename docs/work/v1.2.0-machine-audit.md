# v1.2.0 machine and multiblock audit

## Audit boundary

本审计只产生行为分类和新架构输入，不复制上游 Java、LibVulpes 类、配方
JSON 或资产。上游固定为 `Advanced-Rocketry/AdvancedRocketry` 的
`c5cd5af62fc07cd4e0d24f06a16033f181c47c04`；下载字节先与
`legacy-manifest/java-files.csv`、`recipes.csv` 的 SHA-256 对照后再读取。

## Current implementation baseline

| Area | Current evidence | Extraction consequence |
|---|---|---|
| Process | `ElectrolyzerProcessEngine` 53 行，只表达单配方 pause/resume/completion | 可保留状态转移思想，但需支持可变 Item/Fluid 输出和提交恢复 |
| BlockEntity | `ElectrolyzerBlockEntity` 502 行，同时持有 tick、recipe cache、状态、能力、菜单与迁移适配 | 不能直接变成通用基类；Forge 生命周期应继续薄适配 |
| Storage/ports | `ElectrolyzerStorage` 239 行，固定四槽、单水箱、六个 `LazyOptional` view | side policy 和 view 生命周期可抽契约，具体槽位留在机器适配器 |
| Persistence | `ElectrolyzerPersistence` 236 行，`arce_machine` schema 1，64 KiB 上限 | 旧 decoder 必须保留；新过程提交状态使用独立 schema |
| Recipe | `ElectrolyzerRecipe` 263 行，单 Item ingredient、单 Fluid、双 Item output | 通用定义需有界列表，不能继承固定字段布局 |
| Menu | `ElectrolyzerMenu` 182 行，七个整数同步字段 | 通用同步只提供摘要，不创建结果型 C2S packet |
| Other adapters | Oxygen Vent 405 行、Fuel Loader 396 行、Satellite Terminal 669 行都自行管理 capability 生命周期 | port facade 应复用已有 Forge 约束，但不把非过程设备强塞进 process 基类 |

现有稳定身份：block/BlockEntity/menu 为
`advancedrocketrycommunity:electrolyzer`，recipe type/serializer 为
`advancedrocketrycommunity:electrolyzing`，机器 NBT 根键为 `arce_machine`，
schema 为 1。v1.2 迁移不得改变这些已持久化/公开身份。

## Upstream process-machine classification

维度按上游 `Object[][][]` 的 `depth × rows × columns` 记录；它们只描述旧
行为形状，不是新 pattern 文件格式。

| Legacy class | Shape | Audited recipe shape | Special behavior / risk | Priority |
|---|---:|---|---|---|
| `TileCentrifuge` | 4×3×3 | no JSON recipe in manifest | 大结构、多个 port token | later |
| `TileChemicalReactor` | 2×2×3 | 3 recipes；0–1 Item + 0–2 Fluid → 0–2 Item + 0–1 Fluid | 特殊 NBT/enchantment 消耗，最容易污染通用内核 | after kernel |
| `TileCrystallizer` | 2×2×3 | no JSON recipe in manifest | 重力条件影响运行 | later environment adapter |
| `TileCuttingMachine` | 1×2×3 | 4 recipes；1 Item → 3 Item stacks | 简单 Item-only 验证候选，但 Fluid port 不复用 | fallback representative |
| `TileElectricArcFurnace` | 5×5×5 | 4 recipes；1–2 Item → 2–3 Item stacks | 最大已审计结构、wildcard port、多材料标签 | later stress fixture |
| `TileElectrolyser` | 2×2×3 legacy | 1 recipe；1 Fluid → 2 Fluid | 旧行为与社区版单方块罐装输出不同；仅作历史参考 | selected compatibility machine |
| `TileLathe` | 2×1×4 | no JSON recipe in manifest | 简单结构但缺少本批数据配方 | later |
| `TilePrecisionAssembler` | 3×3×4 | 19 recipes；2–5 Item → 1–2 Item stacks | 多输入、wildcard port、独立进度接口 | selected complex machine |
| `TilePrecisionLaserEtcher` | 3×3×3 | 2 recipes；4 Item → 3 Item stacks | 高能耗、多输出，附带特殊耗材语义 | after kernel |
| `TileRollingMachine` | 2×3×5 | 4 recipes；1 Item + 1 Fluid → 2 Item stacks | 普通多方块同时验证 Item/Fluid/Energy port | selected ordinary multiblock |

十个类全部继承上游 `TileMultiblockMachine` 并导入 4–7 个 LibVulpes 类型。
因此不可将旧继承层复制到新项目；结构、端口、配方和诊断必须由社区版独立
建模。37 个过程配方的汇总范围是：1–12,000 tick、1–600 legacy energy、
0–5 Item inputs、0–2 Fluid inputs、0–3 Item outputs、0–2 Fluid outputs。
这些数值用于测试边界候选，不直接成为新配方平衡值。

## Representative-machine decision

### 1. Rolling Machine — first implementation target

- 普通 2×3×5 多方块，规模足以验证朝向、镜像、controller/part 和卸载。
- Item + Fluid 输入、Item 输出和 Energy 让三类 port 从第一台新机器即参与。
- 与现有 Electrolyzer 共享 Fluid/Item/Energy，但不共享固定槽位和玩家行为。

### 2. Electrolyzer — compatibility migration target

- 保持 v0.2–v1.1 的单方块外形、罐装产物、配方 ID、菜单和 schema 1 读取。
- 迁移只替换内部 process/port 适配，不把旧版多方块外形重新施加给玩家。
- 对比迁移前后 50-cycle ledger、GameTest、旧 NBT fixture 和菜单摘要。

### 3. Precision Assembler — complex validation target

- 2–5 Item 输入和 1–2 输出迫使 process plan 使用有界列表而非固定字段。
- 3×3×4 pattern 与 wildcard port 验证较复杂的 transform 和 port assignment。
- 本版只选择一组新创作/经来源批准的最小配方，不批量复制 19 个旧 JSON。

## Rejected alternatives for this slice

- Cutting Machine 适合作为 Item-only fallback，但不能让 Fluid port 获得第二个
  实际使用者，因此不作为前三台。
- Chemical Reactor 的特殊 NBT/enchantment 语义应作为内核完成后的适配器，
  不应决定第一版通用提交模型。
- Arc Furnace 的 5×5×5 结构适合 pattern 压力 fixture，但其 wildcard 和材料
  规模会扩大首个垂直切片。
- Crystallizer 的重力依赖属于环境扩展点，不进入基础过程状态机。

## Extraction list

只在前置 Gate 解除并冻结契约后实施：

1. 从 `ElectrolyzerProcessEngine` 提取 Minecraft-free 状态与原因，不继承 BE。
2. 把 simulate、commit 与可恢复 journal 分离；配方选择仍由服务端完成。
3. 将 capability side 判断表达为不可变 policy；每个 BE 只创建一次 view。
4. pattern validator 接收有界只读 world view；任何未加载 cell 返回 waiting。
5. controller/part binding 带 Level key、位置、generation 和 schema。
6. 先接 Rolling Machine，再迁移 Electrolyzer，最后接 Precision Assembler。
