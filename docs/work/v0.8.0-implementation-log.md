# v0.8.0 Implementation Log — Progression and data satellites

## Goal

Deliver one complete, server-authoritative research and data-satellite loop:
manufacture components, assemble and launch a logical satellite, let its
mission finish without its owner or chunks being loaded, claim research once,
and spend that research on a persisted celestial discovery.

## Scope and non-goals

In scope: bounded data-driven satellite definitions, logical satellite and
mission state, monotonic game-time scheduling, exact-once research credit,
celestial discovery, one powered Satellite Terminal, bound control chips,
operator recovery, client status, DataGen, dedicated/restart/multiplayer/stress
tests, and release evidence.

Out of scope: satellite entities, full legacy satellite selection, asteroid
mining, terraforming, microwave power, orbital weapons, rocket payload bays,
dynamic dimensions, complete research trees, LibVulpes/ARLib, and copied
upstream assets.

## Assumptions and accepted decisions

- v0.7.0 is `PASSED`; this branch starts from final evidence commit
  `6b33eaf0be1a01b7feceefe785d8fba7e9717b02`.
- ADR-010 is the accepted SavedData, clock, scheduler, claim, and terminal
  authority boundary.
- Existing machine casing, advanced circuit, and data storage recipes form the
  minimum manufacturing prerequisite; no general machine framework is added.
- New Java and generated JSON are community-authored. The locked upstream
  commit supplies behavior context only unless a provenance entry is approved
  before any import.

## Decision log

- `2026-09-01`: use one logical data-satellite type and a single combined
  terminal rather than restoring legacy multiblocks or orbiting entities.
- `2026-09-01`: player offline means the server continues advancing game time;
  a stopped server does not synthesize wall-clock progress.
- `2026-09-01`: research credit and mission claim share one SavedData mutation;
  celestial discovery is replayed idempotently through an explicit phase.
- `2026-09-01`: assembly/launch control uses a UUID-bound chip; clients never
  supply a coordinate, research amount, duration, yield, or authoritative NBT.
