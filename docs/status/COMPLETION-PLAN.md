# 至完成的分会话计划

更新：2026-09-30。v1.5 开发收尾（C1–C5）已在分支 `codex/v1.5.0-orbital-station-warp` 完成并推送；
v1.6 从 C6 开始，另开会话与分支。

本文件把从现在到 `v2.0.0` 的剩余工作拆成可以**一次一个会话**顺序完成的块，
避免单个会话上下文过大。块大小不求一致；每块结束时都有提交与推送，下一块
只需读本文件、`AGENTS.md` 要求的文件和对应版本文档即可开始。

本文件不是 Gate 批准，也不改变 `docs/04`、`docs/16` 的版本顺序与范围；
Codex/Claude 只能推进到 `READY_FOR_AUDIT`，`PASSED`/发布由维护者决定。

## 每个会话的固定做法

1. 读取 `AGENTS.md` 第 2 节要求的文件、本文件、当前版本文档、当前实施日志
   （`docs/work/<版本>-implementation-log.md`）顶部的“Segmented TODO”。
2. 只做本块范围；契约先行（ADR → 独立审核 → 接受 → 实现）。
3. 每个切片：Temp 证据目录 → 完整
   `gradlew clean build test runData runGameTestServer`（JAVA_HOME 为
   `C:/Program Files/Java/jdk-17.0.7`）→ 需要时原生专服 harness →
   `docs/work/<版本>-<切片>/` 证据包 → 校验器 → 提交 → 非强制推送。
4. 失败运行保留为证据；不删除、不放宽测试；不打 tag，不标记 PASSED。
5. 结束时更新本文件对应块的状态和“下一块”指针。
